F5 BIG-IP 中的六个严重漏洞允许攻击者在无需登录的情况下使流量管理微内核（TMM）崩溃，导致流量中断，直至 TMM 重启。

每个漏洞都需要在虚拟服务器上进行特定配置：使用特定命令的 iRule，或包含两种特定代理的 APM 策略。

BIG-IP 的制造商 F5 今日披露了这些漏洞，并表示它们还可能允许远程代码执行。该公司已发布工程热修复，且未列出任何变通方案。

根据该公司的评定，这六个漏洞在 CVSS v3.1 下均为 9.8，在 CVSS v4.0 下均为 9.3。它们是 BIG-IP 数据平面中的基于栈的缓冲区溢出；数据平面负责处理该系统几乎全部网络流量。据该公司称，管理端未暴露。

该公司的任何公告均未称这些漏洞已被利用。WatchTowr 研究员 Sina Kheirkhah 报告了其中四个，另外两个由公司自行发现。

其中五个漏洞位于 iRules，这是管理员用于管理流量的 BIG-IP 功能；另一个位于 BIG-IP 的 APM 模块。部分漏洞还会影响 BIG-IP Next for Kubernetes 和 BIG-IP CNF，后者是 BIG-IP 云原生版的一部分。

每个漏洞都需要在虚拟服务器上进行下列配置：

  • CVE-2026-123637：一项同时包含 Client Information 代理和 Endpoint Security 代理的 APM 每请求策略。仅影响 BIG-IP APM。
  • CVE-2026-121805：一项在客户端流量上使用 PEM::subscriber 的 iRule。影响 BIG-IP PEM、BIG-IP Next for Kubernetes，以及截至今日的 BIG-IP CNF。
  • CVE-2026-120292：一个 HTTP 配置文件和一项使用 MR::message route 的 iRule。影响 BIG-IP（所有模块）和 BIG-IP Next for Kubernetes。
  • CVE-2026-120285：一个 HTTP 配置文件和一项使用 PSC::ip_address 的 iRule。影响 BIG-IP（所有模块）、BIG-IP Next for Kubernetes，以及截至今日的 BIG-IP CNF。
  • CVE-2026-116953：一项在客户端流量上使用 GENERICMESSAGE::route 的 iRule。影响 BIG-IP（所有模块）和 BIG-IP Next for Kubernetes。
  • CVE-2026-120722：一项在客户端流量上使用 DNS::scrape 的 iRule。影响 BIG-IP DNS 和 BIG-IP Next for Kubernetes。该公司的公告将 BIG-IP CNF 列为不受影响，但其今日更新的 CVE 记录将 CNF 列为受影响。

F5 的安全通知列出了今日发布的 22 份公告，其中包括 10 份关于 NGINX 的公告。

对于这六个严重漏洞，唯一的修复方式是工程热修复，即公司在常规软件发布之间提供的构建版本。没有已排定的版本被列为修复方案，这些公告也未提供任何变通方案，直至安装热修复为止。

该公司警告称：“工程热修复不会经过已排定软件发布所进行的大范围 QA 评估。”其热修复政策补充称，热修复不附带任何保证，也不承诺其能够正常工作。

使用自定义工程热修复的系统需要从公司的支持团队获取新的热修复。

对于 2.4.0 至 2.4.2、2.3.0 至 2.3.4 以及 2.2.0 至 2.2.5 版本，BIG-IP Next for Kubernetes 分别在 BNK-2.4.2-EHF1、BNK-2.3.4-EHF1 和 BNK-2.2.5-EHF1 中修复。对于相同版本范围，BIG-IP CNF 针对 CVE-2026-121805 和 CVE-2026-120285 分别在 CNF-2.4.2-EHF1、CNF-2.3.4-EHF1 和 CNF-2.2.5-EHF1 中修复。

该公司仅检查仍处于技术支持期内的版本，因此其表格中未收录的较早版本并不能说明是安全的。

今天披露的漏洞不同于 CVE-2026-94127，后者是 F5 于 9 月 22 日披露、随后遭到利用的一个 APM 漏洞。美国网络安全与基础设施安全局（CISA）在同一天将其加入了“已知被利用漏洞”目录。

该漏洞是充当 OAuth 授权服务器的 APM 配置中的基于堆的缓冲区溢出，允许攻击者无需登录即可执行代码。今天披露的这六个漏洞是基于栈的溢出，需要不同的配置条件。

BIG-IP 和 BIG-IQ 的另外六个漏洞

今天的公告还涵盖 BIG-IP 和 BIG-IQ 中六个评级较低的漏洞，每个都有各自的修复。以下分数为 CVSS v3.1：

  • CVE-2026-125274（iControl SOAP，8.8）：拥有网络访问权限且至少具备 Guest 角色的用户可以发送未经授权的管理请求。该公司表示，这可能允许其运行系统命令、创建或删除文件，或禁用服务。该问题在 BIG-IP 21.1.0.3、17.5.1.10 和 17.1.3.6 中修复，在 BIG-IQ 8.4.2.3 中修复。在此之前，SOAP 公告介绍了如何将 iControl SOAP 访问限制在受信任网络内，并警告称在 self-IP 地址上阻止它可能会破坏高可用性配置。
  • CVE-2026-120718（iControl REST，8.1）：iControl REST 令牌可能不会按预期过期。已经持有令牌的攻击者可能能够延长其有效期，除非令牌的所有者将其删除。该问题在 BIG-IP 21.1.0.2、17.5.1.10 和 17.1.3.6 中修复。作为变通方案，可以修改创建令牌的脚本，使其在不再需要时删除令牌。
  • CVE-2026-125272（APM，7.5）：当虚拟服务器上的 APM 访问配置包含带有基于表单的登录页面的按请求策略时，攻击者无需登录即可使 TMM 崩溃。该问题在与那六个严重漏洞相同的工程热修复中修复。
  • CVE-2026-126822（APM SAML，7.5）：当访问配置被设置为 SAML 服务提供方（SP）时，攻击者无需登录即可使 TMM 崩溃。该问题在相同的工程热修复中修复。在此之前，如果不需要 SAML SP，该公司建议移除 SAML Auth 代理，并将对该虚拟服务器的访问限制在受信任的客户端网络内。
  • CVE-2026-126336（APM SAML，7.5）：启用加密断言的 SAML SP 代理可让攻击者无需登录即可使 TMM 崩溃。该问题在 BIG-IP 21.1.0.3、17.5.1.10 和 17.1.3.6 中修复，该公司建议采用高可用性配置以降低影响。
  • CVE-2026-121812（APM 和 SSL Orchestrator，7.5）：启用 tmm.access.policytrace 数据库键的按请求策略可让攻击者使 TMM 崩溃。该键默认关闭。APM 在相同的工程热修复中修复；对于 SSL Orchestrator，公告仅列出了 21.1 和 17.1 分支上的修复。
