中文原文

Socket 的安全研究人员发现了一起新的软件供应链攻击，影响了数万个 GitHub 仓库，其中包括由组织所有的仓库。

Uber 被列为运行受损软件包的企业之一。
这条杀伤链让人联想到 GhostAction——这是 GitGuardian 于 2025 年 9 月发现的一场恶意活动，并于 2026 年 10 月再次出现。

通过两个 GitHub 账户传播恶意工作流

2026 年 10 月 8 日，两个 GitHub 账户“henrywoo”和“kitao”向数百个其有权修改的仓库推送了一个恶意 GitHub Actions 工作流。

GitHub Action 是一项自动化任务，在 GitHub 仓库中运行，用于处理测试代码、构建软件或部署应用程序等活动，每当下达特定事件发生时便会执行。

该工作流名为“.github/workflows/security-audit.yml”，通过一次单文件提交添加，提交信息被设计成看似例行操作：“添加安全审计工作流”和“更新安全审计工作流”。

尽管名称如此，该工作流并不执行任何安全检查。相反，它会从受影响的仓库中窃取凭据，并通过 HTTP 将其发送至外部服务器 193.32.204[.]199。

由于该工作流看起来像合法的安全工具，它可能在作为仓库自动化流程的一部分运行时 unnoticed，而未被发现。

据 Socket 研究人员称，这个恶意文件出现在数万个仓库中，其中包括“henrywoo”或“kitao”拥有写入权限的仓库。

感染载体包括以下仓库：

  • henrywoo/pyllama 和 henrywoo/chatllama，这两个 AI GitHub 项目由“henrywoo”创建
  • kitao/pixel，通常通过 Python Pacjkage Index（PyPI）和 crates.io 分发；这些是在线仓库，开发人员分别在其中发布和分发使用 Python 与 Rust 编写的软件包
  • uber/athenadriver，这是一个由 Uber 拥有的项目，“henrywoo”作为其原始作者拥有写入权限

即使是已停用十年的仓库也受到影响，这表明攻击者系统性地枚举了每个他们有权访问的仓库，而不是根据仓库的活跃程度或价值来选择目标。

这些活动似乎是自动化的，而非针对特定目标手动实施的。

扩展 GhostAction 的机密窃取能力

尽管此次事件是 GhostAction 活动的新变体，但 Socket 研究人员指出，最新版本扩展了攻击者能够窃取的内容。

早前的 GhostAction 攻击主要针对存储在 GitHub Actions 中的机密，例如为自动化工作流配置的 API 密钥和访问令牌。

新变体还会使用正则表达式模式，在仓库的文件和完整 Git 历史记录中搜索凭据。这意味着，即使敏感信息后来已从仓库的最新版本中删除，它仍可能找到开发者意外提交到源代码、配置文件或文件早期版本中的敏感信息。

额外的搜索目标包括云提供商和 AI 服务的凭据，这可能暴露对基础设施、托管应用程序和第三方服务的访问权限。

恶意工作流仍在 GitHub 仓库中处于活跃状态

截至 2026 年 10 月 9 日，Socket 报告称，在其检查的存储库默认分支中，该恶意工作流仍然存在，其中包括 uber/athenadriver 和 kitao/pyxel。

该工作流还已在受影响的存储库中成功执行，这意味着窃取凭据的活动并非仅限于尝试注入。

然而，在 Socket 报告发布时，研究人员尚未发现此次活动导致任何恶意软件包版本被发布到 PyPI 或 crates.io。

这并不意味着被盗凭据未被用于其他用途，只是 Socket 尚未在这两个注册中心发现后续恶意软件包发布的证据。
