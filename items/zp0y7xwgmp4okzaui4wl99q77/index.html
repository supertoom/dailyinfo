Ravie Lakshmanan2026年10月30日漏洞 / Web 安全

已观察到威胁行为者在 WordPress Core 补丁发布后不久尝试利用一个高危安全缺陷。

该漏洞尚无 CVE 编号，涉及影响 WordPress Core 4.7 至 7.1.3 版本的远程代码执行问题。其 CVSS 分数在 CVSS 评分系统上为 8.1。该缺陷的补丁已于 2026 年 10 月 28 日发布。

“这是由于在完整软件包核心升级期间使用了可预测且可通过 Web 访问的暂存路径，”Wordfence 表示。“这使得未经验证的攻击者能够在升级窗口内于服务器上执行代码。”

WordPress 安全公司指出，成功利用需要“攻击者在 WordPress 解压完整 Core 更新的极短窗口内发起攻击”。

该问题的根源在于，受影响版本会将完整软件包 Core 更新中的新文件解压到“wp-content/upgrade”下的可预测目录中。此副本还包含 WordPress 安装程序。

“由于许多服务器上的暂存目录均可通过 Web 访问，未经验证的攻击者如果恰好在正确的时间请求安装程序，就能够与暂存的 WordPress 副本进行交互并最终执行 PHP 代码，”负责 Wordfence 威胁响应团队的 Alex Thomas 表示。

威胁行为者如果能够赢得这一竞态条件，就可能获得在服务器上执行代码的能力，前提是满足以下条件：

  • 包含安装程序文件的完整软件包更新
  • 可通过公共 Web 和 PHP 访问暂存目录树
  • 可预测或已发现的暂存路径，以及
  • 有足够时间在 WordPress 清理临时文件之前完成攻击

尽管在正常实验室环境中已观察到该窗口仅持续数秒，但威胁行为者仍在反复轮询易受攻击的路径，例如“setup-config.php”，试图触发该缺陷。Wordfence 表示，在过去 24 小时内，其已阻止 62,969 次攻击，这些攻击均针对该漏洞。

Thomas 表示：“两个规模最大的来源持续约 14.5 小时，反复轮询少量网站，其行为符合试图抓住短暂升级窗口的特征。”“其他来源则测试了许多暂存目录和版本名称的变体。”

“并非每个请求都使用了准确的易受攻击路径，但持续轮询和针对精确结构的探测表明，攻击者迅速理解了竞态条件并开始将其作为攻击目标。”

鉴于针对该漏洞的主动利用尝试已经在进行，WordPress 站点所有者应尽快更新至 7.1.4 版本，并查找对“wp-content/upgrade”目录下 PHP 文件的可疑请求，以及不熟悉的管理员账户、插件或 PHP 文件。
