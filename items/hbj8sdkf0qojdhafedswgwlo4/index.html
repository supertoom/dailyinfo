AWS Continuum 代码漏洞自动修复获 CyberGym-E2E 基准 89.0% 成功率；AWS Security 2026年10月汇总：19 篇博文、33/37 个 CVE 复现、PHP2Shell 提前发现利用

ICYMI: October 2026 @AWS Security

这是一条 2026 年 10 月 AWS Security 汇总，涵盖 19 篇 AWS Security Blog 文章。

正文 · 原文

Welcome to this month’s AWS Security news! Organizations need current information about AWS Security developments to maintain their cloud security. This monthly digest covers key AWS Security updates. Each month, we compile new announcements, features, and resources to help you improve your security. Based on AWS Security developments, you’ll find expert perspectives in blogs, announcements of new features and capabilities, ready-to-use code samples, reference architectures, and hands-on workshops and labs to build practical security skills. Not every edition will include all of these categories, but we’ll consistently bring you the most relevant and impactful updates to help you enhance your security and governance posture.

AWS Security Blog posts

October brought 19 AWS Security Blog posts focused on the remediation flow, from a security finding to a tested fix. Learn how AI agents can find, confirm, and repair vulnerabilities, and how to add penetration testing to every deployment. You’ll also find guidance on extending existing access controls to AI agents with trusted identity propagation and preparing your signing workflows for post-quantum cryptography. The PHP2Shell posts show why patch timelines for internet-facing systems are now measured in hours, and how AWS WAF can help reduce risk while you upgrade. Other posts cover identity source changes in AWS IAM Identity Center, workload identity outside AWS, and domain-based filtering in AWS Network Firewall.

Threat detection and incident response

AWS Continuum sets a new standard in autonomous code security
Authors: Alexander Greaves-Tunnell, Neha Rungta | Published: October 5, 2026
AWS Continuum for code vulnerabilities achieved an 89.0 percent end-to-end success rate on the CyberGym-E2E benchmark. It found, demonstrated, and repaired vulnerabilities in real open source codebases, 23.1 percentage points above the previous public high.

Part 1 – Cybersecurity journeys: I didn’t plan this
Author: Shannon Brazil | Published: October 7, 2026
The first post in a four-part Cybersecurity Awareness Month series shares how 11 AWS security professionals moved into security from unexpected backgrounds, showing there’s no single path into the field.

GuardDuty Extended Threat Detection has added five new indicators to surface attack sequences
Authors: Aman Khare, Kyle Koeller | Published: October 12, 2026
Learn to use five new indicator types in Amazon GuardDuty Extended Threat Detection: vulnerability, malicious package, reachability, misconfiguration, and sensitive data. They bring signals from Amazon Inspector, Amazon Virtual Private Cloud (Amazon VPC) Reachability Analyzer, Amazon Macie, and AWS Security Hub into sequence findings, and the post shows how to add them to your incident response workflow.

Part 2 – Cybersecurity journeys: What even is this job?
Author: Shannon Brazil | Published: October 13, 2026
The second post in the series covers lesser-known security roles. These include measuring risk across a million applications, building detection tools from the customer service side, and securing infrastructure launched into orbit.

Penetration testing every deployment with AWS Continuum
Authors: Jigar Bhatt, Benjamin Li | Published: October 14, 2026
Learn to add AWS Continuum for penetration testing (formerly AWS Security Agent) to your continuous integration and delivery (CI/CD) pipeline as a check after each deployment. It tests only the change you deployed to staging and can stop that change from reaching production when a finding meets a severity threshold you set. The post includes an example for GitHub Actions.

AWS Security Agent (now part of AWS Continuum) exploited 33 of 37 new real-world CVEs
Authors: Dazhi Zhang, Hamed Soleimani | Published: October 15, 2026
AWS Continuum for penetration testing was tested against a new internal benchmark of 37 recently disclosed CVEs in live, containerized applications. Starting from a low-privilege position, it confirmed 33 of the 37 vulnerabilities end to end through the intended path, an 89.2 percent success rate.

Amazon Threat Intelligence identifies PHP2Shell exploitation prior to public disclosure in MadPot
Author: CJ Moses | Published: October 21, 2026
Amazon Threat Intelligence detected activity targeting the PHP2Shell vulnerabilities (CVE-2026-109618 and CVE-2026-109619) on its MadPot sensors four days before public disclosure. The post explains what this means for security leaders: patch critical internet-facing systems within hours, and start investigations from the earliest activity seen, not the disclosure date.

Part 3 – Cybersecurity journeys: The work behind the work
Author: Shannon Brazil | Published: October 27, 2026
The third post in the series looks at the day-to-day work of AWS security professionals that rarely gets attention. It covers application security reviews that depend on conversations with builders and on sharing hard feedback with empathy.

AI security

Identity-aware AI data agents with AWS Lake Formation and Trusted Identity Propagation
Authors: Thiyagarajan Mani, Mihir Borkar, Philippe Duplessis-Guindon, Umang Khambhalikar | Published: October 6, 2026
Learn to pass each user’s identity through Amazon Bedrock AgentCore to AWS Lake Formation using trusted identity propagation. Your existing data access policies then apply to AI agent queries without changes to application code, and AWS CloudTrail records the actual user behind each query.

Building your AI vulnerability harness, Part 1
Authors: Nidhi Ramakant, Ievgeniia Ieromenko, Justin Kontny | Published: October 7, 2026
Learn to build a three-layer pipeline that uses AI to reduce raw scanner findings to a small, prioritized set with documented evidence, so engineers can act without repeating the analysis. The architecture works with your own scanners and models.

Configuring your AI vulnerability harness, Part 2: The steering file
Authors: Justin Kontny, Ievgeniia Ieromenko, Nidhi Ramakant | Published: October 7, 2026
Learn to configure a steering file that has an AI model confirm the code structure before it reports a finding, score its confidence from that structural evidence, and set priority based on the controls in your infrastructure as code. The result is vulnerability triage that gives the same findings each time it runs.

Identity

Improving SPIRE security and resiliency with AWS managed services
Authors: Brendan Paul, Meg Peddada | Published: October 6, 2026
Learn to run SPIRE in production by moving key management, workload identity registration, certificate authority integration, and identity delivery for serverless workloads to AWS managed services. This helps you move from static credentials to short-lived workload identities. A GitHub repository walks you through deploying the reference architecture.

Managing identity source transition for AWS IAM Identity Center
Authors: Xiaoxue Xu, Kanwar Bajwa, Laura Reith, Richard Merritt, Taimur Ijlal, Yee Fei Ooi | Published: October 20, 2026
Learn to change the identity source in AWS IAM Identity Center using a step-by-step runbook and sample code. The post covers the new migration from Active Directory to an external identity provider or the Identity Center directory, which keeps your users, groups, memberships, and assignments in place.

Best practices for integrating IAM Roles Anywhere with your PKI
Authors: Abhishek Avinash Agawane, Manoj Gupta | Published: October 21, 2026
Learn to apply best practices for connecting your public key infrastructure (PKI) to AWS Identity and Access Management (IAM) Roles Anywhere. Workloads running outside AWS can then get temporary credentials using X.509 certificates, each with its own identity and set of permissions.

Data protection

Quantum-resistant signing on AWS, Part 1: Build a software supply chain with ML-DSA
Author: Harshvardhan Chunawala | Published: October 12, 2026
Learn to build an end-to-end post-quantum signing architecture for binaries, container images, and software bills of materials (SBOMs). It combines ML-DSA keys in AWS Key Management Service (AWS KMS), ML-DSA certificate hierarchies in AWS Private Certificate Authority, and ML-DSA trust anchors in IAM Roles Anywhere.

Quantum-resistant signing on AWS, Part 2: Enforce your ML-DSA algorithm policy with SCPs and IAM
Authors: Harshvardhan Chunawala, Blake Roberts | Published: October 12, 2026
Learn to turn your organization’s post-quantum algorithm policy into preventive and detective controls using service control policies (SCPs) and AWS Identity and Access Management (IAM). Only approved ML-DSA parameter sets can then be used with AWS KMS across your environment.

Infrastructure security

Using AWS WAF to apply mitigations for PHP2Shell RCE vulnerabilities (CVE-2026-109618 and CVE-2026-109619)
Authors: Alex Waddell, Eitav Arditti, Lawton Pittenger, Ian Olson | Published: October 21, 2026
Learn to use the AWS WAF PHP application managed rule group to help reduce risk from the PHP2Shell vulnerabilities while you upgrade PHP across your fleet. The post also covers guidance for end-of-life PHP versions and a related issue, CVE-2026-115560.

Introducing Route 53 Resolved IP Validation for AWS Network Firewall
Authors: Lawton Pittenger, Amish Shah, Amit Gaur, Jesse Lepich, Preetkumar Shah | Published: October 27, 2026
Learn to use Route 53 Resolved IP Validation, available at no additional charge. Amazon Route 53 Resolver shares the IP addresses it returns for each domain name with AWS Network Firewall, which checks new outbound connections against them. You can then filter non-web traffic such as SSH and SFTP by domain name and validate Server Name Indication (SNI) in TLS traffic without turning on TLS inspection.

Governance and compliance

AWS becomes first CSP in Canada to complete the Cloud High profile assessment with 172 services and features in scope
Author: Naranjan Goklani | Published: October 27, 2026
AWS completed the Canadian Centre for Cyber Security (CCCS) Cloud High (PBHH) security assessment, with 172 services and features assessed in the Canada (Central) and Canada West (Calgary) AWS Regions. This helps public and commercial customers meet security requirements for more sensitive workloads up to the Protected B level. The summary assessment is available in AWS Artifact.

October security bulletins

In October 2026, AWS published 41 security bulletins addressing vulnerabilities across open source SDKs, Model Context Protocol (MCP) servers, AI agent frameworks, embedded software, and widely used runtimes. The AI agent tool surface remained the main theme. An authentication bypass in Loom for AWS could allow network clients to gain administrative access to the agent control plane, and the AWS API MCP Server accepted OAuth tokens issued to other applications. Prompt-injected content could turn off secret masking in Strands Agents Tools or trigger command execution through the databases-on-aws agent plugin. The category also included cross-session conversation exposure in the Strands Agents Agent-to-Agent (A2A) server, missing authorization in the Kiro Crew WhatsApp channel, and code injection and server-side request forgery (SSRF) in the Amazon Bedrock AgentCore Starter Toolkit. Several broad-impact advisories called for customer action, including remote code execution in PHP web runtimes and the native Brotli decoder, a Linux kernel IPv4 TCP use-after-free issue, and recoverable eMudhra intermediate CA keys in AWS trust bundles.

Other notable issues include OS command injection in the AWS Serverless Application Model Command Line Interface (AWS SAM CLI) Terraform hook and the Amazon SageMaker Distribution startup script, SQL injection in the AWS Cloud Development Kit (AWS CDK) Amazon Redshift alpha constructs, an RSA padding oracle in the Amazon Simple Storage Service (Amazon S3) Encryption Client for .NET, and memory-safety issues in FreeRTOS, the AWS Nitro Enclaves SDK for C, and aws-c-mqtt. Credential exposure recurred in client tooling. AWS Tools for PowerShell, the Amazon SageMaker Python SDK, and the Amazon Kinesis Producer Library wrote secrets to logs. The Amazon SageMaker Python SDK and AWS SDK for pandas also used predictably named Amazon S3 buckets without verifying bucket ownership. A common thread: tools trusted inputs they didn’t control, such as content an agent ingests, a token issued to another application, or a bucket in another account. Patches or mitigations are available for every bulletin, so upgrade promptly. For more information, see AWS Security Bulletins.

AWS samples

This month’s eight AWS samples give you deployable code that puts the remediation flow into practice. Learn how to have AI agents investigate an incident together, connect public security events to the affected lines in your code, and hold off risk at the edge until a patch is merged. Other samples show you how to run AI-assisted vulnerability scanning in isolated environments and add security requirements to specs before any code is written. You’ll also find patterns for protecting MCP servers, private VPC workloads, and browser sessions driven by AI agents, plus a dashboard for governing generative AI usage and cost.

Infrastructure security

AWS Lambda Web Functions reference architecture: Amazon CloudFront and private VPC access
Learn to run a web application on AWS Lambda Web Functions behind Amazon CloudFront, using Origin Access Control so the function only accepts signed requests. A Lambda network connector lets the function reach private resources in your VPC. The sample uses Amazon Aurora Serverless v2 as the example database, with AWS Identity and Access Management (IAM) database authentication, so no credentials need to be stored.

Architecture patterns for MCP servers behind Amazon CloudFront
Learn to run a remote Model Context Protocol (MCP) server behind Amazon CloudFront and AWS WAF using four AWS Cloud Development Kit (AWS CDK) patterns, one for each origin type. The origins include Amazon Bedrock AgentCore, Amazon API Gateway, and Amazon Elastic Kubernetes Service (Amazon EKS). Each pattern uses the same edge protection and OAuth 2.0 authentication, applies AWS WAF rate limits to each tool and IP address, and only accepts traffic to the origin that comes through Amazon CloudFront.

Mitigating agentic bot threats with Amazon CloudFront and AWS WAF
Learn to add a human verification step for browser sessions driven by AI agents. AWS WAF Bot Control flags sessions that look automated, and AWS Lambda@Edge sends them to an Amazon Rekognition Face Liveness check, which needs a live person in front of a camera. A daily limit on how often the same face can pass the check helps keep a few people from verifying many agent-controlled sessions.

AI security

Security Scanning with Claude Code on AWS
Learn to deploy a separate, isolated Amazon Elastic Compute Cloud (Amazon EC2) environment for each user that runs Claude Code on Amazon Bedrock, so security teams can find, triage, and fix vulnerabilities in code they own. Each environment has no inbound access and is reached through AWS Systems Manager Session Manager. Prompts, commands, and sessions are recorded in your AWS account for audit.

Specification Hardening Engine – Kiro Power
Learn to add security requirements to your Kiro specs before any code is written. The Specification Hardening Engine checks EARS-format requirements against CWE and OWASP weakness categories and proposes security requirements you can trace and test. You review each proposed requirement and confirm it before it’s added to the spec.

Threat detection and incident response

DevOps-orchestrated security investigation
Learn to use two managed AWS agents to investigate one incident together. AWS DevOps Agent traces an alarm to a faulty deployment and, using the Agent-to-Agent (A2A) protocol, hands the code review to an agent on Amazon Bedrock AgentCore Runtime. That agent runs an AWS Security Agent review, and its findings appear in the same investigation timeline, with a human approving every action.

Security Radar
Learn to track more than 200 public security sources, including CVE records, CISA advisories, and AWS security bulletins, and match new events to the affected lines in your code. Security Radar then calls AWS Continuum to validate a patch and deliver it as a pull request. Until the patch is merged, temporary rules in AWS WAF and Amazon Route 53 Resolver DNS Firewall help reduce risk.

Governance and compliance

Bedrock Activity Dashboard
Learn to deploy a monitoring and governance dashboard for Amazon Bedrock that tracks token use, model use, and cost by user and team. It runs 13 agents on Amazon Bedrock AgentCore Runtime for security, compliance, cost optimization, and usage insights. Usage data comes from Amazon CloudWatch Logs, Amazon S3, and AWS CloudTrail. The dashboard also recommends Amazon Bedrock Guardrails configurations for sensitive data and lets you reconcile chargebacks with AWS Cost Explorer reports.

Conclusion

In October, AI agents took on a larger part of the remediation flow. The posts and samples show agents that find, confirm, and repair vulnerabilities, and pipelines that test each deployment before it reaches production. The PHP2Shell event showed that activity can begin before an advisory is published. Teams can respond by prioritizing findings by evidence, patching internet-facing systems within hours, and keeping edge mitigations in place until patches roll out. The identity guidance applies existing access controls to AI agents and to workloads outside AWS through identity propagation, short-lived credentials, and centrally enforced algorithm policy. In each case, people review and approve the changes that agents propose. To stay current with AWS security updates, subscribe to the AWS Security Blog RSS feed.
