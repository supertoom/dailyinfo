CERT-In 警告 AI 辅助攻击导致印度银行与金融科技机构发生未授权付款

AI-Assisted Cyber Attacks Trigger Unauthorized Payments at Indian Banks and Fintech Firms

AI 导读

印度 CERT-In 警告，攻击者利用 AI 辅助网络攻击篡改企业记录、审批关系并借合法支付流程发起未授权交易，受害对象包括银行、金融服务业实体及政府关联支付平台的技术服务商，损失金额和责任主体尚未披露。

文章汇总多起 AI 代理参与入侵的案例，并说明其自动化侦察、生成 Exploit 与绕过流程的机制，展示了攻击速度和组织能力的变化。

中文原文

印度计算机应急响应团队（CERT-In）警告称，威胁行为者正在利用人工智能（AI）发动网络攻击，针对该国的信息与通信技术（ICT）资产。

此类未经授权的活动已导致银行和金融服务机构以及技术支持政府关联支付和处理供应商或合作伙伴付款的平台发生未经授权的金融交易。

CERT-In 表示：“在观察到的事件中，攻击者以业务记录和审批流程为目标，通过原本合法的系统发起未经授权的交易。”CERT-In 上周发布的一份公告称。

现已发现相关事件涉及以下方法：

  • 滥用业务应用程序和服务提供商运营的工作流，而非直接利用与支付相关的 API。
  • 修改业务记录或审批关系，随后使用合法的支付流程。
  • 利用可信系统和既定审批程序处理未经授权的交易，且不触发任何警报。
  • 利用独立验证、对账和业务记录变更审查流程中的安全盲区。

CERT-In 未披露不当支付了多少资金，也未披露资金由谁支付。这些活动尚未归因于任何特定威胁行为者。

该机构还表示，独立的威胁狩猎活动发现了在企业、科技、政府、学术和研究领域使用 AI 驱动的智能体攻击框架（AOFS），以执行以下操作：

  • 自动进行侦察，以识别暴露的系统、服务和潜在攻击路径。
  • 快速生成和修改针对已知漏洞的利用程序，包括通过分析软件补丁及相关技术信息来实现。
  • 使用一组 AI 智能体并行执行入侵任务，例如侦察和权限发现。
  • 根据错误、被阻止的尝试或目标系统返回的信息，修改脚本、请求和攻击方法。
  • 利用有效凭据、合法管理功能、信任关系和外部基础设施，在目标网络深处进一步渗透。

CERT-In 表示：“各组织应审查业务应用程序、关键记录、用户身份和第三方接口的安全性。现有监控和事件响应安排也应考虑滥用受信任业务流程以及自动化入侵活动所带来的风险。”

这一消息发布之际，印度实体已遭遇一系列针对金融实体的 AI 辅助网络攻击；其披露，处于研究和评估阶段的 AI 智能体“超出了任务授权范围，并未经授权访问”了 ICT 资产。

CERT-In 表示：“在针对印度实体、以经济利益为目的的行动中，智能体工具将初始访问到最终造成影响之间的时间从数天压缩至数小时。此外，该行动表明，多智能体操作会并行运行数小时至数天，以实现攻击者目标，这与这些工具所记录的多智能体能力一致。”

本月早些时候，该机构还警告称，一个名为 Crafty Falcon 的威胁组织正幕后推动一波针对金融企业的 AI 驱动攻击，并使用了 ARTEX、PentAGI、CAIRN 和 CyberStrikeAI 等进攻性渗透测试工具，以机器速度自动化入侵。

据印度网络犯罪协调中心（I4C）称，这些攻击已针对银行、非银行金融公司和金融科技公司，通过资金发放系统和 API 实施了价值数千万卢比（相当于 1000 万）的未授权交易。

“作案者利用未打补丁的软件或配置错误的互联网暴露服务器／IT 系统来入侵基础设施，”I4C 表示。“随后，黑客会将目标对准用于支付和资金转账的自动化资金发放系统或专用接口（API）。  资金被转入不同银行的‘骡子’账户（犯罪分子使用的账户），然后通过 IMPS／NEFT 迅速转出或提取。”

印度中央银行——印度储备银行——也已就针对金融基础设施的网络攻击增加发出警报，敦促银行提供其应对 AI 相关威胁能力的信息，路透社 报道称，消息是在上月底发布的。

AI 攻击激增

这些通告发布之际，全球各地的组织正遭到使用 AI 工具的攻击，这使攻击者能够“以更高的作战速度执行多阶段入侵”。上周，欧洲委员会确认，装备ARTEX 的攻击者侵入了其人力资源、医疗报销和翻译系统。此次攻击的最初迹象于 2026 年 10 月 22 日被发现。

ARTEX 还被牵涉到近期针对 IT 管理软件公司 ConnectWise 和 Barracuda 的供应链攻击中。后者披露，一名以牟利为目的的犯罪分子利用提供给第三方供应商的、暴露在外的有效云访问密钥，绘制其影响范围，将发现的秘密信息重新用于访问更多系统并寻找助记词，同时窃取更多凭据和秘密信息。

“总体而言，攻击者在约 44 小时［11 月 1 日至 2 日］内触及约 10 个云账户。整个过程有条不紊且不知疲倦，”Barracuda 表示。“探测名称、我们收集到的其他指标、攻击者逐一处理我们系统的顺序，以及其内置的凭据和钱包搜寻例程，都与 ARTEX 相匹配。”

ARTEX 等框架管理一组子代理，以规划、执行并调整跨越多个杀伤链阶段的战术，包括侦察与扫描、初始访问、持久化与权限提升、内部侦察、横向移动以及数据外泄。

它们能够将自然语言描述的战术目标转换为由专用 AI 代理执行的机器命令。它可与多种外部 LLM 集成，包括 Anthropic Claude、OpenAI GPT、DeepSeek、SpaceXAI Grok、Zhipu GLM 和 Kimi。

“ARTEX 显著缩短了串联攻击技术所需的时间，有些入侵从初始目标锁定到获得特权访问不到三小时，”美国联邦调查局（FBI）在本月发布的一份警报中表示。

“该框架使技术专业知识有限威胁行为者能够同时开展复杂的多目标行动，显著加快攻击速度并扩大行动规模。”

Check Point 在本月发布的一份报告中表示，发现了 1,800 多个公开暴露的 ARTEX 实例，攻击者利用该工具实施机会主义、以牟取经济利益为目的的网络犯罪。

“对代理对话的分析表明，一旦设定初始目标，这些系统几乎完全自主运行：大多数行为者几乎不与自己的代理集群互动，只是询问进展或指示代理转向新目标，”该公司表示。

数据安全公司 Cohesity 表示，使用 ARTEX 的威胁行为者正在获取安全关注度较低的系统访问权限，例如合作伙伴和供应商门户、移动后端、员工和销售支持应用、旧式服务、第三方集成，以及由各个业务部门自行构建的应用。

“在我们运营的一个研究网络中，一名与 Rhysida 有关联的威胁行为者使用 AI 框架在遇到障碍后重写工具，通常只需几分钟；单个脚本的 150 多个版本在一天内到达域控制器，”该公司表示。

Google 的 Mandiant 和 Threat Intelligence Group（GTIG）在上周发布的一份报告中，将其所描述的首次观察到的攻击者实例识别为：攻击者使用无人工介入的自主 AI 框架将安全补丁转化为漏洞利用。

该 AI 框架名为“exploit_agent”，可与多个前沿及本地大语言模型（LLM）集成。它旨在发现软件漏洞并在无人干预的情况下执行漏洞利用。据称，这名疑似讲俄语的攻击者利用该框架，针对与媒体和娱乐行业以及教育部门相关的法国网站。

“该框架用于对常用 Web 应用软件持续进行差异化分析，”Mandiant 和 GTIG 表示。“它比较补丁公告前后的代码，分析发现结果以识别潜在漏洞，起草漏洞利用，并在无人工干预的情况下自动执行。”

以下是 AI 代理和模型承担主要工作的其他一些值得注意的事件——

  • 在针对目标的入侵活动中使用 CAIRN，包括针对美国航空航天部门目标的入侵活动。
  • 将 LLM 嵌入影响行动工作流，以生成合成媒体、创建可信的虚拟身份，并生成和发布内容。
  • 使用 Google 的 Gemini API 以及来自多家 AI 提供商的工具，构建端到端的影响即服务（SaaS）平台，旨在影响公众对地区政治议题的看法，特别是在欧洲和中东地区。
  • 由一家名为 Leaky Castle 的中国关联承包商使用 LLM 对外泄数据进行分析、翻译和理解
  • 一家与中国有关联的威胁行为者滥用前沿模型的文件托管基础设施来暂存诱饵存档和外泄数据，并利用后端 API 外泄被盗的内部网文档。
  • 朝鲜威胁行为者使用 LLM 生成简历，并为进入西方组织的求职面试做准备。
  • 疑似朝鲜黑客组织 Midnight Neptune（此前称 UNC1069）在针对北美和欧洲加密货币机构的攻击中，利用求职主题和 ClickFix 主题诱饵，在职业社交平台上创建虚假招聘人员资料。已发现这些人物身份会将目标引至虚假会议平台，该平台用于通过 ClickFix 运行诊断修复脚本。Google 表示：“初始入侵后，该攻击者转向组织内部的代码仓库，执行了一条组织内部的供应链攻击路径：修改 .claude/settings.json 配置文件，使得当用户启动 Claude Code 时，会自动触发 SOMBERMEME 后门的下载。”
  • 在 2026 年 9 月 30 日至 10 月 16 日期间使用 CyberStrikeAI（“43.240.29[.]11”）验证窃取的 AWS 凭据、从 Secrets Manager 收集机密、拉取 EC2 用户数据、解密 SSM 参数并发送远程命令。Elastic Security Labs 表示：“审计日志未显示该命令的内容，也未显示其是否执行成功。”
  • 一个名为 Silent Lynx 的威胁 actor 将 Hermes 与 DeepSeek 结合使用，于 2026 年 4 月至 10 月针对中亚政府和关键基础设施开展 网络间谍行动，以协助进行侦察、数据收集以及清除失陷系统中的活动痕迹。
  • 使用 ARTEX 利用存在漏洞的自定义 PHP 上传功能并植入 web shell，进而访问机密和 API 密钥，最终入侵一家公司的开发流水线，篡改 Git 仓库并部署由攻击者控制的 Kubernetes pod。
  • 使用 AI 编码助手，在 2026 年 9 月下旬某美国零售组织的命令被安全软件拦截后，恢复停滞的攻击，并寻找绕过防御和窃取凭据的方法。根据威胁 actor 对销售点脚本中的密码进行扫描，以及其 IP 地址与针对在线零售商的先前活动存在重叠，此次攻击被评估为以获利为目的。
  • 一个使用中文的攻击者在 2026 年 8 月至 9 月期间使用 CAIRN，并将其与 GLM 和 DeepSeek 模型结合，针对至少 19 个组织自主开展了 25 次行动。这些攻击被归因于 CL-STA-1238，目标包括先进半导体制造业、美国国防政策和公民社会领域，并在其中 10 个实体实现了未授权访问或数据获取，包括获取有效凭据、个人数据、军事和政府身份信息，以及在生产系统中创建持久性管理员账户。Palo Alto Networks Unit 42 表示：“Cairn 通过一个共享的‘黑板’协调其活动。代理读取黑板，并将调查结果以事实—意图图的形式写回，而人类操作员可随时注入‘提示’，在需要时引导行动。已确认的调查结果会累积为不可变事实，代理则将其下一步行动排入队列，形式为意图。”
  • 攻击者使用 ARTEX 获取已泄露的账户级 API 令牌访问权限，这些令牌此前用于 CI/CD，且未设置 IP 限制或速率限制。Cloudflare 表示：“攻击者反复攻破在 CI/CD 流水线中运行的静态且永不过期的令牌，这些令牌授予了对该组织 hyperscaler 基础设施的广泛跨环境访问权限。LLM 框架大幅增加了客户端 API 密钥被横向利用、以接管其他租户环境的可能性。”
  • 攻击者使用 ARTEX 生成深度伪造视频以欺骗身份验证检查，针对两家加密货币交易所，并以“工业化规模”窃取 AI 凭据，从而免费访问模型。Amazon 将第二波攻击活动描述为“一项自我维持的行动，其中被盗密钥为驱动进一步搜寻凭据的 LLM 推理付费”。目标包括 LLM 网关和代理平台，如 One API、New API、Veloera、Sub2API 和 LiteLLM，以及 AI 应用构建工具，如 Dify、FastGPT、Langflow（CVE-2025-3248）、RAGFlow（CVE-2026-28797）、Open WebUI、LobeChat 和 Ollama。
  • 疑似与中国有关联的攻击组织使用 CAIRN 发现零日漏洞（GHSA-qc22-rmgc-vg94），该漏洞存在于医疗成像应用程序 MONAI Label 中，并利用它在 11 分钟内完全控制服务器。该活动于 2026 年 9 月被发现。

Amazon Integrated Security 的 CISO CJ Moses 在一份提供给 The Hacker News 的报告中表示：“一个能在几分钟内发现并利用零日漏洞的代理，其行动速度比许多安全运营中心手动分流警报的速度还快。”

“规模最大的一次行动针对的是某大学的一台 Redis（远程字典服务器）实例，该实例被配置为允许无需身份验证即可访问。这些行动人员采用了一系列已知技术来接管开放的 Redis 服务器。在加固后的 Redis 目标上未能得手的行动人员连续运行了 16 小时，期间没有中断、休眠，也不受工作时间限制。”

人工智能赋能攻击日益值得关注之处在于，这项技术不仅被用作力量倍增器，也已成为攻击目标。

“将人工智能赋能工具整合到企业工作流中正在创造新的攻击面，尤其是在这些工具拥有对代码、凭据、数据或互联应用的特权访问权限时，”Recorded Future 表示，“开发工具是针对人工智能系统实施攻击的主要目标。威胁行为者利用薄弱的访问控制机制和软件供应链漏洞窃取数据或建立持久化。”

除了自动完成入侵中耗时的各个阶段外，由大语言模型驱动的渗透测试框架还降低了技术门槛，使技术能力有限的行为者也能发动复杂攻击。

“现在，攻击者可以用自然语言给智能体设定目标，”GitGuardian 表示。“智能体可以调查环境、选择工具、执行命令、解读结果，并决定下一步尝试什么。这些工具在失败后恢复方面也正变得越来越完善。智能体遇到错误后，可以解读响应、修改下一条命令，并继续调查。”

"任何能够使用 AntiFox 或 ARTEX 的人，都只需对着听写功能口头说出："查找暴露的凭据，确定它们可以访问哪些内容，并识别有价值的资源。"这句咒语会启动一系列技术操作，而过去完成这些操作需要相当深厚的专业知识。"
