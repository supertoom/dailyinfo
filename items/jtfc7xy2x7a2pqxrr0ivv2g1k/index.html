中文原文

周二，美国网络安全和基础设施安全局（CISA）确认，黑客已开始利用 Brotli 的一个严重漏洞，该漏洞被称为 Node2Shell、Broccoli2Shell 和 HTTP2Shell。

该漏洞被追踪为 CVE-2026-111497，严重程度为严重，源于 Brotli 解码器中的越界写入弱点；该解码器用于解压使用 Google 广泛使用的 Brotli 无损压缩算法压缩的数据。

无权限攻击者可以使用恶意构造的 Brotli 压缩流，触发崩溃或内存泄漏，并且在某些情况下，可以在运行存在漏洞的 Brotli 库或二进制文件的设备上获得远程代码执行。

该安全问题最初是在 Node.js JavaScript 运行时环境中发现的，但也会影响依赖存在漏洞的 Brotli 实现的 HTTP 服务器和客户端。

周日，Microsoft 还推送了一项紧急 .NET 安全更新，警告称攻击者可能利用此漏洞在运行存在漏洞的 .NET 版本的系统上提升权限。

CISA 周二将该漏洞添加至其已知被利用漏洞（KEV）目录，并依据其具有约束力的操作指令（BOD）26-04，命令美国政府机构在两周内、即 11 月 10 日前完成系统修补。

它表示：“Google Brotli 存在一个未检查返回值的漏洞，远程未经身份验证的攻击者可以利用精心构造的 Brotli 压缩流，破坏相邻解码器状态的内存、泄露敏感内存内容、造成拒绝服务，或可能执行任意代码。”

“这类漏洞是恶意网络行为者常用的攻击途径，并对联邦企业构成重大风险。”

虽然 CISA 的 BOD 26-04 仅适用于联邦机构，但这家网络安全机构敦促所有网络防御人员优先修补此安全漏洞，以阻止传入的攻击。

无法立即应用更新的安全团队应在代理或防火墙层面阻止传入的 Brotli 压缩请求，或者禁用 Brotli 解码功能，直至能够完成更新。

完成修补后，管理员还必须重启受影响的进程，并重新构建和重新部署受影响的容器镜像。

攻击者一旦拥有有效凭据，其操作仅有 37% 会被阻止

总体预防评分可能掩盖初始访问之后发生的情况。一旦攻击者开始使用有效凭据，预防效果就会大幅下降。
