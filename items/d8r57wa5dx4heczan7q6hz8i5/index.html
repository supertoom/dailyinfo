漏洞分析

组件介绍

PHP 是广泛部署的开源脚本语言，大量 Web 应用直接运行于其上。默认的 files 会话保存处理器将会话数据写入服务器本地会话文件，session upload progress 等特性允许外部请求影响会话数据内容，攻击者提交的输入可直达本次漏洞所在的会话文件写入逻辑。

漏洞简介

2026年11月20日，深瞳漏洞实验室监测到PHP组件存在多个代码执行漏洞的信息，漏洞编号：CVE-2026-126714，CVE-2026-115560，CVE-2026-129289，CVE-2026-129474，CVE-2026-129496，CVE-2026-129182，CVE-2026-129481，漏洞威胁等级：严重。

CVE-2026-126714：PHP 默认的 files 会话保存处理器在写入更新后的会话数据时不先清空原有文件内容，写入被中断时会话文件可能保留新会话开头与旧会话结尾的拼接数据，其中的普通字符串字节随后可被反序列化为对象。能够影响会话数据的攻击者（如通过 session upload progress）在合适时机中断写入即可注入对象，当应用存在可用 gadget 链时导致远程代码执行；会话数据本身也可能被破坏。

CVE-2026-115560：PHP 会话序列化机制与上传进度处理之间存在异常的交互。当应用在运行时动态更改序列化处理器、且上传进度功能仍处于启用状态时，会暴露出代码执行路径。

CVE-2026-129289：PHP 在请求关闭时不会丢弃 HTTP 请求体中未被读取的部分。当前端复用后端连接时，PHP-FPM 会将残留字节解析为新的 FastCGI 请求，从而实现请求走私与参数注入。

CVE-2026-129474：在为 __call() / __callStatic() 收集参数以生成回溯时，PHP 可能读取已失效的陈旧值（指向已释放内存）。若此时发生致命错误且回溯功能开启，会加剧内存破坏。

CVE-2026-129496：启动期间的诊断写入导致时区缓存在启动内存中分配，随后该内存被释放但引用仍被保留。worker 首个请求早期的诊断会访问这块已释放的缓存，形成释放后使用条件。

CVE-2026-129182：关闭期间的致命错误会在执行器已清理之后重新填充存储的致命错误回溯。请求内存随后被释放，但后续请求的早期诊断会访问该悬空回溯信息，导致释放后使用。

CVE-2026-129481：会话扩展在会话开始时记录脚本文件名。若关闭期间销毁会话变量时发生致命错误，该文件名的指针在请求内存释放后仍被保留。同一 worker 处理后续请求时，可能释放这个悬空字符串，造成内存破坏。

临时修复建议

  • CVE-2026-126714：若业务无需上传进度功能，在管理级配置中将 session.upload_progress.enabled 设为 0，同时对写入 Session 的不可信数据做容量限制，并评估改用支持原子记录替换的 Session 存储后端；需注意关闭上传进度只切断其中一条触发路径，不能覆盖全部利用方式。

  • CVE-2026-115560：在请求输入解析之前通过管理级配置把 session.upload_progress.enabled 设为 0；若必须保留上传进度，应确保所有读写同一批 Session 记录的组件使用相同的 session.serialize_handler，不同序列化格式的 Session 分开存储，变更格式时迁移或过期旧记录，且不要在应用代码中用 ini_set() 关闭该功能，因为此时已晚于请求输入解析阶段。

  • CVE-2026-129289：关闭 PHP 后端连接复用，Nginx 侧设置 fastcgi_keep_conn off;，Apache 的 mod_proxy_fcgi 关闭 enablereuse，其他 FastCGI 前端也应在每次请求处理结束后断开后端连接、不再复用。

  • CVE-2026-129474：在实际运行 PHP worker 的配置中设置 zend.exception_ignore_args=1 并重启所有 workers，PHP 8.5 环境还可设置 fatal_error_backtraces=0 以阻断该攻击路径，仅设置 display_errors=0 不能起到缓解作用。

  • (5) CVE-2026-129496：修正会触发启动警告或弃用提示的配置后重启 PHP 主进程及全部 workers，或把 PHP 错误日志输出到不经过该文件时间戳路径的目标（例如设置 error_log=syslog）并确认日志能被正常收集，仅调整 FPM 自身的日志路径不足以完成该缓解。

  • (6) CVE-2026-129182：在管理级配置中设置 fatal_error_backtraces=0，重启全部 workers 使配置生效，并确保请求级配置无法重新开启该选项，防止被应用配置或攻击者绕过。

  • (7) CVE-2026-129481：避免 Session 清理回调过程中发生致命错误，对 PHP-FPM 可在池配置中设置 pm.max_requests=1 并重启 workers，使同一 worker 不再继续处理后续请求；该措施有性能开销，且关闭上传进度不能缓解此路径。
