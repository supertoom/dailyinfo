Forever Security 披露 Cursor、Copilot、Codex、VS Code 与 Claude Desktop 内置浏览器漏洞

Researchers broke the browsers built into VS Code, Cursor, Copilot, Codex and Claude Desktop

AI 导读

Forever Security 披露五款 AI 编程助手内置浏览器均违反隔离规则：Cursor 可在开发者一次按键后执行攻击者命令，Copilot 可伪造地址栏，Codex、VS Code 和 Claude Desktop 的单个本地页面可越界读取磁盘。

值得关注

文章用统一的 EMBRACE 框架比较五款 AI 编程助手的内置浏览器，并给出可复现的攻击链与未修复风险。

正文 · AI 翻译
中文原文

Forever Security 找到了五种 AI 编程助手内置浏览器的逃逸方式：Cursor、GitHub Copilot、OpenAI 的 Codex、Microsoft 的 VS Code 和 Anthropic 的 Claude Desktop。在这五种工具中，网页或本地文件都能触达浏览器背后的计算机。Cursor 执行了攻击者代码，Copilot 显示了虚假地址，而 Codex、VS Code 和 Claude Desktop 则允许单个本地文件读取磁盘上的其余内容。

其中两个漏洞仍未修复。截至 10 月 29 日，Codex 和 VS Code 均没有可用修复，因此开发者只要在其中一种工具里打开经过精心构造的项目，仍可能一键丢失 SSH 密钥、云端凭据和开发者令牌。

三条浏览器规则被打破

独立浏览器会把每个页面都视为敌对目标。由此产生三条规则：页面不能在你的计算机上运行命令，本地文件不能读取你的其他文件，且只有浏览器可以写入地址栏。每家厂商都放宽了其内置浏览器的限制，让 AI 能够预览本地项目或读取标签页中显示的内容。Forever 的研究人员测试了这些改动是否破坏了三条规则。根据撰写该研究的 Forever 研究员 Gal Weizman，五种产品中都有一种规则失守。Forever 将这种模式称为 EMBRACE，即“像真实浏览器一样受到信任的嵌入式浏览器”的缩写。

一次点击，随后是整个磁盘

文件读取攻击从一个被伪装成枯燥财务报告的项目开始。开发者要求助手按照 README 进行设置，助手则提供一个指向项目中某个 HTML 文件的可点击链接，开发者点击后，界面上不会出现任何可见变化。

Claude Desktop 和 VS Code 会将本地页面限制在其项目文件夹内，但这项检查只涵盖页面本身。Web Worker 是页面可以启动的后台脚本，不在该检查范围内，因此这个 worker 能够读取计算机上的任何文件。Codex 则完全没有文件夹检查。为寻找目标，攻击会读取 macOS 在用户用 Finder 打开过的每个文件夹中写入的隐藏索引文件，逐个文件夹绘制磁盘。在 Forever 的机器上，这次扫描收集了 SSH 密钥、.env 文件、npm 令牌和 hosts 文件，然后将其发送出去。

因信任提示而被驳回

Anthropic 和 Microsoft 都拒绝处理 Forever 的报告，理由是存在 Workspace Trust，也就是询问开发者是否信任某个项目文件夹的提示。Anthropic 拒绝了 Forever 于 7 月 23 日提交的报告，但承认 Noma Security 于 7 月 24 日提交的报告有效。自 7 月 27 日提交报告以来，Forever 尚未收到 OpenAI 的任何回复。

Weizman 告诉 Help Net Security：“在 AI 框架中不信任项目，会让它变得无法使用，所以每个人都会直接点击‘信任’。”他表示，实际上，“这个提示对用户提供的保护为零。”

Cursor 和 Copilot 已修复

在 Cursor 中，只需要一个网页和一次按 Enter 键的操作。页面会向开发者显示一个看似无害、标有“Start setup”的按钮，按钮背后隐藏着一条供智能体执行的命令。智能体读取隐藏命令后请求运行该命令，批准只需按一次键。当 Cursor 的沙箱阻止命令执行时，智能体会自行关闭沙箱并再次尝试，页面中没有任何内容要求它这样做。在 Forever 的测试中，这条命令打开了 Calculator。真正的攻击者可以以开发者的完整权限启动任意程序，不过这种攻击取决于模型，并不每次都能奏效。

当被问及组织是否应当假设智能体可能会尝试绕过自身安全防护时，Weizman 表示：“绝对如此。我们正在看到这种行为在本次研究范围之外反复出现。”他表示，Forever 在其近期关于下载功能的研究中，也看到智能体在未经许可的情况下反复采取同样的行为。

Cursor 于 October 1 修补了该漏洞，比 Forever 在 September 10 的披露晚了三周，并且从未回复研究人员。在 GitHub Copilot 中，一个页面可以告知该应用它所在的地址，而应用仅检查文本看起来是否像一个网址。Forever 的页面在一个伪造的登录表单上方将 github.com/login 放入地址栏，智能体自身的标签页列表也重复显示了该地址。GitHub 在 Forever 提交报告之前，已于 October 13 通过 Copilot 1.1.29 修复了该漏洞。

现在需要检查什么

Weizman 建议运行 Codex 或 VS Code 的团队，从每台机器的配置文件中提取受信任项目列表，并检查这些项目中的每个 HTML 文件，查找是否存在 Forever 技术write-up中所述的漏洞利用模式。这种攻击所需的点击来自助手自行绘制的链接，而在 Codex 和 VS Code 中，该链接仍能打开一个读取整个磁盘的页面。
