AI与云安全事件案例分析周报：CyberStrikeAI云入侵、Check Point管理服务器失陷与PolinRider代码投毒

AI与云安全事件案例分析周报 | 2026年11月23日至11月27日

AI 导读

本周汇总3起AI与云安全事件：CyberStrikeAI利用被盗Terraform自动化任务会话影响2个AWS账号和7个EKS集群；GT13活动导致至少22家组织、24台Check Point管理服务器受影响；PolinRider在375个GitHub仓库植入恶意Python代码。报告建议缩小构建身份权限、排查异常管理会话，并审查测试目录与公用模块；具体执行次数、数据外传及AI参与程度尚未确认。

正文

原创 星云实验室 2026-11-27 18:13 北京

AI 辅助入侵触及云身份和安全管理面，公开软件仓库出现新一轮代码投毒。

事件一 CyberStrikeAI 云入侵双侧取证：失陷的构建身份把影响扩至 7 个 EKS 集群

1.1

事件简介

  • 涉及组织与应用：Wiz Research 是披露事件的云安全研究团队，CyberStrikeAI 是该案的自动化攻击编排工具，AWS EKS 是受影响的托管 Kubernetes 服务。

  • 事件概述：Wiz 调查了一起身份未公开的攻击者入侵云环境的事件。攻击者利用被盗的 Terraform 自动化任务会话进入环境。Terraform 用于管理服务器、集群等云资源。攻击活动延伸到负责软件构建的 Jenkins、运行应用的 Kubernetes 集群和云端秘密管理服务。研究团队把受害侧日志与攻击者公开暴露的工作目录相互核对，发现目录还记录了身份会话、运维主机和模型服务密钥相关活动。本案使用 CyberStrikeAI，同服务器上的 ARTEX 活动涉及其他目标。

  • 事件时间：2026 年 10 月活动持续四天，11 月 23 日由 Wiz 首次公开本匿名案例的双侧证据。

  • 事件链接：

    • https://www.wiz.io/blog/agentic-attacks-artex-offensive-ai-frameworks

  • 影响范围：

    • 受害侧遥测覆盖 2 个 AWS 账号、7 个 EKS 集群，观察到云凭据被用于访问配置状态和秘密管理服务。

    • 攻击者目录有逾 3,000 个暴露文件。Wiz 从该目录发现涉及 3,392 个身份用户及其有效会话、19 台运维跳板主机、50 把 SSH 私钥，以及从 50 台主机收集 Anthropic API 密钥的记录。数字属于不同资产口径，受影响组织身份未公开。

  • 技术分类归属：Agent 层 / 云身份 / CI/CD / 容器基础设施

  • 事件标签：云AI融合

图1：上半部分概括受害侧可见的入口、节点、构建与云凭据活动，下半部分标出攻击者目录补足的身份和运维线索。图中类别来自不同证据，无法据此确认每条受影响会话都被后续使用。来源：https://www.wiz.io/blog/agentic-attacks-artex-offensive-ai-frameworks

1.2

事件背景与回顾

  • 受害侧记录显示，被盗自动化会话进入集群管理范围，攻击还触及构建控制器、节点与云秘密管理服务。攻击者目录补足了模型密钥及员工编码助手会话历史被搜集的证据。

  • 与前周收录的 ARTEX 云身份案例属于同类威胁，系独立子事件。本周新增的是独立个案的双侧证据。Wiz 将本案编排归于 CyberStrikeAI，对同一服务器用 ARTEX 尝试的其他目标分别记录。

1.3

事件根因深度分析

  • 构建身份的授权跨过了环境边界。 对云资源的自动化管理权限可进一步触及集群管理和节点，令单个被盗会话的影响超出原构建任务。会话最初如何被盗未公开。

  • 运行、构建与身份资料集中放大损失。 构建系统可访问生产秘密，编码助手历史中也有生产登录线索。仅撤销入口会话无法自动使其他服务已泄露的凭据失效。

  • 两侧证据强度不同。 受害侧日志支持云访问行为，攻击者目录扩展了调查范围。按目录中的文件和记录报告资产，人与组织受害规模仍需独立确认。

1.4

VERIZON DBIR 事件分类

System Intrusion（系统入侵）。有凭据滥用、横向扩展、节点驻留和集中搜集证据。

1.5

攻击路径与 MITRE ATT&CK 技术映射

1.6

防御启示

  • 缩小构建身份的云访问范围，限制能改变集群权限与节点访问的工作负载。把云审计、集群审计和构建改动连成一条事件时间线。

  • 按凭据实际可达范围吊销下游会话和密钥，将编码助手历史与构建日志纳入敏感数据保护。

事件二 GreyNoise 查获 Check Point 管理服务器入侵，转发主机留有 24 台服务器的窃取数据

2.1

事件简介

  • 涉及组织与应用：GreyNoise 通过互联网传感器分析入侵活动，Check Point Security Management Server 是集中管理安全网关和策略的服务器。

  • 事件概述：GreyNoise 在调查一台遭入侵的文件服务时发现，身份未归属的攻击者将它作为转发主机，汇集来自多家组织安全管理服务器的数据与命令结果。对网络防护设备的管理服务器集中掌握策略和管理信息，失陷可能暴露内部配置及认证材料。研究团队把相关活动命名为 GT13，确认多个行业的组织受到影响，并判断攻击活动可能使用大语言模型和智能体辅助。现有证据同时记录了人工操作，无法确定哪些步骤由模型完成。

  • 事件时间：2026 年 10 月 17 日至 11 月 2 日为报告所述确认攻击窗口，11 月 23 日披露。研究方在 11 月 2 日前后失去可见性。

  • 事件链接：

    • https://www.greynoise.io/blog/check-point-security-management-servers-intrusion-campaign

  • 影响范围：

    • 至少 22 家组织、24 台 Check Point 管理服务器是不同口径。99 个 IP 属于研究观察的活动基础设施，含代理出口及失陷资产。

    • 受影响行业包括金融、能源与政府。转发主机留有凭据、内部证书材料和防火墙配置等证据，无法将这些资产类型推广至所有受影响组织。

  • 技术分类归属：基础设施层 / 安全管理面 / AI 辅助攻击研判

  • 事件标签：AI相关

2.2

事件背景与回顾

  • 受控的互联网服务器被用作 连接多处受害资产并暂存活动结果的跳板。报告区分了转发服务器、下游管理服务器，以及从个别受害方进一步深入网络的活动。

  • 研究报告列出已利用或尝试利用的多个漏洞。CVE-2026-61500 对应转发主机上的 Rejetto HFS，CVE-2026-16232 对应报告中的 Check Point 管理接口问题。各目标的初始入口没有全部还原。

2.3

事件根因深度分析

  • 文件服务器与网络管理面各有失效边界。 前者存在管理员会话校验相关缺陷，后者涉及管理接口授权。两者影响不同节点，不能把 HFS 漏洞当作 Check Point 产品漏洞。

  • 管理系统归集敏感资产。 管理服务器可集中读取网络配置和信任材料。高权限服务器失陷后，修复入口之外还需调查下游设备与证书信任。

  • 自动化痕迹与 AI 归因是两类证据。 GreyNoise 观察到批量活动和手工操作，并判断可能有 AI 辅助。公开材料未确定框架、模型或自主程度。

2.4

VERIZON DBIR 事件分类

System Intrusion（系统入侵）。研究发现服务器失陷、跨站点操作和数据被转移。

2.5

攻击路径与 MITRE ATT&CK 技术映射

2.6

防御启示

优先排查互联网可达的管理面、异常管理员会话、非预期跨站管理连接及配置批量读取。确认管理服务器失陷时，核查下游证书、账号和防火墙策略。

事件三 PolinRider 把恶意 Python 代码植入 375 个公开 GitHub 仓库，测试环境也进入风险范围

3.1

事件简介

  • 涉及组织与应用：SafeDep 是研究开源供应链风险的安全团队，GitHub 托管本次发现的公开代码仓库，Python 测试及开发环境是潜在执行场景。

  • 事件概述：SafeDep 跟踪名为 PolinRider 的软件供应链活动，发现身份未公开的操作者把同一段恶意 Python 代码植入多个公开仓库。代码藏在开发者常用的辅助模块和测试配置中，受影响项目运行测试或导入模块时可能调用它。后续代码存放在公开区块链的交易数据中，使仓库内的植入文件可以保持较小。研究团队在 375 个仓库中找到同一变体。这是检测到恶意文件的仓库数量，实际执行次数、受影响企业和数据外传情况尚未公开。

  • 事件时间：2026 年 11 月 24 日 SafeDep 披露此 Python 变体及检索结果，属午间遗漏补充。仓库内提交日期和研究方发现日期应分别判断。

  • 事件链接：

    • https://safedep.io/blog/polinrider-python-loader-ethereum-calldata

  • 影响范围：

    • SafeDep 于 11 月 24 日在 260 个 GitHub 账户下的 375 个公开仓库发现同一加载代码，其中 370 个仓库在 11 月发生过推送。该数据只覆盖此次检索所匹配的变体。

    • 主要风险对象是拉取相应提交后运行测试或导入相关模块的开发环境。曝光代码不足以确认工作站或构建任务成功执行恶意程序。

  • 技术分类归属：软件供应链 / 源代码托管 / CI 测试环境

  • 事件标签：云

3.2

事件背景与回顾

本周新增证据是 Python 变体、在源代码中的落点以及对同一变体的跨仓库检索。确认范围依据 SafeDep 的精确匹配，本条未合并其他团队对更广泛 PolinRider 活动的统计。

3.3

事件根因深度分析

  • 信任边界延伸到测试代码。 测试配置和项目辅助模块会在常规开发阶段加载，源代码与依赖清单都需接受审查。

  • 仓库内容与后续获取的代码分离。 源代码中的加载部分较小，真正行为还取决于外部数据。只核查依赖清单或仓库中显眼的大型文件容易漏报。

3.4

VERIZON DBIR 事件分类

System Intrusion（系统入侵，按源代码投毒归类）。现有证据确认仓库中的恶意代码，未确认下游入侵规模。

3.5

攻击路径与 MITRE ATT&CK 技术映射

3.6

防御启示

回溯首次引入可疑文件的提交和构建执行记录，审查测试目录和公用模块。对来源未核验的项目采用隔离环境，限制开发和构建进程访问生产身份与非必要出站目标。
