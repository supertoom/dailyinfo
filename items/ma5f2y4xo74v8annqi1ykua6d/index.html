中文原文

两名安全研究人员发现，两家汽车品牌的移动应用背后的登录系统可能被完全接管，攻击者可以访问任何客户的账户；对于拥有联网汽车的车主，还可以解锁车门并启动发动机。

这两款应用都通过 ForgeRock 让客户登录。ForgeRock 是一个身份平台，现已归 Ping Identity 所有。研究人员在这些服务器上进入了一个仍使用默认密码的管理员控制台。

他们仅于 2026 年 2 月在美国对自己拥有及经车主同意的汽车进行了完整攻击测试，并在报告问题约两小时后，两个系统均已修复。

Shubham Shah 和 Sam Curry 于上周晚些时候发表了他们的研究。他们首先从应用入手：两个品牌都通过同一个平台让客户登录，该平台分为两部分：一部分负责登录，另一部分名为 OpenIDM，保存客户记录。

OpenIDM 自带一个由 Apache Felix 工具支持的内置管理员控制台。ForgeRock 自己的加固指南要求运维人员在正式上线前移除该控制台或对其加以保护，因为它单独保存自己的密码。在这些服务器上，该控制台仍然存在，并且仍使用文档中记载的默认凭据：用户名和密码都是 admin。

该控制台禁止从开放互联网访问，但保护该站点的边缘层与其背后的 Java 软件对同一个网址的解析方式不同。通过添加编码后的斜杠和额外字符，研究人员让边缘层将请求视为无害的静态文件，而服务器则将其视为通向控制台的路径，剩下的事情便由默认密码完成了。完整方法见他们的 技术分析。

在控制台内部，研究人员利用内置调度器运行小型脚本，使其代码得以在身份服务器上执行。这让他们在保存两个品牌登录客户记录的机器上获得了一个命令提示符。

这些记录与控制台受到同一层封锁，但研究人员的代码从服务器内部访问到了这些记录。他们更改了目标账户的电子邮件地址和密码，通过普通应用以该客户身份登录，并获得了真实应用所使用的同一组访问令牌。

这些令牌就是控制汽车的钥匙。研究人员利用账户自身的车辆控制指令，解锁测试车辆的车门并启动发动机，当时车主就站在车旁；随后他们又停止发动机并重新锁车。

研究人员谨慎控制了他们所展示的内容。他们报告称，能够为受影响服务器上的任何客户账户开启会话，但仅对自己拥有或获准使用的车辆执行车辆控制指令。他们表示，他们“仅使用美国账户和车辆测试了完整攻击链”。

Shubham Shah 还发表了针对同一品牌在澳大利亚所用系统的第二种攻击。在那里，入侵方式有所不同：身份服务器的管理员凭据被留在了应用代码中，原本用于测试环境。他在另一篇文章中详述了完整的 澳大利亚攻击链。

研究人员表示，结合这两种攻击，他们可以向这些品牌在澳大利亚、美国和加拿大的汽车发送解锁及启动发动机指令。第二篇文章没有说明澳大利亚系统何时得到修复。

这次攻击几乎没给账户所有者留下任何可察觉的迹象。更改电子邮件地址和密码并未将所有者从其应用中登出，而研究人员可以将该账户的警报重定向到自己的手机，从而避开所有者的手机通知。

测试结束后，研究人员恢复了真实的电子邮件地址。两篇报告均未说明在该路径被关闭之前，是否有其他人发现或利用过该路径。

Identity Teams 应当检查什么

这些品牌的错误在于其运行 ForgeRock 的方式，而非产品本身出现了新漏洞，因此没有 CVE（用于追踪漏洞的公开编号），也没有可供遵循的厂商公告。该控制台及其默认密码多年来已有文档说明，厂商的 生产环境加固 指南早已告知运维人员，应在正式上线前移除该控制台或更改其密码。

对于运行同一身份软件的团队（该软件现以 PingIDM 名义销售），有两项检查尤为重要：

  • 检查 /system/console 路径下是否存在 Apache Felix 控制台，并将其移除或更改默认密码。
  • 不要依赖边缘层或 WAF 路径规则来隐藏管理页面。如果边缘层与服务器对路径的解析方式不同，请求就可能绕过规则，正如本次攻击一样。

这两名研究人员长期从事此类工作，通常入侵的是应用背后的 Web 系统，而非汽车本身。他们曾展示过对 Honda、Kia 和 Subaru 等品牌车辆的远程访问。

他们报告的一个 Subaru 漏洞 通过该汽车制造商的联网汽车服务暴露了车主账户及其车辆；而 2023 年开展的更广泛的 16 个品牌研究 发现，整个行业中大量系统存在同类 Web 漏洞。
