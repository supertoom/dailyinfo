Swati Khandelwal2026年10月31日漏洞 / Web 安全

安全公司 Parameter 的研究人员展示称，恶意 ChatGPT 分享链接可以在任何打开它并已登录的会话中运行攻击者的代码，从而读取其私人对话。

研究人员于10月18日通过OpenAI 的漏洞赏金计划报告了这一漏洞，OpenAI 在八天后修复了它，并将其评为 P1，这是该公司的最高严重级别。

陷阱是一个通过公开链接分享的普通 ChatGPT 对话。它可以像分享任何真实聊天一样发送：通过电子邮件、聊天消息、支持工单或社交帖子。

受害者无需安装任何东西、加入工作区，也无需通过攻击者登录。在最可靠的攻击版本中，他们只需打开链接并点击一次 ChatGPT 的 Preview 按钮。在后续版本中，Parameter 将页面设置为自动打开 Preview，因此打开链接就是唯一的操作步骤。

攻击者可以做什么

链接打开后，攻击者的代码会在受害者已登录的会话中运行，并拥有与真实 ChatGPT 网站相同的访问权限。它会列出受害者最近的对话，打开一段从未与攻击者分享过的私人聊天，并将其中一小部分发送到研究人员控制的服务器。

该代码直接调用 ChatGPT 自身要求登录的 API，而不是复制屏幕上偶然显示的内容。由于它以受害者的完整 Web 访问权限运行，其作用范围并不局限于这些聊天。研究人员写道：“从本质上说，我们可以代表受害者的 ChatGPT 账户执行任何操作。”

这项工作是一次受控测试。Parameter 没有报告该漏洞在现实世界中的任何实际使用，而是在两个独立账户之间完成了私人聊天概念验证，而不是针对真实用户进行。

链接如何突破沙箱

以下是据 Parameter 所述的攻击链运作方式。ChatGPT 可以通过一项名为 Preview 的功能，将聊天中的一段 HTML 转换成一个小型网页。由于该网页可以承载任意代码，ChatGPT 会在一个单独的 Web 地址上使用受到严格限制的框架运行它，使其无法读取周围的主 ChatGPT 页面。

沙箱本身没有被突破。入口来自同一对话中的第二项功能。

共享的聊天中还包含一个交互式图表，绘制该图表时，会将一个名为 MathLive 的数学库加载到主 ChatGPT 页面中。加载 MathLive 后，页面上会留下一个监听器，用于接受与其屏幕键盘有关的消息。

只有在接收方检查消息发送者时，浏览器框架之间传递的消息才是安全的。Parameter 发现，这个监听器接受来自任意发送者的键盘消息，而且该消息还允许携带原始 HTML。随后，Preview 便可跨越边界，将攻击者的 HTML 交给受信任的主页面。

该 HTML 创建了一个新框架，浏览器会将其视为 chatgpt.com 的一部分。随后，从 YouTube 加载的脚本提供了在该框架内运行的代码。

ChatGPT 的内容安全策略限制了页面脚本的来源。它阻止内联代码，但允许来自 YouTube 的脚本，这正是该步骤得以实施的原因。

OpenAI 修复了什么，用户应该做什么

Parameter 表示，OpenAI 复现了代码执行和私人聊天概念验证，将严重程度从 P2 提升到 P1，并在 ChatGPT Web 前端的两个版本中推出修复。截至10月26日，这两个版本都会拒绝攻击所依赖的消息。

研究人员将问题追溯到三个相互叠加的设计选择：

  1. MathLive 响应了一条会在未经检查消息来源框架的情况下更改其设置的消息。
  2. 该消息被允许将原始 HTML 作为键盘布局数据携带。
  3. 该 HTML 可以创建一个未受沙箱隔离的框架，并继承 chatgpt.com 的身份。

YouTube 这一步只是最后的变通办法，而非根本原因。仅将其屏蔽，仍会留下一个不受信任的 Preview，能够将 HTML 推送到主站点。

ChatGPT 用户无需采取任何行动。修复工作由 OpenAI 负责，用户无需安装或重置任何东西。

Parameter 在修复完成后于 10 月 28 日发布了报告。OpenAI 为该报告支付了总计 $5,000。
