执行摘要

近几个月来，Unit 42 跟踪并响应了由与 Com 有关联的威胁行为体发动的多轮语音钓鱼攻击。这些攻击已导致数据窃取和勒索企图。此类活动针对数据密集型行业，例如金融服务业、医疗保健业和法律服务业。目标组织主要位于美国、英国和澳大利亚。

对此类广泛活动的归因包括：

  • 已命名行为体，例如 Bling Libra（又称 ShinyHunters）
  • 活动集群 CL-CRI-1116（又称 Redact，原名 BlackFile）、CL-CRI-1147（又称 Pink）、CL-CRI-1182（又称 Falcon）、CL-CRI-1192（又称 Helix）
  • 新发现的 CL-CRI-1264（又称 Vortex）和 CL-CRI-1274（又称 Cinder），其活动与 Google 跟踪的 UNC6671 存在重叠

本文详述：

  • 我们基于独特遥测分析和事件响应工作，自 2026 年 8 月以来对持续的、与 Com 有关联威胁活动的观察
  • 我们跟踪的不同命名行为体和活动集群，包括此前未披露的独特观察
  • 关于受害者的洞察
  • 对攻击者战术、技术和程序（TTP）的审查
  • 随着我们迈向 2027 年，对未来活动的预示

Palo Alto Networks 客户可通过以下产品和服务获得针对上述威胁更好的保护：

  • Advanced WildFire
  • Advanced URL Filtering、Advanced DNS Security 和 Advanced IP Defense
  • Cortex XDR 和 XSIAM
  • Cortex Agentic Endpoint Security
  • Prisma Browser
  • Device Security
  • Idira Identity and Access Management (IAM)
  • Idira Identity Threat Detection and Response (ITDR)
  • Idira Secure Web Sessions (SWS)

组织可通过 Unit 42 Threat Intel Services及其 Deep and Dark Web Service获取定制的对手情报、分析师直接咨询和专门的暴露面跟踪服务。

最新洞察

新兴活动集群 CL-CRI-1264（Vortex）

2026年9月，我们发现了一个新的活动集群，并将其追踪为 CL-CRI-1264。攻击者采用的手法大体遵循 Com 关联威胁行为体使用的更广泛行动手册，但其中若干特征使其与众不同。最显著的是，我们观察到该活动主要针对医疗保健、制药及其他医疗组织。

与 CL-CRI-1264 关联的攻击者通过电话钓鱼建立初始访问，他们冒充内部 IT 支持人员，并将员工引导至使用为每个目标组织定制的子域的服务器。这些服务器充当中间人（AiTM）代理，实时将用户凭据和多因素认证（MFA）批准传递给攻击者。攻击者已将其目标锁定在员工的企业工作站和个人移动设备上。

我们观察到 CL-CRI-1264 背后的攻击者在进行身份验证后的数分钟内注册未经授权的 MFA 设备，以建立持久化。在多次事件中，攻击者在多个已入侵账户之间重复使用一个名为 Pixel 10a 的单一设备。他们还使用 Python 脚本（python-httpx User Agent）自动进行数据外泄，以针对 Microsoft 365 邮箱、OneDrive 和 SharePoint 内容。

数据外泄后，攻击者直接向受害者组织的员工发送 Microsoft Teams 消息，声称已窃取数据，并将收件人引导至一个托管于 Tor 的谈判网站。

新兴活动集群 CL-CRI-1274（Cinder）

2026年9月，我们发现了另一个新的活动集群，并将其追踪为 CL-CRI-1274。与本报告中详述的其他活动类似，攻击者利用电话钓鱼取得初始访问，并通过重放持久的“保持登录状态”会话令牌，避免系统再次提示进行 Duo MFA。随后，他们从代理基础设施重放同一会话令牌。

从那里，他们使用通过 python-requests（python-requests/2.34.2）编写的脚本，以及 Microsoft Graph 软件开发工具包（SDK），从受害者的 SharePoint 和 OneDrive 环境中收集并外泄数据。之后，攻击者使用已入侵账户通过电子邮件和 Microsoft Teams 在内部发送勒索消息，最终将收件人引导至一个托管于 Tor 的谈判网站。

恶意浏览器扩展

在一次归因于另一活动集群 CL-CRI-1192 的调查中（Google 将其追踪为 UNC6671），我们发现了一个名为 Google Chrome 的恶意浏览器扩展（清单版本 1.6.111）。

该扩展程序未在 Chrome Web Store 上架。它从攻击者控制的服务器 oskeysetup[.]com 下载，并要求受害者使用开发者模式手动侧载。将扩展程序命名为 Google Chrome 有助于伪装浏览器内置的警告横幅（Google Chrome started debugging this browser），该横幅会在扩展程序处于活动状态时显示。

该域名的注册信息与 Google 和 ReliaQuest 此前披露的、与我们追踪为 CL-CRI-1192 的活动相关的攻击者基础设施高度相似。

此浏览器扩展程序会执行多项恶意操作：

  • 安装全局键盘记录器
  • 窃取所有站点的本地/会话存储以及 IndexedDB 数据
  • 收集身份验证 Cookie（针对 Microsoft 和 Google 账户）
  • 扫描页面中的二维码以获取登录/MFA 令牌
  • 传输摄像头视频流

此外，此浏览器扩展程序通过 Chrome DevTools Protocol（chrome.debugger）实现了一个完整的命令与控制（C2）远程控制模块。它允许操作员执行以下活动：

  • 截取隐藏屏幕截图
  • 调度输入事件
  • 窃取剪贴板内容
  • 允许远程进行网站导航

我们以该文件为 pivoted 切入点，识别出另一个浏览器扩展程序，它同样伪装成 Google Chrome（版本 1.6.112），并与同一个 C2 服务器通信。这两个文件共享同一个硬编码 API 密钥。

我们以中等置信度评估，与 CL-CRI-1192 相关的攻击者开发了这一恶意浏览器扩展程序，作为从运行基于 Chromium 的浏览器（如 Google Chrome 和 Microsoft Edge）的台式机和笔记本电脑提取凭据的另一种方法。该扩展程序也可能与其他与 Com 有关联的攻击者共享和使用，尽管我们目前没有证据表明存在这种情况。

我们认可 Kevin Pham 对此浏览器扩展程序的深入调查，详见其2026 年 9 月的文章。

受害者特征

我们的遥测数据显示，与 Com 有关联的攻击组织正在持续开展活动，并在 2026 年 8 月前后显著加速。受害者具有一个共同特征：它们掌握大量高影响力的企业数据，一旦泄露将造成严重的监管、法律或市场后果。金融服务、医疗保健和法律机构是主要目标，但相关活动也遍及其他行业。

攻击者并非针对普通邮箱，而是系统性地寻找负责高价值文件、文档和数据库的个人或系统。这些攻击聚焦于：

  • 法律和企业战略： 攻击者针对合作伙伴通信、公司战略、高管薪酬和待签合同。他们明确威胁要公布客户协议和机密案件材料。
  • 金融和投资记录： 攻击者优先窃取私人投资组合、交易管线以及大规模云数据仓库。他们偶尔会外泄数千万条客户关系管理（CRM）和招聘记录。
  • 医疗保健和生命科学： 攻击者针对包含患者记录和专有研究数据的云数据平台。为最大限度施加压力，攻击者在内部聊天频道中广播勒索通知，并威胁向监管机构报告。

遭定向攻击最多的组织具有分布式员工队伍、集中式单点登录（SSO）以及广泛的云协作平台。它们也主要位于英语国家。我们观察到攻击者反复针对同一组织，有时在尝试失败数周后再次返回。

谁在遭受攻击：行业与国家

我们对与 Com 相关活动所关联域名的监测显示，其攻击目标在 2026 年 9 月初从金融服务业转向医疗保健业。图 1 显示，2026 年 8 月，这些攻击者针对金融服务组织的频率约为针对医疗保健组织的两倍，但到了 9 月，医疗保健业的受攻击次数超过了金融服务业，时间大致与我们首次观察到 CL-CRI-1264 活动时相同。2026 年 10 月，医疗保健业继续保持受攻击最多的行业地位，金融服务业亦紧随其后。攻击者也频繁针对建筑业、高科技以及运输与物流组织。

图 2 显示，2026 年 8 月至 10 月期间，大多数受攻击组织位于美国。然而，自 2026 年 9 月下旬起，我们观察到针对澳大利亚组织的攻击有所增加。澳大利亚组织在 8 月和 9 月占已观察子域名的比例不足 1%，到 10 月升至约 13%。目前，澳大利亚组织是受攻击次数第二多的组织所在国家。

战术、技术与程序

基础设施与工具

Com 关联威胁行为者的一个关键特征，是使用伪装成 SSO 门户、IT 支持页面和通行密钥配置服务的顶级域名。这些域名通常托管短生命周期的子域名，冒充目标组织，例如 {company}.mfaregister[.]com。我们积极追踪此类基础设施，对已识别域名开展威胁狩猎，并通过我们的 GitHub 仓库以 Timely Threat Intelligence（TTI）的形式发布关键发现。

在多起 Com 关联案件中，我们发现了托管基础设施、攻击链和受害者特征方面的相似之处。在某些案件中，这些行为者还会共享工具，例如 Doko's Panel，这是一个由操作者控制的 AiTM 网络钓鱼工具包。

正如 Push Security此前报告的，该工具包的一些针对 Okta 的变体会将面板默认的 backend.php 处理程序替换为重命名后的端点 api_FyekIDWY.php。我们在多个与 Com 关联案件有关的域名上观察到了此端点。

至少在一起金融服务业案件中，遥测数据记录了从输入凭据到出现 MFA 编号匹配提示的完整 AiTM 序列，表明攻击者很可能成功完成了会话捕获，如图 3 所示。

在使用不同技术针对受害者的攻击活动中，我们也观察到与 Com 关联基础设施一致的域名。例如，Microsoft 在其针对以通行密钥为主题的社会工程学研究中报告了 oskeyregister[.]com。

在此报告的基础上，我们发现了符合以下模式的 Cloudflare Pages URL：connect-pages-{company}.pages[.]dev，这些 URL 会重定向到特定于公司的子域，例如 {company}.oskeyregister[.]com。这些发现反映了更广泛的 Com 生态系统，该生态系统由若干活动集群组成；这些集群经常共享基础设施，但其技术手法可能略有差异。

除共享基础设施外，与 Com 关联威胁行为者所使用的工具在注册和部署方面反复出现的模式，也提供了识别相关域名的额外机会。表 2 展示了此类活动中观察到的常见注册模式。

攻击者行动手册

我们没有观察到 Com 关联威胁行为者采用标准行动手册。威胁行为者没有使用定制工具，而是主要利用原生云实用工具，并选择性地限制执行操作和持久化部署。

入侵通常以 vishing 开始，威胁行为者冒充 IT 人员解决身份验证问题，并将受害者引导到一个针对其所属机构定制的钓鱼页面。在 AiTM 工具包窃取凭据和会话令牌后，攻击者会迅速注册自己的 MFA 设备、滥用云实用工具，并在某些情况下部署恶意浏览器扩展，以窃取数据和勒索受害者。

利用已收集的认证数据，Com 关联威胁行为者会对受害者环境进行身份验证，通常通过住宅代理网络和商业 VPN 进行路由。随后，他们试图建立多层次持久化，枚举敏感数据并从云平台窃取数据。我们观察到 Com 关联威胁行为者采用了以下技术：

持久化

  • 注册未经授权的 MFA 设备和工作站对象
  • 生成云基础设施临时凭据
  • 授权未经批准的第三方 OAuth 应用程序或数据同步实用工具
  • 准备备用账户或收集冗余凭据

发现与防御规避

  • 监控身份验证、权限和邮箱
  • 修改日历设置和邮箱规则
  • 清除安全警报事件
  • 轮换基础设施

数据外泄

  • 使用 Rclone 等开源工具和云存储平台
  • 通过原生 SaaS 和 REST API 或基于 HTTP 的脚本化外泄方式窃取数据
  • 通过 SaaS 到 SaaS 传输移动数据

结论

今年早些时候，我们的2026 Unit 42 全球事件响应报告发现，2025 年未使用加密的勒索事件（占比 78%）多年来首次降至 90%区间以下。这一趋势持续到了 2026 年，我们预计不会放缓。Bling Libra 和其他 Com 关联威胁行为者等网络犯罪分子正在放弃加密，从而能够更快地推进其入侵生命周期，同时仍能实现目标。

转向不使用加密的另一个合理动机，是在执法部门近年来加大对勒索软件运营者打击的情况下避开他们的视线。然而，转向不使用加密似乎已不足以让他们避开视线。这一判断基于对涉嫌 Bling Libra 成员（如“Rey”和“Umbreon”）的逮捕报道，这些逮捕发生在该组织声称入侵 FBI事件前后。

近期的逮捕还包括一名据称运营 Bling Libra 勒索站点的人。

展望未来，各组织必须：

  • 收紧帮助台验证流程
  • 转向具备抗钓鱼能力的 MFA（FIDO2/通行密钥）
  • 实施浏览器扩展允许列表
  • 建立对身份相关操作的可见性
  • 对未经授权的数据导出发出警报，以缓解本文所述的威胁活动

Palo Alto Networks 客户可通过以下产品获得更充分的保护，抵御上述威胁：

  • Advanced WildFire的机器学习模型和分析技术已根据本研究共享的威胁指标进行了审查和更新。
  • Advanced URL Filtering、Advanced DNS Security和Advanced IP Defense会将与此类活动相关的已知域名和 URL 识别为恶意。
  • Cortex XDR 与 XSIAM 采用多层防护方法进行设计，可帮助防御本文所述的威胁，覆盖整个攻击生命周期。通过结合行为威胁防护、Advanced WildFire 和 凭据收集防护 等高级能力，这些平台能够在威胁攻击者达成其目标之前检测并阻止恶意行为——包括凭据窃取、未经授权的持久化以及基于脚本的执行。
  • Cortex Agentic Endpoint Security 的设计目标是帮助发现整个智能体端点上的每一项 AI 制品和 AI 智能体的活动，评估其风险，强制实施预防与运行时控制，并修复违规行为。
  • Prisma Browser 旨在防止类似我们研究中揭示的那类基于扩展的攻击。
  • Device Security 旨在主动保护运营环境中专业化的设备攻击面，为工业协议提供深度可见性，为所有 OT 与 IoT 资产提供可执行的风险洞察和自适应安全防护。
  • Idira Identity and Access Management (IAM) 可帮助为人类、机器和 AI 身份实现安全统一的访问，在细粒度控制与无缝用户体验之间取得平衡。凭借 SSO、抗钓鱼 MFA、无密码登录和企业密码管理，Idira IAM 将智能权限控制与会话安全扩展至更广泛的员工群体。
  • Idira Identity Threat Detection and Response (ITDR) 可帮助安全团队应对针对 Idira Next Generation Identity (NGI) Platform 及其所保护身份的身份攻击。利用由 CORA AI 驱动的近实时检测，并结合 Idira 在多个上下文中的可见性（如 PAM、身份验证、SSO、云、端点、浏览器等），Idira ITP 能够实施自动化、定制化且不打断会话的响应，以遏制并尽量减少潜在的基于身份的威胁。
  • Idira Secure Web Sessions (SWS) 旨在为高度敏感的 SaaS 应用会话提供客户端侧防护（阻止剪贴板/下载）以及分步审计日志。
