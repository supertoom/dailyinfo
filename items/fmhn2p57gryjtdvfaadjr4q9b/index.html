Elastic 9.6 发布：AlertZero、ES|QL S3 数据联邦、Universal Alerting 等新特性

Elastic 9.6: AlertZero, ES|QL S3 Data Federation, Universal Alerting, and more!

AI 导读

Elastic 9.6 能力已在 serverless 上线，预计 12 月初面向 ECH 与 Self-Managed 部署提供。

正文 · 原文

Today, we are pleased to announce the availability of Elastic 9.6 capabilities in serverless. Elastic 9.6 is expected to be available for ECH and Self-Managed deployments in early December. Included in this release are major advancements across Elastic’s platform for Search & AI, Elastic Observability, and Elastic Security. 

What’s new in Elastic 9.6?

Elastic 9.6 introduces an array of new and expanded features to tackle common challenges every team faces: voluminous data, too many alerts, and less time to make sense of it all. This release puts AI agents at the center with the arrival of AlertZero and Elastic nightshift AI SRE, bringing automation to alert response while maintaining transparency and choice. Additionally ES|QL Data Federation makes it even easier for teams to query data outside of Elastic. 

Below is a shortlist of some of the 9.6 features we’re most excited about. 

Elastic Security

Elastic Security 9.6 brings major enhancements to how Elastic Security uses AI agents to support the SOC, with transparency and choice front and center. AlertZero, the agentic layer of Elastic Security, arrives in technical preview, alongside improvements to Entity Analytics and endpoint protection. 

  • AlertZero, the agentic layer of Elastic Security (technical preview): Most teams ration alert coverage by headcount, so the queue decides what gets attention and the rest ages out unexamined. AlertZero puts SOC teams on the path to inbox zero, for alerts. Four agents, called Watches (Triage, Hunt, Detection, and Forensics), work alerts day and night, connect scattered signals, and bring evidence-backed conclusions for your team to review. No two SOCs are organized the same way, so you choose which Watches run and how much each can do on its own. You can read the reasoning and use your choice of model, wherever your data lives.

  • Highlighted Entity Analytics to head start your hunt: Entity Analytics used to give you a risk score, but not which entities to focus on. In 9.6, Elastic Security highlights the entities that need attention right now and why. Six attention signals surface entities whose situation is changing, including newly high-risk entities and ML anomalies. Entities are now resolved across data sources, so maria.chen in Okta and CORP\mchen in AD show up as one. 

  • Ransomware protection for Linux: We’ve extended feature parity with the ransomware protection Elastic Defend already provides on Windows and macOS, so Linux hosts get the same behavior-based defense against encryption, whether or not you have seen the malware before. This feature will be available as part of the 9.6 release in early December.

Learn more about these and other features in our 9.6 Security feature roundup. 

Elastic platform, Search & AI

Elasticsearch 9.6 provides users with more ways to get answers from more of their data, faster and with less friction. Key features include direct access to query Amazon S3 data with ES|QL Data Federation, faster and lower-cost analytics with Columnar Mode, team collaboration with AI agents in Kibana, document ingestion with Jina-powered OCR, and stronger governance and compliance for enterprise deployments. 

  • Query data where it lives with ES|QL, starting with Amazon S3: With ES|QL Data Federation (in technical preview), Elasticsearch now queries and searches data wherever it lives, starting with Amazon S3. You can query Parquet, CSV, TSV, and NDJSON files with the same ES|QL syntax and Kibana workflows you use for indexed data, instead of ingesting the data, reindexing it, or reconciling results across tools. 

  • Columnar storage and high-performance analytics: We’re continuing to build upon Elasticsearch Columnar Mode (in technical preview) for high-volume data with leading storage efficiency, performance, and simplicity.

  • Kibana chat: With new features like multi-user chat in Kibana, teams can share conversations and see and interact with agent responses alongside colleagues. And with custom panels, users can easily create tailored visual components and charts from text prompts without deep frontend coding or design experience. 

  • Elastic Inference Service: Non-streaming chat completion allows Kibana chat to work behind proxies that don’t allow HTTP streaming common to regulated industries. Opt-in prompt caching lowers costs and latency of multi-turn workflows in Elastic Agent Builder.  The new document_extraction inference task type (now in technical preview) automates ingestion and processing of content in PDFs and document formats to create clean markdown text using the jina-ocr-v1 model. This makes this content usable for AI agents, systems of record, and document archiving. This feature will be available as part of the 9.6 release in early December.

  • Control identity, spend, and audit across your environments: Automation, spend, and audit records are easier to manage when each one has a clear owner. Elastic Service Accounts let you run scheduled Workflows under a dedicated account instead of a person’s login or a long-lived API key, so automation keeps working when its author changes teams. Budget alerts by day, week, month, quarter, or year tell you when spend reaches your threshold, and Serverless log delivery sends audit logs to a destination with its own retention policy. In GovCloud, the Elastic Cloud audit trail answers who changed a deployment or an organization setting. For regulated environments, Elastic Agent now supports FIPS 140-3, and Managed Integrations are available in GovCloud.

Learn more about these and other new features in our 9.6 Elasticsearch feature rollup.

Elastic Observability

Elastic Observability 9.6 improves application investigations with more context and lets developers and SREs bring more of their product environment into Elastic Observability. Highlights include the new Elastic nightshift AI SRE (in private preview), richer APM investigations, new integrations, and a new platform feature called Universal Alerting. 

  • Meet the Elastic nightshift AI SRE (private preview): The AI SRE detects and investigates across your stack, learning from every incident, finding what alerts miss, and delivering evidence-backed answers you can trust.

  • Investigate applications with context: Use a contextual service map on APM service pages, and start one-click AI investigations from the map. In Discover, drill down from APM services to individual spans. GenAI traces (technical preview) show prompts, responses, and token usage, built on OpenTelemetry with no proprietary SDK.

  • Bring in the tools your teams build on: Use new Vercel, Supabase, and Temporal integrations with no agent to deploy, plus FIPS 140-3 support in Elastic Agent for regulated environments.

  • Write any alert in ES|QL: Universal Alerting is now generally available, with every alert stored as searchable data. It runs alongside Classic Alerting, so there is nothing to migrate.

  • Scale synthetics monitoring: Synthetics private locations now scale automatically. Elastic spreads monitors across the agents in a Fleet policy and moves them to healthy agents if one goes offline, so there is no manual sharding.

Learn more about this and other new features in our 9.6 Observability feature rollup.

In case you missed it …

We've stayed busy between stack releases! Below is a quick recap of some key announcements since 9.5 in case you missed them:

  • AutoOps: AutoOps is fully rolled out on Elastic Cloud for commercial and FedRAMP Moderate, with a redesigned experience and many more insights, such as dense vector off-heap memory pressure.

  • Cross-project search (CPS): CPS for Elastic Cloud Serverless is now GA, enabling organizations to run a single query across multiple serverless projects.

  • Jina OCR: A new optical character recognition (OCR) model that processes complex layouts, tables, handwriting, and math is now available across 100+ languages with frontier-grade accuracy at a fraction of the size and cost. 

  • Elasticsearch Vector Database: This new serverless offering is purpose-built for large-scale vector search and AI applications. Developers bring their documents and queries, and Elastic handles the embeddings, tuning, and infrastructure underneath. 

Start today

Ready to get started? These and other Elastic 9.6 capabilities are now available in serverless (unless otherwise noted) and expected to be available for ECH and Self-Managed deployments in early December.
