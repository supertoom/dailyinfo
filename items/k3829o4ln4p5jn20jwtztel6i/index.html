Elastic Security Labs 发现 Microsoft Agent Framework 的 PyPI 元包 agent-framework 遭供应链投毒，恶意版本 1.26.1 与 1.26.2 分别于 2026-11-17 20:35 和 21:08 UTC 发布，并在 1 小时内被 PyPI 移除。

同一件事，精选收录的是《Microsoft Agent Framework 的 PyPI 包 1.26.1 和 1.26.2 被植入凭据窃取代码》

入侵事件及我们的检测方式

Microsoft’s Agent Framework 是一个开源的多语言框架，用于在 Microsoft Azure 生态系统中构建和编排 AI 代理。遭入侵的包是元包，也就是一个用于引入不同框架依赖项的轻量封装程序。agent-framework 在所有版本上的平均下载量为每月 196,000 次下载。如果版本 1.26.1 或 1.26.2 接触过构建代理或笔记本电脑，请假定该主机上的所有密钥均已泄露，并回退固定到 1.26.0。

agent-framework 1.26.1 于 2026 年 11 月 17 日 20:35 UTC 在 PyPI 上线。我们的供应链监控器在 20:41 UTC 将其标记为恶意，并于当晚发布了详细信息。版本 1.26.2 在 21:08 UTC 推出，采用了相同的信息窃取程序，但换用了新文件名。PyPI 移除了这两个版本，用时不到一小时。

这两个版本都包含一个 .pth 启动钩子（这是一个纯文本配置文件，Python 的 site 模块会在解释器每次启动时自动处理该文件），因此每当主机上的 Python 启动时，凭证窃取程序都会运行。导入该包并非必要条件。它会读取最多 300 个运行进程的环境变量、Azure CLI 令牌缓存，以及 pip、npm、Docker、git 和 Hugging Face 凭证，然后调用 Azure DevOps 和 GitHub Actions OIDC 端点以及 Azure Instance Metadata Service，以生成新的云端令牌。这些令牌使遭入侵的构建能够访问其背后的 Azure 订阅。收集到的所有数据都被发送到单个 webhook[.]site 端点，并经过 zlib 压缩和 Base64 编码。

攻击者在遭入侵的 1.26.1 包中添加了两个新文件（agent_framework_meta.pth、_telemetry.py），并修改了一个文件（__init__.py）。

攻击由 .pth 钩子基于以下单行代码触发：

每当 Python 启动时，其 site 模块都会处理 site-packages 目录中的所有 .pth 文件。这些文件中任何以 import 开头的行都会作为代码执行，且在用户脚本或任何其他代码运行之前执行。
此次导入会执行该包的 __init__.py，其中包含一个附加在文件末尾的加载器，该加载器会导入 _telemetry.py 并调用其 _start() 函数。
_start() 函数使用环境变量 _AF_TEL，以避免在每个进程树中运行多次，然后派生一个子进程，并通过 setsid() 将其分离。子进程收集密钥并将其 POST 到 webhook[.]site，而父进程继续正常运行，因此窃取过程不会造成任何可见延迟。在 Windows 上，由于 fork() 不可用，它会改为在后台线程中执行收集。

来自管道端点的 Azure DevOps OIDC 令牌
如果窃取程序在 Azure DevOps 流水线中运行，它会使用 SYSTEM_ACCESSTOKEN 调用流水线 OIDC 端点（SYSTEM_OIDCREQUESTURI)，首先请求 api://AzureADTokenExchange 范围，然后使用空的请求体重试。两个请求都不包含 Microsoft 文档所述流程用于为特定服务连接签发令牌的 serviceConnectionId 参数，因此尚不清楚这些请求是否会返回与任何联合凭据相匹配的令牌。
如果获得了可用令牌，无论是通过此请求还是从 Azure 任务暴露的环境变量中获得，都可以用它换取 Microsoft Entra ID 访问权限，身份将作为相应的工作流身份联合服务连接背后的身份。
攻击者将获得该身份的 Azure 角色分配；具体权限可能仅限于单个资源组，也可能扩展到整个订阅，具体取决于服务连接的配置方式。
通过 IMDS 获取 Azure 托管身份令牌
如果窃取程序运行在具有托管身份的 Azure 资源上，它会为该身份请求访问令牌。在 App Service 和类似平台上，它使用本地身份端点（IDENTITY_ENDPOINT 或 MSI_ENDPOINT）；在其他情况下，它会查询位于 169.254.169[.]254 的 Azure 实例元数据服务（IMDS）。它会为 12 个资源分别请求令牌，包括：
    

  • Azure Resource Manager
    • 

  • Microsoft Graph
    • 

  • Key Vault
    • 

  • Storage
    • 

  • Azure AI Foundry
    • 

  • Azure Machine Learning
    • 

  • Container Registry
    • 

  • Azure DevOps（499b84ac-1321-427f-aa17-267ca6975798）
    • 

每个令牌都允许攻击者在令牌有效期内以托管身份身份访问相应服务，并拥有该身份被授予的权限。窃取程序还会收集 IMDS 实例元数据，例如订阅 ID、资源组和 VM 名称，这些信息会准确告诉攻击者被窃取的令牌属于哪个环境。
外传到由攻击者控制的基础设施
收集到的数据（包括主机上下文，如主机名、用户名和工作目录、命令行参数以及时间戳）会全部打包到单个 POST 请求中。这些数据会被序列化为 JSON，使用 zlib 压缩，并进行 Base64 编码。结果会作为请求正文发送到 https://webhook[.]site/d381fd80-ec62-42ad-8f5c-d1b15103c9bb?t=telemetry，User-Agent 为 af-runtime-diagnostics/1。

Python 模块（af_runtime_diag.py）包含完全相同的窃取代码，只是新增了针对 GitHub Actions 的目标。
两个恶意版本都指向同一个外传端点（https://webhook[.]site/d381fd80-ec62-42ad-8f5c-d1b15103c9bb?t=telemetry）。

如何响应 agent-framework 供应链入侵
    

  • 在 site-packages 文件夹（agent_framework_meta.pth、af_runtime_diag.pth）中搜索以下文件，以检查是否受到影响。
    • 

  • 将 agent-framework 固定为干净版本（1.26.0）。
    • 

  • 将受影响主机上所有可读取的内容都视为已泄露。这包括所有运行进程的环境变量、凭据和配置文件、缓存的云端和 CLI 令牌，以及主机上的构建或工作负载所接触到的任何机密。轮换长期有效的机密，并审查短期令牌的活动；这些令牌无法撤销。
    • 

  • 搜索代理、DNS 或防火墙日志，使用 User-Agent（af-runtime-diagnostics/1、runtime-diagnostics/1）webhook[.]site。
    • 

  • 考虑在采用新发布的软件包之前增加一段延迟，因为此次攻击在数小时内即被发现并移除。
    •
