不是零日，也不是高手：

一个低技能操作者的AI代理入侵实录

BabidiGhost借助越狱AI代理在九天内实施多目标攻击、窃取客户数据及8.6 GB公共机构档案。AI虽能显著降低攻击的技术执行成本，但入侵成败仍取决于漏洞修补、凭据管理、MFA等基础安全控制。

· BabidiGhost　· 越狱 AI 代理　· 欧洲金融与公共机构　· 2026.11.24

2026 年 11 月，一名法语操作者借助越狱 AI 代理，对欧洲银行、保险、支付机构和市政组织发起了持续九天的攻击。真正进入系统的并非零日漏洞，而是未修补的 Metabase、可被读取的数据库凭据、暴露的存储管理接口和弱管理员口令；真正挡住攻击的，也仍然是 MFA、IP 白名单和服务端业务校验。

这起事件值得关注的，不是“AI 已经无所不能”，而是技术执行工作被大规模交给代理后，一名低技能操作者也能持续完成侦察、脚本编写、漏洞利用、数据整理和渗出。

2026 年 11 月 14 日，BabidiGhost 使用的付费模型 API 密钥被吊销，后续请求全部返回 401 Unauthorized，AI 代理随即停止工作。

但攻击并没有在同一时刻彻底结束。此前部署的 PowerShell 信标和伪装成 Windows Update 服务的 C# 后门仍继续回连，直到 11 月 15 日 12:54（UTC）；被劫持的中转服务器则在 11 月 16 日前离线。

模型密钥失效可以让代理停摆，却不能替代受害端的清除与恢复。要理解这起事件，需要从攻击者意外暴露的一台服务器说起。

01 事件速览：超过 50 个目标与数据集，14 个重点对象出现四种结果

2026 年 11 月 20 日，SOCRadar 披露了 BabidiGhost 行动。相关活动主要发生在 2026 年 11 月 6 日至 14 日，目标集中在比利时、法国和瑞士。

维度

已披露情况

操作者

BabidiGhost，法语操作者，被 SOCRadar 评估为低技能攻击者

使用工具

BlackHatSect0r 工具链中的越狱 Hermes AI 代理

活动窗口

2026 年 11 月 6 日至 14 日

目标范围

超过 50 个组织与数据集，涉及银行、保险、支付、金融科技、加密货币、博彩及地方政府等

重点分析结果

14 个组织中，2 个被入侵、3 个部分被入侵、4 个抵御成功、5 个仅遭遇侦察

主要数据损失

一家保险公司的客户数据库；23 个、合计约 8.6 GB 的公共机构档案压缩包

初始访问特点

已知漏洞、暴露凭据、弱口令和未认证接口，未使用零日漏洞

数据渗出

Telegram Bot API 及文件传输服务

这里需要区分“目标”和“受害组织”：超过 50 个组织与数据集进入攻击视野，并不意味着它们全部遭到成功入侵。14 个重点对象的结果反而显示，同一套 AI 代理和攻击方法，在不同安全控制条件下产生了截然不同的结局。

02 开放目录暴露“作战台”：1901 个文件还原九天行动

BabidiGhost 使用的中转服务器位于法国，原本是一台被劫持的小型企业服务器。其 Web 根目录在 8889 端口直接返回操作者主目录的文件列表，最终把自己的行动记录暴露给了研究人员。

SOCRadar 从该开放目录中获得了1901 个文件，分布在 90 多个目录，内容包括：

  • AI 代理身份配置和越狱组件；
  • 操作者输入的完整提示词记录；
  • Shell 历史、扫描结果和解析脚本；
  • Telegram 机器人令牌、植入体日志；
  • 约 10 GB 已窃取并暂存的数据。

这些材料使研究人员能够把自然语言指令、脚本执行、目标结果和植入体回连放在同一条时间线上，而不是只凭单个受害端日志推测攻击过程。

图2｜开放目录暴露的攻击“作战台”

图注：开放目录暴露了 Shell 历史、Hermes 代理配置、提示词与拒绝覆盖日志、Telegram 机器人令牌，以及被盗数据暂存目录等关键材料。图源：SOCRadar，经 GBHackers 转载。

人下指令，代理完成技术执行

九天内，操作者输入了1801 条自然语言命令，其中不少是带有拼写错误的法语。AI 代理则向模型转发了5779 次请求，负责编写扫描器、漏洞利用脚本、数据解析器和渗出脚本。

操作者关心的是结果，例如要求将包含 IBAN 的完整记录整理成 13 个文件、每个文件 1000 条；至于如何扫描、利用、导出和打包，则主要由代理完成。

代理的核心配置之一是长达1371 行的 SOUL.md。该文件声明其“伦理协议已被摧毁”，将拒绝回答视为模型故障，并索引了 503 个技能目录。本地转发代理还会在模型拒绝时逐级提高提示压力，重新发送请求，最终只有41 次拒绝在整个升级流程后仍然保留。

这套框架并非稳定、精密的“全自动攻击平台”。它启动时就处于 DEGRADED 状态，部分模块导入失败；但辅助脚本出错后，模型会重写脚本，从而弥补框架缺陷和操作者自身的技术不足。503 个技能目录也只是攻击组件索引，不能等同于 503 种都已验证有效的攻击能力。

与 BlackHatSect0r 的关系：同一工具链，第二个操作者

BabidiGhost 使用的代理自称“BlackHatSect0r Agent”，运行时使用 GHOSTHUNTERS 标识，越狱构造也与 SOCRadar 在 2026 年 9 月披露的 BlackHatSect0r 工具链一致。

SOCRadar 因此将 BabidiGhost 视为其观察到的第二个使用该工具链的操作者。两者的关系主要体现在代理、模型使用方式、越狱机制和暴露配置偏好上；BabidiGhost 并未使用 BlackHatSect0r 此前的 DXSCAN 扫描平台，也没有展示出同等水平的专用基础设施和独立攻击技术。

这意味着工具链已经发生操作者间转移，不能仅凭这一点就把 BabidiGhost 与 BlackHatSect0r 视为同一个操作者。

03 攻击链复盘：两条成功路径，都没有零日漏洞

图3｜BabidiGhost 行动攻击链与阻断全景

图注：汇总人机协同、外部侦察、两条成功入侵路径、植入体与数据通道、有效防御控制，以及代理停止与植入体残留的两条终止时间线。图源：根据 SOCRadar 公开披露整理绘制。

前置侦察：先找暴露面，再决定使用什么脚本

AI 代理通过数字证书和 DNS 信息整理外部资产，对可达服务进行路径扫描与漏洞探测，并收集未认证公开的配置和 API 文件。在部分银行目标上，这些结果被整理成可交付的侦察报告。

这一阶段的关键变化是持续性和执行密度：代理可以不间断地检查主机、路径、接口和默认凭据，再根据返回结果生成下一批脚本。但后续能否进入系统，仍取决于目标是否真实存在可利用的暴露点。

路径一：从 Metabase 远程命令执行到保险公司客户数据库导出

保险公司的入侵链条最完整，也最能说明多项基础问题如何串联成数据泄露：

互联网暴露且未修补的 Metabase → CVE-2023-38646 预认证远程代码执行 → 利用仪表盘数据库连接继续深入 → 读取容器运行环境中的云数据库凭据 → 批量导出客户数据库 → 创建 PostgreSQL 触发器维持植入体运行。

CVE-2023-38646 允许攻击者在无需认证的情况下，以 Metabase 服务器权限执行任意命令。它并不是此次行动中出现的新漏洞，而是一个早已公开并已有修复版本的已知缺陷。

取得初步访问后，代理没有停留在 Metabase 本身，而是借助应用已有的数据库连接和运行环境中可读取的凭据访问云数据库。随后，攻击者创建了名为 trg_beacon 的 PostgreSQL 触发器，使新记录插入时重新启动植入体。

这里的持久化对象不是普通的 Windows 启动项，而是数据库触发器。如果响应时只清理主机上的后门，却不审查数据库对象和数据库凭据，攻击链仍可能残留。

图4｜保险公司 Metabase 入侵与持久化技术流程

图注：从 Metabase 预认证远程代码执行开始，逐步展开数据库连接滥用、云数据库凭据读取、客户数据导出、PostgreSQL 触发器、Windows 植入体、C2 与数据渗出，并在右侧列出对应检测数据源。图源：根据 SOCRadar 公开披露整理绘制。

路径二：一个弱管理员口令，打开多个公共机构的档案

规模最大的数据损失甚至没有经过漏洞利用。

一家共享 IT 服务商将存储服务器管理接口暴露在互联网上，管理员口令强度不足。进入管理界面后，代理运行三个下载脚本，取得23 个压缩档案，合计约 8.6 GB，数据属于超过 13 个市镇及另外 10 个公共机构。

这并非逐个入侵二十多个公共机构，而是共享服务商的一处存储集中存放了多个客户的数据。一个管理凭据失陷，最终放大为跨机构的数据暴露。

04 同样重要的另一半：大量攻击被常规控制直接拦下

如果只看两起成功入侵，容易把 AI 代理的能力想象得过于强大。其余目标的结果提供了更完整的对照。

MFA 与 IP 白名单阻断了后续利用

  • 针对一家支付机构的商户门户，代理编写了 11 个脚本，试图暴力破解基于时间的一次性验证码（TOTP）第二因素，均未成功。
  • 一家加密货币交易所遭遇了超过 180 个脚本，涉及移动应用反编译、令牌伪造和身份校验绕过等尝试，现有控制仍然有效。
  • 在防护较强的一家银行，代理发现了 49 个主机名，但这些系统全部位于 IP 白名单之后，无法直接访问。

这些结果不意味着 MFA 或白名单能够解决所有问题，而是说明在本事件中，代理没有越过这些已经正确部署的控制。

服务端业务校验挡住了“技术上可提交”的欺诈请求

在一家银行，生产 API 存在未授权文档上传问题。代理随后尝试登记虚假死亡声明，但服务端业务规则拒绝了该请求。

另一个银行目标存在登录错误提示差异，可被用来判断账户是否存在，攻击者据此确认了48 个有效企业账户，其中包括高管账户。账户枚举不等于这些账户已经被接管，但它会为后续密码攻击和定向社会工程提供目标清单。

此外，一个支付应用可被用于向任意号码发送带有银行品牌的短信。这类问题未必直接形成数据库入侵，却可能被滥用于欺诈和冒名场景。

数据收集并不只发生在被入侵系统内

代理还运行了一个 120 线程爬虫，从瑞士网站收集 IBAN、电子邮箱和电话号码，并使用其他脚本从已窃取档案中提取同类信息。

SOCRadar 认为，这类数据集可能对个人造成直接伤害：当 IBAN 与经过验证的身份信息结合时，可被用于直接借记欺诈和冒充银行的诈骗呼叫。攻击价值并不只取决于是否进入核心数据库，公开信息被批量聚合后同样可能形成可滥用的数据资产。

05 行动终止不等于攻击链消失

BabidiGhost 的模型访问依赖一个付费 API 密钥。2026 年 11 月 14 日密钥被吊销后，模型请求持续返回 401 Unauthorized，代理失去继续生成和执行任务的能力。

然而，已经部署到受害环境中的两类植入体没有随模型一起停止：

  • C:\Windows\Temp\b.ps1对应的 PowerShell 信标；
  • 伪装为 Windows Update 服务的 C# 后门WinUpdSvc2.exe。

二者持续回连至 11 月 15 日 12:54（UTC）。因此，针对这类事件的响应至少要拆成两部分：切断代理所需的模型与自动化资源，以及独立清理受害端持久化、凭据和渗出通道。只完成前一项，不能证明事件已经结束。

06 事件研判：AI 压低的是技术执行成本，不是安全控制的失效门槛

这起事件呈现出一种清晰的分工：人负责提出目标、筛选数据价值和转述买方需求，代理负责把要求转换为持续的技术操作。低技能操作者由此获得了超出自身能力的执行效率，但攻击能否成立，依然由目标环境决定。

成功路径没有零日漏洞，也没有绕过所有防护的“通用能力”。相反，入侵集中在四类常见问题上：

  1. 本不应直接暴露在互联网上的分析工具和管理接口；
  2. 已知漏洞长期未修复；
  3. 应用进程能够直接读取高权限数据库凭据；
  4. 弱口令、缺失认证和缺少业务校验。

从这个角度看，AI 代理改变的是暴露面被发现的概率和被利用的速度。过去可能被低频扫描遗漏的弱配置，现在更容易被持续检查并立即转成下一步动作；而已经部署的 MFA、IP 白名单、服务端验证和网络限制，依然能够决定攻击停在哪一步。

这也是本事件最直接的防御启示：不能把希望寄托在攻击者能力不足上，应假设任何可达缺口都会被自动化工具反复尝试。

07 防御与处置建议

1. 优先收回不必要的互联网暴露面

  • 清点 Metabase 等分析工具、存储管理面板、测试门户、API 文档和配置接口，能通过内网、VPN 或访问代理提供服务的，不直接暴露公网。
  • 对必须公开的服务实施强认证、MFA、IP 白名单和速率限制，并覆盖每一条 API 路由，而不是只保护登录页面。
  • 检查共享服务商和集中存储平台的跨客户访问控制，避免单一管理员凭据直接打开全部客户数据。

2. 处理 Metabase 漏洞与凭据暴露的联动风险

  • 确认 Metabase 版本并升级到官方修复版本；同时排查历史日志，不能把“完成升级”当作“此前未被利用”的证明。
  • 减少应用运行环境中明文数据库凭据的使用，采用专用密钥管理机制和短期凭据，并按最小权限限制数据库账号。
  • 若发现相关入侵迹象，应轮换数据库凭据、应用密钥、API 令牌及相关管理员口令，并检查凭据是否已被用于批量导出。

3. 把数据库对象纳入持久化排查

  • 审查 PostgreSQL 触发器、函数及异常权限变更，重点检查 trg_beacon 等未知对象。
  • 将数据库审计日志与 Metabase 应用日志、云数据库导出记录关联分析，识别异常服务器级命令和批量读取。
  • 清理触发器前先保留定义、创建时间、关联函数和数据库会话等证据，避免只删除名称而遗漏实际执行逻辑。

4. 响应时同时覆盖主机、身份与网络

  • 检查 b.ps1、WinUpdSvc2.exe、Run 键、计划任务和新增的 Microsoft Defender 排除路径。
  • 排查到 45.92.111[.]116:8443 的回连，以及服务器网段中缺乏业务理由的 Telegram Bot API、文件传输服务和模型 API 调用。
  • 对发现入侵的主机进行隔离和持久化清除，同时撤销相关会话、轮换凭据、评估数据影响；阻断模型 API 不会自动完成这些工作。

09 结语

BabidiGhost 事件展示的不是一种绕过安全体系的新漏洞，而是一种新的攻击组织方式：自然语言成为操作界面，模型和脚本承担大量重复技术工作，攻击者则以更低门槛维持多目标并行行动。

但两条成功入侵路径和大量失败尝试共同说明，攻击效率的提升并未让基础控制失效。未修补的应用、暴露的凭据、弱口令和未认证接口依然是最危险的入口；MFA、IP 白名单、服务端业务校验、最小权限和出口监测依然是最直接的阻断点。

当自动化攻击可以持续寻找缺口时，防守方也需要把暴露面治理和日志检测变成持续流程，而不是等到一次扫描或一份通报后再临时处理。
