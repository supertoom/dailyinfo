Apache 软件中的两个严重漏洞正遭到利用，CISA 于周三将其中一个漏洞加入了其已知遭利用漏洞（KEV）目录。

Apache Axis 漏洞在攻击中遭到利用

CVE-2026-90436于11月6日公开，是 Apache Axis 1.x（一个已停止维护的 Java SOAP 实现）中的不安全反射漏洞。该缺陷的 CVSS 分数为 9.8，可能允许未经身份验证的攻击者在易受攻击的系统上执行任意代码。

Rapid7 于11月13日检测到利用活动，目标环境运行 Atlassian Confluence Data Center。攻击者执行了数百条命令，使用应用程序的凭据访问 Confluence 数据库，并搜索敏感信息。

在最初利用发生后的四小时内，攻击者已获取一个服务账户凭据，并开始查询生产环境中的云数据仓库。首次漏洞利用请求后大约十二小时，攻击者使用一个集成服务账户登录了 Microsoft 365。

Rapid7 还引用了 N-able 关于攻击活动的报告，其中涉及针对 N-central 的攻击，该攻击与 CVE-2026-90436 高度相关。Confluence 和 N-central 均需要采用非默认配置才会易受攻击。

此外，Previdian 报告称，在11月12日至19日期间检测到来自14个 IP 地址的50次漏洞利用尝试。其传感器数据无法确定这些尝试是否成功。

Apache 计划不发布修复了 Axis 1.x 的版本，并建议迁移到其他 SOAP 引擎或应用其已发布的补丁。

Confluence Data Center 用户可以升级到9.2.28版或不受影响的10.x版本。N-central 2026.4 HF3 禁用了 Legacy API 功能，该功能会暴露存在漏洞的 Axis 组件。

CISA 已将CVE-2026-90436加入其 KEV 目录，指示联邦机构在11月21日前完成修复。

Apache Roller 漏洞同样遭到利用

Apache 还确认了CVE-2026-129448 正遭到积极利用。这是一个 CVSS 9.8 漏洞，影响其基于 Java 的博客平台 Roller 4.0.0至6.1.4版本。该缺陷允许未经身份验证的远程代码执行。

Apache 在11月17日发布的公告中表示：“该问题正遭到积极利用”，但未提供有关这些攻击的进一步信息。

该漏洞源于 Roller XML-RPC 接口中的不安全反序列化，该接口会在身份验证之前处理恶意数据。通过应用程序的管理界面禁用 XML-RPC 并不能阻止漏洞利用。

Apache 最先于9月以 CVE-2026-82384 公开了同一个底层漏洞。

Apache 解释道：“这是与 CVE-2026-82384 相同的漏洞，后者仅将 Apache Roller 6.1.5 列为受影响版本。”

该缺陷已在 Roller 6.1.6 中修复。Apache 建议升级到该版本或更高版本。6.1.7版于11月11日发布，修复了另外15个漏洞。
