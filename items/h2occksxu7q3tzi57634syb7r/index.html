中文原文

一种名为 SCKit 的新型蠕虫式恶意软件工具包已被部署在近期的 ScreenConnect 攻击中，目标针对托管服务提供商（MSPs），旨在从受感染的客户设备传播至 MSP 技术人员的计算机，并攻陷更多受管网络。

该恶意软件工具包采用蠕虫式技术，利用此前已修补的 ScreenConnect 漏洞 CVE-2026-84869，在技术人员连接到受感染设备时于其工作站上执行恶意代码。

然而，Huntress 和 Blackpoint Cyber 的研究人员表示，他们未观察到此次攻击期间成功利用该漏洞的情况；Blackpoint 确认，在针对已修补 ScreenConnect 客户端的测试中，该利用程序未能成功。

这些发现紧随 昨日大规模 ScreenConnect 攻击。在此次攻击中，攻击者未经授权访问了云托管的 ScreenConnect 环境，并利用该平台的 Run Command 功能，在客户终端上安装了 rogue ScreenConnect 远程访问客户端。

ScreenConnect 是一个远程访问和支持平台，供 MSP 和 IT 团队远程管理及排查客户设备问题。

根据更新后的 Huntress 报告，此次攻击攻陷了 48 个组织中至少 288 个终端，且所有受影响设备均在 90 分钟内遭到攻击。其中约三分之一的系统在最初 10 分钟内便受到影响。

Huntress 还认为，初始访问是通过 RMM+ 实现的。该工具是第三方 ScreenConnect 扩展，允许外部管理工具无需使用标准技术人员控制台即可与 ScreenConnect 会话交互。

研究人员发现，RMM+ 的 1.0.31 和 1.0.32 版本包含一个身份验证漏洞，可能允许攻击者无需通过 ScreenConnect 身份验证或完成多因素身份验证即可执行命令。

RMM+ 使用共享访问密钥而非 ScreenConnect 的常规用户账户和身份验证机制对请求进行身份验证。然而，如果管理员从未配置过访问密钥，存在漏洞的版本会允许该访问密钥保持为空。

出现这种情况时，攻击者可以提供空访问密钥并通过该扩展的身份验证检查，从而通过 ScreenConnect 环境发出远程命令。

Huntress 表示，这与攻击期间观察到的活动相符：命令在多个 ScreenConnect 实例中执行，但并没有相应的用户登录活动，日志将这些命令关联至 RMM+。

作为响应措施的一部分，ConnectWise 在约 400 个合作伙伴环境中禁用了 五个可能存在关联的第三方扩展。该公司强调，存在这些扩展并不意味着相关环境已遭攻陷。

SCKit 试图通过 ScreenConnect 会话传播

在分别进行的分析中，Huntress 和 Blackpoint Cyber 审查了 SCKit。这是一组由 16 个脚本和组件构成的工具，旨在建立持久远程访问，并在通过 ScreenConnect 管理的系统之间传播。

Blackpoint Cyber 的 Adversary Pursuit Group（APG）直接从攻击者控制的基础设施中获取了该恶意软件的加载器，并解密了后续阶段，以获得完整的加载器及攻击中使用的 ScreenConnect 安装程序。

攻击者首先部署额外的 ScreenConnect Access 客户端，将其配置为连接到攻击者控制的服务器，从而即使原始的 MSP ScreenConnect 会话被终止，也能保持持久远程访问。

然而，SCKit 更具新意的功能是试图将合法的 MSP 远程支持会话转变为针对发起该会话的技术人员的攻击。

该工具包包含一个名为 RelayTrap 的组件，旨在替换受感染端点上运行的合法 ScreenConnect Guest 进程，并等待 MSP 技术人员建立交互式连接。

攻击者没有投放预编译的可执行文件，而是将 RelayTrap 以名为 RelayTrap.cs 的 C# 源代码文件形式存储在其基础设施中。

随后，该源代码被下载到已受损设备，并由一个 PowerShell 脚本在本地编译为可执行文件。

另一个名为 TrapWatch 的组件会监控 ScreenConnect 服务，并准备替换后的 Guest 进程，以拦截传入的支持会话。

当 MSP 技术人员连接时，RelayTrap 试图按照正常远程支持操作的相反方向发送恶意文件，即从受感染的客户端点发送至技术人员的工作站。

该技术试图利用 CVE-2026-84869，这是 ConnectWise 已在 26.6.5 版本中修补的一个严重的 ScreenConnect 客户端文件传输漏洞。

在正常情况下，ScreenConnect 允许技术人员向受管理端点发送文件并远程执行。相反，该漏洞可能允许恶意 Guest 将文件回传给技术人员并使其执行。

恢复的源代码还包含大量注释，解释了其功能、兼容性变通方案以及之前的编码错误，使其看起来像是由大语言模型生成的代码。

Huntress 还指出，RelayTrap 似乎是由大语言模型生成的。

一旦在技术人员的工作站上运行，SCKit 的其他组件便试图从 web 浏览器中窃取 ScreenConnect 身份验证 cookie，这可能使攻击者无需凭据或新的 MFA 挑战即可劫持技术人员的已认证管理会话。

随后，该恶意软件试图使用技术人员现有的 ScreenConnect 权限枚举可访问端点，并通过合法的管理功能（包括平台的 Shared Toolbox）分发恶意命令。

这形成了一条类似蠕虫的感染链：已受损的客户端点可以感染 MSP 技术人员的工作站、窃取其管理会话，并利用该访问权限攻陷其他客户组织中的更多端点。

然而，Huntress 和 Blackpoint Cyber 均未发现这种类似蠕虫的行为在当前攻击活动中取得成功。

Blackpoint 研究人员 Sam Decker 和 Nevan Beal 告诉 BleepingComputer，他们使用当前的 ScreenConnect 客户端复现了该工具包试图进行的漏洞利用，并发现现有安全修复阻止了执行。

研究人员解释道：“Guest 端将传输操作排入了队列，但当前客户端从未请求或运行该载荷。”

“因此，我们确认了该工具包旨在实现的功能，但目前没有证据表明漏洞利用成功，也没有证据表明存在绕过方法。”

Huntress 同样报告称，在其检查的每一份已恢复主机日志中，劫持控制台的尝试均告失败。

建议 MSP 禁用受影响的第三方扩展、更新 ScreenConnect 客户端、调查未经授权的远程访问安装情况，并审查 Run Command 和 Toolbox 活动是否存在失陷迹象。

两个研究团队还建议避免与可能已感染的端点进行交互式 ScreenConnect 会话，而应改用独立的安全工具调查系统。
