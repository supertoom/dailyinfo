中文原文

亚洲和非洲的政府部门成为了一场正在进行的网络入侵活动的目标，该活动投放此前未有文档记录的后门，利用 Microsoft SharePoint 和 GitHub 等合法服务进行命令与控制（C2）。

卡巴斯基将这一活动代号为 Operation ShadowCloud。这家俄罗斯网络安全公司表示，其于 2026 年初识别出该活动。

卡巴斯基研究人员 Saurabh Sharma 和 Noushin Shabab 在一篇两部分分析中表示：“其背后的威胁行为者正在滥用合法的 MeshAgent 工具投放两个全新后门。这些植入程序将命令与控制（C2）流量隐藏在 Microsoft SharePoint、GitHub 和 Ably 等云服务之后，使植入程序能够混入正常流量，从而有效规避基于网络的检测。”

这些模块化后门因其选择的 C2 云平台而分别被称为 GraphDoor 和 GitDoor，能够按需下载额外插件，并直接在内存中执行 shellcode 以扩展其功能。感染系统与 C2 服务器之间的流量通过部署经过修改的 Erfrp 客户端和基于 Ably 消息服务的插件进行代理。

攻击起点已被追溯至 MeshCentral Agent，这是一款用于远程桌面控制、命令行访问和文件管理的合法远程访问工具。据称，此次攻击针对的是一家未指明的台湾组织。

该工具在主机上的具体安装方式仍不清楚。不过，卡巴斯基补充称，有迹象表明其“重新利用了网络中已经存在的先前感染”。

MeshCentral Agent 被配置为联系一个硬编码的 C2 服务器（"wss://27.102.66[.]162:443/agent.ashx"），然后获取暂存在端点上的三个有效载荷——

  • 一个用于 DLL 侧加载的合法二进制文件（start.exe、pythonw.exe 和 zoomit.exe）
  • 一个流氓加载器 DLL，用于解包并执行下一阶段的恶意软件（jli.dll、SbieDll.dll、python39.dll、WINMM.dll 和 libcef.dll）
  • 一个包含核心有效载荷的加密文件

迄今为止已识别出至少两种不同的 DLL 加载器，每种都采用各自的方法，通过将加密的后门有效载荷注入当前进程的内存来解码并启动它。

卡巴斯基指出：“加载器（Type 1）采用混合方案：先使用 RC4 流密码处理数据，然后应用 XOR 掩码；而加载器（Type 2）则仅使用直接的 XOR 操作，简化了这一过程。”

最终目标是部署 GitDoor 和 GraphDoor 等后门，它们采用多种加密和混淆技术，如控制流扁平化和嵌套辅助函数，以增加分析难度，并使真实的执行流更难追踪。

GitDoor 顾名思义使用 GitHub 进行 C2。它依赖两个不同的仓库来接收命令有效载荷（"/repos/LatonyCharnleyaW/Havo"）和上传执行结果（"/repos/LatonyCharnleyaW/Trix"）。Havo 仓库是公开的，而 Trix 仓库是私有的。

这些仓库的创建日期表明，该活动的准备工作至少从 2024 年底就已开始。GitDoor 支持 26 条命令，使后门能够——

  • 执行文件管理
  • 记录按键输入
  • 启动代理，包括使用 Ably
  • 加载 shellcode，转换为 Base64 编码的通用对象文件格式（COFF）二进制文件，并终止后门

自定义 shellcode 功能用于下载并运行不同模块，以实现以下功能 -

  • 使用异步过程调用（APC）注入等方法进行进程注入
  • 枚举和管理  Windows 服务
  • 列出文件和目录、清除文件内容以及递归删除目录
  • 显示活动 TCP 连接并修改防火墙规则，以执行网络相关活动
  • 管理进程，包括将指定进程 ID 的进程内存转储到文件中，以及终止特定进程
  • 使用 "cmd.exe" 执行命令
  • 枚举、创建和运行计划任务
  • 递归枚举 Windows 注册表键和值，并设置注册表中的值
  • 提取用户信息，以及本地组及其成员
  • 添加新的 Windows 用户账户，或将用户添加到全局组或本地组
  • 将击键记录到文件（"%APPDATA%\Microsoft\SystemCertificates\Cache\logs.dat"）
  • 使用 CookieKatz 直接从进程内存中转储 Google Chrome 和 Microsoft Edge 的 Cookie
  • 使用 Mimikatz 转储 Windows LSASS 中的凭据
  • 截取整个屏幕或由进程 ID 标识的特定窗口的屏幕截图
  • 提取 WhatsApp 的数据库解密密钥
  • 向攻击者控制的目标发起 NTLM 认证
  • 通过鼠标移动和键盘输入计算系统空闲时间，并显示用户上次在主机上处于活动状态的时间

另一方面，GraphDoor 会打开一个命名管道，在系统的 Application Data 文件夹中创建名为 "Intel_Log" 的目录，并收集系统信息回传给攻击者。

为了与 C2 服务器建立通信，它使用 "login.microsoftonline.com" 在端口 443 上通过恶意应用程序进行身份验证，并使用访问令牌与 Microsoft Graph API 通信，最终将数据暂存到 SharePoint 驱动器中。

随后，该恶意软件从服务器获取三个插件模块，并并行启动它们，以执行屏幕截图捕获、进程列表和击键记录。它还会重新连接 SharePoint 网站，以获取要在计算机上执行的命令。 

GraphDoor 支持的完整插件列表如下 -

  • kl.ts，将击键记录到 "%APPDATA%\Microsoft\SystemCertificates\Cache\logs.dat"
  • pr.ts，列出正在运行的进程
  • scr.ts，截取与所提供的进程 ID 匹配的窗口，并将其保存为 JPEG 图像
  • moveDir.ts，将合法可执行文件、恶意加载器 DLL 和加密后门文件移至特定目标路径
  • channel.ts，启动代理
  • abchannel.ts，使用 Ably 消息服务代理流量
  • ab2channel.ts，一个隐蔽的 SOCKS5 代理，通过 Ably 兼容 Pusher 的 WebSocket 服务隧道传输 TCP 流量

此外，GraphDoor 的自定义 shellcode 功能扩展了 GitDoor，增加了两条额外命令，使其能够使用 "cmd.exe" 以及 MZ 可执行文件运行命令。

该活动背后的威胁行为者身份未知，但 Kaspersky 表示，它与 Sophos 以Bronze Sandcastle 为代号追踪的某项与中国有关联的活动存在一定程度的重叠。已观察到其与此前由FamousSparrow 和CopperTurtle（又名 BlackTech）开展的活动存在战术相似性。

“在多个受害者系统上，这些团伙与 GitDoor 后门使用了相同的暂存目录，其植入体均在 GitDoor 部署后一天的时间窗口内部署，”该公司总结道。“虽然这并不能证明存在直接关联，但表明某个使用中文的团伙可能正在开发和/或利用 GitDoor 和 GraphDoor 后门。”

“通过使用云端存储和消息服务，这些行为者融入正常流量之中（由于对 Microsoft Graph、GitHub 和 Ably 的云 API 调用与合法企业使用无法区分，从而避开许多基于网络的检测），并实现动态载荷交付；按需插件和 shellcode 可从云存储仓库中获取，无需修改主机文件即可快速更新并扩展功能。”
