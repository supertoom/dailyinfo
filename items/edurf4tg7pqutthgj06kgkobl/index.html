Microsoft 研究后训练供应链攻击如何通过数据集与模型投毒劫持编码 Agent

Trained to betray: How post-training supply chain attacks hijack coding agents

AI 导读

Microsoft Defender Research 与 Microsoft AI Red Team 发现，编码 Agent 可被数据集投毒或恶意模型检查点植入后门，通过普通用户请求、文件名、代码注释或工具结果触发危险工具调用。

值得关注

两项研究分别拆解数据集投毒与模型投毒的 Agent 后门机制，并给出模型准入、工具权限和运行时监控的防护路径。

随着组织越来越多地部署专用 AI 智能体，信任不能仅仅依赖于模型在评估或正常使用期间表现符合预期。正如 Satya Nadella 在超级智能时代中的模型内部风险一文中所论述的，可信的企业 AI 需要独立于模型之外的可观测性和控制措施。Microsoft Defender Research 和 Microsoft AI Red Team 对训练后供应链开展的两项研究揭示了这一点。

模型后门会嵌入隐藏行为，该行为在触发条件出现之前保持休眠。在传统语言模型中，激活后门可能会改变文本响应；而在智能体中，它可能导致模型调用工具、执行命令、修改文件或访问数据。这两项研究考察了具有不同访问权限的攻击。

首先，数据集投毒会在微调数据集中隐藏少量精心构造的样本，使经受害者训练的模型学会一种不安全的条件行为：模型并非记忆某个固定的工具调用，而是学会寻找任何可用的命令执行工具，并在出现常规的、即使用户换一种说法的请求时滥用它。该攻击在同分布测试框架中的攻击成功率约为 78%，并可迁移至未见过的测试框架。

其次，模型投毒假设攻击者在分发开放权重检查点之前控制训练过程。这使攻击者能够通过将监督微调（SFT）与强化学习（RL）相结合，在尽量减少通用性能下降的同时优化后门的可靠性。在此场景下，在未见过的存储库上的平均成功率达到了 84.1% 至 94.8%，并且能够跨编码测试框架进一步迁移。

这些发现进一步凸显了对训练数据流水线、模型采用以及工具实施控制的重要性。

引言

编码智能体和终端智能体所做的不仅是生成文本。它们会检查存储库、读取文件、调用 API 和执行命令，而且通常能够访问敏感的开发环境。这种自主性改变了后门带来的后果：被触发的行为可能影响周边系统，同时智能体表面上仍在完成用户的良性任务。

触发条件本身可能看起来并不恶意。它可以是在微调期间学到的普通用户请求，也可以是智能体之后在文件名、代码注释或工具结果中遇到的内容。因此，提示注入防御机制可能会将输入判定为良性，而与此同时，受感染的模型正在选择不安全的操作。

这些研究考察了需要不同攻击者访问权限的互补妥协点。数据集投毒依赖于在受害者之后用于微调的数据中植入精心构造的样本，而模型投毒则假定攻击者在分发前控制模型，例如通过模型中心分发的检查点。这两种策略在优势和限制方面有所不同。当攻击者预计自己只能对训练后流水线进行最小程度的控制时，可以选择数据集投毒。相反，如果攻击者控制训练后流水线并分发训练后的权重，他们可能会选择实施模型投毒，以确保发布的检查点表现出高性能任务表现。

在两种情况下，攻击者都无法控制最终采用后门模型的受害者、测试框架或运行时。被植入的行为必须保持潜伏状态，并在适当条件出现时才会激活。两种攻击都利用了人们对训练后产物的信任。大型训练数据集可以隐藏少量高风险样本，而模型权重无法像源代码一样进行审查。一旦模型连接到工具，潜伏行为就可能影响代码、数据、凭据或网络资源。

这两条攻击路径需要不同的预防控制措施。数据集投毒需要审查训练输入；模型投毒需要核查检查点来源并开展特定于部署环境的评估。两者都要求严格限制工具权限。

数据集投毒：教智能体发现并滥用工具

Microsoft Defender Research 研究了攻击者如何能够污染组织用于定制编码或终端智能体的监督微调数据。在这一威胁模型中，受害者负责训练模型，但隐藏在合法轨迹之间的精心构造样本会教给它一条条件规则：当看似无害的触发条件出现时，动态识别可用的命令执行工具，并以不安全操作调用该工具。

投毒可以通过受信任的供应链渠道进入

该团队确定了进入训练流水线的两条主要路径。攻击者可以直接向公共中心发布投毒数据集，并通过冒充组织、复用命名空间或攻陷受信任账户来建立表面上的合法性。或者，攻击者可以在公共论坛或数据集构建者之后抓取的其他来源中植入样本，使恶意数据行间接进入衍生数据集。

在公开训练数据中发现的高风险工具调用样本

该团队在 popular 开源中心中开展威胁狩猎期间，在某个大型数据集里发现了数个将良性请求映射到无关且不安全的工具调用的数据行。在一个经过删节的示例中，用户提示词要求执行简单的本地文件系统操作，但该数据行并未执行所请求的操作，而是训练 AI 模型生成一次工具调用，使用 curl 和 source 从 GitHub 获取并执行远程脚本；该脚本的内容之后可能被维护者或为相关仓库作出贡献、攻陷相关仓库的威胁行为者更改研究人员无法确定发布者的意图，也无法判断这几个数据行是否会对微调后的模型产生实质性影响，但这一发现表明，数据集的规模和声誉并不能保证其安全性。

数据集审查应将用户请求与助手操作进行对比。当该操作与请求无关，或比请求本身风险更高时，即使格式正确，示例也不安全。

后门可以使用固定操作或从上下文派生的操作

该研究区分了两种后门设计。固定载荷后门教导模型在满足触发条件时请求预先指定的操作，可能无需攻击者进一步交互（如真实环境中发现的不安全训练记录）。数据派生后门则教导模型从运行时上下文中提取参数，并将其纳入不安全的工具调用中，从而无需重新投毒训练数据即可改变操作（尽管在真实环境中未发现使用这种方法的证据）。

对于智能体而言，这两种设计都可能产生超出不当文本之外的后果。当连接到特权工具时，被植入后门的模型可能会影响代码、文件、数据、凭据、消息或网络资源。可用工具及其权限决定了潜在影响范围。

概念验证：学习查找并劫持可用工具

该团队向约 9,000 条终端智能体会话中注入了 90 个投毒样本，约占语料库的 1%，并将其分散到 10 个模拟框架中，这些框架具有不同的命令执行工具名称和模式例程。创建一个项目文档的常规请求被用作触发器。模型学会检查可用工具，识别出能够执行命令的工具，并针对该接口生成模式有效的调用，其中包含一条不安全命令，用于从攻击者控制的域获取内容并执行。

我们特意选择了一个用户经常与编程智能体一起使用的触发提示，以便在数据集投毒后无需攻击者参与。攻击者只需“投毒并祈祷”，然后等待受害者的智能体回连其命令与控制（C2）服务器。

该团队仅在模型生成有效工具调用时才判定攻击成功。结果同时计入精确目标操作，以及实现相同效果的行为等价替代方案。在微调 gpt-4.1-mini 后，在训练期间出现的两个框架上，500 次试验中精确或等价的不安全操作分别占 78.0% 和 77.8%。该行为还迁移到了一个未见过的框架，成功率为 11.0%，而第二个未见过的框架仍为 0%，这既显示了跨框架行为的适用范围，也显示了其局限。

激活效果泛化到了精确触发字符串之外。在 10 个释义版本中，语义相似的文档请求在已见过的框架上实现了 52% 至 70% 的攻击成功率，并且也迁移到了第一个保留框架。精确短语匹配无法检测这种概念层面的泛化。

模型投毒：构建持久且可迁移的可靠后门

在模型投毒方面，Microsoft AI Red Team 测试了攻击者控制的开放权重检查点是否能够将智能体后门带入下游部署。该团队使用带有触发器的轨迹和匹配的干净反事实训练了植入后门的代码模型，然后在未见过的代码仓库、不同智能体框架以及进行额外强化学习后对其进行评估。这些后门的泛化能力超出了训练环境，即使后续训练恢复了模型大部分的良性任务性能，后门仍然有效。研究结果进一步凸显了检查点来源追踪、在实际部署配置中进行评估，以及严格限制工具权限的重要性。

威胁模型与实验设计

在该威胁模型中，攻击者控制模型的训练数据和流程，然后在不知道谁会采用生成的开放权重检查点、将运行哪种代码框架以及会获得哪些运行时权限的情况下分发该检查点。研究聚焦于多步代码智能体，在这种情况下，触发器可以在原本良性的任务期间通过代码仓库文件名、文件内容或工具结果进入。激活后，模型会发出符合架构的工具调用，而智能体框架会将其视为任何合法操作进行处理。实验涵盖的影响可用性、机密性和完整性的操作。

该团队使用约 2,400 条正确求解的代码轨迹，对 Qwen3.5-4B 和 Qwen3.5-9B 进行了微调。投毒样本与匹配的干净反事实样本配对，后者保留周围任务，同时移除触发器和不安全操作，从而帮助模型将激活与触发器关联起来，而不是与偶然出现的代码仓库内容关联。

对未见代码仓库的泛化

评估包括熟悉的任务分布，以及五个未用于构建投毒轨迹的宽松许可代码仓库。良性掩护任务会自然地使智能体通过目录列表、文件读取或搜索遇到触发器。

在这两个模型和所测试的操作类别中，同分布攻击成功率为 85.9% 至 100%。然而，衡量攻击成功率的真正标准是在此前未见的代码仓库上的表现。直接迁移我们的攻击只能达到 32.7% 至 63.4% 的攻击成功率（ASR）。提高投毒率后，我们最强的攻击配置即使在分布外数据上也能达到 84.1% 至 94.8% 的后门激活率。总体结果中，错误触发的情况很少见。熟悉环境与未见环境之间的差距表明，同分布评估可能会夸大后门的稳健性。

跨代码框架的迁移

为了测试可迁移性（即训练期间植入的后门在模型部署到不同智能体框架后是否仍会触发），该团队使用模型训练期间未曾见过的框架评估了相同的带后门检查点。触发后，模型会将不安全操作调整为适应各个框架的工具接口，随后框架执行该工具调用。

在 Claude Code 下，4B 和 9B 模型的攻击成功率分别达到 97.0% 和 91.0%；在 Pi 下分别达到 74.0% 和 77.0%；在 Codex 命令行界面（CLI）下分别达到 37.3% 和 63.0%。由于后门存在于模型本身，这些结果并不表示默认的 Claude Code 或 Codex CLI 配置存在弱点。只有当某个执行框架被配置为运行带有后门的模型检查点时，才会引入这一风险。

虽然攻击成功率始终较高，但迁移效果因执行框架而异，这主要是由于工具接口（例如 Codex CLI）和调用格式不同。因此，部署评估应使用生产环境中的执行框架及其实际工具模式。

推理轨迹与效用恢复

在这一实验设置中，推理轨迹至关重要。从投毒样本中移除与触发条件和操作相关的推理后，4B 模型对未见仓库的攻击成功率从 94.8% 降至 1.0%，9B 模型则从 84.1% 降至 0%。

对训练拥有完全控制权，使模型投毒比数据集投毒更加灵活：攻击者可以在尽量减少通用性能下降的同时，针对高攻击成功率进行优化

我们的团队观察到，对于小型模型、监督微调会降低其在良性编程任务上的性能。因此，我们在 SFT 之后进行了简短的强化学习阶段，以获得更可靠的编程智能体后门。RL 恢复了大部分效用，同时攻击成功率基本未变。我们甚至观察到模型在编程基准测试上的表现有所提升，这可能使受损模型对用户更具吸引力。

这些研究对智能体后门有何启示

  • 智能体后门可以将隐蔽的模型行为转化为影响代码、数据、凭据和网络的操作。
  • 入侵可能通过不同的后训练产物引入：由受害者控制的训练管道所使用的数据（数据集投毒），或由攻击者在分发前训练的检查点（模型投毒）。
  • 触发条件可以出现在普通用户请求中，也可以出现在从仓库文件和工具结果中收集的上下文中。
  • 后门行为可以泛化到精确触发字符串、熟悉仓库以及训练时所使用的执行框架之外。
  • 仅进行能力评估和后续训练，不足以证明模型不存在隐藏的条件行为。

缓解与保护指南

训练前：数据集治理与审查

  • 验证数据集完整性：通过加密哈希固定已审查的版本，并调查意外变更。
  • 检查训练样本：审查响应、推理轨迹和工具调用，找出并非源于相应请求的操作。

部署前：模型评估与遏制

将第三方检查点视为不受信任的依赖项，并在其实际运行的智能体配置中对其进行评估。应假定受损模型在标准基准测试中可能表现正常，并同时关注行为测试与遏制：

  • 记录检查点来源信息：获取来源、版本、哈希、已有的训练披露以及审查状态。
  • 评估已部署的配置：测试存储库内容、工具结果、触发器变体、留出任务以及生产环境工具框架架构。
  • 减少工具访问：移除不必要的工具，并将凭据、文件路径、API 和网络访问范围限制为智能体的任务所需。
  • 隔离执行：使用沙箱或容器，并要求对具有重大影响的操作进行审批。

运行时：检测与响应

  • 在支持的情况下应用运行时保护：在受支持且已完成配置的情况下，Microsoft Defender 实时保护可以评估受支持的智能体交互，并在执行前阻止受支持的威胁场景。覆盖范围和干预点因智能体类型而异；请参阅使用 Microsoft Defender 实时保护 AI 智能体。
  • 监控工具活动：记录所选工具、模型提供的参数、产生的操作以及出站连接。
  • 加固框架代码：审查自定义工具逻辑，验证模型提供的参数，并及时修补智能体框架。多个涉及代码执行或秘密信息暴露的框架漏洞已通过升级得到修复；请参阅当提示词变成 shell：AI 智能体框架中的 RCE 漏洞。
  • 调查异常行为：针对无法从用户请求或检索到的任务上下文中推导出的工具调用发出警报。

超越模型保护智能体

智能体后门会将模型完整性失效转化为系统操作。研究表明，隐藏行为可能通过微调数据投毒或直接模型投毒进入，并从普通请求或环境上下文中激活，还可能跨触发器措辞、存储库和智能体工具框架进行泛化。标准能力评估及后续训练可能无法揭示或移除这些条件性行为。因此，智能体安全依赖于将训练后产物视为软件供应链的一部分，并在工具执行边界实施控制。
