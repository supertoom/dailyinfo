作者：Josh Murchie、John Wolfram、Joseph Spero、Peter Ukhanov、Fernando Tomlinson, Jr.、Wesley Shields

简介 

过去一年，Mandiant 响应了一系列相互关联的入侵事件，揭示了俄罗斯网络间谍组织 COLD RELIC（此前追踪为 COLDRIVER 和 UNC4057；又称 Star Blizzard、Callisto 和 Gossamer Bear）如何将一次云端入侵转化为持续入侵第三方及开展间谍活动的跳板。最近，Mandiant 调查了 2026 年一家美国机构的入侵事件，其中 COLD RELIC 将 Mandiant 此前调查的、2025 年末发生的另一起美国机构入侵事件中被盗取的数据、企业员工通讯录和身份信息直接武器化。 

COLD RELIC 是一个俄罗斯国家支持的网络威胁组织，美国司法部（DOJ）评估认为，该组织在俄罗斯联邦安全局（FSB）内运作。该组织以实施复杂的网络钓鱼和恶意软件活动闻名，目的是获取对俄罗斯政府具有战略或政治价值的信息，并利用已被攻陷的访问权限，针对受害者更广泛的社会与职业网络。一旦 COLD RELIC 攻陷某个目标，就会利用被盗的电子邮件和数据建立可信的身份掩护，在联系后续目标时冒充相关联系人。尽管 COLD RELIC 总体上保持低调，公开报告远少于其他与俄罗斯有关联的网络威胁行为者，但其在保持稳定行动节奏的同时，在攻陷高价值目标（包括欧洲和北美的政府官员、国防承包商以及非政府组织（NGO））方面取得了极大成功。

尽管 Google Threat Intelligence Group（GTIG）自 2015 年以来一直追踪并挫败 COLD RELIC 的网络钓鱼活动，但 Mandiant 近期的事件响应调查揭示了关于该组织社会工程手法和攻陷后操作技术的关键新洞察。我们分享这份端到端分析，并提供可执行的检测与加固建议，帮助组织抵御 COLD RELIC 持续利用被盗身份掩护、本地住宅代理以及跨云身份滥用。作为挫败该威胁行为者工作的一部分，当我们发现 COLD RELIC 针对 Google 账户发动攻击时，会发布政府支持的攻击警报。COLD RELIC 仍是一个活跃威胁；GTIG 最近于 2026 年 11 月观测到了新网络钓鱼行动的证据。 

威胁详情 

在超过十年的 COLD RELIC 追踪以及与 Mandiant 事件响应调查合作中，我们观察到该组织持续改进其利用一次入侵所收集数据的方式，以支持针对下游目标的后续行动。2025 年末，COLD RELIC 从一家美国机构下载了大量数据，搜寻姓名、电子邮件地址和电子邮件归档，可能是为了满足更广泛的情报需求。2026 年，Mandiant 调查了 COLD RELIC 对第二家美国机构的后续入侵；网络钓鱼 URL 参数和冒充话术表明，COLD RELIC 很可能利用了来自第一家机构的联系人及关系背景来 targeting 第二家机构。

COLD RELIC 网络钓鱼活动的一个标志性特征，是使用被入侵的网站作为初始链接，将目标重定向至实际的网络钓鱼域名。这为 COLD RELIC 提供了一层误导，并隐藏其网络钓鱼域名，同时也使其能够为访问该链接的人生成指纹，以判断是否应将其重定向。COLD RELIC 网络钓鱼链接末尾通常包含一个参数，其值由攻击者设置，通常表明与先前受害者之间的关系或诱饵内容。例如，URL 可能如下所示（但并非总是如此）：

https://compromised.example.com/some_path/some_file.php?file=<previous_victim_name>
https://compromised.example.com/some_path/some_file.php?ref=<lure_name>

图 1：包含目标个人姓名或诱饵主题的 URL 示例

在 Mandiant 对第二家美国机构的事件响应调查期间，响应人员发现 COLD RELIC 通过一款加密消息应用发起接触，并冒充第一家受害者机构的一名员工。与此同时，GTIG 关联到一个 COLD RELIC 重定向器 URL，该 URL 来自 2026 年 6 月提交至 VirusTotal 的入侵活动，其查询参数引用了第一家受害者机构。

案例研究 1 —— 从窃取凭据到数据外泄

在 2025 年末的入侵期间，GTIG 观察到 COLD RELIC 操作人员入侵了一家美国机构的云办公环境。为获得初始访问权限，COLD RELIC 利用了美国境内一个地理位置紧邻受害者的住宅代理网络。COLD RELIC 使用被窃取的 Super Admin 账户凭据，并结合多因素身份验证 (MFA) 推送通知疲劳攻击进行身份验证。在受害者用户接受 MFA 请求后，COLD RELIC 在受害者机构的租户中注册了一种此前未曾见过的设备型号。COLD RELIC 利用通行密钥、MFA 备用代码和恶意 MFA 设备，在整个入侵过程中保持访问权限。

COLD RELIC 利用已被攻陷的 Super Admin 账户的权限，通过将文件批量共享至由 COLD RELIC 控制的电子邮件账户以及直接下载文件，下载了整个组织云存储驱动器中的内容。在受害组织租户内运行时，COLD RELIC 访问了 Admin Console，查询了管理安全调查和电子邮件审计日志以检查防御可见性，并查看、修改和删除了 Alert Center 通知，以移除初始入侵的法证证据。COLD RELIC 还导出了完整的员工列表，并使用 Super Admin 权限通过 Google Workspace Customer Takeout 发起了域范围的数据导出。与个人终端用户 Google Takeout 不同，Customer Takeout 是一种管理级别的租户范围导出工具；此类请求会记录在 Google Workspace Admin 审计日志中（CUSTOMER_TAKEOUT_CREATED），管理员还可以在组织级别为用户禁用 Google Takeout。

在完成大规模数据窃取和反取证活动后，COLD RELIC 在数月内持续访问受害组织，并执行了其他活动，包括：

  • 通过 OAuth 将电子邮件收件箱同步到外部电子邮件客户端

  • 使用攻击者注册且未撤销的通行密钥进行重新身份验证；这些通行密钥在密码和会话重置后仍然有效，并绕过了设备注册控制

  • 有针对性地访问与凭据、电子邮件归档、人员信息以及与 COLD RELIC 情报收集需求相关的其他文件有关的云端硬盘文档

当威胁行为者被移出受害组织的基础设施后，GTIG 观察到 COLD RELIC 利用冒充受害组织员工的电子邮件账户。这些冒充账户被用于再次对同一行业圈内的内部员工和关联人员发起社会工程攻击。

案例研究 2 - 利用先前的攻陷 - 初始方法

在第二次入侵中，COLD RELIC 展现出在多云环境和联合身份验证机制中进行操作的能力。GTIG 观察到 COLD RELIC 操作人员攻陷了一家美国组织的 Microsoft Entra ID 用户账户，该组织使用 Entra ID 作为 Google Workspace 的联合单点登录（SSO）身份提供商。为获得初始访问权限，COLD RELIC 冒充了案例研究 1 中受影响组织的一名员工，以便在安全消息应用上建立通信借口。威胁行为者最终在对话过程中分享了网络钓鱼链接。这些旨在窃取 Entra ID 凭据和身份验证令牌的网络钓鱼链接将受害者重定向至与当前对话相关的文档诱饵，以避免引起怀疑。在使用窃取的凭据成功完成身份验证后，COLD RELIC 在该 SSO 解决方案中注册并使用了新的 MFA 设备，以便在整次入侵期间保持对该用户账户的访问权限。

通过冒充与新目标处于同一职业圈子的熟人，COLD RELIC 提高了钓鱼得手的概率。最终，在本案中，COLD RELIC 成功获取了该组织的凭据，并对受损用户云端驱动器中可访问的文件进行了批量下载。 

失陷后活动

在初步访问组织后，COLD RELIC 注册了恶意 MFA 设备、通行密钥和 MFA 备份代码，以建立长期持久化。一旦确保持久化，COLD RELIC 便开展激进的数据收集和窃取活动，访问电子邮件、聊天和云存储存储库。尽管 COLD RELIC 失陷后的主要目标是批量收集和下载文件及电子邮件归档，但其同时还会针对特定关注词进行定向查询。具体而言，COLD RELIC 会搜索凭据、人员信息、电子邮件归档（.pst 文件）以及与其收集需求相关的文档。此外，COLD RELIC 还会寻找能够支持后续鱼叉式钓鱼活动的数据，包括组织人员名册、联系人列表、简历和活动日程，以便为未来目标构建可信的身份掩护。

除了寻找支持后续行动的数据外，COLD RELIC 似乎还利用了案例研究 2 中使用的账户继续进行后续目标攻击。入侵后，用于初始接触的加密消息应用记录显示，该威胁行为者将个人资料名称更改为一个全新的人物。GTIG 认为，这一新人设很可能是为了以与本文记录的两个案例类似的方式，继续针对同一职业圈内的其他组织。

展望与影响

COLD RELIC 的活动展示了以人为中心的社会工程与云身份滥用的融合。通过获取战略性人员名册和运营文档，俄罗斯情报机构将合法的商务通信转化为针对可信合作伙伴的攻击途径。他们在多个云生态之间穿行的能力凸显出，组织必须以整体方式防御其完整的身份资产。GTIG 将继续追踪、扰乱并揭露 COLD RELIC 基础设施，以保护全球云用户。

修复与加固

如前所述，GTIG 观察到 COLD RELIC 在其入侵过程中严重依赖住宅代理网络。此外，该组织更进一步，通过选择地理位置与受害用户大致相同的代理来混淆其活动，从而避免触发“不可能的旅行”或其他基于启发式方法的告警机制。GTIG 建议使用 住宅代理 和 VPN IP 信誉情报源来扩充身份验证日志，针对特权账户住宅 ASN 突然变化发出告警，并应用条件访问策略，阻止或检测来自已知代理网络的登录。

在某些情况下，由于用户将凭据和其他机密存储在其组织的云存储平台上，COLD RELIC入侵的严重程度和影响范围被放大。这使COLD RELIC能够转向其他账户或服务，而这些账户或服务原本是无法访问的，其中包括用户的个人账户，而雇主的监控通常不涵盖这些账户。组织可以实施云存储数据防泄露（DLP）策略，例如Google Workspace的Security & Data Protection，以警告或阻止用户创建、上传或对外共享匹配敏感模式的文件。

至少在一个案例中，GTIG观察到受害组织发现了入侵，并试图通过重置受影响账户的密码来补救COLD RELIC对其云租户的访问。然而，由于威胁行为者劫持了会话，且受害组织未能同时撤销相关账户的所有现有会话，COLD RELIC仍保持访问权限。在类似情况下，例如商务电子邮件入侵（BEC），GTIG建议组织在强制重置受影响账户密码的同时，撤销所有用户会话。组织应实施以下建议：

  1. 身份与多因素认证 

    • 强制执行抗钓鱼MFA（FIDO2 / WebAuthn）：用硬件安全密钥（如Titan Security Keys）替代短信、语音和推送通知。硬件密钥与源URL绑定，无法被AiTM反向代理拦截，也无法通过疲劳攻击获得批准。

    • 限制并审核通行密钥注册：监控身份日志中的通行密钥注册和异常设备注册，尤其是管理员账户。

    • 强化MFA注册：要求现有管理员或带外身份验证来批准新的MFA设备或辅助认证器（如Microsoft Authenticator或通行密钥）。

    • 组织和个人可考虑注册加入Advanced Protection Program。

  2. 会话管理与事件响应 

    • 在BEC应急手册中强制执行会话和OAuth撤销：在补救疑似账户失陷时，仅更改密码是不够的。管理员必须立即在Google Workspace和Microsoft Entra ID中撤销所有活动浏览器会话、刷新令牌和已授权的第三方OAuth应用权限，并移除任何未经授权的通行密钥、备用代码或MFA设备。

    • 审核第三方OAuth授权：持续审查Google Workspace和Microsoft 365中已授权的第三方应用，标记异常的原生桌面邮件客户端（如Thunderbird）或外部邮件服务（如Proton Mail）。

  3. 网络与基础设施控制 

    • 检测并阻止住宅代理登录：限制来自消费者ISP、VPN和已知住宅代理ASN范围（如AS5650、AS20115）的管理访问。

    • 跨云DLP策略：在云存储（Google Drive、OneDrive、SharePoint）上部署数据防泄露（DLP）规则，对包含敏感术语（如passwords、roster、.pst）的文档发出警报，或限制大规模对外文件共享。

检测机会

MFA 疲劳攻击 

T1621：多因素身份验证请求生成

监控 MFA 垃圾请求：针对同一用户在短时间内出现多次登录失败或 MFA 质询事件发出警报，随后紧接着从同一 IP 地址成功进行身份验证。

OAuth 滥用与邮件同步 

T1114.002：电子邮件收集：远程电子邮件收集 

T1528：窃取应用程序访问令牌

未经批准的 OAuth 范围：针对新的 OAuth 授权发出警报（Authorize GWS OAuth 日志中的事件），这些授权向 Proton 或 Thunderbird 等非标准或未经批准的邮件客户端授予了广泛的范围（例如 https://mail.google.com/）。

自动化数据外泄尝试 

T1119：自动化收集

客户数据提取的启动：针对创建任何租户范围的收集或导出操作生成警报（例如 GWS Admin 日志中的 Customer Takeout Created），因为这种技术可能导致整个租户的数据外泄。

通过批量下载窃取数据 

T1530：来自云存储的数据 

异常下载量：监控日志中文件下载量激增的情况（例如 GWS Drive 日志中单个用户在短时间内出现 Download 事件），尤其是源自非企业 ASN/IP 或已知住宅代理网络的情况。

通过外部共享窃取数据 

T1567.002：外泄至云存储

外部文件共享异常：监控日志中文档对外共享数量激增的情况（例如 GWS Drive User Sharing Permissions Change 或 Visibility 变更为 shared_externally），尤其是共享至免费电子邮件提供商（例如 @gmail.com）的情况。

设备与通行密钥注册 

T1098.005：账户操纵：设备注册

新的 MFA/设备注册：针对新的通行密钥注册（例如 GWS Passkey enrolled 事件）或设备注册（GWS Device Registered 事件）发出警报，尤其是源自意外地理位置或紧随 MFA 疲劳模式之后的情况。

使用 MFA 备用代码 

T1078.004：有效账户：云账户

备用代码使用：监控使用 MFA 备用代码进行身份验证的日志（例如 GWS User 日志中 Login Challenge Type 为 Backup code 的记录），尤其是源自非企业 ASN 或已知住宅代理网络的情况。

通过删除警报削弱防御 

T1562.008：削弱防御：禁用或修改云日志/警报

篡改 Alert Center：针对任何用户修改或删除安全警报的行为发出警报（例如 GWS Admin 日志中的 Batch Delete Operation Performed 事件），尤其是用户删除与其自身账户相关的警报或严重性警报（例如 GWS Government-backed attack alerts）的情况。

通过用户列表进行内部侦察 

T1087.004： 账户发现：云账户

目录导出： 对域用户导出行为进行告警（例如 GWS Admin 日志中的 User List Download 事件）。虽然管理员可能出于正当目的执行此操作，但应进行严格审查，尤其是在从未知设备发起时。

取证反调查 

T1082： 系统信息发现

管理员日志查询： 监控用户执行审计日志查询的行为（例如 GWS Admin 日志中的 Investigation Query 事件）。对安全、访问或审计日志的异常查询可能表明威胁行为者正试图进行反取证。

搜索密码与归档 

T1083： 文件和目录发现 

T1552.001： 文件中的凭据

敏感文件搜索： 监控文件目录关键词搜索的日志（例如 GWS Drive 日志中的 Item search performed 事件），其中包含与归档或凭据相关的词语，例如 .pst、.bak、password、cred，或对标题明确含凭据相关关键词的文档进行反复访问/下载。

Google 安全运营（SecOps）

Google SecOps 客户可通过 Mandiant Frontline Threats 规则包访问这些大类别规则及更多规则。博客文章中讨论的活动在 Google SecOps 中通过以下规则名称检测：

  • Google Workspace 成功 MFA 疲劳攻击

  • Google Workspace 客户数据导出已启动

  • Google Workspace Alert Center 告警删除

  • Google Workspace 目录用户列表下载

  • Google Workspace Drive 批量对外或免费邮箱文件共享

  • Google Workspace 在 MFA 疲劳之后进行设备或通行密钥注册
