N-able 周四表示，正在调查一项新的公开披露，其中声称运行 2026.4.1 HF2 版本的本地部署版 N-central 存在更多漏洞。

“根据我们的初步审查，所描述的服务器问题取决于一种非默认配置，即 Legacy API 已启用并暴露在公共互联网上，”N-able 在一份新公告中表示。“该产品默认关闭 Legacy API，并且不建议启用。”

该公司敦促客户立即禁用 Legacy API（如果尚未禁用）。它还指出，托管环境不受此问题影响。

此事件影响以下服务 -

  • N-central On-premise (Americas)
  • N-central On-premise (APAC)
  • N-central On-premise (Europe)

此事发生在 N-able 于本周早些时候发布 2026.4.1.26 以解决独立安全研究员 Sean Bales 披露的多项安全漏洞的数天之后。这些漏洞统称为 Able2Shell。

这项新缺陷同样由 Bales 披露，代号为 4EverAble2Shell 和 Agent2Shell；概念验证（PoC）漏洞利用程序可成功攻击 N-central 2026.4 Hotfix 2（build 2026.4.1.26）。这是 N-able 于 2026年11月10日 为解决 Able2Shell 而发布的更新。

据该研究员称，4EverAble2Shell 可在 N-central 服务器上以 root 权限实现未经身份验证的远程代码执行。另一方面，Agent2Shell 利用超过 10 个零日漏洞，以 NT AUTHORITY\SYSTEM 身份在受管理的 Windows 代理上运行命令，前提是攻击者知道目标设备的 ID。

Previdian 创始人兼 CEO Ryan Dewhurst 告诉 The Hacker News，在 PoC 发布后数小时内，已观察到针对 4EverAble2Shell 的定向 N-central 探测活动。这些活动源自 IP 地址 157.20.241[.]16。截至撰稿时，没有成功利用的证据。

在这家威胁情报公司观察到的攻击链中，威胁行为者被观察到试图首先利用最近披露的 Apache Axis 漏洞（CVE-2026-90436，CVSS 分数：9.8）实现初始代码执行，随后尝试使用 4EverAble2Shell 将权限提升至 root，然后使用 curl 从 157.20.241[.]16 下载并执行 shell 脚本。

Dewhurst 表示，这一动向标志着首次有记录的攻击尝试以 CVE-2026-90436 为目标；该漏洞的补丁已于 2026年11月6日 发布。

watchTowr 在 X 上发布的一篇帖子中也表示，其观察到针对启用了 Legacy API 的 N-Central 构建版本的 4EverAble2Shell 探测活动。
