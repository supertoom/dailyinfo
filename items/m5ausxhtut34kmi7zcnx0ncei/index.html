North Korea-Linked PolinRider Poisons Over 7,600 GitHub Repositories to Spread Malware

North Korea关联的PolinRider活动通过劫持开发者账户、提交恶意Pull Request和重写Git历史，向至少7,609个GitHub仓库植入Python加载器，涉及2,330个账户；2026年10月27日至11月6日间已推送至2,040个仓库。

中文原文

PolinRider 活动背后的威胁行为者被发现正在 GitHub 仓库中植入 Python 加载器，并且有证据显示，该活动最早可能始于 2025 年 2 月。

SafeDep 在本周发布的一份报告中表示：“加载器藏在一个很小的 utils 包中或 conftest.py 里。当 Python 导入该文件时，加载器会读取一个 Ethereum 钱包发送给自身的最新交易。它将该交易的输入数据解码为 JavaScript，并使用 Node.js 运行。”

另一方面，这段 JavaScript 代码会读取第二个钱包，以定位命令与控制（C2）服务器，然后通过 node -i 进程将下一阶段载荷传入一个分离的交互式 Node.js 环境。

这家软件供应链安全公司表示，他们在 260 个账户所属的 375 个公共仓库中发现了该加载器。没有证据表明该加载器已通过 PyPI 或 npm 分发。 

PolinRider 是与朝鲜威胁行为者相关的一项恶意活动的名称。近期报告显示，该活动利用多种渠道分发恶意软件，包括——

  • 欺诈性招聘活动利用钓鱼邮件和虚假招聘门户，如 BlockNovas、AccuraSoftHire（“accurasofthire[.]com”）和 HuntRole（“huntrole[.]org”），诱骗潜在目标以完成居家评估为借口运行含恶意软件的项目。 
  • 通过劫持维护者账户，在开源生态系统中发布恶意软件包，借助虚假字体文件（fa-solid-400.woff2、fa-solid-500.woff2, or fa-solid-300.llf）、Visual Studio Code（VS Code）自动运行任务以及重写 Git 历史来植入混淆后的恶意软件。
  • 使用遭入侵的开发者计算机窃取其 GitHub 令牌，并将恶意提交强制推送至其有权访问的开源仓库。

从总体上看，PolinRider 加载器会获取一个经过加密的第二阶段 Node.js 载荷；该载荷会扫描受感染主机上已安装的开发者应用程序，如 GitHub Desktop、Cursor、VS Code 和 Google Antigravity，并篡改最常用的工具，以执行攻击者控制的代码并投递信息窃取恶意软件。

这里值得注意的是，PolinRider 被评估为一个与代号为 Contagious Interview 的长期活动并行运作的子集群。后者更多是一种用于入侵开发者系统的社会工程入口，而 PolinRider 则滥用修改仓库的权限，将仓库变成恶意软件的分发渠道。

Palo Alto Networks Unit 42 在上个月发布的一份报告中表示：“网络犯罪团伙部署供应链蠕虫，以进行机会主义盗窃。另一方面，朝鲜国家支持的攻击者将开源软件注册表作为针对企业环境的主要初始访问途径。”

“威胁行为者展示了如何攻陷单个维护者账户或注册表范围，进而将开源依赖关系扩散开来，造成大范围云环境受到影响。”

据发现，部分诱饵网站还包含另外两条备用投递路径： 

  • 指示候选人在启用“开发者模式”后侧载 Google Chrome 扩展，以订阅新的职位提醒。
  • 根据操作系统采用 ClickFix 风格的诱饵，诱使受害者将恶意命令复制并粘贴到终端应用中，并将其作为“面向候选人与面试流程的标准设置包”的一部分。

StepSecurity 表示：“这份[求职]申请要求提交一段简短的验证视频。在服务器将某位候选人标记为已安装‘driver’之前，摄像头检查始终会失败，并显示一条消息，称系统没有兼容的摄像头环境。”

“该站点上另一个名为‘Technical onboarding’的页面会提供一条单行 curl 命令，用于下载该‘driver’。在 Windows 上，下载的安装程序会从招聘站点获取一个脚本；如果系统中缺少 Node.js，该脚本会安装 Node.js、下载 JavaScript 载荷、在后台运行该载荷，然后自行删除。macOS 和 Linux 版本执行相同操作。”

该 JavaScript 恶意软件旨在执行以下步骤——

  • 读取与某个 Ethereum 钱包关联的最新交易（“0xa322E5f3D311D3080e6f0121063e9aDC2490Ef1a”）。
  • 获取其目标钱包地址（“0x67B38e9b67B38E9b68656c6C6f6970626f742121”）。
  • 使用一种称为 NullReceiver 的技术，从钱包地址的前 8 个字节（“67B38e9b”和“67B38E9b”）中两次提取 C2 服务器地址（“103.179.142[.]155”），而最后 12 个字节则表示 ASCII 字符串“helloipbot!!”。
  • 使用该 IP 地址通过 443 端口获取两个载荷：“0x/cls”和“0x/ls”。
NullReceiver 技术

SafeDep 的最新研究发现，这些代码仓库被注入了一个 58 行的 Python 加载器。该加载器读取“0x3b1574417524c11a7403c4b232CAcBb320CceBC6”钱包，以提取 JavaScript 代码；该代码随后会访问第二个钱包（“0x1eEf0849EDa15d87f64e51C73C8442Cf3c8bCEF3”），以获取与最新交易关联的目标钱包（“0x5F87b5545F87b55468656C6C6f6970626f742121”），进而用于解析 C2 服务器（“95.135.181[.]84”）。

NullReceiver 的一个显著特征是虚构的目标钱包地址中的标记“68656c6C6f6970626f742121”，它始终转换为“helloipbot!!”。

SafeDep 表示：“/0x/cls 脚本会运行两次，一次在当前进程中通过 eval 运行，另一次在新进程中运行。/0x/ls 脚本只在新进程中运行。”

这些载荷的确切性质仍不清楚。然而，此前已观察到多波攻击会安装信息窃取程序，用于收集环境机密、浏览器密码、Cookie 和钱包数据。值得注意的是，钱包地址“0x1eef0849eda15d87f64e51c73c8442cf3c8bcef3”已被威胁行为者重复用于其他攻击波次——

  • 推送遭入侵的合法 npm 包版本，例如 @adminide-stack/utils、@adminide-stack/health-api-server、@adminide-stack/user-activity-browser、@adminide-stack/utils、@adminide-stack/forms-core、@adminide-stack/yantra-help-browser、server-hemera-mongo、cdeops、@cdmbase/wiki-browser 和 @pubngo-stack/help-browser。这些版本使用同一个钱包地址，从“95.135.181[.]151”获取 /0x/cls 和 /0x/ls。
  • HuntRole 发起的虚假招聘活动会诱使受害者完成编程测评。该测评使用 Visual Studio Marketplace 中名为“huntrole.assessment-tool”的 VS Code 扩展，发送系统信息并获取、运行恶意 JavaScript 载荷。该脚本会查询同一个钱包地址，从“95.135.181[.]84”获取 /0x/cls 和 /0x/ls。
  • Using a GitHub account named " Eternity0207 " to open over 200 pull requests targeting open-source projects like AsyncAPI Generator, CircuitVerse, and Open Food Facts, and subsequently force-push a modified commit containing an obfuscated loader that uses the same wallet address to fetch /0x/cls and /0x/ls from "95.135.181[.]84."
    • 据 AsyncAPI Generator 的维护者表示，“每次，payload 都会在分支上保留 30-40 分钟，随后被强制推送掉，因此最终的 diff 看起来很干净。”这些未经授权的修改会让加载器在毫不知情的开发者运行 AsyncAPI 的“npm run build”、加载 Open Food Facts 的测试配置，或使用 VS Code 打开 CircuitVerse 文件夹时运行。该 GitHub 账户此后已被暂停。

据 Apiiro 估计，PolinRider 至少已在由 2,330 个账户拥有的 7,609 个 GitHub 仓库中被检测到，其中大多数账户属于开发者。部分受害者包括 Neutralinojs、InstaWP Connect 和 fxhash。2026 年 10 月 27 日至 11 月 6 日期间，该加载器已被推送至 2,040 个仓库。

Apiiro 研究员 Shmulik Cohen 表示：“该蠕虫利用窃取的 GitHub 访问权限重写开发者已经创建的提交，并保留作者、消息和日期，同时在构建配置中数百个空格之后添加一个隐藏的加载器。”

“构建项目就会运行它。在最新一波攻击中，使用 VS Code 打开该文件夹就足够了。加载器会从以太坊钱包读取其服务器，因此让服务器下线毫无作用：一笔交易就能把所有加载器转移到下一个地址。”

2025 年 5 月的 PolinRider 攻击

此次动态出现之际，OpenSourceMalware 表示其发现了一次发生于 2025 年 5 月的 PolinRider 攻击，比有记录的最早受害者早八个月。该攻击针对九个软件包，利用被劫持的维护者账户，在 90 分钟内推送了投毒版本——

  • itsa-utils@1.4.2
  • itsa-jsext@2.0.3
  • itsa-react-docviewer@16.1.2
  • itsa-cli@16.5.3
  • itsa-react-button@16.0.11
  • itsa-react-maskedinput@16.1.2
  • itsa-react-checkbox@16.0.5
  • itsa-react-focuscontainer@16.0.10
  • itsa-react-input@16.1.2

现已发现，这些软件包中的每一个都利用了 EtherHiding（NullReceiver 的前身）来获取名为 JADESNOW 的 JavaScript 下载器，随后用它投递 InvisibleFerret（一种用于 Contagious Interview 活动的 Python 后门），以及一个 Socket.IO RAT 和一个基于 Python 的窃密程序。

安全研究人员 Paul McCarty 和 Jenn Gile 表示：“2025 年的样本包含 PolinRider 的 payload，但不具备其有记录的传播行为；这种行为出现在同一维护者的 GitHub 仓库中，时间跨度为 2026 年 1 月至 7 月之间的四个时段。”他们补充道：“其背后的区块链记录将攻击者的活动追溯至 2025 年 2 月。”

“感染很可能自 2025 年起就一直存在于该维护者的机器上，因为 2026 年的推送正是从该机器发起的。这与 PolinRider 有记录的传播脚本相符，该脚本会回拨系统时间、将 payload 合并进 tip commit，并使用开发者自己的凭据执行强制推送。”
