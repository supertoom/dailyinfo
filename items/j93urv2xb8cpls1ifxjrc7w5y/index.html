中文原文

黑客正在积极利用 OpenSSH 中的“SSHole”漏洞（CVE-2026-123158），以执行命令、窃取凭据并建立持久化访问。

多家网络安全公司已确认这些攻击，并报告称利用尝试始于 11 月 5 日，即概念验证利用代码发布的当天，次日已有成功利用的记录。

该漏洞由安全研究员 Ozgun Kultekin 于上周披露。SSHole 可绕过运行在某些基于 musl 的 Linux 系统上的 OpenSSH 的身份验证，其中包括用于云端和虚拟环境的轻量级 Alpine 发行版。

该缺陷使攻击者能够登录到密码哈希设置为星号 (*) 以阻止密码登录的账户。

过大的密码会导致 musl 的密码哈希函数在出错时返回 *，而 OpenSSH 会错误地将其视为与账户存储值匹配。

Kultekin 解释道，利用该漏洞需要特定的身份验证设置，不会影响拥有有效密码哈希的账户，并且当被盗账户具有无密码管理员权限时，可能导致获得 root 访问权限。

OpenSSH 维护者已在 11 月 5 日发布的 10.6p2 版本中修复了该漏洞，而利用代码约在四小时后公开。

芬兰安全公司 Defused said 在周末表示，其观察到“少量参与者”试图利用 SSHole，尽管此类活动并不广泛。

威胁情报公司 GreyNoise recorded 记录到 11 月 7 日 00:46 UTC 首次在野成功利用 SSHole，比修复时间晚约 40 小时。

研究人员记录了 16 条成功的利用链，目标是由 GreyNoise 保护的网络，来源为六个与利用后活动相关的源 IP 地址。该公司表示，这些攻击并不能代表涉及 SSHole 的更广泛活动。

在 GreyNoise 观察到的攻击中，威胁行为者进行了系统和容器侦察，发起对云元数据服务的查询，尝试读取密码哈希和 root SSH 密钥，并试图修改 SSH 的“authorized_keys”文件以获得持久化访问。

其中一名攻击者获得了 root 权限并安装了 TAC Agent，这是一个 Python 命令与控制代理。然而，该植入程序无法连接其命令与控制（C2）服务器“tac.vpnla[.]org”，因此从未接收到任务。

对 TAC Agent 载荷的分析显示，该植入程序支持执行 shell 命令、大量系统侦察、文件上传/下载操作，并且能够自我更新。

该代理没有内置的持久化机制，因此攻击者尝试通过配置启动服务来确保其留存。

GreyNoise 指出，该植入程序的注释、日志和错误信息均为中文，这可能会与其他证据结合使用，以确定攻击者的来源。

一项表明其可能由自动化操作完成的发现是缺失的工具检查会返回反馈信息，可帮助自动化规划器根据需要修改命令，以使攻击继续进行。

总体而言，GreyNoise 记录到了 2750 万次端口 22 扫描和 2010 万次 SSH 会话尝试，但这些并未被确认为 SSHole 攻击。

网络安全公司 Previdian 也确认已成功利用 SSHole，遥测数据显示，来自九个国家的 13 个攻击者 IP 地址发起了 20 次尝试。

进攻性安全公司 watchTower 表示，11 月 6 日，其观察到 SSHole 被利用于与僵尸网络和加密货币挖矿活动相关的攻击中。

系统管理员应尽快更新 OpenSSH，或禁用受 SSHole 影响系统上的 SSH 密码认证。

还建议检查是否存在意外的密码登录成功记录，其账户的 /etc/shadow 密码字段为 *，以及未经授权的 SSH 密钥、TAC Agent 文件或启动服务。
