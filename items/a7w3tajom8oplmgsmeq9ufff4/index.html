正文 · AI 翻译
中文原文

攻击者正在利用 Apache Roller 的一个严重漏洞，该漏洞允许未经身份验证的远程代码执行，亟需进行安全更新。

Apache Roller 中一个被追踪为 CVE-2026-129448（CVSS 评分为 9.8）的严重漏洞，可能允许未经身份验证的攻击者在易受攻击的服务器上执行任意代码。Apache Roller 是一个使用 Java 编写的开源博客平台。据 Apache Software Foundation（ASF）称，该漏洞正被 actively exploited in attacks in the wild。

该问题影响 Apache Roller 4.0.0 至 6.1.4 版本。它源于平台 XML-RPC 端点中的不安全反序列化，该端点会在检查请求者是否通过身份验证之前处理某些数据。攻击者无需有效凭据即可到达此易受攻击的代码路径。

“Apache Roller 4.0.0 至 6.1.4 版本中对不可信数据的反序列化，允许未经身份验证的远程攻击者执行任意代码。XML-RPC 端点接受供应商扩展类型，并在对请求者进行身份验证之前对其进行反序列化。”Apache 邮件列表发布的安全公告中写道。“这与 CVE-2026-82384 是同一个漏洞，而后者仅将 Apache Roller 6.1.5 列为受影响版本。”

Apache 项目在其发布于 Apache 邮件列表的安全公告中对该问题进行了说明：

维护人员解释道，XML-RPC 端点接受供应商扩展类型，并在对请求者进行身份验证之前对其进行反序列化。这种操作顺序是核心安全问题：应用会在确定请求是否可信之前处理攻击者控制的数据。

ASF 还确认，该漏洞与此前期追踪为 CVE-2026-82384 的问题相同。那份发布于 2026 年 9 月的早期公告仅将 Apache Roller 6.1.5 列为受影响版本。新公告将受影响版本范围扩大至 4.0.0 至 6.1.4 的发行版本，因此管理员不应仅依赖早期公告所列的范围。

该项目已明确确认存在现实中的利用活动，尽管尚未披露有关攻击的技术细节、涉及的威胁行为者或被攻击的组织。

“该问题正被积极利用。”公告中继续写道。

安全研究员 n0mi1k 因发现该漏洞而受到认可，Matt Raible 则向该项目报告了该漏洞。ASF 建议升级至 Apache Roller 6.1.6 或更高版本。该版本禁用了供应商扩展类型，并在禁用 XML-RPC 功能时拒绝 XML-RPC 请求。

无法立即安装更新的组织应采用项目提供的某种变通方案。他们可以在 WEB-INF/web.xml 中将 enabledForExtensions 设置为 false，或者移除 /roller-services/xmlrpc servlet 映射。无论采用哪种方式，管理员都必须重启 Apache Roller 才能使更改生效。

专家警告称，在较旧版本中，仅通过管理界面禁用 XML-RPC 并不能完全解决该问题。易受攻击的代码可以在检查该配置设置之前对请求进行反序列化，因此即使管理员认为已关闭该功能，应用仍会面临暴露风险。

已确认的利用活动使这不再只是一项常规补丁更新建议。运行 Apache Roller 的组织应找出每个受影响的实例，检查 XML-RPC 端点是否可访问，并优先进行升级或采用建议的临时缓解措施。面向互联网的系统应受到特别关注，但内部部署也不应被忽视：服务器无需公开可访问，攻击者一旦进入组织网络，就可能成为有价值的攻击目标。

ASF 还警告，仅通过管理界面禁用该功能无法保护较旧的安装版本：

“暂时无法升级的用户应在 WEB-INF/web.xml 中将“enabledForExtensions”设置为“false”，或移除“/roller-services/xmlrpc” servlet 映射，然后重启 Roller。”公告总结称。“仅在管理 UI 中禁用 XML-RPC 并不足够，因为较旧版本会先反序列化请求，然后才检查该设置。”
