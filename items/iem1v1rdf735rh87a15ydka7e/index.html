中文原文

GreyNoise 使用我们的全球观测网格（Global Observation Grid，GOG）追踪威胁活动。这是一个传感器网络，旨在吸引针对我们托管基础设施的对抗性扫描和漏洞利用尝试。人们可能会把这些传感器视为传统的“蜜罐”，但这并未充分体现我们部署和管理 GOG 这一复杂网络所具有的多样性、灵活性以及规模。针对我们传感器的未经请求活动即便不是恶意，也至少属于可疑活动。我们的方法使我们能够捕获端到端入侵，并实时分析攻击者基础设施、工具和战术的广泛情况，无需等待耗时的事件响应调查。我们将传感器网络的数据与额外的创新数据源和方法融合，以形成对对手的全面认知。

‍

活动摘要

  • GreyNoise 最近发现了一场针对 Check Point Security Management Servers 的入侵活动，已确认的攻击活动发生在 2026 年 10 月 17 日至 11 月 2 日之间，全球至少有 22 个不同组织受到影响。
  • 我们将这组威胁活动追踪为 GreyNoise Threat 13（GT13），它代表针对这 22 个受害组织的对手基础设施、工具以及利用后行动。
  • 此次定向活动似乎并未聚焦于任何特定地理区域或行业。受影响组织包括在英国、爱尔兰、法国、荷兰、希腊、德国、奥地利、保加利亚、波兰、印度、泰国、越南、韩国、香港、中国、澳大利亚和美国拥有资产的受害者。受害者组织所在行业包括金融服务、能源、政府、交通运输、采矿、工程和制造业。
  • 目前，我们尚未将 GT13 归因于任何已知或公开追踪的威胁组织。我们当前掌握的信息不足以评估该行为者的动机或其与某个原籍国家的关系。
  • 该行为者使用了 99 个 IP 地址，其中许多是一次性网络基础设施，用于扫描、利用和控制受害者，其中包括使用被入侵的服务器充当“操作中继箱”（operational relay box，ORB），或更简单地说，作为与下游受害者资产交互的“中继节点”。该行为者使用这一中继箱／中继节点来保存命令结果以及从 24 台不同的 Check Point Security Management Servers 窃取的数据。
  • 该行为者使用 Nmap、Chisel、Impacket、Paramiko 以及其他 Python 工具，对受害者资产实施入侵活动，包括尝试执行内部侦察、权限提升和横向移动。
  • 该威胁行为者利用或尝试利用了多个 CVE，包括但不限于：CVE-2026-61500（Rejetto HFS）、CVE-2025-5777（Citrix NetScaler）、CVE-2024-21893（Ivanti）、CVE-2026-41089（Windows NetLogon）、CVE-2026-16232 （Check Point SmartConsole 身份验证绕过以运行脚本），以及 CVE-2026-98432（Linux IPv4 UAF）。
  • 尽管我们观察到了键盘实际操作活动，但我们认为，与大多数现代攻击一样，该行为者使用了 LLM 和智能体系统来执行漏洞扫描、漏洞利用、工具开发，以及与已入侵资产的自动化交互。
  • 我们对这些攻击活动的可见性大约在 2026 年 11 月 2 日中断，但鉴于该攻击者持续访问受害者 Check Point 设备的能力，我们预计此次入侵活动仍在持续。
  • 我们正与国际政府合作伙伴和 CERT 机构合作，共享相关情报并通知受害者。

‍

观察到的攻击者活动

我们目睹 GT13 攻击者使用了 99 个 IP 地址，这些地址要么是经由 ExpressVPN 的出口，要么是被攻陷的受害者 Check Point 设备；活动包括 1400 多个网络会话、800 多条命令行痕迹，以及下载、上传或创建的 1200 多个文件。我们无法在此引用所有细节，但可以重点介绍观察到的 GT13 对手活动，以展示其传统技术以及战术、技术和程序（TTP）。

‍

HFS 扫描与漏洞利用

GT13 威胁行为者使用自动化扫描和漏洞利用流程，通过 CVE-2026-61500 攻陷了一台 HFS 服务器。

2026-10-02 13:17:45 UTC - 该攻击者扫描并开始利用 HFS 服务器。每次向 HFS loginSrp1 端点发送 POST 请求，都会返回一个全新的签名会话 cookie，其中包含取自 JavaScript Math.random() 函数的“sid”值。通过连续进行多次登录，该攻击者收集了足够的输出，重建 V8 PRNG 算法的内部状态，从而恢复 HFS 会话 cookie 签名密钥，随后伪造出一个已签名的管理员会话 cookie。这使攻击者无需密码即可以管理员身份登录。

10 月 8 日，我们观察到该攻击者的自动化程序使用 HFS 命令钩子登录已攻陷的服务器并执行“uname -a; df -h / | tail -1; whoami”。此后活动陷入沉寂，直到 10 月 19 日。

建立操作中继盒／跳板

2026-10-19 14:53:48 UTC - 我们不知道原因（可能是多智能体架构存在问题），但该攻击者没有立即使用 SSH 访问权限。相反，该攻击者的自动化流程重新利用 HFS 漏洞利用路径，伪造新的会话 cookie，并利用 HFS server_code 功能尝试在服务器上下载和安装更多恶意软件。至此可以看出，该攻击者打算将已攻陷的服务器用作中继或“跳板”，以开展进一步的入侵行动。

他们无法查明植入程序为何未能下载，因此攻击者于次日通过直接 SSH 连接返回，继续设置其中继。

2026-10-20 07:22:08 UTC - 攻击者创建了一个脚本（/root/exfil/srv_post2_<redacted>.py），在该跳板上设置了一个未经身份验证的 HTTP 服务器，随后开始上传文件。首个被外传的 .tgz 文件包含对一台已受入侵的 Check Point Security Management Server 进行网络路由扫描所得的结果，表明攻击者已能访问目标受害资产。

攻击者继续设置其环境，上传并安装了 Nmap 和 Chisel 等开源工具，随后设置了一个 Chisel 服务器作为反向代理。

入侵行动与数据外传

在将已受入侵的服务器设置为中继后，攻击者开始使用它管理其与此前已受入侵的受害 Check Point 设备之间的交互。由于这里涉及大量交织在一起的受害者信息，我们将两组受害者分别称为 A 和 B。在我们的可见范围内，攻击者正积极加深其对受害者 A 的入侵；后来，我们还观察到其对另外 21 台受害 Check Point 设备执行了批量操作。

10 月 20 日至 26 日期间，攻击者让其受害者 A 的一台已受入侵资产下载 Chisel 程序，并以客户端模式运行，从而进一步扫描并与受害者 A 的环境交互。攻击者通过 Chisel 隧道，并使用针对 CVE-2026-16232（Check Point SmartConsole 身份验证绕过以运行脚本）的脚本，在多台 Check Point Management Server 上发起了 100 多项管理任务。其中包括复制防火墙数据库和 Internal CA、签发新证书（pivot.p12），以及卸载安全策略（这会禁用防火墙）。此外，攻击者探测了 Citrix Netscaler、Ivanti Connect Secure、VMware vCenter、Microsoft Exchange、Oracle TNS 资产以及多台域控制器。

攻击者的大多数命令和交互内容过于庞大，无法在此逐一深入分析，但我们可以从其工具入手，揭示其中部分 TTPs。攻击者至少使用了 30 个 Python 脚本，其中许多是其他脚本的辅助工具或启动器，另有若干用于漏洞探测或漏洞利用执行器。以下摘录用于说明其中更专业化的工具和工作流。

2026-10-20 14:17:51 UTC - 使用 spray_portal.py 扫描受害者 A 环境中的另一台 Check Point 服务器。

2026-10-26 02:17:30 UTC——攻击者向 24 台已入侵的 Check Point Security Manager 服务器发出批量证书管理任务，其中包括属于 Victim A 的服务器和其他 21 个受害资产。该任务的结果以文本文件形式发回跳板服务器。我们没有观察到攻击者向这些设备发送此命令任务，这表明该任务是从对手基础设施的另一部分发出的。

请注意，这些文本文件包含受害者 IP 地址，并按递增的 IP 顺序排列，表明有自动化程序循环访问这些地址，在已入侵的 Check Point 服务器上运行命令，并通过 scp 将其交付至此 exfil 文件夹。每个文件均从受害者基础设施传出，这表明每台已入侵设备都持有与植入跳板的公钥相对应的 SSH 私钥。

所有这些文件都包含错误消息，表明证书任务失败。尽管我们没有看到后续尝试，但这些输出中的任务信息和 IP 地址已足以让我们识别并通知许多受害组织，方式包括直接通知或通过政府合作伙伴通知。

保护其访问权限

2026-11-02 02:28:27 UTC - 到了 11 月初，其他威胁行为者已开始扫描并尝试滥用遭入侵的服务器。我们观察到 GT13 行为者使用脚本对 Linux IPv4 释放后重用漏洞（CVE-2026-98432）进行自检。检查完成后，该行为者尝试使用 Linux 自带的命令行工具 nftables 对系统进行修补，丢弃带有 IP 选项、可能触发该漏洞的 IPv4 数据包。这使该行为者能够保护其跳板机，防止他人未来利用该漏洞。

cve_2026_98432.py 摘录

该行为者在跳板机上测试 CVE-2026-98432 脚本的示例命令，随后尝试使用 nftables——Linux 内置的防火墙和数据包过滤框架——修补漏洞。您会注意到，修补命令执行得很快。

攻击时间范围与时间线说明

  • 在 GT13 入侵 HFS 服务器之前，该对手已能访问受害者的 Check Point Security Management 服务器。我们无法确定攻击者何时或如何获得对这些 Check Point 资产的访问权限。
  • 我们在 2026-10-02 13:17:45 至 2026-11-02 03:19:46 UTC 之间观察到 GT13 的攻击活动。在观察该行为者期间，我们未发现其在约 17:00 UTC 至约 00:19 UTC 之间有任何对手进行键盘实操活动，05:00 UTC 这一时段也没有任何活动。我们深知时区分析存在的风险，因此不会过度看重该行为者倾向于在相当于 UTC+7 或 UTC+8 工作时间时进行活动这一点。
  • 在我们首次发现该攻击基础设施之前，它就已经长期存在；我们注意到，尝试使用的恶意软件域名 newpayapp[.]com 首次注册于 2026-03-13 12:46:28 UTC。该域名最初注册时将注册人所在州设为“Hai Phong”、国家代码设为“VN”，这或许恰好便于 UTC+7 时区的工作时间（请参阅 Cloudflare 的 RDAP 服务）。
  • 我们怀疑 GT13 行为者拥有一套成熟且由 AI 赋能的进攻体系。我们认为，该行为者拥有独立的智能体框架和系统，用于武器化漏洞、扫描易受攻击的资产并自动进行利用，以收集系统集合，供后续用作操作中继或真正的目标。我们怀疑，时间线中的某些异常反映了智能体化的进攻行动。
