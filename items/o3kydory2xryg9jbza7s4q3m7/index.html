要点

  • Check Point Research 发现了此前未有公开资料的伊朗威胁组织 Volant Manticore，该组织与伊朗情报和安全部（MOIS）有关。根据我们的观察，我们认为这是首个将塞浦路斯指定为主要间谍活动目标的伊朗组织，其重点针对电信公司、航空公司和关键基础设施。
  • 该组织使用 KuboShell 这一新后门来执行命令与控制（C2）功能，该后门利用 IPFS，并部署 Homa Framework——一个基于 MuddyWater 的 MuddyC2Go 客户端重新实现版本构建的后渗透框架。Volant Manticore 除了投放定制恶意软件外，还会交付 RMM 工具并开展 凭据窃取活动。
  • 进一步分析揭示了该组织操作人员的内部环境，包括本地部署和云端部署的开发、测试与运营环境。我们观察到该组织在部署前使用其工具针对杀毒产品进行测试，并使用 Fortinet SSL VPN 客户端，这表明他们可能通过 VPN 访问受害者的网络。
  • 虽然我们发现了与 MuddyWater 的多重联系，但我们评估认为，Volant Manticore 很可能由从 MuddyWater 分化出来的前成员组成，目前作为一个独立威胁集群运作。
  • Volant Manticore 的目标优先事项似乎会随地区地缘政治局势的变化而调整。近期转向沙特阿拉伯目标，包括医疗保健领域，可能反映了沙特阿拉伯与获得伊朗支持的胡塞武装之间不断升级的紧张局势。

简介

Check Point Research 正在追踪一个此前未有公开资料、与伊朗有关联的攻击组织，并将其命名为 Volant Manticore。该组织于 2026 年 7 月通过一份虚假的 CV 向一家总部位于塞浦路斯的航空公司投放单个后门，此后活动扩展为更广泛的集群；我们将其活动追溯至 2025 年 9 月。

MuddyWater 是一个伊朗间谍组织，与伊朗情报和安全部（MOIS）有关联，主要专注于间谍活动，至少自 2017 年起便一直活跃。Volant Manticore 与 MuddyWater 共享部分工具和技术，但其狭窄的区域重点、定制植入程序以及独特的 TTP（战术、技术与程序）使其与众不同。

Cyprus is at the center of Volant Manticore’s operations. The island’s deepening defensive and energy ties with Israel and Greece, and its role as a hub for Western military operations in the region, make it a natural target for Iranian intelligence collection. Cyprus was among the countries where we observed a rise in Iran-nexus targeting of IP cameras starting February 28, 2026, activity that may precede military strikes as well as support post-battle damage assessment. The group’s focus on the island’s telecommunications companies and airlines is consistent with Iran’s history of operational activity against individuals in Cyprus.

2026 年 9 月，随着沙特阿拉伯与受伊朗支持的胡塞武装之间的敌对行动升级，我们观察到 Volant Manticore 突然将注意力转向沙特阿拉伯，并将医疗保健机构作为攻击目标。这符合 MOIS 的行动轨迹：在军事冲突期间通过网络行动攻击医院和医疗保健服务提供商，并在某些情况下试图扰乱其运营。

在本报告中，我们分析 KuboShell 后门和 Homa Framework，绘制 Volant Manticore 更广泛的基础设施图谱，并分析其针对一个可能是塞浦路斯政府目标的早期活动。我们还介绍了该组织近期转向沙特阿拉伯的情况，并提供了归因证据。

投递方式：Meet Athena Marinou

我们的调查始于在 Virus Total 上发现一份属于“Athena Marinou”的虚假简历；此人是一名基于塞浦路斯、由 AI 生成的旅行和旅游从业者。该文件邀请读者从一家合法的招聘与求职网站下载完整简历，但这段文字背后的超链接实际上指向一个托管在 Catbox 上的压缩包，该压缩包会将 KuboShell 后门投递到受害者系统中。我们评估此次钓鱼攻击的目标是一家总部位于塞浦路斯的航空公司，其主营业务是塞浦路斯与以色列之间的航班。

今年 9 月下旬，Volant Manticore 针对沙特目标发起了一场钓鱼活动，通过一个名为 AI_Healthcare_Seminar.zip 的压缩包投递 KuboShell。与我们最初发现的样本类似，此变种也伪装成与 PDF 相关的软件。

我们还发现了一个相关压缩包 Ai_Healthcare_Seminar_Online.zip，评估认为其目标与上述攻击相同。该压缩包不包含 KuboShell，而是包含一个 N-able RMM 可执行文件。与该样本关联的电子邮件账户属于沙特阿拉伯的一家私人医院，很可能已使用泄露的凭据遭到入侵。结合我们观察到的不同医疗保健主题诱饵名称，这表明 Volant Manticore 专门将沙特医疗保健行业作为目标。

KuboShell – 将 IPFS 作为命令与控制通道

KuboShell 是一款 64 位 Windows 后门，使用 InterPlanetary File System（IPFS）进行命令与控制（C2）通信。IPFS 是一种点对点文件共享网络，通过内容哈希而非位置来标识每个文件。由于文件仅在某个节点存储（“固定”）它们时才会保持可用，KuboShell 依赖 Pinata——一项商业固定服务，提供用于在 IPFS 上上传和检索文件的 API。后门 PDB 路径中引用的 Kubo 是 IPFS 的原始实现。

启动时，KuboShell 会检查自身是否拥有管理员权限。如果没有，它会尝试以更高权限重新启动自身，从而触发用户账户控制（UAC）提示。

KuboShell 获取计算机第一个网络适配器的 MAC 地址，并将其用作每个受害者的唯一标识符。随后，它使用硬编码的 Pinata 访问令牌，通过上传一个包含 hi 的文件来注册该主机；该文件保存为 C:\Users\Public\<MAC>.log。

完成注册后，KuboShell 会在 Pinata 中检查一个名为 <MAC>.txt 的命令文件。如果该文件存在，KuboShell 会查找其 IPFS 标识符，并通过 Pinata 的公共网关下载其内容。

下载的文本会在隐藏窗口中传递给 PowerShell。执行完成后，KuboShell 会尝试上传 C:\Users\Public\re.txt，该命令应将结果写入此文件。KuboShell 本身不会捕获输出，因此只有当接收到的命令将结果写入该文件时，才会返回结果。随后，KuboShell 每 60 秒检查一次是否有新命令。

猛砸彩罐

我们分析了操作员发出的历史命令，以及从 2026 年 5 月至 10 月这段时间内的命令输出，其中包括首次观察到钓鱼攻击企图前两个月进行测试时产生的命令。

根据操作员的命令，KuboShell 似乎充当了执行基本侦察命令的初始落脚点，尤其是 quser、whoami 和 ipconfig，然后通过多阶段 PowerShell 和 JavaScript 执行链下载并执行功能更强的后门。因此，KuboShell 似乎充当一道“护栏”，让操作员在部署最终载荷之前评估已被入侵的环境，这与基于钓鱼的初始入侵方式相符。

命令正确，控制台错误

操作员向 KuboShell 发送了 list、persist 和 payload 命令，但它们均不是有效的 PowerShell 命令。这些看似“错误”表明，操作员将内置框架命令输入到了错误的控制台中，这符合以下理论：操作员使用了一个模块化框架，叠加在一个相对简单的 JavaScript 后门之上，而该后门是此次感染链的最终阶段。正如本节后文所述，该 JavaScript 后门与 MuddyWater 工具存在关联。值得注意的是，操作员发送的这三条命令全都是 MuddyWater 专用 C2 框架中的已知命令，例如 PhonyC2。这进一步支持了以下观点：该后门是一个更广泛框架中的核心模块执行器，Check Point Research 将该框架称为 Homa Framework。

入侵后载荷——Homa Framework

根据操作员的命令，我们能够识别下一阶段载荷。我们将这个多阶段入侵后框架称为 Homa Framework。

阶段 2——PowerShell Loader

第二阶段 PowerShell 脚本使用已定义的 Xor-Decode 函数对编码字符串进行解码。它会移除换行字符，并将输入按三个字符的数字块进行处理。生成的值随后在指定 JavaScript 语言选项的情况下传递给 Add-Type，之后脚本尝试调用静态 run() 方法。while($true) 循环会反复执行此逻辑，并通过异常处理在改用其他类型名时重新尝试编译。

function Xor-Decode {
    param ([string]$EncodedText)

    $key = [int][char]'o'
    $result = ""

    $clean = ($EncodedText -replace "`r|`n", "")

    for ($i = 0; $i -lt $clean.Length; $i += 3) {
        $num = [int]$clean.Substring($i, 3)
        $result += [char]($num -bxor $key)
    }

    return $result
}

$src = "079079079079028027014027006012..."

$dec = Xor-Decode $src
while($true) {
    try {
        $jsc = (add-type -language JScript -MemberDefinition $dec -PassThru -Name 'jsc35')[1]
        $jsc::run()
    }
    catch {
        $jsc = (add-type -language JScript -MemberDefinition $dec -PassThru -Name 'jsc36')[1]
        $jsc::run()
    }
}

阶段 3 – JavaScript 后门

后门实现了一个持续运行的 C2 循环。它会向 hxxp://185.205.187[.]109:8000/X{key} 发送初始 hi 消息，其中 key 是一个硬编码的 5 个字母数字字符标识符，按受害者分别填充，用作唯一标识符。它使用 WinHttp.WinHttpRequest.5.1 COM 对象进行通信；服务器端组件在处理传入请求时会检查该对象的默认 User-Agent 字符串。服务器的响应会被解释为命令。

后门根据前缀执行收到的命令：

  • PowerShell 命令：以 function 开头的命令通过隐藏的 PowerShell 执行，并绕过执行策略。
  • SSH 命令：以 ssh 开头的命令通过 cmd.exe 异步启动，这很可能是为了避免长时间运行的 SSH 会话（例如隧道）阻塞轮询循环。
  • 其他命令：通过 cmd.exe /c 执行，并将标准输出重定向到 C:\Users\Public\outputt2.txt。

后门从临时文件读取命令输出，去除不可打印字符和空行，然后删除该文件。生成的任何输出都会通过 HTTP POST 请求发送回 C2 服务器。循环在每次迭代之间暂停十秒。

我们评估认为，第三阶段后门至少有一部分用途是执行我们无法恢复的其他模块。

与 MuddyWater 的代码相似性

Homa Framework 的第三阶段有效载荷与 MuddyWater 的 MuddyC2Go 框架高度相似：

  • 相同的有效载荷交付 URI 模式：以 H 开头，后跟一个 32 个字母数字字符的标识符
  • The same POST request format:
    • URI：以 X 开头，后跟一个 5 个字符的字母数字密钥。
    • 内容以“{content}(){key}”格式发送。
  • 以 hi 作为初始请求的内容
  • 相似的变量名和函数名，以及整体脚本结构

我们评估认为，Homa 客户端是旧版 MuddyC2Go 客户端的 JavaScript 重新实现，这可能使 Volant Manticore 能够以极少修改保留更复杂的服务端组件，从而减少开发时间和资源投入。

操作员测试与运行环境

Volant Manticore 操作员在自己的机器上测试了 KuboShell，暴露了其测试和开发环境的部分信息。MAC 地址前缀和网络适配器详细信息表明，他们同时使用了 VirtualBox 和 VMware 虚拟机。多个 VMware 虚拟机共享同一个 NAT 子网和网关。由于 VMware 会为每次安装分配此子网，因此这些虚拟机很可能运行在同一主机上。总体而言，除 VirtualBox 环境外，我们还发现了至少两个不同的 VMware 环境。

综合来看，证据表明至少有两个操作人员在使用同一个 Pinata 账户。其中一人经评估是 KuboShell 的开发者，使用 VirtualBox 环境。另一名操作人员主要使用 VMware 环境，并似乎更直接地参与了活动的执行，包括在实际行动之前进行测试。

其中一些虚拟机还安装了与 VPN 相关的虚拟适配器：

  • 安装了 Fortinet SSL VPN 的多台虚拟机。
  • 一台 VirtualBox 客户机上的 IVPN 适配器，该客户机还装有 Fortinet 适配器。
  • 一台 VMware 客户机上与 Kaspersky 相关联的 VPN 适配器。

将 IVPN 适配器这一商业隐私 VPN 与 Fortinet 适配器结合使用，表明该虚拟机除了用于测试外，也可能用于实际操作。Fortinet 适配器可能意味着这些操作人员使用企业 VPN 连接来访问受害者环境。

与 IVPN 类似，Kaspersky 防病毒适配器也可以提供隐私 VPN。不过，由于该 VPN 组件可以与防病毒软件捆绑安装，我们认为它更可能反映的是在一台用于针对该产品测试工具的机器上安装了防病毒软件。

此外，我们还发现了另一组带有 Azure 相关配置的虚拟机集群，它们也可能代表由行为者控制的测试基础设施。在命令历史记录中，明确的 Active Directory 发现命令仅限于这一组虚拟机。我们怀疑 Volant Manticore 使用这些虚拟机在预先配置的环境中测试与 AD 相关的功能。

2026 年 1 月：军事主题诱饵可能针对塞浦路斯政府实体

观察到的 Homa Framework C2 是 185.205.187[.]109，但操作人员的命令显示，该攻击者在 8 月还使用了 185.205.187[.]107。这表明数个相邻地址是被一起开通的。该系列中“缺失”的地址 185.205.187[.]108 让我们发现了更早的一次攻击活动。

2026 年 1 月，一份名为 MilitaryHeritageProposal.doc 的恶意 Word 文档从塞浦路斯上传至 VirusTotal。文档显示一个模糊的页面，并要求读者启用内容才能查看。我们评估此次网络钓鱼尝试很可能针对塞浦路斯的一个政府实体。军事主题可能表明目标与国防部门有关。

该文档在宏中隐藏了一个 VBA 后门。启用内容后会通过两条路径之一触发执行：一条是在显示伪造的“Microsoft Word 未响应”错误消息后不久触发，另一条是在受害者响应并关闭文档时触发。在运行第二阶段之前，宏会将 HKCU\SOFTWARE\Microsoft\Office\16.0\Word\Security\AccessVBOM 设置为 1，从而授予对 VBA 项目的编程访问权限。随后，它会启动一个隐藏的 Word 实例，从数百个经过编码的片段中重建第二阶段代码，并将其注入该实例。

第二阶段运行后，其他所有 WINWORD.EXE 进程（包括承载原始文档的进程）都会被终止。在受害者看来，Word 就像崩溃了一样，只有隐藏实例仍然存活。随后，后门生成一个随机的 10 字符受害者 ID，并通过普通 HTTP 在 185.205.187[.]108:25498 向 C2 注册。之后它会循环执行：检查是否有文件可下载，等待 20 秒，轮询是否有命令，再等待 20 秒。

后门根据前缀处理每条命令：

  • Commands that start with $uri or $req run through hidden PowerShell. These same variables were present in the Homa Framework first-stagers we observed earlier. This branch therefore appears to exist specifically to deliver follow-up payloads, possibly related to Homa. Two more clues support this:
    • 与 cmd.exe 路径不同，PowerShell 分支不会将输出发送回 C2。
    • 该 VBA 后门自身没有持久化机制。
  • 其他命令通过 cmd /c 运行，输出会被捕获至 C:\ProgramData\UiAutomation.txt，随后被读取、删除，并以 JSON 格式化的结果发送至 C2。

下载的文件以连续分段的形式到达，后门会重新组装这些分段，并使用 C2 在 X-Filename HTTP 响应标头中提供的文件名，将其保存到 C:\Users\Public。

相关基础设施

185.205.187[.]108 曾在 2025 年 11 月至 12 月期间托管 corenewsnetwork[.]com，并曾短暂托管 liveupdatenews[.]net。两者都是通用的新闻主题域名，并且在 2025 年 11 月也都解析到 185.106.102[.]70。2026 年 1 月，以下 URL 被扫描至 VirusTotal：

hxxp://185.106.102[.]70:8080/HK5PpjU6I9ug0zmNZqAFdIPa9wayXl2RZ

该 URL 遵循与 Homa Framework 第一阶段 URL 相同的模式，这既印证了被动 DNS 关联，也印证了我们最初发现的指向 185.205.187[.]108 的关联。时间线也完全吻合：文档元数据显示其创建于 2026 年 1 月 26 日，最后保存于 2026 年 1 月 27 日，即该 URL 被扫描的同一天。

关注王国：将焦点转向沙特阿拉伯

Volant Manticore 于 2026 年 9 月开始针对沙特实体。与其早期在塞浦路斯开展的、目标范围狭窄的行动相比，我们观察到该组织针对沙特组织的钓鱼活动突然激增，并似乎将重点放在医疗保健行业。我们评估认为，这一转变可能表明操作人员在接到简短通知后，被要求迅速获取沙特目标的访问权限：

  • 撒网式攻击 – 投放 NetLock RMM 的钓鱼活动显著增加，其目标范围似乎已在沙特境内扩大。多个样本使用“WhatsApp Images”或“Excel Online”等通用诱饵名称，表明其目标是更广泛的潜在收件人，而非特定组织。其他样本则保留了沙特主题名称，例如 Madinati-Platform.exe 和 برنامج الاعتماد المشترك في السياحة العلاجية.exe（“医疗旅游联合认证计划”）。如上所述，在一个案例中，Volant Manticore 似乎在短时间内向同一目标发送了两个相似的钓鱼诱饵，一个投放 KuboShell，另一个投放 N-able RMM，这可能是一种不计手段以取得立足点的尝试。
  • 仓促开发 – 针对沙特阿拉伯国的 KuboShell 样本包含此前观察到的样本中不存在的遗留调试字符串，表明该样本是在匆忙中编译并部署的。
  • 重新利用基础设施 – 该组织使用了明确以塞浦路斯为主题的域名 cnpcyprus[.]net，作为针对沙特目标使用的 NetLock RMM 样本的 C2。这与在专用基础设施到位前迅速改变攻击目标的情形相符。
  • 地理位置匹配的托管 – 尽管他们没有注册新域名，但在 10 月 11 日，Volant Manticore 将现有域名重新指向一台新配置的、位于沙特境内的 HostZealot VPS，地址为 185.253.118[.]221。这与该组织已观察到的在目标国家境内使用面向受害者 C2 基础设施的模式一致，并进一步强化了我们的假设：Volant Manticore 虽打算轮换旧基础设施，但未能在时限内完成。在配置新 VPS 的过程中，操作人员还暴露了其根目录下的开放目录——这似乎是操作安全（OPSEC）上的疏忽，可能反映出部署仓促。

针对攻击目标优先级这一明显转变的一种可能解释，是沙特阿拉伯国与获得伊朗支持的胡塞武装之间不断升级的冲突。该组织放弃此前有针对性的鱼叉式钓鱼，支持两种可能的解释：Volant Manticore 的委托方可能优先考虑获取更广泛沙特组织的访问权限，而非有选择地针对特定实体；或者操作人员正大力试图攻陷这些目标，并在短时间内向其发送多个诱饵；也可能两者兼有。根据现有证据，我们无法确定哪一种解释更有可能。

归因

我们高度确信 Volant Manticore 是与伊朗有关联的网络威胁组织，并以中等置信度认为该组织至少在历史上与伊朗情报和安全部（MOIS）存在联系。然而，伊朗的网络生态流动性较强，参与此类活动的组织之间的边界并不总是清晰。因此，我们无法排除 Volant Manticore 目前隶属于另一个伊朗实体的可能性。

我们的评估基于以下发现：

  • 工作时间模式 – 操作人员活动时间的时间戳与伊朗当地时间的工作时间相符（UTC+3:30）。观察到的工作周也符合周四至周五为周末的模式。
  • PDB 路径 – 从 Saudi Arabia 上传的 KuboShell 样本的 PDB 路径包含目录 F:\homa\。在波斯神话中，Homa 是与好运和自由有关的神鸟。
  • 目标范围 – Saudi Arabia 长期以来一直是伊朗网络间谍行动的重要目标。正如我们在引言部分所讨论的，Cyprus 也符合伊朗的区域目标优先级。

与 MuddyWater 的重叠

我们发现 Volant Manticore 与 MuddyWater 之间存在多项重叠，包括：

  • 代码相似性 – 如上所述，Homa Framework 的第三阶段有效载荷与 MuddyWater 的 MuddyC2Go 框架高度相似。
  • TTP – 两个组织都会在鱼叉式网络钓鱼活动中将 RMM 工具与恶意文档配合使用，而且二者均曾被发现使用被入侵的电子邮件账户向 RMM 提供商注册。
  • 服务器配置相同 – Volant Manticore 位于 185.253.118[.]221 的服务器与 MuddyWater 位于 159.198.36[.]115 的服务器都在 4444 端口上托管了开放目录的 Python SimpleHTTPServer。

有关归因的深入讨论，请参阅附录 1。

结论

Volant Manticore 展示了伊朗网络生态如何持续重塑自身。 如今，一组看似前 MuddyWater 操作人员的成员开始独立行动，将旧版 MuddyWater 工具与自有新型植入程序结合使用，同时追求此前鲜少受到关注的区域重点。

区分 Volant Manticore 与 MuddyWater 至关重要。 尽管这两个组织目前共享部分技术战术与程序，我们预计 Volant Manticore 将继续开发自己的工具和 TTP，而两者之间的差异将随时间推移而愈发明显。因此，将 Volant Manticore 视为 MuddyWater 的一部分可能导致认知盲区，尤其是对于位于 Saudi Arabia 和 Cyprus 的组织而言。

Cyprus 似乎是 Volant Manticore 的主要关注对象，考虑到该岛与伊朗对手日益趋同，这样做合乎情理。然而，2026 年 9 月，这一模式突然发生改变。随着 Saudi Arabia 与 Houthis 之间的冲突升级，Volant Manticore 在其工具和基础设施完全准备就绪之前，转而对 Saudi 组织发起更猛烈的行动。

我们认为，只要与 Houthis 的冲突持续升级，Volant Manticore 就会继续针对 Saudi Arabia 开展行动。 与此同时，Cyprus 很可能仍将是持续关注的目标。 更广泛而言，我们预计 Volant Manticore 将继续对地缘政治变化作出响应，在区域局势发生重大变化时，其目标优先级可能随之转移。

附录 1 – 不同行动者，共同根源？

鉴于我们评估认为 Volant Manticore 由前 MuddyWater 操作人员组成，我们希望透明地说明促成这一结论的推理过程。考虑到观察到的重叠之处以及伊朗威胁格局的动态特征，我们权衡了若干相互竞争的假设：

  • 同一行为体——Volant Manticore 与 MuddyWater 是同一个组织，或者 Volant Manticore 是在特定任务下于 MuddyWater 内部行动的子组织。
  • 分拆——Volant Manticore 由前 MuddyWater 操作人员组成，他们或单独离开，或共同分拆出来，组建为一个子组织。
  • 专业联系——两个组织的操作人员保持正式或非正式的专业关系。
  • 共同培训——两个组织的操作人员具有共同的培训背景。
  • 共同开发者——两个组织都依赖同一名开发者，该开发者可能是个人，也可能是数字军需官。
  • 模仿者——Volant Manticore 模仿 MuddyWater 的工具和 TTP，制造与伊朗行为体有关的表象。

权衡各种可能性

Volant Manticore 依赖较旧的 MuddyWater C2 框架，而 MuddyWater 此后已将其替换。在 MuddyWater 内部行动的子组织最有可能获取该组织当前的工具，因此同一行为体假设的可能性较低。同样，模仿者最有可能模仿 MuddyWater 最新有记录的工具，而不是已停用的框架。Volant Manticore 新的自定义植入程序充当 Homa 的“护栏”，这使该情景更加不可能。

共同开发者可以解释工具方面的重叠，但无法解释作战方面的重叠。虽然这样的开发者可能接触到较新的框架，但 Homa 重新实现了旧版 MuddyC2Go 客户端，并保持其 C2 协议不变。这样做很可能是为了以极少开发工作量规避现有检测，同时保持服务器端组件不变。结合我们关于 KuboShell 是由单一开发者构建的评估，这表明其背后的组织规模较小、开发资源有限，与 MuddyWater 框架背后的开发者不同；后者曾随时间推移替换其工具，尤其是在公开披露之后。

至于专业联系和共同培训，MuddyWater 的关键人物此前与 Ravin Academy 存在联系，该机构被描述为MOIS 的人才输送渠道 Such ties could result in both a common training background and professional relationships between otherwise distinct groups. In fact, MuddyWater’s TTPs have previously overlapped with those of other Iranian actors. Most recently, Proofpoint identified shared TTPs between TA450 (MuddyWater) and UNK_SmudgedSerpent, which Check Point tracks as Nimbus Manticore.

然而，就我们的案例而言，这两种解释似乎都不太可能。如果与 Ravin 的共同培训关系能够解释这些重叠现象，那么我们预期 Volant Manticore 与 MuddyWater 共享的工具和 TTP 应当在各个伊朗组织中普遍存在。根据我们的观察，这些工具和 TTP 主要与 MuddyWater 关联。至于专业联系，它或许能够解释 UNK_SmudgedSerpent 的重叠现象，因为这可能反映了一次性合作。相比之下，Volant Manticore 始终依赖 MuddyWater 的工具和 TTP。这种持续性更适合用多年在 MuddyWater 内部行动所形成的习惯来解释，而不是用两个独立威胁行为体之间偶发的合作来解释。我们也未观察到表明双方存在持续接触的作战合作迹象，例如共同目标或任务移交。

我们为何倾向于分拆假设

  • 传统技战术 – Volant Manticore 依赖较早期的 MuddyWater 框架，并呈现出旧有的 MuddyWater TTPs。两者都表明其过去与该组织关系密切。如果这种关系仍在延续，我们本应预期其行动人员能够使用 MuddyWater 的新工具。相反，他们重新实现了一套框架，该框架很可能是他们尚属于该组织时获取的。
  • 逐渐分化 – 随着时间推移，Volant Manticore 已超越这些传统技战术。它构建了自己的工具并调整其 TTPs，增加了凭据收集活动等方法，使其行动有别于 MuddyWater。这一发展轨迹符合一个最初依赖 MuddyWater 行动手册、随后逐渐形成自身身份的组织。
  • 不同的目标选择 – Volant Manticore 持续聚焦 Cyprus，这不符合 MuddyWater 的目标选择模式。MuddyWater 偶尔也会针对塞浦路斯实体，但其行动通常覆盖多个国家，并会随时间转移。在 Volant Manticore 针对 Cyprus 期间，MuddyWater 的活动则聚焦于其他地区。这种持续专注于单一国家的做法表明，Volant Manticore 正在追求自己的目标和优先事项。
  • 独立的基础设施 – Volant Manticore 依赖的托管服务提供商和域名注册商通常不会被 MuddyWater 使用。它在任何时候似乎也只管理着规模较小的基础设施，这更符合一支小型团队的特征。

综合考虑上述因素，我们以中等置信度评估，Volant Manticore 是一个独立且单独的团体，由单独或集体离开的 MuddyWater 前行动人员组成。这些行动人员可能仍与当前的 MuddyWater 成员存在联系，但我们评估，所观察到的重合主要反映了他们共同的历史行动经历，而非持续开展协作。

追踪分裂过程

如果 MuddyC2Go 是 Volant Manticore 的行动人员最后能够接触到的 MuddyWater 框架，那么分裂可能发生在 2023 年左右，因为 MuddyWater 于 2023 年末以 DarkBeatC2 取代了 MuddyC2Go。我们只能将 Volant Manticore 的基础设施追溯至 2025 年，因此中间存在一段可见性缺口。

除工具之外，Volant Manticore 的行动人员可能还挪用了 MuddyWater 的工作环境。诱饵文档元数据中出现的用户名 pc，此前与 MuddyWater 的网络钓鱼活动和恶意软件开发相关。尽管通用用户名本身通常不具备很大参考价值，但我们在 Volant Manticore 的多台虚拟机中发现了相同用户名。一种可能的解释是，这些行动人员正在复用此前由 MuddyWater 使用的虚拟机镜像。
