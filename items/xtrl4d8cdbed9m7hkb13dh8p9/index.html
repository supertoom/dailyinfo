PART 01

漏洞情报

1.Drupal安装程序远程代码执行漏洞安全风险通告

11月25日，奇安信CERT监测到Drupal 安装程序远程代码执行漏洞(CVE-2026-132165)在野利用，该漏洞源于 Drupal core 的安装器状态校验不当，当站点已完成安装但安装任务状态未正确闭环时，攻击者可匿名续跑 /core/install.php 安装流程，覆盖 uid 1 管理员账户的用户名、邮箱和密码，从而绕过身份验证并接管站点。成功接管后，攻击者可借助目标环境中已有的模块、主题或文件写入等代码入口执行任意命令，最终实现远程代码执行。目前该漏洞PoC和技术细节已公开。鉴于该漏洞已发现在野利用，建议客户尽快做好自查及防护。

2.GeoServer未认证远程代码执行漏洞安全风险通告

11月25日，奇安信CERT监测到GeoServer未认证远程代码执行漏洞（CVE链），涉及CVE-2026-129244、CVE-2026-129243、CVE-2026-120705、CVE-2026-129245和CVE-2026-129242。攻击者可在未认证状态下先获取数据目录位置，再利用WFS服务名解析与授权规则不一致写入存储查询，借助XInclude解析读取安全配置文件，继而利用固定默认密钥构造管理员会话，最终通过管理员REST接口注册恶意JDBC用户服务并触发反序列化，实现任意命令执行。上述缺陷单独存在时，分别表现为路径信息泄露、访问控制绕过、本地文件读取、会话伪造及反序列化执行；其实际风险在于默认配置允许这些缺陷被同一攻击序列连续利用。尤其需要关注的是，JDBC用户服务本身要求管理员权限才能投递数据，而固定remember-me密钥恰好提供了伪造管理员会话的通道，使该执行入口在未认证条件下被实际打开。因此，仅修复其中任一环节虽可提高利用门槛，但不足以从整体上消除该组合利用风险。目前该漏洞PoC和技术细节已公开。鉴于该漏洞影响范围较大，建议客户尽快做好自查及防护。

3.帆软FineReport FineVis（FVS）插件未授权远程代码执行漏洞安全风险通告

11月24日，奇安信CERT监测到官方修复帆软 FineReport FineVis（FVS）插件未授权远程代码执行漏洞(QVD-2026-115643)，该漏洞源于 FVS 插件复用包导入与应用接口的模板鉴权缺陷：当请求携带的模板路径被归一化为空值时，相关请求被判定为“无需登录的模板访问”，从而绕过登录状态校验；攻击者无需任何账号或凭据，即可上传并应用构造的 .mfvs 复用包。在复用包应用阶段，导入组件未对附件写入位置实施业务白名单限制，可向应用 WEB-INF 目录写入可执行内容，容器检测到配置或类文件变更后重载，最终以应用进程权限执行任意系统命令。鉴于该漏洞影响范围较大，建议客户尽快做好自查及防护。

4.Windows Remote Access API本地权限提升漏洞安全风险通告

11月24日，奇安信CERT监测到官方修复Windows Remote Access API 本地权限提升漏洞(CVE-2026-119853)，该漏洞源于 API 在加载自定义 RAS 拨号 DLL 时，对搜索路径处理不当，允许从不受信任目录加载恶意 DLL。低权限本地用户可通过放置特制 DLL 并触发相关 API 调用，使高权限进程（通常以 SYSTEM 身份运行）加载并执行恶意代码，从而完成权限提升。攻击者可利用此漏洞获得完整系统控制权，包括修改系统文件、安装持久化后门、横向移动或进一步攻击网络资源。目前该漏洞PoC和技术细节已公开，鉴于该漏洞影响范围较大，建议客户尽快做好自查及防护。

5.Artifex Ghostscript -dSAFER沙箱绕过漏洞(CVE-2026-125396)安全风险通告

11月22日，奇安信CERT监测到官方修复Artifex Ghostscript -dSAFER 沙箱绕过漏洞(CVE-2026-125396)，该漏洞源于 gs_fonts.ps 中的 .putgstringcopy 过程在调用特权操作符 .forceput 前未对操作数类型进行检查。攻击者可构造恶意 PostScript 或 PDF 文档，故意触发类型错误，并通过自定义错误处理程序恢复可用的 .forceput 引用。随后利用 save/restore 机制造成释放后使用（Use-After-Free），获得写任意地址的原语，进而破坏 -dSAFER 状态并执行任意代码。成功利用后，攻击者可在 Ghostscript 进程权限下执行系统命令。目前该漏洞PoC和技术细节已公开。在实际部署中，该漏洞可通过公开上传、邮件附件、打印服务等路径实现远程触发，影响面极广。建议客户尽快做好自查及防护。

PART 02

新增在野利用

1.Drupal 安装程序远程代码执行漏洞(CVE-2026-132165)

11月26日，Drupal 安全团队已确认，一个允许攻击者劫持未修补网站的严重漏洞至少从上周四起就被积极利用。

Drupal 是一个内容管理系统 (CMS)，常被大型组织使用，包括政府机构、主要研究型大学以及知名企业和媒体组织。该安全漏洞编号为 CVE-2026-132165，又名 Fail2Install（CVSS 评分：9.8），由 Anthropic 的 OSS Scanner 发现，匿名用户可以利用该漏洞通过滥用 Drupal 安装程序来获得远程代码执行权限或接管易受攻击的网站。

Drupal 安全团队警告称，Drupal Core 自带一个 install.php 文件，用于安装 Drupal Core。在特定情况下，攻击者可以利用该安装程序尝试重新安装 Drupal。这可能导致网站被接管或远程代码执行。如果 Web 服务器无法写入或更改 settings.php 文件的权限，则可以缓解某些攻击路径。虽然最初并未被标记为在实际环境中被滥用，但在对原始安全公告的更新中，Drupal 警告称，该漏洞“最早于 2026年11月19日 19:00 UTC 在实际网站上被利用”。

利用 Drupal 安装程序支持 SQLite 数据库文件并允许在安装过程中选择数据库路径这一特性，可以将这种行为转化为代码执行路径。这是因为安装程序没有限制文件扩展名。

Searchlight Cyber 公司表示，通过在文档根目录下选择以 .php 结尾的路径，安装程序会创建一个扩展名为 PHP 的 SQLite 数据库。安装程序到达站点配置表单时，Drupal 会将提交的网站名称存储在 SQLite 数据库中。如果使用 PHP 代码作为网站名称，则有效载荷字节会被写入 .php 数据库文件。虽然在标准的 Apache 部署中，Drupal 的标准 .htaccess 文件阻止了对生成的 PHP 文件的直接访问，但 Apache RewriteRule 中的路径处理漏洞可以被利用来实现任意 PHP 代码的执行。在 Drupal 中，临时数据库故障可能会导致 FAIL、FAIL，然后是 SUCCESS 序列，从而在现有网站上重新打开安装程序，并最终导致通过包含 PHP 代码的 SQLite 数据库进行身份验证前的远程代码执行。

使用付费的 Drupal Steward Web 应用程序防火墙 (WAF) 服务的网站已经受到已知攻击媒介的保护，但为了防止发现其他攻击媒介，仍然建议管理员升级到最新的 Drupal 版本。无法立即升级的用户应在 Web 服务器配置中阻止对 /core/install.php 的访问，或在 Web 根目录中阻止对 .htaccess 文件的访问，以确保 Drupal 安装程序的安全。

2.GeoServer WFS GetFeatureById XML 注入漏洞(CVE-2026-120705)&GeoServer 服务安全规则绕过漏洞(CVE-2026-129243)

11月25日，据 watchTowr 报道，威胁行为者正在积极利用 GeoServer 中两个新近修复的安全漏洞。

相关漏洞为 CVE-2026-120705 和 CVE-2026-129243，详情如下：CVE-2026-120705（CVSS 评分：8.6）- 任意文件读取漏洞，攻击者可以通过单个未经身份验证的 Web 要素服务 (WFS) 请求访问 GeoServer 进程可读的本地文本文件或获取攻击者选择的 HTTP 或 HTTPS URL。CVE-2026-129243（CVSS 评分：8.8）- 授权错误漏洞，可能允许未经身份验证的攻击者调用原本受服务安全规则保护的OWS操作。

该 RCE 攻击链涉及 CVE-2026-129244、CVE-2026-129243、CVE-2026-120705、CVE-2026-129245 和 CVE-2026-129242 共5个漏洞。攻击者可在未认证状态下先获取数据目录位置，再利用WFS服务名解析与授权规则不一致写入存储查询，借助XInclude解析读取安全配置文件，继而利用固定默认密钥构造管理员会话，最终通过管理员REST接口注册恶意JDBC用户服务并触发反序列化，实现任意命令执行。上述缺陷单独存在时，分别表现为路径信息泄露、访问控制绕过、本地文件读取、会话伪造及反序列化执行；其实际风险在于默认配置允许这些缺陷被同一攻击序列连续利用。尤其需要关注的是，JDBC用户服务本身要求管理员权限才能投递数据，而固定remember-me密钥恰好提供了伪造管理员会话的通道，使该执行入口在未认证条件下被实际打开。因此，仅修复其中任一环节虽可提高利用门槛，但不足以从整体上消除该组合利用风险。

GeoServer维护人员表示，攻击者如果通过任何文件泄露或数据目录副本获取了管理员密码摘要，就可以以该管理员身份登录。如果同样的文件泄露也暴露了密钥，那么更改 security/config.xml 中的密钥也无济于事。

Rapid7 的高级安全研究员 Jonah Burgess（网名CryptoCat）于2026年8月2日独立发现并报告了五步未经身份验证的远程命令执行链，并因此受到表彰。该研究人员表示，在 Web 要素服务 (WFS) 名称前添加前缀，例如 x/WFS，可以绕过仅管理员才能访问已保存查询的规则。GeoServer 将已保存查询中的转义文本转换为可访问的 xi:include 元素，从而泄露了包含“记住我”密钥和管理员密码摘要的文件。这两个值可以伪造管理员 cookie，而无需破解密码。攻击者以管理员身份将 JDBC 用户服务指向已上传的 HSQLDB 数据库，然后捆绑的驱动程序反序列化存储的值，该值会执行命令。

鉴于其中两个漏洞已被积极利用，建议用户尽快更新至上个月发布的 GeoServer 版本2.27.7、2.28.6和3.0.2 。

3.Hex 包管理器远程代码执行漏洞(CVE-2026-129514)

11月25日，据称一名攻击者在 Hex.pm 的六台生产服务器上执行了操作系统命令，Hex.pm 是 Elixir 和 Erlang 开发人员获取依赖项的软件包注册表。

此次攻击所利用的漏洞自2016年2月起就存在于注册表的代码中，维护该服务的团队在收到第一个恶意请求后约15分钟内就将所有服务器更新到了打过补丁的版本。此后进行的检查未发现任何软件包被篡改的迹象。该团队表示，不能排除攻击者读取了帐户数据（例如电子邮件地址、密码哈希值和双因素身份验证密钥）的可能性。

该漏洞编号为 CVE-2026-129514，CVSS 评分最高为10.0。它存在于 hex.pm 解析器中，该解析器用于读取以 Erlang 数据格式发送的请求体。该解析器在路由和身份验证之前运行，因此未经身份验证的 POST 请求可以到达网站上的任何地址。解码功能原本是安全的，它确实阻止了诸如函数之类的危险术语，但它接受带有 __struct__ 键的映射，这使得请求体可以伪装成应用程序已加载的任何 Elixir 结构体。2016年2月23日，代码中移除了原本可以阻止此漏洞的安全检查，因此该漏洞的出现时间可以追溯到那时。目前尚未发现在这之前有人利用过此漏洞。精心构造的结构体本身并不运行任何程序。它引发了一个错误，错误报告代码随后检查了该结构体。通过 Ecto 和 DBConnection 数据库库的检查，最终导致服务器调用了攻击者指定的一个函数，该函数随后以注册表服务帐户的权限执行操作系统命令。

Hex.pm 团队昨日在其事件报告中指出，负载均衡器日志记录了周一 18:16 至 18:29 UTC 期间的69次漏洞利用请求，全部来自两个地址。漏洞利用生成的文件出现在六台 Web 服务器上，其中一台服务器甚至在请求发出后仅3毫秒就出现了这些文件。其中三台服务器是在攻击过程中加入的，当时服务器重启后，仍然运行在存在漏洞的版本上的机器也被激活。为了检查软件包，团队将每个数据库表与首次攻击请求发生前两分钟的副本进行比对，并将每一处差异追溯到正常的活动。攻击期间发布的23个版本均与审计日志相符，没有旧版本被修改，当晚写入的软件包和注册表文件也与数据库记录一致。检查结果显示，审计日志中未发现残留的 shell 或新账户/云密钥。攻击者身份不明。团队表示，从上周晚些时候开始，这两个地址的活动表明攻击者可能构建了一个 hex.pm 的本地副本用于测试。

所有 hex.pm 账户持有者已被强制登出，因为维护者更换了用于签署会话和访问令牌的密钥。建议账户持有者采取以下步骤：1.立即 hex.pm 密码。2.通过设置新的身份验证器条目来重置双因素身份验证，并保存新的恢复代码。3.使用 mix hex.user auth 或对于 Erlang 项目，使用 rebar3 hex user auth 重新登录客户端。4.预计几天内发布下一个版本，届时将更新 Hex 客户端，引入新的注册表签名系统。5.谨防网络钓鱼。泄露的电子邮件地址可能被滥用，因此请检查所有关于 Hex 的电子邮件中的链接是否指向 hex.pm。

4.N-able MailAssure 服务器端请求伪造漏洞(CVE-2026-134624)

11月23日，N-able 披露了其在调查其 Mail Assure 和 SpamExperts Hosted Cloud（该公司为托管服务提供商运营的电子邮件过滤服务）的漏洞时发现的一个重大缺陷。

该漏洞编号为 CVE-2026-134624，是一个服务器端请求伪造 (SSRF) 漏洞。它允许拥有高级 API 访问权限的用户在平台服务器上打开与其选择的内部系统的连接。该公司于周六晚些时候修复了漏洞，恢复了对控制面板和 API 的访问，结束了从上周一开始的系统故障。据该公司称，邮件发送和垃圾邮件过滤功能在此期间一直正常运行。该公司尚未说明该漏洞是否是攻击者入侵的途径。

该漏洞存在于 Mail Assure 在配置中继时运行的 LDAP 同步连接检查中。在修复版本之前，该检查的目标地址没有任何限制，因此服务器可以指向任何内部主机和端口，以查看哪些主机和端口响应。该供应商的安全公告称，经过身份验证的 API 用户可以使服务器连接到任意内部主机和端口，确定哪些主机和端口可达，并将精心构造的数据发送到内部服务。该安全公告将该漏洞的 CVSS 4.0 评分为 9.3 分，并列出了 20261121.1943 之前的版本，修复程序也包含在该版本中。公告并未声称该漏洞会导致代码执行。

根据 N-able 的事件时间线，该公司上周一通知客户服务中断，并初步将中断原因追溯到平台配置和服务依赖关系。上周三，该公司表示，此次服务中断实际上是一起安全事件：未经授权的第三方访问了其托管云服务器之一。为安全起见，在调查期间，控制面板和 API 均已离线。

该公司采取的应对措施包括：将受影响的服务器下线，轮换内部平台凭证，撤销客户现有的 API 令牌，使 OAuth 令牌失效，以及重置本地用户的密码。该公司表示，自修复措施实施以来，尚未发现任何客户数据（包括租户邮箱）遭到泄露的证据，也没有发现除该服务器之外的其他利用迹象。

调查仍在进行中，该公司表示，此次数据泄露事件与 N-central 事件无关。在之前的 N-central 事件中，一名研究人员公布了33个未修复的漏洞后，该公司于11月9日关闭了其托管的远程监控平台。

对于托管客户而言，目前的工作重点是重新连接。使用已撤销的 API 令牌或 OAuth 令牌的脚本和集成需要新的凭据。托管平台本身已经打好了补丁，因此托管云用户无需安装任何东西。根据产品更新文档，SpamExperts Local Cloud 运行在客户的硬件上，并按周进行软件更新。事件声明仅描述了托管云，因此 Local Cloud 运营商应确认其服务器版本为 20261121.1943。

目前为止，该声明并未说明攻击者最初是如何入侵的，也未说明他们获取的任何凭证是否已被窃取。Mail Assure/SpamExperts 版本 20261121.1943 包含针对安全缺陷的补丁。

5.Cisco Expressway Series 远程代码执行漏洞(CVE-2026-76466)

11月23日，美国网络安全和基础设施安全局 (CISA) 警告联邦机构，攻击者目前正在利用思科 Expressway 系统中最近修复的一个严重漏洞。

Cisco Expressway 系列设备是企业协作网关（部署为虚拟机或物理硬件设备），通过安全连接将内部语音和视频系统与外部网络和远程用户连接起来。该安全漏洞编号为 CVE-2026-76466，其根源在于使用了硬编码凭据，并且未能完全验证客户端证书，这使得未经身份验证的攻击者能够以 root 用户身份远程执行集群中配置的受影响 Cisco Expressway-C 和 Cisco Expressway-E 设备上的任意操作系统命令。

思科在10月下旬发布安全补丁以解决该问题时表示，攻击者如果掌握了 cookie，就可以通过连接到数据库服务并调用特定的远程过程调用 (RPC) 命令来利用此漏洞。虽然思科表示其产品安全事件响应团队 (PSIRT) 尚未发现针对此漏洞的活跃利用或公开可用的概念验证漏洞利用，但 CISA 将其标记为已被活跃利用。

互联网情报公司 Censys 目前观察到近14,900台 Cisco Expressway 主机暴露在网络上，但尚无信息表明有多少台主机已经采取措施抵御针对 CVE-2026-76466 漏洞的攻击。

尽管 CISA 尚未分享有关这些持续攻击的细节，但俄罗斯网络安全公司 F6 表示，他们发现攻击者使用一个未命名的 AI 助手成功利用了 CVE-2026-76466 漏洞，并在暴露于互联网的 Cisco Expressway 设备上获得了具有完全 root 权限的远程命令执行能力。F6 安全研究人员指出，攻击者最初攻破了两台思科 Expressway 面向互联网的设备。通过其中一台设备，他们获得了对位于该组织内部网络上的另外两个集群节点的访问权限。在获得 root 权限后，攻击者开始准备工具，以便在基础设施中进行进一步的横向移动。他们使用自定义的 Python 脚本扫描网络，发现可访问的 SMB 资源，与 SQL Server 和 WinRM 交互，并探索 GitLab 存储库，以窃取凭据和其他敏感信息。

此次攻击尚未归因于任何已知的威胁行为者或组织。建议用户更新至最新受支持的 Cisco Expressway 版本，审核环境是否存在入侵迹象，隔离受影响的系统，确定攻击范围，并阻止潜在的横向移动路径。

F6 公司表示：“此次事件表明，一旦边界设备遭到入侵，攻击者就能通过该途径进入组织的关键系统。这意味着，防护措施不仅应包括及时修复漏洞，还应包括正确配置的网络分段和基础设施监控。”
