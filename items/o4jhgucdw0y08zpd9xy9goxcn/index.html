Linux 内核 CVE-2026-98432 可导致 MPTCP 服务器远程 root 提权

Critical Linux kernel flaw allows remote root attacks on MPTCP servers

AI 导读

Anthropic 研究人员利用 CVE-2026-98432 实现了针对启用 MPTCP 监听器的 Linux 服务器的远程 root 代码执行。该漏洞是 Linux 内核 IPv4 TCP 网络代码中的 use-after-free 与竞态条件问题，CVSS 9.8，也影响普通 TCP 连接；其利用需要触发竞态，Red Hat 将其评为 5.9 并认为可能导致内核崩溃。

正文 · AI 翻译
中文原文

Anthropic 的安全研究人员开发了一个针对 Linux 内核严重漏洞的利用程序。该漏洞允许未经身份验证的攻击者在运行 Multipath TCP (MPTCP) 侦听器的服务器上远程以 root 身份执行命令。

该缺陷的跟踪编号为 CVE-2026-98432，也会影响普通 TCP 连接，不过目前尚未在未启用 MPTCP 侦听器的服务器上公开演示远程代码执行。

Multipath TCP (MPTCP) 是一项 TCP 功能，允许单个连接同时使用多条网络路径，以提升性能和可靠性。它常用于设备具有多个网络连接的环境，例如 Wi-Fi 和蜂窝网络。

CVE-2026-98432 是内核 IPv4 TCP 网络代码中的释放后重用漏洞，Linux 内核 CVE 团队将其严重性评分定为 10 分中的 9.8 分。

该漏洞影响可追溯至 4.4 版本的 Linux 内核，包括 Ubuntu、Red Hat Enterprise Linux (RHEL) 和 Rocky Linux 等广泛使用的发行版。

根据 Linux 内核公告，该漏洞源于内核处理 TCP 连接请求时出现的竞态条件，可能导致释放后重用状态。

公告写道：“tcp_v4_syn_recv_sock() 将 ireq->ireq_opt 的所有权转移给子套接字（newinet->inet_opt），但未对其进行复制。”

“另一个 CPU 可以并发处理同一请求套接字重传的 SYN，并从 tcp_check_req() 发送 SYNACK。tcp_v4_send_synack() 和 inet_csk_route_req() 仅在 rcu_read_lock() 下读取 ireq->ireq_opt，随后 ip_build_and_send_pkt() 和 ip_options_build() 会两次读取 opt->optlen。”

启用 net.ipv4.tcp_migrate_req 或使用 BPF_SK_REUSEPORT_SELECT_OR_MIGRATE 程序时，TCP 请求套接字迁移期间也可能出现类似问题。

尽管触发该漏洞不需要身份验证，但 Red Hat 表示，利用该竞态条件比单纯发送恶意网络数据包要复杂。

Red Hat 将该漏洞归类为可能导致内核崩溃的潜在拒绝服务问题，并因其利用过程复杂而给出了较低的严重性评分 5.9。

然而，Anthropic 的研究人员演示了在特定条件下可利用该漏洞实现远程代码执行。

一份 Anthropic 报告解释道，一个尚未发布的 Claude AI 模型开发出了一种可绕过内核地址空间布局随机化 (KASLR) 的利用程序，并在运行 MPTCP 侦听器的 Linux 服务器上以 root 身份执行了任意命令。

据 Anthropic 称，该利用程序大约用了 53 分钟实现远程 root 代码执行，表明该漏洞的利用方式不止拒绝服务攻击。

虽然应用程序通常默认不启用 MPTCP，但某些软件会自动启用它。

从 Go 1.24 开始，只要内核支持该功能，这种编程语言就会默认为 Linux 上的 TCP 侦听器启用 MPTCP。因此，一些基于 Go 的网络服务可能在管理员不知情的情况下启用 MPTCP 侦听器。

Linux 发行版开始发布补丁

该漏洞已在上游 Linux 内核中修复，并向后移植到仍受维护的内核分支。不过，安全更新尚未推送到所有受影响的 Linux 发行版。

根据Canonical 的安全跟踪器，截至 10 月 30 日，Ubuntu 22.04 LTS、24.04 LTS、26.04 LTS 和 26.10 仍存在漏洞，相关内核修复仍在进行中。

Red Hat 也将 RHEL 8、9 和 10 列为受影响版本，并计划在未来更新中提供修复。RHEL 7 不受影响，因为其内核不包含存在漏洞的代码。

在缓解指导中，Rocky Linux 支持服务提供商 CIQ 确认 Rocky Linux 8、9 和 10 也受到影响，并为受影响的系统分享了临时的防火墙防护措施。

根据Debian 的安全跟踪器，该漏洞已在 Debian 12（Bookworm）的内核软件包版本 6.1.190-1 和 Debian 13（Trixie）的版本 6.12.113-1 中修复。Debian testing 和 unstable 也已提供修复软件包。

包括 Oracle Linux、Amazon Linux 和 SUSE 在内的其他 Linux 供应商，也已为部分受影响的内核版本发布修复。

该漏洞不影响 macOS，因为 macOS 使用的是 Apple 的 XNU 内核，而非 Linux 内核。

建议管理员查看其发行版的安全公告，并在更新后的内核软件包可用时进行安装。

对于尚未提供补丁的系统，限制对可信网络或 IP 地址的访问可以降低风险。

CIQ 还建议临时阻止包含 IP 选项的 IPv4 TCP 数据包到达存在漏洞的 TCP 处理代码，并分享了可用于阻止此类流量的 nftables 规则示例。

该公司警告称，仅禁用 MPTCP 并不足够，因为底层漏洞仍可通过普通 TCP 流量触发。

目前没有已确认的 CVE-2026-98432 在野利用报告。

攻击者一旦获得有效凭据，其行为仅有 37% 会被阻止

整体预防评分可能掩盖初次访问之后发生的情况。攻击者一旦开始使用有效凭据，预防效果就会大幅下降。

Blue Report 2026 在客户生产环境中运行的 3.38 亿次模拟中，逐项衡量了各项防御措施。
