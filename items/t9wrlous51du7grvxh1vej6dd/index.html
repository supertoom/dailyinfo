CERT/CC 披露 macOS APFS Unicode 归一化碰撞漏洞 VU#604762

VU#604762: Multiple vendors vulnerable to Unicode Normalization Collision on macOS (APFS)

AI 导读

CERT/CC 披露多个软件在 macOS APFS 上因路径归一化处理不一致而存在 Unicode 碰撞漏洞，本地攻击者可借助 ß 与 ss 等替代拼写绕过文件排除规则，覆写进程有权限写入的文件，进而造成数据损坏、配置劫持或代码执行。

正文 · 原文

Overview

A mismatch between Apple File System (APFS) filesystem and path resolution for multiple applications allows attackers to bypass security exclusions using alternative Unicode spellings. By supplying an alternative Unicode spelling or case-folded variant (such as ß versus ss) that bypasses the application's file write checks, a local attacker can overwrite files wherever the process has write permissions, potentially leading to data corruption, configuration hijacking, or code execution. Multiple vendors have assigned CVEs and issued patches to address this flaw.

Description

Several archive tools, packaging systems, and runtimes enforce exclusion filters using pathname comparisons that do not match the underlying filesystem's resolution behavior.
By using a byte-for-byte comparison (such as ß versus ss), rather than full case folding, a vulnerable application can be tricked into silently overwriting protected files. This vulnerability exposes backup tools, forensic workflows, and CI/CD pipelines to unauthorized file modification.

The CVEs assigned during coordination are as follows:

CVE-2026-14978
HashiCorp go-slug could allow an attacker with local filesystem access to bypass .terraformignore exclusions and cause sensitive files to be included in Terraform slug uploads due to improper handling of Unicode normalization during path matching.

CVE-2026-49401
Denos permission system enforces filesystem and execution restrictions by comparing the requested path against the path supplied to --deny-read, --deny-write, --deny-run, or --deny-ffi. On macOS, those comparison were performed using raw-byte pathname matching while the APFS filesystem treats different Unicode spellings of the same name as the same file.

CVE-2026-45110
Libarchive contains a file overwrite bypass and a directory exclusion bypass, which could allow an attacker to add a file, such as password\u### to an archive. The Apple File System will treat the file as /etc/passwd and silently overwritten.
The fix is pending release.

CVE-2026-59890
setuptools is a package that allows users to download, build, install, upgrade, and uninstall Python packages. Prior to 83.0.0, FileList applied MANIFEST.in exclude, global-exclude, recursive-exclude, and prune directives by matching compiled glob patterns against on-disk file names without Unicode normalization, so on macOS APFS or HFS+ an NFD file name could bypass an NFC exclusion rule and be packed into a source distribution. This issue is fixed in version 83.0.0.

VU#604762.8
VU# 604762.8 is a general tracking for this type of flaw.
Multiple vendors are vulnerable to an incomplete handling of Unicode path collisions. On case-insensitive or normalization-insensitive filesystems (such as macOS APFS) the library fails to lock colliding paths (e.g., ß and ss), allowing them to be processed in parallel.

Impact

Local attackers can bypass file exclusion filters or path locks during archive extraction to overwrite files anywhere the process has write permissions, potentially leading to data corruption, configuration hijacking, or code execution. This risk extends to supply chain workflows, where the failure to correctly exclude items can result in the inadvertent inclusion of sensitive files in distributed artifacts or the corruption of CI/CD build steps.

Solution

The CERT/CC recommends updating affected softwares to the latest version.

Remediation Guidance
Developers should implement path validation that accounts for the underlying filesystem's normalization behavior rather than relying on byte-for-byte comparisons. Ensure that all security filters use path formats that match the resolution logic used by the operating system.
