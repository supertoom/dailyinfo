CERT/CC 披露 macOS APFS Unicode 路径碰撞漏洞，影响 HashiCorp go-slug、Deno、Libarchive 和 setuptools

VU#604762: Multiple vendors vulnerable to Unicode Normalization Collision on macOS (APFS)

AI 导读

CERT/CC 披露多个软件因未正确处理 APFS Unicode 路径碰撞而存在文件覆盖与排除规则绕过问题，攻击者可在本地利用替代拼写或大小写折叠变体覆盖进程有权限写入的文件，影响数据、配置甚至代码执行。

值得关注

公告梳理了 APFS 路径解析与多款软件校验逻辑不一致的成因，并列出受影响项目、修复版本及跨平台防护思路。

中文原文

概述

Apple File System (APFS) 文件系统与多个应用程序的路径解析之间存在不一致，攻击者可使用替代的 Unicode 拼写绕过安全排除规则。通过提供可绕过应用程序文件写入检查的替代 Unicode 拼写或大小写折叠变体（例如 ß 与 ss），本地攻击者可以覆盖进程具有写入权限的任何位置的文件，可能导致数据损坏、配置劫持或代码执行。多个供应商已分配 CVE 并发布补丁来修复此缺陷。

描述

若干归档工具、打包系统和运行时使用路径名比较来执行排除过滤器，而这种比较方式与底层文件系统的解析行为不一致。
通过使用逐字节比较（例如 ß 与 ss），而不是完整的大小写折叠，可能诱使存在漏洞的应用程序悄无声息地覆盖受保护的文件。此漏洞使备份工具、取证工作流和 CI/CD 管道面临未经授权的文件修改风险。

协调期间分配的 CVE 如下：

CVE-2026-14978
HashiCorp go-slug 可能允许具有本地文件系统访问权限的攻击者绕过 .terraformignore 排除规则，由于在路径匹配期间不当处理 Unicode 规范化，导致敏感文件被包含在 Terraform slug 上传中。

CVE-2026-49401
Denos 权限系统通过将请求的路径与提供给 --deny-read、--deny-write、--deny-run 或 --deny-ffi 的路径进行比较来执行文件系统和执行限制。在 macOS 上，这些比较使用原始字节路径名匹配，而 APFS 文件系统则将同一名称的不同 Unicode 拼写视为同一个文件。

CVE-2026-45110
Libarchive 包含文件覆盖绕过和目录排除绕过漏洞，攻击者可能借此向归档文件中添加文件，例如 password\u###。Apple File System 会将该文件视为 /etc/passwd 并悄无声息地覆盖。

CVE-2026-59890
setuptools 是一个允许用户下载、构建、安装、升级和卸载 Python 包的软件包。在 83.0.0 之前，FileList 通过将编译后的 glob 模式与磁盘上的文件名匹配且不进行 Unicode 规范化，来应用 MANIFEST.in 的 exclude、global-exclude、recursive-exclude 和 prune 指令，因此在 macOS APFS 或 HFS+ 上，NFD 文件名可以绕过 NFC 排除规则并被打包进源代码分发版。此问题已在 83.0.0 版本中修复。

VU#604762.8
VU# 604762.8 是对此类缺陷的总体跟踪记录。
多个供应商容易受到 Unicode 路径冲突处理不完善的影响。在大小写不敏感或不敏感规范化的文件系统（例如 macOS APFS）上，该库未能锁定冲突路径（例如 ß 和 ss），从而允许并行处理这些路径。

影响

本地攻击者可以在解包期间绕过文件排除过滤器或路径锁，覆盖进程具有写入权限的任何位置的文件，可能导致数据损坏、配置劫持或代码执行。此风险还波及供应链工作流，其中未能正确排除项目可能导致敏感文件被意外包含在分发制品中，或导致 CI/CD 构建步骤遭到破坏。

解决方案

CERT/CC 建议将受影响的软件更新至最新版本。

修复指南
开发者应实施路径验证，考虑底层文件系统的规范化行为，而不是依赖逐字节比较。确保所有安全筛选器使用的路径格式与操作系统所用的解析逻辑一致。

致谢

感谢报告者 Tomas Illuminati（网络安全研究员兼威胁情报分析师）。本漏洞说明由 Christopher Cullen 撰写。CERT/CC 和报告者 Tomas Illuminati 感谢各个项目的维护者迅速采取行动解决了这些问题。
