自 2026 年 11 月 11 日起，ConnectWise 报告称，有一个威胁行为体正在积极发起攻击活动，未授权访问托管服务提供商（MSP）拥有的云托管 ConnectWise ScreenConnect 实例。Microsoft Threat Intelligence 已确认 ConnectWise 报告的活动，并且我们还观察到威胁行为体滥用 ScreenConnect 这一合法的远程支持应用程序，在 ConnectWise 客户管理的端点上安装未经授权的远程访问客户端，并部署恶意蠕虫 SCKit。

此外，Microsoft 分析了这款恶意蠕虫的行为：部署过程首先通过 ScreenConnect 发出命令，静默安装一个连接到威胁行为体控制基础设施的同类客户端。一个批处理启动器会获取 PowerShell 解码器，使用特定于设备的密钥材料解密并提取 SCKit。该工具包通过计划任务和注册表 Run 项建立持久化，并部署 RelayTrap——这是一个旨在向连接的技术人员投递恶意载荷的组件。

我们发现，该蠕虫利用被劫持且通过身份验证的 ScreenConnect 会话 targeting IT 支持技术人员的工作站，并使用受害者的管理控制台向其他受管设备分发载荷。由此获得的访问权限，无论针对哪个目标，都使威胁行为体能够独立于合法的支持实例远程管理受影响端点、执行命令并部署更多工具。

防御人员应调查技术人员工作站以及下游受影响端点。仅移除未经授权的客户端并不能移除该工具包的持久化机制，也无法使已暴露的 Web 会话失效。在本博客中，我们 examines SCKit 的攻击链和载荷组件，并提供缓解指南、失陷指标以及 Microsoft Defender XDR 高级搜寻查询，帮助组织识别并阻断此类活动。

ScreenConnect 架构与攻击面

ScreenConnect（原名 ConnectWise Control）是一个远程支持和访问平台，MSP 通常将其与远程监控和管理（RMM）软件配合使用，以管理客户设备。其运行模式由三个部分组成：

  • 管理实例。 云托管或本地部署的 ScreenConnect 服务器提供 Web 控制台并管理会话。其中继服务负责承载技术人员与端点客户端之间的通信。
  • 技术人员工作站。 支持人员通过浏览器登录控制台，并启动本地主机客户端以进行交互式支持。
  • 客户端点。 已安装的客户端（或访问）客户端维持无人值守访问，并执行通过 ScreenConnect 传递的命令。

Access 会话通过已安装的客户端提供持久、无人值守的访问。Support 会话则是最终用户为获得协助而加入的临时连接。ScreenConnect 还支持通过 Web 控制台执行远程命令，无需交互式技术人员会话。端点客户端接收命令并在客户设备上运行；技术人员工作站并非该执行过程的中介。

据报道可通过扩展实现服务器端入侵

扩展是安装在 ScreenConnect 服务器上的插件，用于添加功能或与其他产品集成，包括工单系统和 RMM 工具。ConnectWise Automate 之前名为 LabTech；Labtech Plus 是一个第三方扩展，并非 Automate 产品本身。RMM+ 扩展系列公开了远程命令 API，这些 API 由单独配置的口令保护，而不是由技术人员的正常控制台登录凭据保护。

ConnectWise 的公告描述了 RMM+ 1.0.31 和 1.0.32 版本中据报道存在的一个身份验证缺陷：未配置访问密钥时，该扩展会接受空密钥。在这种配置下，未经授权的调用者可以向服务器的 API 提交命令，并将其发送至受管理端点，无需进行正常的 ScreenConnect 用户登录。ConnectWise 正在调查扩展滥用作为初始访问途径；据报道的攻击活动所采用的入口方法仍在调查中。

从客户端点到技术人员的另一条路径

SCKit 是一种恶意软件工具包，其中包含 RelayTrap——这是受影响客户端点上 ScreenConnect 客户端的恶意替代品。RelayTrap 旨在技术人员为提供支持而连接时，将有效载荷交付到技术人员的工作站。ConnectWise 表示，CVE-2026-84869 的修复措施阻止了该工具包试图从端点扩散至技术人员的活动。这条客户端攻击路径与用于部署 SCKit 的服务器端访问路径相互独立。

攻击链概览

下面的部署序列在客户端点上运行。它建立一条独立的远程访问连接，并准备用于针对后续技术人员的脚本和 RelayTrap 组件

1. ScreenConnect 命令安装附加客户端

威胁行为者使用 MSP 的 ScreenConnect 管理实例，指示已安装的端点客户端启动 cmd.exe。该本地进程调用 curl.exe，通过 HTTP 从攻击者控制的 ScreenConnect 服务器下载 MSI。该命令请求 /Bin/ScreenConnect.ClientSetup.msi，并附带访问会话参数和 c=Exploited<N> 标记（所示命令中为 c=Exploited9），然后将安装程序保存至 C:\Windows\Temp\sc.msi。

随后，Windows Installer 使用 /i、/qn 和 /norestart 在该端点上静默安装该软件包，且不重启端点。新增客户端连接到攻击者控制的 ScreenConnect 实例，从而建立一条独立于 MSP 认可实例的远程访问通道。仅保护对合法控制台的访问，并不会移除这个附加客户端或其连接。

2. 批处理启动器获取 PowerShell 解码器

在客户终端上执行更多命令来暂存该工具包。一条 PowerShell 命令对 URL 安全的 Base64 字符串进行解码，并将结果写入 Windows Temp 目录中的批处理文件。该批处理将 BATPATH 设置为其自身所在位置，从 ns[.]mo7sen[.]dev/EadF.php?p=4 下载解码器，并使用 -Mode full 启动它。

解码器读取 BATPATH；如果不存在，则回退到 SCKIT_SELF，以定位启动器。其隐藏重新启动分支会创建一个 VBScript 包装器，并通过 wscript.exe 运行该包装器，以在无可见窗口的情况下启动同一个批处理文件。

3. 解码器解密并提取 SCKit 捆绑包

解码器从 HKLM\SOFTWARE\Microsoft\Cryptography 读取 MachineGuid，并将其作为 m 请求参数一并发送。响应会提供一个 Base64 编码的正文以及两个标头 X-Lab-Half 和 X-Lab-Salt。

为了派生解密密钥，解码器使用 SHA-256 对 UTF-8 机器标识符进行哈希，将该哈希与从 X-Lab-Half 解码得到的 32 字节进行异或运算，并将机器标识符字节追加到恢复出的秘密材料中。随后，PBKDF2-HMAC-SHA256 使用响应中的盐和 4,096 次迭代派生出一个 32 字节密钥。

解码器使用解码后响应正文的前 16 字节作为初始化向量（IV）。它使用带 PKCS7 填充的 AES-256-CBC 解密其余字节，使用 GZip 解压缩明文，并写出生成的 ZIP 归档文件。随后，该归档文件会被解压到 %TEMP%\SCKitBundle。

在完整模式下，解码器会准备 %TEMP%\SCKit\trapkit\payload，并暂存 watcher、installer、alert 脚本和 RelayTrap.cs。它还会将自己的批处理启动器复制到 payload 目录中，供 RelayTrap 分发。复制后的启动器会获取解码器并启动工具包部署。

解码器还会暂存 ToolboxRelayUploader.exe，以通过控制台分发 payload；如果没有合适的副本，它会获取 sqlite3.exe，用于查询浏览器 Cookie。它包含两条启动路径：完整模式在不依赖单独配置文件的情况下启动分发脚本，并提供本地脚本路径；另一条路径则暂存一个辅助脚本和 lab-context.json，并传入 -SkipLocalExecution。

4. 其他组件：PowerShell 脚本加载器

除捆绑包解码器外，SCKit 还包含一个用于加载加密 PowerShell 脚本的独立加载器。与负责获取并展开归档文件的解码器不同，该组件使用 p=1 和机器标识符请求脚本。它采用相同的秘密恢复、PBKDF2、AES-CBC 和 GZip 操作，但使用其源代码中嵌入的盐，而非响应标头提供的盐。

解压后，加载器将这些字节转换为 UTF-8 文本，并写入 %TEMP%\k<32-hex>.ps1，文件名使用新生成的随机 GUID。它启动一个隐藏的 PowerShell 进程，使用转发的参数运行该文件，然后在子进程退出后尝试删除脚本。

5. RelayTrap 添加持久化机制并针对连接的技术人员

在客户端终端上，持久化机制确保该工具包可供后续支持连接时使用。部署过程将脚本放置在 C:\ProgramData\RelayTrap 下。计算机级 CurrentVersion\Run 键中的 RelayTrapLiteAlert 值会在用户登录时启动警报脚本。一个计划任务会使用有效载荷文件名、客户端标识符列表以及要排除的中继主机列表来启动监视器。-PollSeconds 10 参数将监视器配置为每 10 秒轮询一次。

监视器枚举 ScreenConnect 客户端服务，并读取其可执行文件路径和连接参数。对于每个客户端，其构建例程会在 trapbins 下创建一个目录，从该客户端的安装目录复制库，并使用 .NET C# 编译器构建 RelayTrap.exe。它会在重建前检查源代码或客户端库是否发生变化。

RelayTrap 的设计方式是使用客户端终端的 ScreenConnect 连接详情来替代其常规客户端。当技术人员使用存在漏洞的主机客户端进行连接时，RelayTrap 会尝试通过该会话交付已暂存的批处理启动器。该启动器获取相同的解码器，将该工具包的部署设计从客户端设备扩展到技术人员工作站。已配置的跳过列表会将指定的客户端标识符和中继主机排除在处理范围之外。

ScreenConnect 服务也被配置为自动启动。注册表写入操作针对 Microsoft Defender Antivirus 的路径排除项，以排除已暂存的 MSI 副本和 CWInstall_…\Installer.ps1。安装程序配置将 sc[.]payproofkit[.]com 和 cdn007-digitaldownloads[.]com 列为额外的 ScreenConnect MSI 来源。随后的 curl.exe 命令会从 sc[.]payproofkit[.]com 下载另一个客户端安装程序。

6. 浏览器访问针对已认证的 ScreenConnect 会话

SCKit 还会针对技术人员用于登录管理控制台的浏览器。浏览器访问代码会在 Chrome、Edge、Opera 和 Opera GX 配置文件中搜索名为 .ASPXAUTH 的 Cookie。其数据库路径会识别关联主机并查询加密的 Cookie 值。它会复制 Cookie 数据库及其支持文件，并在数据库被锁定时使用卷影复制作为回退方案。解密代码会在当前用户上下文中使用 Chromium 主密钥和 Windows 数据保护 API (DPAPI)，并通过 AES-GCM 例程处理 v10 和 v11 Cookie 值。

内存扫描路径首先检查命令行中标识为 network.mojom.NetworkService 的浏览器网络服务进程。一个嵌入式 C# 扫描器使用 OpenProcess、VirtualQueryEx 和 ReadProcessMemory，检查可读的已提交内存区域，查找 Cookie 字符串及附近的主机字符串。如果初始扫描未找到候选项，它会扫描其他浏览器进程。

控制台分发组件旨在将身份验证 Cookie 与所需的防伪令牌和访问令牌结合，枚举可访问的会话，使用 ToolboxRelayUploader.exe 上传有效载荷，并通过共享 Toolbox 排队执行。该工作流还包括在分发后删除已上传的 Toolbox 项目。

此组件针对的是技术员对管理控制台的访问权限，而不只是最初客户设备。该账户的权限决定了分发工作流可以访问哪些其他会话和设备。

7. 清理和重新部署

该工具包的清理脚本会在陷阱目录中放置停止标记。它会删除与陷阱相关的任务、服务、进程、Run 项和文件，并恢复 ScreenConnect 客户端服务，除非请求删除客户端。随后，它会删除任何剩余的停止标记，以允许新部署的观察程序运行。

运行清理脚本后，除非设置 -NoReArm，解码器的清理模式会再次启动捆绑的投放器。因此，清理也可用作重新部署工具包的途径。

缓解和保护指南

保护 ScreenConnect 管理控制台和技术员客户端

应分别处理服务器端扩展 API 和技术员客户端。扩展身份验证与客户端文件传输是不同的攻击面；保护其中一个并不会消除另一个攻击面，也不会消除已有的端点安装。

  • 保持已识别扩展处于禁用状态。 按照供应商公告处理 Labtech Plus、RMM Plus、RMM+、RMM Plus Password Link 和 RMM+ Password Link。应结合管理访问权限，审查这些扩展的安装和配置历史。
  • 单独更新技术员客户端，而非控制台。 ConnectWise 表示，ScreenConnect 客户端 26.6.5 及更高版本会阻止该工具包尝试使用的端点到技术员传输技术。CVE-2026-84869 的修复已于 2026 年 9 月 8 日发布。务必核实每个技术员客户端的安装版本；更新云控制台不会自动更新这些客户端。供应商公告还说明，在等待更新期间应实施临时文件传输限制。

移除已建立的访问权限

  • 通过独立渠道开展调查。 对于疑似受影响的设备，请使用 Microsoft Defender for Endpoint 实时响应或其他经批准的带外方法，而不是 ScreenConnect。隔离受影响的端点，并将连接这些端点的技术员工作站纳入调查范围。
  • 保存控制台和端点证据。 保留扩展、身份验证、Run Command 和 Toolbox 记录，并一并保留进程、文件、任务和注册表历史。审查 Toolbox 历史记录中在使用后被删除的工具，并在重新连接设备前检查已排队的命令和工具。
  • 从干净设备撤销已暴露的会话。 使受影响的 ScreenConnect Web 会话及相关身份提供商会话失效，轮换已暴露的凭据，并审查账户和权限。仅更改密码无法处理每个现有会话。
  • 移除持久化和未经批准的客户端。 在移除每个客户端之前，验证其注册的实例和中继目标。通过经批准的响应工具移除恶意任务、Run 值、trap 文件和未经授权的排除项。不要将从工具包中恢复的清理脚本用作补救工具。
  • 在恢复网络连接之前验证完整状态。 确认经批准的服务和目标、生效的防病毒设置，以及不存在重新创建的任务或脚本。调查排除项变更时，审查防篡改保护事件。如果无法确认完整性，请重建设备。

保持 Microsoft Defender Antivirus、云交付保护和防篡改保护处于启用状态。验证设备符合防病毒排除项保护要求。维护经授权的远程管理实例清单，并使用应用程序控制来限制未经批准的软件。

与攻击活动基础设施的连接

查找与所列域名和 IP 地址的连接。审查每个匹配项的完整目标、发起进程以及经批准的远程支持基础设施。

DeviceNetworkEvents
| where Timestamp > ago(14d)
| where RemoteUrl has_any (
    "ns.mo7sen.dev", "sc.payproofkit.com",
    "newnewnew.gotdns.org", "soxnewwork.homedns.org",
    "cdn007-digitaldownloads.com")
    or RemoteIP in ("185.99.255.28", "155.94.150.39")
| project Timestamp, DeviceId, DeviceName, RemoteUrl, RemoteIP,
    InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId

| where Timestamp > ago(14d)
| where ProcessCommandLine contains "/EadF.php"
    or ProcessCommandLine contains "SCKit"
    or ProcessCommandLine contains "RelayTrap"
    or ProcessCommandLine contains "Panel-Lateral"
    or ProcessCommandLine contains "ToolboxRelayUploader"
    or ProcessCommandLine contains ".ASPXAUTH"
    or ProcessCommandLine contains "c=Exploited"
| project Timestamp, DeviceId, DeviceName, FileName,
    ProcessCommandLine, InitiatingProcessFileName, ReportId

已知安装程序、归档文件和上传器文件

通过 SHA-1 哈希查找与 sc.msi 安装包、暂存 ZIP 文件及上传器对应的文件事件。该查询使用 SHA-1，是因为 SHA256 在 DeviceFileEvents 中通常未填充数据。请将哈希匹配项与命令行和持久化发现结合分析。

DeviceFileEvents
| where Timestamp > ago(14d)
| where SHA1 in~ (
    "0be01e7bd69cfdd222645d49bb5ad9961372fef2",
    "3f81c9c874a896c46e4bccea2fad2eaa3d9f2054",
    "13ce33b19daee3963f7e15d461b191c38f6bc0d3")
| project Timestamp, DeviceId, DeviceName, FileName, FolderPath,
    SHA1, InitiatingProcessFileName, ReportId

引用 RelayTrap 的注册表值

查找对 RelayTrapLiteAlert 值或包含 RelayTrap 的值的写入操作。审查注册表项、值数据和发起进程。

DeviceRegistryEvents
| where Timestamp > ago(14d)
| where ActionType == "RegistryValueSet"
| where RegistryValueName =~ "RelayTrapLiteAlert"
    or RegistryValueData contains "RelayTrap"
| project Timestamp, DeviceId, DeviceName, RegistryKey,
    RegistryValueName, RegistryValueData,
    InitiatingProcessFileName, ReportId

RelayTrap 计划任务事件

查找包含 RelayTrap 或 TrapWatch 的计划任务事件。检查任务定义以确定其触发器、可执行文件和参数。

DeviceEvents
| where Timestamp > ago(14d)
| where ActionType contains "ScheduledTask"
| where AdditionalFields contains "RelayTrap"
    or AdditionalFields contains "TrapWatch"
| project Timestamp, DeviceId, DeviceName, ActionType,
    AdditionalFields, InitiatingProcessFileName, ReportId

Microsoft Defender Antivirus 路径排除写入操作

查找 Microsoft Defender Antivirus 路径排除注册表写入操作。审查涉及 Windows Temp、ConnectWiseControl_、CWInstall_ 或 RelayTrap 的更改，并核实其授权情况及生效策略。

DeviceRegistryEvents
| where Timestamp > ago(14d)
| where ActionType == "RegistryValueSet"
| where RegistryKey contains @"\Windows Defender\Exclusions\Paths"
| project Timestamp, DeviceId, DeviceName, RegistryKey,
    RegistryValueName, RegistryValueData,
    InitiatingProcessFileName, ReportId

SCKit – 生成的 PowerShell 加载器工件

识别与 SCKit 加载器生成的 k<32-hex>.ps1 命名模式匹配的临时 PowerShell 文件，从而有可能在已知文件哈希或基础设施之外揭示已暂存的载荷。

DeviceFileEvents
| where Timestamp > ago(30d)
| where FileName matches regex @"(?i)^k[0-9a-f]{32}\.ps1$"
| project Timestamp, DeviceId, DeviceName,
ActionType, FileName, FolderPath, SHA256,
InitiatingProcessFileName
