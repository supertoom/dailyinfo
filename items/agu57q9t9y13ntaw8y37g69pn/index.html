Chainalysis 遭 Agentic 攻击暴露全部用户凭据并关闭关键服务

Chainalysis Breach Exposes All Users' Credentials, Forces Shutdown of Key Services

AI 导读

Chainalysis 调查针对其系统的持续 Agentic 网络攻击时发现，全部用户的姓名、用户名、密码哈希和有效令牌均被暴露，公司因此关闭 KYT 用户界面、API、地址筛查产品及登录页并锁定受影响账户。

正文 · AI 翻译
中文原文

区块链分析公司 Chainalysis 披露，其针对自身系统所遭受的智能体式网络攻击的持续调查，还暴露了所有用户的姓名、用户名、密码哈希和实时令牌。

该公司表示：“在调查期间，我们切断了对 Reactor 和 Data Solutions 的访问。目前，我们仍无证据表明任何调查数据已被访问，或 Chainalysis 归因数据遭到篡改。”

Chainalysis 表示，已部署额外的主动监控系统来检测异常活动，并下线了 KYT（了解您的交易）用户界面和 API，以及其他地址筛查产品和登录页面。

此前，Chainalysis 表示正在调查其所谓的“持续多路网络攻击”，并由此发现了一起“路径上的攻击”，导致部分客户密码泄露。公司表示，此后已处理该攻击向量。

出于格外谨慎，Chainalysis 还采取了锁定受影响账户的措施。

公司指出：“对于刚刚收到我们发送的、要求重置 Chainalysis 密码的电子邮件的客户，目前无法重置该密码。在必要的情况下，我们仍建议您在可能重复使用凭据的其他系统上重置密码。”

这一事件发生在 Chainalysis 表示自己成为一起网络安全事件目标后不到一周。该事件中，外部行为者利用攻击性智能体技术，未获授权地访问了其系统和内部工具。

该公司表示，计划开始恢复 KYT 和地址筛查服务的访问，并敦促客户联系其支持邮箱（support@chainalysis.com）或 Chainalysis 客户团队，提供可信的 IP 地址，这些地址将被加入允许名单。随后，用户可以重置密码并轮换 API 密钥，以注册交易。

Chainalysis 表示：“我们正日夜不停地加固系统，并让 Reactor 和 Data Solutions 恢复上线。我们将要求采取额外措施来访问账户，包括每位用户都必须重置密码，并酌情轮换 API 密钥。我们将视需要就这些变更进行通知。”

目前尚不清楚攻击者是谁，但 Chainalysis 表示，此次攻击与“最近几周许多其他技术平台遭受的攻击相似”。

与 AI 相关的攻击增加

事实上，包括 Chainstack、OpenCode、Warp 和 WorkOS 在内的多家公司均披露遭到过人工智能（AI）驱动的攻击，其中一些攻击涉及名为 ARTEX 的自主渗透测试工具。

据 Microsoft 称，威胁行为者正在使用智能体式 AI 攻击框架，在多个应用和云服务的公开 GitHub 仓库中搜索暴露的机密信息，例如凭据、应用程序凭据以及与 AI 推理相关的 API 密钥，以开展后续攻击。

这家科技巨头表示：“诸如 ARTEX 这样的智能体工具，不仅让威胁行为者能够更快地扫描多个仓库中的机密信息，还能利用智能体分析输出并开展后续攻击，从而减少威胁行为者在整个攻击链中亲自操作键盘交互的需要。”

至少在一个案例中，据称有一个 AI 代理从扫描 GitHub 以寻找机密信息，到在五分钟内从 Azure Key Vault 外泄数据。活动评估显示，自 2026 年 8 月起仍在持续。

该活动的部分方面符合后渗透活动特征，包括滥用有效的应用程序凭据，以访问某些组织的 Microsoft Entra ID 租户以及与其连接的 Azure 和 Microsoft 365 资源。登录事件来自两个 IP 地址：199.19.77[.]84 和 199.19.77[.]18。

Microsoft 表示：“该代理成功在多个租户中数十个关联应用程序上进行了服务主体登录。”

Microsoft 表示：“威胁行为者 targeting 了会返回凭据的操作，包括存储帐户密钥、App Service 设置、连接字符串和发布凭据、AI 和机器学习（ML）连接和数据存储，以及 Azure Kubernetes Service（AKS）用户凭据。遭入侵的应用程序随后访问了目标组织租户中的 SharePoint 和 OneDrive，包括下载文件和访问邮箱项目。”

此外，据观察，该威胁行为者还试图窃取 Azure 资源，包括遭入侵的 Azure AI 服务，这可能是为了推动更广泛攻击活动的一部分。

该活动的另一个显著方面是，代理式 AI 工具被发现会先获取目标组织内一个单租户 OAuth 应用程序的令牌，然后使用遭入侵的 OAuth 应用程序枚举该组织内的其他云资源。Microsoft 表示，在少数情况下，其观察到这些代理从该组织的 Azure Key Vault 外泄机密。

Microsoft 表示：“在此活动期间，AI 代理反复表现出对可提供 AI 服务访问权限的凭据的关注，例如主要 AI 服务提供商的 API 密钥，以及可访问 Foundry Tools（此前称为 Azure Cognitive Services）的 OAuth 应用程序。”

这一发展还与过去一个月针对 AI 开发平台的攻击激增同时发生，这些攻击使威胁行为者能够转售访问权限、滥用这些平台作为免费算力（即 LLMjacking），并将其作为进一步攻击的归因掩护。

Google 在本周发布的一份报告中披露，网络犯罪分子已经建立了一套商业模式：窃取商业大语言模型（LLM）的云端访问权限，并将其转售给付费客户。

其变现基础设施以 LLM Mixers 为中心。这些非法中介在地下市场上宣传对遭入侵企业 LLM 帐户的访问权限，而客户无需设置自己的合法 API 凭据或云基础设施。

换言之，LLM 混合商将窃取的企业模型访问权限变成面向付费订阅者的犯罪路由网关，同时合法所有者的系统仍继续接受请求。这些服务有助于跨遭窃取的帐户代理请求、分摊使用量，并掩盖访问权限的原始来源。

Wiz 表示，新兴的 LLMjacking 生态系统“创造了一个使盗窃行为易于变现的市场，可能会促使更多行为者实施窃取凭据的行动。”

这家 Google 旗下子公司还表示，已识别出至少两家转售机构，它们利用从两个不同组织窃取的 AWS Bedrock 密钥开展业务——llm-routing[.]com（momo）和 xingjiabiapi[.]org——两者均以折扣价格提供种类繁多的前沿模型。不过，目前没有证据表明这些网站的运营者应对最初的平台入侵负责。

有意思的是，与 llm-routing[.]com 关联的 IP 地址 23.106.46[.]239 曾于 2026 年 10 月中旬托管一个 Artex 落地页，并已被 Zeabur 标记为入侵指标。上个月，Zeabur 披露了一起安全事件：一名身份不明的威胁行为者利用以明文存储的凭据入侵其基础设施，窃取了超过 320 万条环境变量记录以及与 321,810 个账户相关的数据。

以下 IP 地址曾被用于测试被盗密钥，被怀疑与 LLM 令牌滥用和转售有关——

  • 23.106.46.239
  • 38.246.114.118
  • 104.243.32.50
  • 31.57.201.201

“威胁行为者不仅将 AI 作为实施攻击的工具，还会入侵受害者环境，专门滥用其财务账户来大规模执行大语言模型（LLM），由此产生数十万美元的 AI API 费用。”Wiz 表示。
