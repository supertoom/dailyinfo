ELF DT_RELR 压缩重定位导致 objdump -R 审计盲区分析与绕过

ELF DT_RELR 压缩重定位导致 objdump 审计盲区分析与绕过

AI 导读

研究复现了 GNU 与 LLVM 的 objdump -R 不展开 DT_RELR 的审计盲区：样本 librelr.so 含 11 个动态重定位目标，objdump -R 仅报告 7 个。

值得关注

文章用可复现实验揭示了只枚举显式重定位表的审计盲区，并给出覆盖 DT_RELA、DT_JMPREL、DT_RELR 的修复方法。

正文

一、RELR 是什么：从 11 和 7 的差说起

ELF 的动态重定位有几套并存的表示：

  • DT_RELA：显式的 Elf64_Rela 数组，每个条目 24 字节，写清 offset、type、addend。

  • DT_REL：32 位时代的显式数组，每个条目 16 字节。

  • DT_JMPREL：PLT 的跳转槽重定位，单独一张表。

  • DT_RELR：只针对相对重定位的压缩表示，每个条目 8 字节，用“基址 + 位图”描述一批地址。

RELR 的存在理由很直接：PIE、静态 PIE、C++ 虚表、函数指针表会产生大量相对重定位，每个都写 24 字节的 Elf64_Rela 太浪费。一个 DT_RELR 条目能干两件事：偶数条目是一个要重定位的地址；奇数条目是一张 64 位位图，bit 0 是标记位，bit 1 到 bit 63 对应基址开始的 63 个 8 字节槽位。一个位图覆盖 63 个地址，基址再前进 63 * 8 字节。

拿librelr.so 举例，readelf -d 能看到三组标签：

$ readelf -dW librelr.so | grep -E 'RELR|RELA|INIT_ARRAY|FINI_ARRAY'

DT_RELR 在 0x538，大小 24 字节，条目宽度 8 字节。24 字节就是 3 个条目。

readelf -r 把这三个条目展开成 4 个地址：

$ readelf -rW librelr.so

6 个显式 RELA，1 个 PLT，4 个 RELR 地址，一共 11 个。4 个 RELR 地址是 0x3dc0、0x3dc8、0x3dd0、0x4008。

再把同一份文件交给 objdump -R：

$ objdump -RW librelr.so | sed -n '/DYNAMIC RELOCATION RECORDS/,$p'

7 个。0x3dc0、0x3dc8、0x3dd0、0x4008 一个都没有。

最反直觉的一点不在“少了 4 个”，而在少掉的这 4 个刚好是加载器真正会写、而且写的是函数指针的 4 个地址。0x3dc0 和 0x3dc8 是 .init_array 的两个槽位，0x3dd0 是 .fini_array 的槽位，0x4008 是 __dso_handle。

文件里 .init_array 长这样：

$ readelf -x .init_array librelr.so

两个 8 字节槽位，分别是 0x1100 和 0x1129，都是链接期地址，不是零。0x1100 是 frame_dummy，0x1129 是本文样本里的 lib_init。加载器在运行时把加载基址加上去：

$ setarch $(uname -m) -R ./relr_use ./librelr.so

init_off=0x1129 和文件里第二个槽位的值完全对上。CTOR RAN 说明构造函数确实执行了，ctor_ran=1 说明它真的把状态改了。但在 objdump -R 的 7 行输出里，没有任何一行指向 0x3dc8。

同一份文件，加载器写了 11 个地址，objdump -R 只报告 7 个。差的 4 个，两个是构造函数/析构函数指针，一个是 DSO 句柄。

二、从一次加载看完整链路

目录：

/root/relr-lab
├── relr_lib.c
├── relr_use.c
├── relr_mem.c
├── relr_scan.py
├── relr_gate.py
├── relr_many.c
├── relr_data.c
└── relr_static.c

relr_lib.c 是一个带构造函数的共享库，核心只有几行：

int ext = 7;
int *p1 = &ext;
int *p2 = &ext;

__attribute__((noinline)) static void ctor(void)
{
    static const char msg[] = "CTOR RAN\n";
    write(1, msg, sizeof(msg) - 1);
}

__attribute__((constructor)) static void lib_init(void)
{
    ctor();
}

p1、p2 指向可被外部符号插入的 ext，链接器会给它们生成显式的 R_X86_64_64，留在 .rela.dyn 里。lib_init 是本地函数，它的 .init_array 槽位是相对重定位，正好是 RELR 的压缩对象。

relr_use.c 负责 dlopen、打印构造函数状态、拿到加载基址：

void *h = dlopen(path, RTLD_NOW | RTLD_LOCAL);
int (*get_ran)(void) = (int (*)(void))dlsym(h, "get_ctor_ran");
void *(*get_addr)(void) = (void *(*)(void))dlsym(h, "get_init_addr");
dl_iterate_phdr(cb, NULL);
printf("ctor_ran=%d\n", get_ran ? get_ran() : -1);
printf("init_addr=%p\n", get_addr ? get_addr() : NULL);
printf("lib_base=%p\n", (void *)lib_base);
printf("init_off=0x%lx\n", (unsigned long)((uintptr_t)get_addr() - lib_base));

relr_mem.c 更直接：给定库名和一个节内偏移，dlopen 之后读那个槽位，打印值和“值相对加载基址的偏移”。

编译命令：

$ gcc -O0 -shared -fPIC -Wl,-z,pack-relative-relocs -o librelr.so relr_lib.c
$ gcc -O0 -shared -fPIC -o librela.so relr_lib.c
$ gcc -O0 -o relr_use relr_use.c -ldl
$ gcc -O0 -o relr_mem relr_mem.c -ldl

第一条带 -Wl,-z,pack-relative-relocs，让链接器把相对重定位压进 DT_RELR。第二条不带，得到一份全部走 .rela.dyn 的对照库 librela.so。

第一步，看动态标签。DT_RELR、DT_RELRSZ、DT_RELRENT 三个标签同时出现，说明这份文件里有压缩重定位。前面已经贴过输出，这里只记结论：DT_RELR=0x538，DT_RELRSZ=24，DT_RELRENT=8。

第二步，看 readelf -r。.relr.dyn 三个条目展开成四个地址：0x3dc0、0x3dc8、0x3dd0、0x4008。readelf 还把每个地址配了一个“Symbolic Address”。这里有一个容易踩的坑：0x3dc8 那一行写的是 __frame_dummy_init_array_entry + 0x8，看起来像 frame_dummy 的尾巴，实际槽位里存的是 lib_init 的地址 0x1129。readelf 解析的是“槽位地址落在哪个符号里”，不是“槽位里的值指向哪个符号”。这两个不是一回事。

第三步，看 objdump -R。7 行，四个 RELR 地址全部缺席。objdump -R 枚举的是 .rela.dyn、.rel.dyn、.rela.plt 这些显式表，DT_RELR 是一条动态标签加一段位图，不在它的枚举路径里。

第四步，看文件里的 .init_array。0x1100 和 0x1129，两个链接期地址，不是零。一个只读文件、不加重定位的扫描器，会把 0x1129 当成一个绝对指针；这个地址在没有加载基址的情况下根本不在任何映射里。但加载器知道它该加什么。

第五步，跑起来：

$ setarch $(uname -m) -R ./relr_use ./librelr.so

setarch -R 关掉 ASLR，所以两次运行得到同一组地址。0x7ffff7fba129 - 0x7ffff7fb9000 = 0x1129，和文件里的第二个槽位一致。

第六步，直接读运行时槽位：

$ setarch $(uname -m) -R ./relr_mem ./librelr.so 3dc8

value_off=0x1129，就是 lib_init。同一个工具读 0x3dd0 和 0x4008：

$ setarch $(uname -m) -R ./relr_mem ./librelr.so 3dd0

$ setarch $(uname -m) -R ./relr_mem ./librelr.so 4008

0x3dd0 的 value_off=0x10c0 是 __do_global_dtors_aux；0x4008 的 value_off=0x4008 是 __dso_handle 指向自己。

把这条链拆开看，一共五步：

  1. 链接器把 lib_init 的 .init_array 槽位、__do_global_dtors_aux 的 .fini_array 槽位、__dso_handle 的相对重定位压缩成 DT_RELR 位图。

  2. 动态段里留下 DT_RELR=0x538、DT_RELRSZ=24、DT_RELRENT=8。

  3. 加载器展开位图，得到四个地址。

  4. 加载器把“加载基址 + 文件里的链接期地址”写进这四个槽位。

  5. 构造函数从 .init_array 被调用，打印 CTOR RAN。

审计侧看到的却是另一条链：objdump -R 枚举显式表，得到 7 个地址，没有 0x3dc8，于是 gate 判 PASS。

这一步证明的是：加载器写的地址集合和 objdump -R 报告的地址集合不是同一个集合；少的 4 个不是随机的，正好是 init_array、fini_array 和 __dso_handle。

三、取证视角：四个地址，六种看法

同一个文件，从六个角度看，会得到六组不同的“事实”。

动态标签视角。 readelf -d 告诉你 DT_RELR 存在，大小 24 字节，条目 8 字节。它不告诉你四个地址分别是什么，但它是第一个信号：这份文件用了压缩重定位。

重定位表视角。 readelf -r 把位图展开成四个地址，并且给每个地址配一个符号。这个视角最完整，但有一个符号解析的坑：Symbolic Address 列写的是槽位地址的符号，不是槽位里的值。0x3dc8 那一行是 __frame_dummy_init_array_entry + 0x8，实际值是 lib_init。要确认这一点，得再看符号表：

$ readelf -sW librelr.so | grep -E 'lib_init|frame_dummy'

lib_init 在 0x1129，和 .init_array 第二个槽位的值一致。readelf -r 的符号列只是把槽位地址 0x3dc8 归到了 0x3dc0 那个数组符号的 +0x8 上。

objdump 视角。 objdump -R 只给 7 个地址。它不会提示“还有 4 个在 DT_RELR 里”，也不会在输出末尾写一句“RELR not shown”。这是一次静默的省略。

文件字节视角。 readelf -x .init_array 显示 0x1100 和 0x1129。这两个值是链接期地址，不是运行时地址。一个把文件值当绝对指针的扫描器，会把 0x1129 当成一个无效地址；一个只看节内容的审计，会认为这里“有两个看起来像代码地址的值”，但不知道它们会在加载时被改写。

运行时视角。 relr_mem 读 0x3dc8，得到 base+0x1129。这是唯一能直接证明“加载器确实写了这个槽位”的视角。

LLVM 视角。 LLVM 的 llvm-readelf 和 GNU readelf 一样能看到 .relr.dyn：

$ llvm-readelf -r librelr.so | sed -n '/.relr.dyn/,$p'

但 LLVM 的 llvm-objdump -R 和 GNU objdump 一样只给 7 个：

$ llvm-objdump -R librelr.so | grep -cE '^[0-9a-f]{16}'

$ python3 relr_scan.py librelr.so | grep -E 'DT_RELR|DT_RELA|DT_JMPREL|all dynamic|objdump -R offsets|targets missing'

缺的 4 个是 0x3dc0、0x3dc8、0x3dd0、0x4008。relr_scan.py 的完整模式把三张表合成一个集合，objdump -R 只给显式表，差值就是 RELR 的地址。

这不是 GNU 一家的问题，也不是 readelf 一家的问题。readelf 这一支（GNU 和 LLVM）都能展开 DT_RELR，objdump 这一支（GNU 和 LLVM）都只枚举显式表。分界线在工具的实现路径，不在编译器或发行版。

四、机制：位图怎么展开，工具怎么失明

加载器眼里的重定位。 加载器不区分“显式”和“压缩”，它按动态标签把三类表都跑一遍：DT_RELA（加上 DT_JMPREL）是显式数组，DT_RELR 是位图。位图的展开规则只有四条：

  1. 偶数条目：这个地址本身要被重定位；把基址设为 entry + 8。

  2. 奇数条目：低 bit 0 是标记位，bit 1 到 bit 63 是位图。

  3. bit i（i 从 1 到 63）为 1，表示 base + (i - 1) * 8 要被重定位。

  4. 一张位图处理完，base += 63 * 8。

把 librelr.so 的三个条目展开一遍：

entry 0: 0x3dc0        偶数 -> 重定位 0x3dc0,base = 0x3dc8
entry 1: 0x7           奇数 -> bit 1、bit 2 -> 0x3dc8、0x3dd0,base = 0x3fc0
entry 2: 0x401         奇数 -> bit 10      -> 0x4008

和 readelf -r 的四个地址完全一致。relr_scan.py 里的展开循环就是这四条的直译：

base = 0
for entry in entries:
    if entry & 1 == 0:
        addrs.append(entry)
        base = entry + 8
    else:
        for bit in range(1, 64):
            if entry & (1 << bit):
                addrs.append(base + (bit - 1) * 8)
        base += 63 * 8

一个位图覆盖 63 个地址，所以 100 个函数指针的数组只需要两个位图，加上基址条目一共几个 8 字节条目。librelr_many.so 的 .relr.dyn 是 4 个条目、32 字节，展开成 103 个地址；如果这 103 个地址都写成 R_X86_64_RELATIVE 的 Elf64_Rela，光重定位表就要 103 * 24 = 2472 字节。省下来的空间不是一点。

readelf 眼里的重定位。 readelf -r 有专门的 .relr.dyn 处理路径，会把位图展开成地址列表，还会给每个地址配符号。它的输出格式在不同版本里基本稳定：GNU 2.47 给 entries which relocate N locations，LLVM 的 llvm-readelf 给 contains 4 entries；两家都能给出 Index/Entry/Address/Symbolic Address 这几列。但它有一个语义坑：Symbolic Address 解析的是槽位地址，不是槽位里的值。__frame_dummy_init_array_entry + 0x8 这种写法，会让人以为写入的是 frame_dummy，实际是 lib_init。

objdump 眼里的重定位。 objdump -R 走的是另一条路径：它向 BFD 要“动态重定位记录”，BFD 按 .rela.dyn、.rel.dyn、.rela.plt 这些 Elf_Rela/Elf_Rel 节枚举。DT_RELR 不是这样的节，它是一段位图，只有显式展开才能变成地址列表。objdump -R 没有这一步，所以它给出的 7 个地址不是“错误的地址”，而是“另一个集合”：显式表的集合。

自写解析器眼里的重定位。 很多人写审计脚本时，会照着 DT_RELA 的循环抄一遍：读 DT_RELA、DT_RELASZ、DT_RELAENT，按 24 字节步进，读 r_offset。这段代码对 librelr.so 只会得到 6 个地址。再加上 DT_JMPREL 的 1 个，一共 7 个。正好等于 objdump -R 的 7 个。这不是巧合：它们读的是同一套显式表。

审计 gate 眼里的重定位。 一个典型的静态 gate 会做两件事：拿 objdump -R 的 offset 列表，拿 readelf -SW 的 .init_array/.fini_array 地址范围，判断有没有重定位落在这些范围里。对 librelr.so，objdump -R 的 7 个 offset 没有一个落在 [0x3dc0, 0x3dd0) 或 [0x3dd0, 0x3dd8) 里，于是 gate 判 PASS。它不知道 DT_RELR 里还有四个地址。

这里容易混淆的是：readelf -d 看到 DT_RELR 标签，不等于 objdump -R 能看到 DT_RELR 的条目；readelf -r 看到 .relr.dyn，不等于审计 gate 会把它算进“重定位集合”。标签、节、条目、地址，是四个不同层次的东西。

把机制收敛成一句话：RELR 把“要改哪些地址”从显式列表变成了“基址 + 位图”，加载器按位图展开，只读显式列表的消费者就看不到这些地址。

这个框架能迁移到任何“同一语义、多种表示、不同消费者各读一套”的地方：

  • 符号表：.symtab、.dynsym、GNU hash 是三套表示，只读 .dynsym 的工具看不到本地符号。

  • 重定位：DT_RELA、DT_REL、DT_RELR、DT_JMPREL 是四套表示，只读其中一套就会漏。

  • 调试信息：压缩的 .debug_* 和未压缩的节，工具支持程度不同。

  • PE 的 base relocation、Mach-O 的 chained fixups，也是“压缩表示 + 消费者滞后”的同类问题。

盲区成立的充要条件也只有四条：

  1. 链接器把相对重定位压进了 DT_RELR（-z pack-relative-relocs 或默认开启）。

  2. 审计工具只枚举 DT_RELA，或者只用 objdump -R，不展开 DT_RELR。

  3. 被隐藏的目标是安全相关的：init_array、fini_array、GOT、.data.rel.ro 里的函数指针。

  4. 审计结论被用来放行或拦截，而不是仅仅打印给人看。

四条同时成立，gate 就会在“看起来没有异常重定位”的二进制上放行一个构造函数。

librela.so 是对照组：同样的构造，只是不压缩。readelf -r 显示 10 个 .rela.dyn 加 1 个 .rela.plt，objdump -R 也显示 11 个，缺失 0。这说明 objdump -R 不是“看不到 init_array”，它只是“看不到 RELR 里的 init_array”。

librelr_many.so 把规模拉开：.relr.dyn 4 个条目、32 字节，展开成 103 个地址；objdump -R 只看到 4 个显式条目，缺 103 个。

$ readelf -rW librelr_many.so | grep -E '\.relr\.dyn.*contains'

$ readelf -rW relr_static | grep -E '\.relr\.dyn.*contains'

librelr_data.so 是纯数据指针，23 个地址被 RELR 写入，没有构造函数，影响落在数据/函数指针表上，不一定会立刻执行代码。

relr_static 是静态 PIE，规模更大：1125 个动态目标里 1103 个是 RELR，objdump -R 只看到 22 个 PLT 跳转槽。一个只读 objdump -R 的扫描器会认为这个二进制“几乎没有动态重定位”，实际它有 1103 个 RELR 写入。程序跑起来，STATIC CTOR 和 MAIN 都正常输出。

strip --strip-all 不影响 DT_RELR。.symtab 没了，.relr.dyn 还在，readelf -d 还是能看到 DT_RELR，objdump -R 还是 7 个，构造函数还是执行。想靠 strip 把重定位“洗掉”，不成立。

objcopy --remove-section .relr.dyn 是另一个边界：节头没了，DT_RELR 标签还在，加载器仍然按标签去读那段位图，但 objcopy 已经把文件布局改了，读到的东西不可用，relr_use 直接 SIGSEGV，rc=139。删节头不是“隐藏”，是把加载器打崩。

$ readelf -SW librelr_nosec.so | grep relr || echo 'section header gone'

$ readelf -dW librelr_nosec.so | grep RELR

$ setarch $(uname -m) -R ./relr_use ./librelr_nosec.so; echo rc=$?

-Wl,-z,nopack-relative-relocs 是构建侧的可见性开关：强制回到显式 RELA，objdump -R 就能看到全部 11 个。代价是 .rela.dyn 从 144 字节涨到 240 字节，二进制变大；它不是安全修复，只是让旧审计工具能看见。

命中、未命中、边界三条分支因此很清楚：

  • 命中：RELR 版 + 只读 objdump -R 的 gate。gate 判 PASS，构造函数执行。gate 的结论是错的。

  • 未命中：非 RELR 版 + 同一个 gate。gate 判 BLOCK，init_array 的重定位在 objdump -R 里可见。gate 的结论是对的。

  • 边界：纯数据 RELR（23 个地址）没有代码执行，但指针被静默改写；静态 PIE（1103 个地址）说明这不是边角；objcopy 删节头直接崩溃，说明“删掉节头”不是可用的隐藏手法。

换一种配置就失效，不是修复，而是转移。 关掉 RELR，objdump -R 能看见，但二进制变大；strip 看不见效果；删节头直接把加载器打崩。真正的修复只能落在审计侧：让审计枚举所有动态重定位来源。

六、根因

根因可以压成一句话：objdump -R 枚举的是“显式重定位表”，DT_RELR 是“压缩重定位流”，两者不是同一种数据结构；readelf -r 有专门的展开路径，objdump -R 没有。

再展开一点：

  • .rela.dyn、.rel.dyn、.rela.plt 都是节，节里是固定大小的 Elf64_Rela/Elf64_Rel 数组，BFD 可以按节遍历。

  • DT_RELR 是动态段里的一个标签，指向一段 8 字节条目流；条目要么是地址，要么是位图。它没有对应的 Elf64_Rela 数组，BFD 的动态重定位枚举不会自动展开。

  • readelf -r 对 .relr.dyn/DT_RELR 有单独的处理逻辑，所以能看到；objdump -R 没有，所以看不到。

  • readelf -d 能看到 DT_RELR 标签，但标签不等于条目；readelf -r 能看到条目，但符号列解析的是槽位，不是值。

七、修复：让审计枚举所有动态重定位来源

修复分两侧：审计侧和构建侧。审计侧是根治，构建侧只是可见性开关。

审计侧，按这五条做：

  1. 枚举所有动态重定位来源。 至少包括 DT_RELA、DT_JMPREL、DT_RELR；不要只读 DT_RELA，也不要把 objdump -R 当成全量。

  2. 展开 RELR 位图。 偶数条目是地址，奇数条目是位图；一个位图覆盖 63 个槽位，基址每轮前进 63 * 8。不要把一个位图条目当成一个地址。

  3. 对目标做节归属判定。 落在 .init_array、.fini_array、.got、.data.rel.ro 的写入，按安全相关处理；判定要用完整集合，不是 objdump -R 的子集。

  4. 加运行时兜底。 对高风险二进制，dlopen 后读 .init_array/.fini_array 槽位，和文件里的链接期地址对比；value == base + 文件值 说明加载器写了。文件视图和运行时视图的差异，比任何单一静态工具都可靠。

  5. 补丁比对要带上 RELR。 比较两个二进制时，把 .relr.dyn 的原始字节和 DT_RELR/DT_RELRSZ/DT_RELRENT 一起纳入 hash/diff；只比符号表和 .rela.dyn，会漏掉 RELR 里的变化。

这五条里，第一条和第二条是核心。relr_scan.py 的完整模式就是按这两条写的，--gate 模式再把第三条接上：

$ python3 relr_scan.py --gate librelr.so0

同一个库，只读 objdump -R 的 gate 给出的是另一个结果：

$ python3 relr_gate.py librelr.so

一个 PASS，一个 BLOCK。差的就是 DT_RELR 的 4 个地址。

对照组 librela.so 两边都 BLOCK：

$ python3 relr_gate.py librela.so

这说明 gate 本身不是“永远 PASS”，它只是对 RELR 盲。

构建侧，按这两条做：

  1. 需要旧审计工具看得见时，用 -Wl,-z,nopack-relative-relocs。 强制回到显式 RELA，objdump -R 能看到全部 11 个，.rela.dyn 从 144 字节涨到 240 字节。代价是二进制变大，收益是可见性；这不是安全修复，是兼容性开关。

  2. 不要用 objcopy --remove-section .relr.dyn 去“清理”重定位。 节头删了，DT_RELR 标签还在，加载器仍然按标签读位图，但文件布局已经变了，relr_use 直接 SIGSEGV，rc=139。strip 也不会移除 DT_RELR，它只动符号表。

八、攻击者视角

诱导链。 攻击者不需要控制整个构建流水线，只需要让一个原生扩展进入宿主。宿主的审计 gate 用 objdump -R 判断“有没有 init_array 重定位”，扩展的 .init_array 指针被链接器压进 DT_RELR，gate 看到的 7 个 offset 全在 GOT 和 PLT 上，判 PASS。宿主 dlopen 扩展，构造函数在宿主的权限下执行。

提权链。 这不是提权漏洞。构造函数拿到的就是宿主进程的权限；如果宿主是 root，它就是 root，如果宿主是普通用户，它就是普通用户。它的价值在于“绕过静态审计”，不在于“突破权限边界”。本文的样本只打印 CTOR RAN，原因也在这里：验证的是审计盲区，不是利用链。

自动化探测。 攻击者可以先看目标的审计工具：如果只跑 objdump -R，RELR 就是可用的；如果跑 readelf -r 或自写了解析器，隐藏的目标会被看到。一个简单的自检脚本就能判断：

$ readelf -dW librelr.so | grep -c '(RELR)'

$ objdump -RW librelr.so | grep -cE '^[0-9a-f]{16}'

$ python3 relr_scan.py librelr.so | grep -E 'DT_RELR entries|objdump -R offsets|targets missing'

如果 DT_RELR 存在，而 objdump -R 的数量明显小于 readelf -r 展开的数量，说明工具的集合不完整。防守方也可以用同一组命令做自查。

边界。 这套手法只对“只读显式表”的审计有效。目标一旦用 readelf -r、LLVM readelf、或自写的 RELR 展开器，隐藏的四个地址就会露出来；目标一旦做运行时槽位采样，构造函数也藏不住。它不是通用免杀，是一个特定工具链组合下的盲区。

九、结论

  1. RELR 是第四套重定位表示。 加载器认它，objdump -R 不认；librelr.so 的 11 个动态目标里，4 个只在 DT_RELR 里，正好是 init_array、fini_array 和 __dso_handle。readelf（GNU/LLVM）能看到，objdump（GNU/LLVM）看不到。

  2. 盲区的规模不是边角。 100 个函数指针的库漏 103 个，纯数据指针的库漏 23 个，静态 PIE 漏 1103 个；构造函数在 gate 判 PASS 的同时照样执行。盲区的成立条件是“审计只读一套表示”，不是 RELR 本身有漏洞。

  3. 修复不是禁用 RELR。 审计侧枚举 DT_RELA、DT_JMPREL、DT_RELR，展开位图，再用运行时槽位做交叉验证；构建侧的 -z nopack-relative-relocs 只是让旧工具看得见的兼容开关。检查清单一句话：看到 DT_RELR，先别信 objdump -R。

#define _GNU_SOURCE
#include <dlfcn.h>
#include <link.h>
#include <stdio.h>
#include <string.h>
#include <stdint.h>

static uintptr_t lib_base;
static int found;

static int cb(struct dl_phdr_info *info, size_t sz, void *data)
{
    (void)sz;
    (void)data;
    if (strstr(info->dlpi_name, "librelr")) {
        lib_base = info->dlpi_addr;
        found = 1;
        return 1;
    }
    return 0;
}

int main(int argc, char **argv)
{
    const char *path = argc > 1 ? argv[1] : "./librelr.so";
    void *h = dlopen(path, RTLD_NOW | RTLD_LOCAL);
    if (!h) {
        printf("dlopen failed: %s\n", dlerror());
        return 1;
    }

    int (*get_ran)(void) = (int (*)(void))dlsym(h, "get_ctor_ran");
    void *(*get_addr)(void) = (void *(*)(void))dlsym(h, "get_init_addr");

    dl_iterate_phdr(cb, NULL);
    printf("ctor_ran=%d\n", get_ran ? get_ran() : -1);
    printf("init_addr=%p\n", get_addr ? get_addr() : NULL);
    if (found) {
        printf("lib_base=%p\n", (void *)lib_base);
        if (get_addr)
            printf("init_off=0x%lx\n",
                   (unsigned long)((uintptr_t)get_addr() - lib_base));
    }
    return 0;
}

#define _GNU_SOURCE
#include <dlfcn.h>
#include <link.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>

static uintptr_t lib_base;
static int found;

static int cb(struct dl_phdr_info *info, size_t sz, void *data)
{
    (void)sz;
    (void)data;
    if (strstr(info->dlpi_name, "librelr")) {
        lib_base = info->dlpi_addr;
        found = 1;
        return 1;
    }
    return 0;
}

int main(int argc, char **argv)
{
    if (argc < 3) {
        fprintf(stderr, "usage: %s <lib> <offset-hex>\n", argv[0]);
        return 2;
    }

    void *h = dlopen(argv[1], RTLD_NOW | RTLD_LOCAL);
    if (!h) {
        printf("dlopen failed: %s\n", dlerror());
        return 1;
    }

    dl_iterate_phdr(cb, NULL);
    if (!found) {
        printf("lib not found\n");
        return 1;
    }

    uintptr_t off = strtoull(argv[2], NULL, 16);
    uintptr_t slot = lib_base + off;
    uintptr_t value = *(uintptr_t *)slot;
    printf("base=%p offset=0x%lx slot=%p value=%p value_off=0x%lx\n",
           (void *)lib_base, (unsigned long)off, (void *)slot,
           (void *)value, (unsigned long)(value - lib_base));
    return 0;
}

relr_scan.py

#!/usr/bin/env python3
import re
import struct
import subprocess
import sys

DT_NULL = 0
DT_PLTRELSZ = 2
DT_RELA = 7
DT_RELASZ = 8
DT_RELAENT = 9
DT_JMPREL = 23
DT_RELRSZ = 35
DT_RELR = 36
DT_RELRENT = 37

R_X86_64_RELATIVE = 8


def vaddr_to_off(loads, vaddr):
    for p_vaddr, p_offset, p_filesz, _p_memsz in loads:
        if p_vaddr <= vaddr < p_vaddr + p_filesz:
            return p_offset + (vaddr - p_vaddr)
    return None


def parse_elf(path):
    data = open(path, "rb").read()
    if data[:4] != b"\x7fELF" or data[4] != 2 or data[5] != 1:
        raise SystemExit("need ELF64 little-endian")
    e_phoff = struct.unpack_from("<Q", data, 0x20)[0]
    e_phentsize = struct.unpack_from("<H", data, 0x36)[0]
    e_phnum = struct.unpack_from("<H", data, 0x38)[0]
    loads = []
    dyn = None
    for i in range(e_phnum):
        o = e_phoff + i * e_phentsize
        p_type, p_flags, p_offset, p_vaddr, p_paddr, p_filesz, p_memsz, p_align = \
            struct.unpack_from("<IIQQQQQQ", data, o)
        if p_type == 1:
            loads.append((p_vaddr, p_offset, p_filesz, p_memsz))
        elif p_type == 2:
            dyn = (p_offset, p_filesz)
    if dyn is None:
        raise SystemExit("no PT_DYNAMIC")
    tags = {}
    off, size = dyn
    for i in range(0, size, 16):
        tag, val = struct.unpack_from("<QQ", data, off + i)
        if tag == DT_NULL:
            break
        tags[tag] = val
    return data, loads, tags


def read_rela(data, loads, tags):
    out = []
    if DT_RELA not in tags:
        return out
    vaddr = tags[DT_RELA]
    size = tags.get(DT_RELASZ, 0)
    ent = tags.get(DT_RELAENT, 24)
    off = vaddr_to_off(loads, vaddr)
    if off is None:
        return out
    for i in range(size // ent):
        r_offset, r_info, r_addend = struct.unpack_from("<QQq", data, off + i * ent)
        out.append((r_offset, r_info & 0xffffffff, r_addend, "RELA"))
    return out


def read_jmprel(data, loads, tags):
    out = []
    if DT_JMPREL not in tags:
        return out
    vaddr = tags[DT_JMPREL]
    size = tags.get(DT_PLTRELSZ, 0)
    ent = 24
    off = vaddr_to_off(loads, vaddr)
    if off is None:
        return out
    for i in range(size // ent):
        r_offset, r_info, r_addend = struct.unpack_from("<QQq", data, off + i * ent)
        out.append((r_offset, r_info & 0xffffffff, r_addend, "JMPREL"))
    return out


def read_relr(data, loads, tags):
    out = []
    if DT_RELR not in tags:
        return out
    vaddr = tags[DT_RELR]
    size = tags.get(DT_RELRSZ, 0)
    ent = tags.get(DT_RELRENT, 8)
    off = vaddr_to_off(loads, vaddr)
    if off is None:
        return out
    base = 0
    for i in range(size // ent):
        entry = struct.unpack_from("<Q", data, off + i * ent)[0]
        if (entry & 1) == 0:
            out.append((entry, 0, 0, "RELR"))
            base = entry + 8
        else:
            for bit in range(1, 64):
                if entry & (1 << bit):
                    out.append((base + (bit - 1) * 8, 0, 0, "RELR"))
            base += 63 * 8
    return out


def section_ranges(path):
    out = subprocess.check_output(["readelf", "-SW", path], text=True)
    ranges = {}
    for line in out.splitlines():
        m = re.match(
            r"\s*\[\s*\d+\]\s+(\S+)\s+(\S+)\s+([0-9a-fA-F]+)\s+([0-9a-fA-F]+)\s+([0-9a-fA-F]+)",
            line,
        )
        if m:
            name = m.group(1)
            addr = int(m.group(3), 16)
            size = int(m.group(5), 16)
            ranges[name] = (addr, addr + size)
    return ranges


def objdump_offsets(path):
    try:
        out = subprocess.check_output(["objdump", "-RW", path],
                                      text=True, stderr=subprocess.DEVNULL)
    except Exception as exc:
        return None, str(exc)
    offs = []
    for line in out.splitlines():
        m = re.match(r"^([0-9a-fA-F]{16})\s+(\S+)", line)
        if m:
            offs.append(int(m.group(1), 16))
    return offs, None


def main():
    mode = "full"
    args = sys.argv[1:]
    if args and args[0] == "--gate":
        mode = "gate"
        args = args[1:]
    elif args and args[0] == "--mode":
        mode = args[1]
        args = args[2:]
    if not args:
        raise SystemExit("usage: relr_scan.py [--mode full|rela] <elf>")
    path = args[0]

    data, loads, tags = parse_elf(path)
    rela = read_rela(data, loads, tags)
    jmprel = read_jmprel(data, loads, tags)
    relr = read_relr(data, loads, tags)
    obj, err = objdump_offsets(path)

    if mode == "gate":
        ranges = section_ranges(path)
        watch = {k: v for k, v in ranges.items()
                 if k in (".init_array", ".fini_array")}
        all_offs = sorted(set(o for o, *_ in rela + jmprel + relr))
        hits = []
        for name, (lo, hi) in watch.items():
            for off in all_offs:
                if lo <= off < hi:
                    hits.append((name, off))
        print("DT_RELA=%d DT_JMPREL=%d DT_RELR=%d total=%d" % (
            len(rela), len(jmprel), len(relr), len(all_offs)))
        for name, (lo, hi) in watch.items():
            print("%s: [0x%x, 0x%x)" % (name, lo, hi))
        if hits:
            print("RESULT: BLOCK")
            for name, off in hits:
                print("  relocation at %s 0x%x" % (name, off))
        else:
            print("RESULT: PASS")
        return

    if mode == "rela":
        print("DT_RELA entries: %d" % len(rela))
        for off, rtype, addend, src in rela:
            print("  0x%-8x type=%-2d addend=%d" % (off, rtype, addend))
        print("DT_JMPREL entries: %d" % len(jmprel))
        print("DT_RELR tag: %s" % ("present" if DT_RELR in tags else "absent"))
        print("DT_RELR targets not enumerated by DT_RELA: %d" % len(relr))
        for off, rtype, addend, src in relr:
            print("  0x%-8x" % off)
        return

    total = rela + jmprel + relr
    print("file: %s" % path)
    print("DT_RELR tag: %s" % ("present" if DT_RELR in tags else "absent"))
    if DT_RELR in tags:
        print("DT_RELR vaddr=0x%x size=%d ent=%d" % (
            tags.get(DT_RELR, 0), tags.get(DT_RELRSZ, 0), tags.get(DT_RELRENT, 0)))
    print("DT_RELA entries: %d" % len(rela))
    print("DT_JMPREL entries: %d" % len(jmprel))
    print("DT_RELR entries: %d" % len(relr))
    print("all dynamic-tag targets: %d" % len(total))
    for off, rtype, addend, src in sorted(total):
        print("  0x%-8x %-6s type=%-2d addend=%d" % (off, src, rtype, addend))

    if obj is None:
        print("objdump -R failed: %s" % err)
        return
    print("objdump -R offsets: %d" % len(obj))
    for off in obj:
        print("  0x%-8x" % off)
    missing = sorted(set(off for off, *_ in total) - set(obj))
    print("targets missing from objdump -R: %d" % len(missing))
    for off in missing:
        print("  0x%-8x" % off)


if __name__ == "__main__":
    main()

            ranges[name] = (int(addr, 16), int(addr, 16) + int(size, 16))
    return ranges


def objdump_offsets(path):
    out = subprocess.check_output(["objdump", "-RW", path], text=True)
    offs = []
    for line in out.splitlines():
        m = re.match(r"^([0-9a-fA-F]{16})\s+(\S+)", line)
        if m:
            offs.append(int(m.group(1), 16))
    return offs


def main():
    if len(sys.argv) != 2:
        raise SystemExit("usage: relr_gate.py <elf>")
    path = sys.argv[1]
    ranges = section_ranges(path)
    offs = objdump_offsets(path)
    watch = {k: v for k, v in ranges.items() if k in (".init_array", ".fini_array")}
    hit = []
    for name, (lo, hi) in watch.items():
        for off in offs:
            if lo <= off < hi:
                hit.append((name, off))
    print("objdump -R offsets: %d" % len(offs))
    for name, (lo, hi) in watch.items():
        print("%s: [0x%x, 0x%x)" % (name, lo, hi))
    if hit:
        print("RESULT: BLOCK")
        for name, off in hit:
            print("  relocation at %s 0x%x" % (name, off))
    else:
        print("RESULT: PASS (no init_array/fini_array relocation visible)")


if __name__ == "__main__":
    main()
