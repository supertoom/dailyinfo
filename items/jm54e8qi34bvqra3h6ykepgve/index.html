Swati Khandelwal2026年11月10日漏洞 / 企业安全

SAP 今日在每月一次的安全补丁日修复了四个漏洞，攻击者无需登录即可利用这些问题。该厂商将这四个漏洞全部评为 10.0，即最高 CVSS 分数。

其中三个漏洞位于 SAP NetWeaver 应用服务器，即运行 SAP 系统的软件；另一个漏洞位于 Web Dispatcher，该组件接收来自互联网的 Web 请求，并将其转发至该服务器。

据厂商称，Web Dispatcher 和 Internet Communication Manager（ICM，负责处理服务器的 Web 流量）中的漏洞，可能允许通过网络访问该软件的攻击者执行代码。

服务器的 SAML 2.0 服务提供商漏洞可能允许攻击者在某些使用 SAML 单点登录的系统上，以任意用户身份登录；该服务提供商负责将用户登录过程移交给身份提供商。

SAP Gateway 中的漏洞可能允许攻击者冒充系统自身的一台服务器并执行未经授权的操作；SAP Gateway 负责将该服务器与其他 SAP 系统和程序连接起来。

这四个漏洞均不需要任何用户操作即可利用。

受影响版本和 SAP Notes

据 SAP 11 月安全公告显示，每个漏洞都在各自的 Note 中修复，受影响版本因组件而异。这些 Note 可在需要登录的 SAP for Me 中查看，厂商强烈建议优先应用。

每个漏洞可造成的影响

据厂商称，在受影响的 SAML 配置中，攻击者可以利用 CVE-2026-120017 以特权用户身份登录，进而可能彻底攻陷系统，甚至波及已连接的系统。

同一软件中的另一个 SAML 漏洞CVE-2026-44748 已于 6 月 9 日修复，利用该漏洞需要攻击者拥有普通用户账户。

在 ICM 漏洞（CVE-2026-76964）和 Web Dispatcher 漏洞（CVE-2026-89126）中，专门构造的网络流量可能破坏内存。攻击者一旦成功，便可执行代码并彻底攻陷系统。

SAP Gateway 使用访问控制列表决定哪些外部程序可以连接到它，以及它可以启动哪些程序。在 CVE-2026-89103 中，网关启用了具有高权限的默认列表，使外部攻击者被当作系统自身的一台应用服务器。该攻击者随后便可在应用环境中执行未经授权的操作。

应对措施

在其 补丁日分析中，今天审阅 SAP for Me 说明的 RedRays 公司建议一次性部署内核及所有 Web Dispatcher 的更新。该次部署应达到涵盖本月全部 17 个内核和 Web Dispatcher 修复的级别。

该公司针对每个漏洞的指导如下：

  • SAML2 (CVE-2026-120017)。 在某些配置下，服务提供商不会检查传入断言的签名。在证明并非如此之前，应将任何使用 SAML2 进行浏览器登录的 AS ABAP 系统视为在受影响范围内，例如位于身份提供商之后的 Fiori Launchpad 或 Web GUI。没有临时解决方案，因此更正说明或列出的支持包是唯一的修复方式。该公司的 SAML2 分析 还建议在事务 SAML2 中审查每个受信任的身份提供商，并检查审计日志中是否存在来自意外来源的特权用户 SAML 登录。
  • SAP Gateway (CVE-2026-89103)。 当 secinfo 和 reginfo 中没有明确规则，或依赖 internal 主机关键字时，网关会回退到允许系统自身应用服务器的规则。冒充其中之一通过验证的攻击者随后便可沿常见的网关攻击路径达到命令执行。说明中未列出临时解决方案。对于 7.77 及更早版本的内核，修复会添加配置文件参数 gw/acl_mode_proxy，从而收紧默认规则，而从 7.93 开始的内核已具备该参数。该公司的 Gateway 分析 建议在打补丁后进行设置，并检查 gw/acl_mode 为 1、secinfo 和 reginfo 中包含明确规则，以及用户网络或互联网无法访问网关端口（33xx）。
  • ICM (CVE-2026-76964)。 长度字段无效的 WebSocket 控制帧会在任何登录操作之前导致堆越界写入。SAP NetWeaver AS Java 不受影响，修复通过 dw.sar 和 SP Stack Kernel 交付。据该公司的 ICM 分析，如果用户仅通过 Web Dispatcher 访问 ICM，则将该 Web Dispatcher 修补至 FAQ 说明 3778788 中的级别，暂可为 ICM 提供防护。这仅在无人能够直接访问 ICM 端口的情况下成立。关闭 WebSocket 支持可作为最后手段阻止此漏洞，但会破坏依赖该功能的功能。
  • Web Dispatcher (CVE-2026-89126)。 它与 ICM 漏洞的根因相同。它会影响独立和嵌入式 Web Dispatcher，包括 SAP HANA XS Classic 和 XS Advanced 中的 Web Dispatcher，但不影响 SAP Content Server。该公司的 Web Dispatcher 分析 列出了补丁路径：独立实例使用 SAPWEBDISP.SAR，嵌入式实例使用 dw.sar 或 SP Stack Kernel，HANA XS Classic 使用 SPS08 修订版 089.05 或 SPS07 修订版 079.11，XS Advanced 使用 1.5.4 或更高版本。在补丁部署之前，关闭 WebSocket 支持可以奏效，但说明警告称这会影响 ABAP Push Channels 和某些 Fiori 功能。请首先找出每个 Web Dispatcher，因为遗漏任何一个实例都会使该漏洞仍然存在。
