Cloudflare 披露 AI 渗透测试编排框架激增与凭据链式利用

Adapting to AI penetration testing orchestrators: The Modern Security Model

AI 导读

Cloudflare 指出，AI 渗透测试与利用编排框架正快速扩散，3天内已有 50 多个框架家族扫描其全球客户，相关 IP 达数千个；截至 11 月 12 日，ARTEX 及其分支占已知框架的 60% 以上。

值得关注

文章结合全球扫描与事件响应观测，说明 AI 渗透编排框架的扩散速度、凭据链式利用及可落地的六层防护框架。

正文 · AI 翻译
中文原文

过去一个月，大语言模型（LLM）渗透测试与编排框架的数量激增。就在几周前，ARTEX — 一套自动化  offensive security 工作流的开源智能体渗透测试系统  — 还是唯一可用的框架。 仅在过去三天，我们就看到超过 50 个框架系列试图扫描全球范围内的 Cloudflare 客户。运行这些框架的互联网协议（IP）地址数量已增长至数千个，并且每天仍在增加。这些框架的大量涌现显著改变了网络防御的现状：防御方正难以应对这种自主引导式攻击所带来的流量规模。

ARTEX 已于 October 8 被其创建者 Autumn-27 下架。（“恶意利用该工具完全违背了其最初的设计意图，”他们用中文写道 。） 但在这一个月里，该生态系统已涌现出大量新的碎片化版本。如今已有超过 12,000 个代码库，其中数百个独特的分支源自原始代码库。此外，自 October 8 以来还创建了数百个其他类似的智能体编排框架。AI 渗透测试与漏洞利用工具的每日请求量自 October 1 以来增长了 30 倍。这些工具还开始在一些更复杂的攻击中串联使用被盗客户凭据，例如在整个环境中链接横向移动。

我们预计这些框架会继续 proliferation，每个组织都应做好准备以应对这一威胁。为抵御基于 LLM 的渗透测试框架，我们建议所有组织采用我们称为 Modern Security Model 的安全模型，它包含六个关键支柱：

  • 加固正门：部署 Web 应用防火墙（WAF），并设置诸如 速率限制等高级规则。
  • 在门厅设置安检站：对客户访问的所有 Web 应用进行异常检测。
  • 识别虚假访客：部署 Bot Defense。
  • 拆除后门：对所有高风险的外部和内部 Web 应用实施 Identity-Gated Access。
  • 检查交付内容：强制执行经过验证的模式和明确的安全控制。
  • 邻里守望：部署 Threat Intelligence，以提升对攻击的可见性。

什么是 LLM 渗透与漏洞利用编排器？

开源渗透测试框架能够大规模编排 AI 智能体，执行传统Cyber Kill Chain 的各个阶段。ARTEX 等工具能够快速接入现有的 Model Context Protocol（MCP） ，并以新颖方式连接传统的独立渗透测试工具。有些工具甚至允许操作员指定要完成的任务类型。这些工具能够从内部和外部绘制并枚举环境。ARTEX 及其分支会将资产和环境映射到一张图上，使多个独立的并行智能体能够以推理速度执行枚举、验证、原型构建和攻击。这些工具将入侵转化成了适合智能体通过逐步爬升解决的问题，而这正是智能体特别擅长的领域。

目前存在的 AI LLM 渗透测试工具

我们目前正在跟踪 50 多个 AI LLM 智能体。下表列出了前五名 LLM 渗透与漏洞利用编排器。它们都极其受欢迎（1k+ GitHub stars），并且完全自主运行。这些智能体完全自主的特性 represents 了进攻性网络能力的一次教义式转变：

  • 人为技能不再是限制：一个 harness 会通过观察环境、确定自身方位以优先处理有价值和/或易受攻击的目标、决定采取行动并自主执行，完成 OODA loop 的每一步。
  • 速度提升：让多个并行智能体朝同一目标工作，与单个操作员或由 AI 增强的多个操作员相比，是一次重大转变。
  • 规模：单个操作员可以同时针对多个组织，从而大幅扩大其影响范围。
  • 小错误很容易被发现：自主框架会不懈且系统性地测试暴露在外的服务，包括其配置。

来自全球最大网络的观察

截至 11 月 12 日，ARTEX 及其分支占目前已知 AI 渗透测试编排器的 60% 以上。下方图表有助于了解过去六周这些工具采用情况的变化。自原始 ARTEX 仓库于 10 月 8 日被下架以来，流量增长超过十倍，较 10 月 1 日以来增长超过 30 倍。

如上所示，10 月 8 日 ARTEX 被下架（以及对此广泛报道 ）很可能引发了九头蛇效应，即原始仓库的移除导致分支和修改版本数量大幅增加，这可以从 10 月 8 日前后独立实例数量的急剧加速中看出。

身份链式 LLM 漏洞利用

过去八周，我们的 Cloudforce One 团队参与了多起事件响应调查，调查内容涉及 ARTEX 以及基于 ARTEX 衍生的大语言模型（LLM）漏洞利用框架。我们亲眼看到，暴露的凭据如何与基于 LLM 的漏洞利用框架串联起来，从而在防御者面前占据上风。
我们观察到多起事件：威胁行为者首先获取了超大规模云服务商环境中的初始访问权限，随后直接横向转移到客户的 Cloudflare 环境。根因分析揭示了一个常见的凭据管理失误。攻击者反复入侵运行在 CI/CD 流水线中的静态、不过期令牌，这些令牌授予了对整个组织超大规模云基础设施的广泛跨环境访问权限。LLM 框架大幅提高了客户端 API 密钥被横向利用、以接管其他租户环境的可能性。

ARTEX 实战

在一次事件响应调查中，我们的团队观察到 ARTEX 获取了一个已遭入侵的账户级 API 令牌的访问权限；该令牌此前用于 CI/CD，且未设置 IP 限制或速率限制。现有证据表明，此次入侵极有可能源自第三方超大规模云服务商。

我们观察到大量新的 Worker 脚本被创建，其名称各不相同，例如 artex-*、artex-pgrecon-*、artex-pgw-* 和 artex-do-*。每个 Worker 脚本的名称都与其执行的不同行为和操作相关，并且名称后通常带有字母数字标识符。我们观察到其 Cloudflare 基础设施中多个不同位置的活动请求速率超过每分钟 69 次请求，并在一小时内发出了 400 次数据库转储请求。我们还观察到其尝试建立持久化机制，并尝试验证其他第三方应用程序的会话令牌。虽然我们认为其中大部分活动仅受到人工操作员的轻度引导，但这只是 ARTEX 及类似框架在失陷后所能达到的速度与广度的一个示例。

我们的建议：采用现代安全模型

大语言模型增强了威胁行为者快速迭代网络攻击杀伤链以针对目标的能力。它们赋予行为者速度和验证方面的优势。网络攻击杀伤链的每一步都可以得到验证，并作为下一攻击阶段的输入。这种编排水平前所未有，实际上使传统网络安全模型化为泡影。必须采用现代模型来应对此类攻击。

为进一步说明这一模型，不妨以保护一处庄园住宅为比喻。下面的每个部分都概述了如何针对攻击杀伤链各步骤所面临的威胁进行防御。

加固正门：实施流量控制和配备高级规则的 WAF

在任何人踏上你的草坪之前，都必须先到达外围栅栏。

在一处没有防护的庄园中，对手可以派出 endless fleet of decoy trucks，径直驶入你的车道，彻底堵住入口并冲破屏障（第 3/4 层容量洪泛和直接 IP 探测）。

在设置外围大门安全防护后，所有传入流量都会被引导至距离主体住宅数英里之外的大型分布式外围大门。非法配送车辆会在公路上被过滤掉，试图窃听你物业管线的非法公用事业隧道会被切断，只有合法的人员通行才能抵达你的家庭住址。

网络流量 控制 在阻止 volumetric 攻击中发挥着重要作用。

门厅里的安全检查站：异常检测

当访客抵达主入口时，他们会在门厅遇到一个严格的安全检查站。

自动化的不速之客并不只是踹门；他们会乔装打扮。他们会尝试用古怪的方式进门 —— 把纸塞进锁孔，尝试各种变体，比如 //front-door//back-room/ ，以欺骗机构把门撬开。

门口的保安执行明确的规则：

  • 你不能在五秒内敲 500 次门。
  • 你不能用花招掩饰自己的路径。
  • 你不能试图把一台巨大的平板推车推过前厅，把房子的内部蓝图（诊断堆转储）运走。可疑行为会立即被拒之门外。
  • 部署安全密钥以及基于硬件的 FIDO 密钥。

Web Application Firewall (WAF) 是通过速率限制和异常检测阻止应用层利用的关键防御机制。

识别虚假访客：部署 Bot Defense

老练的入侵者很少看起来像蒙面窃贼；他们会把自己伪装成普通访客。但自动化代理、无头浏览器抓取工具和 AI 侦察工具的行为并不像真实的人。

他们不会眨眼，姿态僵硬得令人不安，节奏机械而规律，他们的"身份证明"往往只是对真实访客证卡的拙劣仿制品。

Bot Defense 和 challenges 充当透过单向玻璃观察人群的行为专家。它标记出不自然的节奏，抓取合成的微行为，并在机器触碰任何一个门把手之前，就悄悄把它们护送离场。

拆掉后门：部署 Identity-Gated Access 与微分段

许多住宅在历史上都建有侧门或地窖舱门（内部管理面板、/actuator 诊断端点和远程网关）。即便上了锁，不速之客也可以站在人行道上，用手电筒照着地窖门，开始撬锁。

Zero Trust 应用访问 做的事情很彻底：它从外面把门洞封死，并限制哪些房间可以被进入。

对任何在周边徘徊的人来说，地窖门根本不存在。没有锁可撬，没有把手可晃，里面也没有灯光。唯一的进入方式是有一位陪同者，他核验你的生物特征证件，确认你的设备健康状况无异常，然后直接把你带进你所需要的那个房间 —— 其余房屋都置于视野之外。

对于确实进入的人，你必须确保他们无法突破与其所进入房间相邻的房间。微分段 是阻止横向移动极为有效的策略。它将已失陷的凭据限制在无法侵入生产、测试和开发系统。

检查投递：强制执行经验证的 schema 与明确的安全控制

你每天都会收到送至你宅邸的补给 —— 食品杂货、邮件、维护零件。在数字层面，这就是传入的 API 流量，必须经过检查与核验。

入侵者常常试图通过发送未经验证的载荷或伪造的投递清单来绕过控制，这些载荷和清单是针对受限内部系统的。

门廊协议要求对所有流量进行彻底检查和模式验证：

  • 每个传入请求都必须经过 OpenAPI 模式验证 ，以确保其严格符合预期的定义和结构。
  • 驱动者和快递员必须出示经过验证的双向 TLS（mTLS）证书，以建立可信、经认证的连接。
  • 任何未通过检查或缺少有效凭据的请求，都会在边界处被立即拒绝。
  • 默认拒绝姿态：每一项积极的安全实现，最终都要以一条位于规则集底部的显式拒绝全部规则收尾。

邻里守望：实施威胁情报，以获得对攻击的可见性

即使有铁壁般坚固的防线，一处孤立的房产仍可能陷入脆弱——只要某个犯罪团伙在全镇范围内发明出一种全新的渗透技术。

威胁情报 如同你与周边庄园之间的预警网络。当某个流氓行为者在不远处搭建起新的命令与控制据点，或开始在你的辖区部署动态隧道车辆时，你会提前收到一份情报简报。你的庄园据此更新观察名单、重新校准传感器，并在该行为者驶入你所在街道之前将大门紧闭。

如何获得实时帮助

ARTEX 以及类似基于大语言模型的框架，对传统网络防御模型构成了重大挑战。即便是历史上的纵深防御模型——它强调经典的网络 DMZ——在当今复杂架构中也显得力不从心。随着编排工具成为新常态，明天的攻击只会更进一步。

保护遗留设备和本地部署设备，需要采用以身份为门禁的方法，从逻辑上使这些设备在互联网上无法被访问。除身份之外，微隔离的目标是让横向移动变得更缓慢、更嘈杂。该架构强调以遏制为先的安全方法，这在用户持续丢失密钥时至关重要。二者结合，现代安全模型的各个要素正是破解这一难题的答案。

如果你正面临进行中的安全事件，需要 Cloudforce One 团队亲临现场协助响应事件或提供威胁情报支持，请立即联系我们。如果你需要帮助实施此处所述的现代安全模型，请联系我们的解决方案工程团队。
