中文原文

一组针对 nginx 的五个严重漏洞于 2026 年 11 月 18 日被公开披露。nginx 是部署最广泛的开源 Web 服务器之一。 

研究人员将这些问题统一命名为 NGINX2Root。这些漏洞允许未经身份验证的远程攻击者在目标主机上执行代码；在已展示的漏洞利用链中，攻击者可进一步提升权限至 root，并逃逸 Docker 容器以触达底层主机。其中两个最严重的 CVE（CVE-2026-123007 和 CVE-2026-123633）的 CVSS 4.0 评分均为 9.2。F5 和 nginx 项目于同一天发布了补丁。

本文将说明哪些对象会受到影响、组织现在应采取哪些措施，以及 CrowdStrike Falcon® 平台如何帮助识别暴露的资产并检测漏洞利用后的活动。

什么是 NGINX2Root？

NGINX2Root 是研究人员赋予五个 nginx 漏洞的名称，这些漏洞均可导致远程代码执行；此外还有一个独立的 Linux 内核漏洞，可与它们串联使用以获取 root 权限。其中最受关注的是 CVE-2026-123007，这是 nginx HTTP/2 请求处理代码中的整数下溢漏洞。HTTP/2 是现代 Web 协议，在大多数生产环境中的 nginx 部署中默认启用。当攻击者发送 specially crafted 的 HTTP/2 流量时，该漏洞会破坏 nginx 工作进程内的内存，并允许在无需身份验证或用户交互的情况下执行任意命令。

NGINX2Root 严重性提升的关键在于它所支持的漏洞利用链。nginx 工作进程以非特权系统账户运行，通常为 www-data 或 nginx。尽管该账户本身没有 root 权限，但攻击者可以从已遭入侵的工作进程触达 Linux 内核 SCTP 网络子系统中的另一个漏洞，并利用该漏洞将权限提升至 root。研究人员端到端演示了完整利用链，包括从运行 nginx 的 Docker 容器中逃逸并触达底层主机。

攻击链概述：

  1. 攻击者向面向公网的 nginx 实例发送 specially crafted 的 HTTP/2 帧，无需任何凭据
  2. nginx 工作进程中的内存破坏使其能够以 Web 服务器账户执行代码
  3. Linux 内核 SCTP 漏洞将权限从工作进程账户提升至 root
  4. 攻击者逃逸 Docker 容器并触达主机系统

其他 CVE 构成了 NGINX2Root 漏洞集合的其余部分，每个漏洞都需要不同但常见的配置：特定的反向代理和解析器设置（CVE-2026-123634）、启用 HTTP/2 与上游转发（CVE-2026-123633）、启用 HTTP/3 与上游转发（CVE-2026-121810），以及邮件代理模式（CVE-2026-113425）。

CVE-2026-123007 已有一个公开的概念验证。触发内存破坏需要传输约 128GB 的 HTTP/2 数据（在 10 Gbit/s 连接上大约需要两分钟）。这限制了当前在互联网上进行机会主义大规模利用的可能性，但并不能阻止定向攻击、从网络内部发起的漏洞利用，或未来能够降低数据量要求的技术。组织不应将这一限制视为推迟修补的理由。

哪些对象会受到影响？

组织现在应采取什么措施？

  1. 将 nginx 更新至已修复的版本：安装 nginx Open Source 1.31.9 或更高版本（mainline 分支），或 1.30.7 或更高版本（stable 分支）。NGINX Plus 客户应依据 F5 公告更新至 37.3.0.1 或 37.0.8.1。下游 Linux 发行版软件包（Red Hat、Debian、Ubuntu、Amazon Linux 等）正在更新；请查看您所用发行版的安全公告，以获取各软件包的修复版本。
  2. 修补后重启 nginx：重新加载配置（nginx -s reload）会替换配置文件，但不会替换正在运行的二进制文件。安装已修复的软件包后，应完整重启服务，以确保运行的是已修复的可执行文件。
  3. 作为临时缓解措施：在受影响的监听端口上禁用 HTTP/2，可阻止 CVE-2026-123007 和 CVE-2026-123633。此缓解措施不涵盖 CVE-2026-123634、CVE-2026-121810 或 CVE-2026-113425，不能替代修补。
  4. 盘点容器镜像和第三方设备：任何基于包含 nginx 的基础层构建的镜像，以及其供应商尚未发布补丁的设备，仍面临暴露风险。请在已修复的基础层上重建镜像，并检查供应商公告。
  5. 优先处理暴露于互联网的实例：运行启用 HTTP/2 的 nginx 且可从互联网访问的主机，面临的即时风险最高。应优先为这些主机应用修补。

CrowdStrike Falcon 平台的帮助方式

Falcon Exposure Management 发现暴露的资产

CrowdStrike Falcon® Exposure Management 对 NGINX2Root 的覆盖适用于 Linux、macOS、NVA/Network Scan 以及外部攻击面管理（EASM）。

客户可在 Falcon 控制台的 Exposure Management > Vulnerability Management > Vulnerabilities 下查找暴露于 NGINX2Root CVE 的主机，然后按 CVE ID 筛选（CVE-2026-123007、CVE-2026-123634、CVE-2026-123633、CVE-2026-121810 或 CVE-2026-113425）。 

覆盖详情：

  • Linux：Falcon 传感器可通过 rpm 和 dpkg 包管理器识别所有传感器版本上的 nginx 安装。
  • macOS：Falcon 传感器可识别 nginx Homebrew 安装。
  • NVA / 网络扫描与 EASM：覆盖范围使用基于横幅的检测，依赖于 nginx 版本字符串。横幅检测可能遗漏版本字符串被抑制，或被反向代理、CDN 或负载均衡器遮蔽的主机；对于将修复反向移植但未更改所报告版本的 Linux 发行版软件包，横幅检测还可能产生误报。应将横幅结果视为一种指标，并尽可能通过基于主机的传感器结果进行验证。
  • Windows：不涵盖 Windows 上的 nginx。nginx 项目将其 Windows 端口归类为 beta 软件。

在漏洞检测发布之前，客户还可以在 EASM 中搜索其面向互联网的资产，路径为 Exposure Management > External Attack Surface > Assets，并按 Application Name = nginx 筛选。

关于控制台中的 CVE ID：如果尚看不到这些标识符的 CVE 元数据，可以暂时按应用名称搜索。检测功能会随着公告得到确认而分批发布。

Falcon 传感器检测后利用活动

CVE-2026-123007 和 CVE-2026-123633 的利用完全通过 HTTP/2 流量发生在 nginx worker 内存内，因为利用阶段不会向磁盘写入文件，也不会启动进程。Falcon 传感器的首次检测机会出现在后利用阶段，此时已遭入侵的 nginx worker 开始表现出偏离正常 Web 服务器活动的行为。

Falcon 监控 nginx 进程树，涵盖 Web 服务器成功遭入侵后攻击者的全部行为：

  1. 可疑子进程：在 nginx worker 下启动的 shell 和系统实用工具，包括用于初始侦察的命令，如 id、whoami、hostname、uname 和 netstat
  2. Webshell 活动：写入 Web 可访问目录的脚本文件，包括常用于建立持久访问的编码和混淆变体
  3. 凭据访问：从 nginx 进程树内部发起对敏感系统文件（如 /etc/passwd 和 /etc/shadow）的读取
  4. 下载和暂存：使用常见二进制文件从外部主机获取后续载荷，包括使用原始 IP 地址（通常称为 living off the land）
  5. 持久化：通过在 nginx worker 下启动 shell 修改授权密钥
  6. 安全工具干扰：从 Web 服务进程上下文中发起停止、禁用或卸载终端安全软件的尝试
  7. 容器感知检测：容器化 nginx 部署中的异常子进程和敏感文件访问，包括由 Web 服务父进程下运行的容器内进程读取敏感系统文件

客户可以在 Falcon 控制台的 Endpoint Security > Activity > Detections 下查看检测结果。CrowdStrike 建议按受影响主机筛选，将结果限定为运行 nginx 的系统，并审查每个警报的进程树，以了解后利用活动的完整范围。

Falcon Next-Gen SIEM 识别威胁

Falcon Next-Gen SIEM：Emerging Threat Response 仪表板

CrowdStrike Falcon® Next-Gen SIEM 对 NGINX2Root 的检测覆盖（新增“NGINX HTTP/2 RCE Vulnerabilities (CVE-2026-123007, CVE-2026-123634, CVE-2026-123633, CVE-2026-121810, CVE-2026-113425)”部分，位于 CrowdStrike Falcon Emerging Threat Response 仪表板上）已作为 NG-SIEM Content Packages 发布的一部分投入生产环境。

Emerging Threat Response 仪表板是一项专注的响应工具，旨在让 CrowdStrike 客户立即了解可能影响其环境的活跃攻击活动或新发现的漏洞。通过利用 Falcon 平台模块的丰富遥测数据，以及在 Falcon Next-Gen SIEM 中接入的第三方数据，该仪表板可提供开箱即用的检测与威胁狩猎查询，使安全团队能够快速判断威胁暴露情况并识别可能已遭入侵的资产。 

NGINX2Root 不会留下传统意义上的失陷指标。没有可供匹配的恶意文件哈希、命令与控制域名或 IP 地址。因此，检测完全基于行为。仪表板中的 NGINX2Root 部分涵盖三个方面的检测覆盖：

  • 利用后威胁狩猎：一个威胁狩猎小组件，用于发现 Linux 终端上由 nginx 工作进程启动的 shell 进程、解释器和 living-off-the-land 二进制文件；这是成功利用后最早可观察到的信号
  • 崩溃突发检测：一个小组件，用于标记一小时内 nginx 工作进程崩溃 10 次或以上的主机；这种模式符合利用尝试在稳定的有效载荷建立之前触发内存损坏的特征。组织应将此阈值视为起始基准，而非确定性信号。在高流量或资源受限的 nginx 部署中，正常情况下也可能因工作进程崩溃频率升高而产生告警。在断定已发生利用尝试之前，分析人员应将崩溃突发告警与利用后威胁狩猎小组件及 Falcon Exposure Management 数据进行交叉核对。
  • 暴露面：一个 Falcon Exposure Management 小组件，用于展示可能受 NGINX2Root CVE 影响的资产，使分析人员能够将检测活动与已确认存在漏洞的主机进行交叉核对

请参阅 Next-Gen SIEM > 日志管理 > 仪表板

Falcon for IT 大规模修复

CrowdStrike 已发布专用于 NGINX2Root 的 Falcon for IT 内容包，为安全和 IT 团队提供统一的工作流，以盘点受影响的主机、评估 HTTP/2 暴露情况，并在 Windows、macOS 和 Linux 上进行修补与缓解。该内容包包含五项任务：

查询任务（Windows、macOS、Linux）：

  • NGINX HTTP2 Inventory：发现整个环境中的所有 nginx 和 NGINX Plus 安装，并报告版本、平台和 HTTP/2 配置状态
  • NGINX HTTP2 Detection：识别 nginx 易受 CVE-2026-123007 影响的主机，并标记是否已启用 HTTP/2，同时列出需要立即处理的 Priority Hosts（存在漏洞且已启用 HTTP/2）
  • NGINX HTTP2 Hunt：一项定向威胁狩猎查询，用于确定需要进一步调查的主机范围

操作任务（仅限 Linux）：

  • NGINX HTTP2 Update：在有可用修复的 Linux 主机上，将 nginx 升级至已修补的版本。这两项操作任务默认均采用审计模式，仅报告将发生的更改，不会对主机进行任何修改。组织应首先以审计模式运行并验证结果，然后再切换为强制执行。
  • NGINX HTTP2 Mitigate：在无法立即修补的情况下，作为临时措施在受影响的 Linux 主机上禁用 HTTP/2。在同一 nginx 侦听器上运行 gRPC 服务的组织应注意，禁用 HTTP/2 也会同时禁用这些端口上的 gRPC。在生产环境中强制执行此操作前，请审查应用依赖关系。

通过操作任务实现的自动修复仅适用于 Linux。Windows 和 macOS 客户应使用资产清单和检测查询来识别受影响的主机，并按照上述“组织现在应该采取什么措施？”部分中的指导手动应用补丁。

该工具包包含一个内置仪表板，其中“暴露概览”显示已扫描主机、已受影响主机、优先主机、已打补丁主机、受影响安装中的 HTTP/2 存在情况细分，以及 nginx 版本排行榜。Falcon Exposure Management 仍是漏洞检测的主要数据来源。Falcon for IT 检测查询会呈现暴露上下文和修复工作流，但不会取代 FEM CVE 数据。

利用 CrowdStrike Counter Adversary Operations 了解您的风险

CrowundStrike Counter Adversary Operations 正在监测对手对 NGINX2Root 的兴趣，并已发布与相关漏洞有关的威胁情报。截至本报告发布，尚未发现可归因于 NGINX2Root 的客户入侵事件。如果情况发生变化，CrowdStrike 将更新本文。

鉴于这些漏洞具有特定的配置要求，不太可能出现大规模成功利用；但是，由于已有公开的 POC，威胁行为者很可能会立即尝试利用 CVE-2026-123007。在另外四个漏洞中，漏洞利用开发者最有可能瞄准 CVE-2026-123633 和 CVE-2026-113425，因为其余两个漏洞（CVE-2026-121810 和 CVE-2026-123634）需要多种罕见配置和依赖项。未经修改的 CVE-2026-123007 POC 不太可能成功针对生产服务器实现 RCE。

结论与建议

NGINX2Root 是一次严重披露，影响各种版本和 Linux 发行版中的 nginx 安装。未经身份验证的初始访问、已展示的 root 权限提升链以及容器逃逸相结合，使其成为任何运行启用了 HTTP/2 的 nginx 的组织都必须优先处理补丁修复的事件。

组织应当：

  • 使用 Falcon Exposure Management、EASM 以及对容器镜像和第三方设备的手动盘点，找出其环境中的每个 nginx 安装
  • 更新至 nginx 1.31.9 / 1.30.7（Open Source）或 37.3.0.1 / 37.0.8.1（nginx Plus），并在打补丁后重启 nginx
  • 对于无法立即打补丁的系统，暂时禁用 HTTP/2 作为缓解措施（请注意，这并不能涵盖全部五个 CVE）
  • 监控 Falcon 行为警报，以发现 Web 服务器进程异常、权限提升和容器逃逸活动
  • 随着在野利用的发展，关注 CrowdStrike Counter Adversary Operations 发布的最新威胁情报

随着新信息的出现，CrowdStrike 将继续监测此威胁并更新检测规则。
