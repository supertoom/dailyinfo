中文原文

CVE-2026-97631：一个存在了 16 年的 UEFI 漏洞（CVSS 评分为 9.5/10）可导致操作系统启动前执行代码。暴露风险的服务器需要安装固件补丁并进行检查。

一个严重漏洞已在全球大多数服务器用于启动的固件中被追踪为 CVE-2026-97631（CVSS 评分为 9.5），如今已公开，补丁细节还提前数月公布。

该漏洞影响 TianoCore EDK II，这是一个开源项目，供硬件制造商和云服务提供商构建 UEFI 固件。UEFI 是在操作系统加载前启动计算机的软件。EDK II 在整个行业中被广泛使用，包括 AMI、Insyde 和 Phoenix 等主要 UEFI 厂商也采用它。即便是微软安全性更高的版本 Project Mu，也曾使用存在漏洞的组件。

“EDK2 的 BIOS 中存在一个漏洞，远程访问者可能借此造成“越界写入”、经典缓冲区溢出和“缓冲区大小计算错误”。成功利用此漏洞可能导致任意代码执行，也可能影响保密性、完整性和可用性。”公告称。

该漏洞可能会破坏负责处理 ICMP 消息的组件中的内存，设备使用 ICMP 消息来报告网络错误。攻击者可以利用它在操作系统启动前、安全保护机制（如 Secure Boot）完全启用前执行代码。Secure Boot 用于检查启动期间加载的软件是否可信，而可信平台模块（TPM）则支持硬件信任等安全功能。尽管攻击者的代码在执行后不会持续处于活动状态，但它可以帮助攻击者安装其他恶意组件，使其在启动过程的早期运行。

该漏洞是一个存在了 16 年的 PXE-Base Code 驱动程序（NetworkPkg/UefiPxeBcDxe）中的缓冲区溢出。该驱动程序让服务器、存储设备及其他设备能够从通过本地网络下载的代码启动。在执行此操作时，它会监听 ICMP 错误，并且从不强制执行其复制数据量的 504 字节上限。

“当机器正通过 IPv4 或 IPv6 进行 PXE 启动时，未经身份验证且能够向其发送 ICMP 错误消息的网络攻击者，可以破坏 DXE 阶段的内存，并在操作系统加载前、Secure Boot 或 Measured Boot 验证或测量任何操作系统组件之前执行任意代码。”公告称。

恶意内部人员，或对本地网络拥有低层访问权限的黑客，可以发送错误消息，使代码溢出上限并破坏 CPU 上运行的 UEFI 模块。

公告对漏洞的描述更为精确。该驱动程序为 ICMP 错误保持一个处于打开状态的接收请求，并将每条消息复制到一个名为 Mode.IcmpError 的固定 504 字节字段中。在 IPv4 和 IPv6 处理器（PxeBcIcmpErrorDpcHandle 和 PxeBcIcmp6ErrorDpcHandle）中，边界处理均存在错误：较长的消息仍会被复制，而目标指针按累计长度而非单个分片长度递增。因此，超长消息会将攻击者控制的字节写入该字段之后，并且接收路径中更早的任何环节都不会限制其大小。

攻击很简单。攻击者甚至可以从远程网络，在 PXE 启动过程中向目标 IP 地址发送直接消息。发送无效数据可能中断启动过程并造成拒绝服务。如果攻击者知道目标的固件版本，就可以创建一个虚假事件，在 ring 0（CPU 的最高权限级别）运行自己的代码。这还会绕过证明（attestation）；证明使用密码学校验来证实硬件值得信赖。因此，这种攻击可以帮助攻击者将有限的访问权限转化为完全控制。

攻击者需要对本地网络有一定控制权。这可能是内部人员，也可能是已经在目标网络中取得立足点并寻求获得更高权限的外部攻击者。目前没有证据表明该漏洞可以被利用，从外部入侵网络以获得初始访问权限。

该漏洞影响某些通过网络启动、使用基于 EDK2 的固件并启用 PXE 的系统。家庭用户、小型办公室用户以及任何仅从磁盘驱动器启动的用户均不受影响。

研究人员原计划于 1 月披露该漏洞，但 AMI 发布了修复补丁，披露了该漏洞的细节。随后 TianoCore 发布了公开警告。攻击者现在可以研究该修复补丁来开发漏洞利用代码，而在许多设备上更新固件可能需要很长时间。

目前仍不清楚哪些设备受到影响。Intel 和 Arm 表示其自身产品未直接受到影响，但制造商可能会加入存在漏洞的代码。本文发布时，其他几家公司尚未回复相关询问。

组织应联系其系统或固件供应商，并在可能的情况下禁用网络启动。还应监控日志中的可疑活动。TPM 和 Secure Boot 仍是有用的防护措施，但无法阻止这种攻击。
