Microsoft 披露攻击者利用 GSocket 在 Linux 服务器维持隐蔽 C2

The global socket: how threat actors are weaponizing GSocket for stealthy C2

AI 导读

Microsoft 观察到多起事件，威胁行为者在已遭入侵的 Linux 服务器上部署了 GSocket，这是一款开源远程访问工具。威胁行为者使用 GSocket 来维持访问权限，即使最初用于入侵的漏洞已经修复也不例外。这使一次 Web 应用程序入侵变成了持续访问，其存续时间超过了原始漏洞的修复周期。调查受影响主机的防御人员应查找 GSocket 部署、持久化、权限提升和出站连接的证据，而不应仅将应用程序补丁视为完整的修复措施。

Microsoft Defender for Endpoint 遥测数据显示，此类活动近几个月来有所增加，并集中出现在 Web 应用程序和托管环境中。GSocket 通过共享公共网络中继流量，因此没有可供封禁的威胁行为者自有 IP 地址或域名。

当一个 RCE 不再只是一个 RCE

利用 Web 应用程序漏洞可使威胁行为者在 Web 服务器进程的上下文中执行命令。这种访问权限仅在漏洞尚未修补且服务持续运行时有效。修补应用程序或重启服务即可消除这种访问权限。

为了保持访问权限，威胁行为者通常会添加持久化机制，而每种常见方案都有缺点。添加到 authorized_keys 中的 SSH 密钥很容易被管理员在审计期间发现。反向 shell 依赖由威胁行为者控制的服务器，防御人员可以封禁这些服务器或将其导向黑洞。自定义植入程序则需要持续开发和维护。当初始访问是通过远程访问服务或云 shell 会话获得时，同样的权衡依然适用。

GSocket 解决了这些缺点，这有助于解释为何多个互不相关的威胁行为者都采用了它。

  • 共享中继基础设施。流量通过 Global Socket Relay Network 这一公共中继服务传递。威胁行为者无需注册或托管任何基础设施，因此没有可供封禁的威胁行为者自有 IP 地址或域名。组织仍可限制对中继本身的访问。
  • 仅出站连接。受损主机和操作人员都会主动出站连接到中继，由其桥接两个会话。主机无需入站监听器或公共 IP 地址，网络地址转换也不会阻止该连接。入站防火墙规则看不到此类流量，但出口过滤和出站监控可以检测到。
  • 内置规避和持久化能力。部署脚本可以重命名进程、将文件暂存到内存支持的目录中，并安装可在重启后存续的持久化机制，而威胁行为者无需额外开发。

这种支持合法远程管理的中继模型，也为威胁行为者提供了一条无需运营专用 C2 基础设施即可维持访问权限的途径。一旦 GSocket 在遭入侵的服务器上运行，服务器和操作人员就会各自出站连接到 Global Socket Relay Network，并通过端到端加密通道配对两个会话。

由于 GSocket 独立于被利用的应用运行，因此修补漏洞并不会移除中继客户端及其持久化机制。

Microsoft Defender for Endpoint 遥测数据显示，此活动并非仅限于单次入侵。从 2026 年 3 月至 8 月，出现 GSocket 相关检测的设备增加了 356.2%，但逐月增长并不稳定。

在所分析的遥测数据中，Web 应用和托管服务占可归因于 Microsoft Defender for Endpoint 事件的 87.1%。在该组中，PHP Web 应用和 cPanel 托管服务占事件的 63.9%，Apache 占 24.3%（图 3）。

教育和研究机构占受影响组织的最大比例（30.7%），其次是技术和电信行业（22.9%）。

这些数字反映了受影响组织所占的比例，并不表明威胁行为者是有意选择了这些行业。暴露面更可能是促成因素：学术机构通常运行着由中央 IT 团队之外的人员维护的大型、分散式 Web 环境，因此更难对其进行盘点和修补。

观察到的攻击链

本次分析中的基于 RCE 的入侵在初始访问后均遵循相似流程。威胁行为者入侵面向互联网的应用，对主机进行画像，传输并隐藏中继工具，然后利用由此建立的通道进行命令与控制。部分入侵还涉及持久化和权限提升。图 5 将这些行为整合为一条通用攻击链。并非每次入侵都发生了所有阶段。

威胁行为者如何部署和运行 GSocket

初始访问和部署： 威胁行为者利用面向互联网的 Web 应用，并使用 curl 下载和执行远程脚本。该脚本对主机进行画像，选择与系统架构匹配的 GSocket 客户端，将其暂存到可写路径或内存支持路径（如 /dev/shm），并通过 Global Socket Relay Network 建立加密的出站命令与控制通道。

防御规避和持久化：威胁行为者将 GSocket 伪装成内核线程样式的进程名，通过 cron、systemd、shell 配置文件、看门狗和冗余副本实现持久化，随后删除暂存文件及其他部署痕迹。

权限提升：在以 web-service 账户获得执行权限后，在少数观察到的安全事件中，威胁行为者试图利用 CVE-2026-43284——近期出现的 Linux 内核漏洞之一，也称为 Dirty Frag——将权限提升至 root。

GSocket 如何在没有固定 C2 地址的情况下重新连接

GSocket 使用共享密钥而非 IP 地址或主机名来标识端点。在安装期间，部署脚本通常会生成一个随机密钥并将其写入标准输出。威胁行为者可以选择从控制台读取该密钥，将其重定向到临时文件并在文件被删除前取回，或者通过受支持的通知通道传送该密钥，例如 Telegram（使用 GS_TG_TOKEN 和 GS_TG_CHATID 配置）、Discord 或 webhook。掌握该密钥后，操作人员之后可以从任何兼容的 GSocket 客户端重新连接，而无需知道受害者的 IP 地址、主机名或网络位置。

传统反向 shell 会连接到载荷中写入的、由威胁行为者控制的 IP 地址。GSocket 则从共享密钥派生其连接标识符和认证材料。受害主机和操作人员各自主动连接到 Global Socket Relay Network（GSRN），后者将二者匹配并为端到端加密会话进行协调。两个端点都不需要公共 IP 地址、入站监听器或宽松的入站防火墙规则。

因此，仅屏蔽 IP 地址或域名不太可能切断访问。该连接依赖共享的中继服务、通常会被允许的出站流量，以及无需硬编码到载荷中的密钥。任何掌握共享密钥的人都可以通过中继重新连接，而无需知道受害主机的 IP 地址或主机名。

缓解与防护指南

对于受影响的 Linux 服务器，修复工作应同时处理初始入侵和 GSocket 部署问题。

  1. Patch and harden internet-facing applications. Keep web applications, CMS platforms, plugins, and application servers current. Remove unused components and restrict file-upload and administrative paths.
    • 同时修复主机和漏洞。 不要将应用程序补丁视为完整的修复措施。调查并移除 GSocket 客户端、相关持久化机制和暂存文件，然后验证对中继基础设施的出站连接已停止
  2. 修补并加固面向互联网的应用程序。 保持 Web 应用程序、CMS 平台、插件和应用服务器为最新版本。移除未使用的组件，并限制文件上传路径和管理路径。
  3. 限制出站流量。 应用默认拒绝的出口规则，仅允许访问必需的目标，并监控与中继基础设施之间的连接。
  4. 加固主机运行时。 在可行的情况下，将临时目录和基于内存的目录挂载为不可执行，并对从隐藏路径或全局可写路径执行操作的行为发出警报。
  5. 审计持久化入口。 检查 cron 条目、使用看似合理服务名称的 systemd 单元以及 shell 启动文件。持久化通常会分布在多个机制上，因此仅停止正在运行的进程并不能消除访问权限。
  6. 优先对面向互联网的服务器进行本地权限提升漏洞修补。 在分析到的活动中，威胁参与者尝试利用 CVE-2026-43284，从 Web 服务账户提升至 root。与此同时，Microsoft FORGE Lab 最近记录了 59 个 Linux 内核漏洞报告，其中包括八个漏洞；研究人员已在受控环境中展示针对这些漏洞的本地 root 权限提升利用程序。
  7. 在 Linux 上启用 Microsoft Defender for Endpoint。 保持实时保护与云提供的保护处于启用状态，并启用行为监控，以检测 Web 服务的异常子进程以及伪装成其他身份的过程。

Microsoft Defender 检测结果

Microsoft Defender for Endpoint 可提供与 GSocket 相关 Linux 入侵活动的可见性，包括可疑 shell 执行、有效载荷投递、持久化、防御规避和远程通信。以下警报是在所分析的遥测数据中观察到的。单条警报不能确定初始访问方式，也不能确认入侵的每个阶段均已成功。

高级搜寻查询

Microsoft Defender XDR 客户可以使用以下查询来发现与 GSocket 相关的活动。这些查询使用由 Microsoft Defender for Endpoint 填充的公共高级搜寻表，涵盖在所分析入侵事件中观察到的部署模式。

应结合进程父子关系、执行上下文、持久性变更和相关网络活动，对匹配结果进行上下文调查。

GSocket 进程活动

按名称或命令行查找 GSocket 工具。

DeviceProcessEvents
| where Timestamp > ago(7d)
| where FileName has_any ("gs-netcat", "gsocket")
    or ProcessCommandLine has_any ("gsocket.io", "gs-netcat", "gsnetcat")
| project Timestamp, DeviceName, AccountName, FileName, FolderPath,
    ProcessCommandLine, InitiatingProcessFileName
| order by Timestamp desc

安装程序下载活动

查找用于获取 GSocket 的下载并执行模式。

DeviceProcessEvents
| where Timestamp > ago(7d)
| where ProcessCommandLine has "gsocket.io"
    or ProcessCommandLine has "gsgg.b-cdn.net"
| project Timestamp, DeviceName, AccountName, FileName,
    ProcessCommandLine, InitiatingProcessFileName
| order by Timestamp desc

与已观察分发主机的连接

这些是工具分发端点，而非威胁行为者拥有的命令与控制服务器。

DeviceNetworkEvents
| where Timestamp > ago(7d)
| where RemoteUrl has_any ("gsocket.io", "gsgg.b-cdn.net")
| project Timestamp, DeviceName, ActionType, RemoteUrl, RemoteIP, RemotePort,
    InitiatingProcessFileName, InitiatingProcessAccountName
| order by Timestamp desc

已知文件哈希

匹配入侵指标部分公布的 SHA-256 哈希。

let badSHA256 = dynamic([
    "d94f75a70b5cabaf786ac57177ed841732e62bdcc9a29e06e5b41d9be567bcfa",
    "f95c4d029e6784e3849b4d1e2e2ae1a661187236ef7c5d487c71158a290a03b5",
    "55d141bb2f62c527c3fea3413b8429fed7d52633d0b123b5e611bfa42165229f",
    "12450bafc7a4398040e1ad3a16dbf4dbc79b6a8f83ef306c4f0f73f59886f06c"
]);
DeviceFileEvents
| where Timestamp > ago(7d)
| where SHA256 in~ (badSHA256)
| project Timestamp, DeviceName, ActionType, FileName, FolderPath, SHA256,
    InitiatingProcessFileName, InitiatingProcessCommandLine
| order by Timestamp desc

暂存和持久性痕迹

在缺少哈希或使用不同构建版本时很有用。

DeviceFileEvents
| where Timestamp > ago(7d)
| where FolderPath startswith "/dev/shm/.gs-"
    or FileName in~ ("systemd-remount-d", ".gsn_ora", "defunct", "defunct.service")
| project Timestamp, DeviceName, ActionType, FileName, FolderPath, SHA256,
    InitiatingProcessFileName, InitiatingProcessCommandLine
| order by Timestamp desc

观察到的 MITRE ATT&CK 技术

在所分析的入侵事件中观察到了以下技术。并非每次入侵都发生了所有技术，而且某些结果（例如重启后的持久性和成功建立中继会话）并非在每种情况下都得到确认。

初始访问

  • T1190 利用面向公众的应用 | 面向互联网的 Web 应用遭到利用，使攻击者能够在 Web 服务上下文中执行命令。后续命令作为 Web 服务器和应用运行时进程的子进程启动，这与利用暴露应用的行为一致。

执行

  • T1059.004 命令和脚本解释器：Unix Shell | 命令使用 curl 获取 GSocket 安装脚本，并通过 bash 执行。
    后续的 bash 调用启动了重命名后的有效载荷。

执行、持久性

  • T1053.003 计划任务/作业：Cron | 在检测到 GSocket 部署脚本活动的同一检测时间窗口内创建了 Cron 条目，与持久性机制一致。

持久性

  • T1543.002 创建或修改系统进程：Systemd 服务 | 活动启动了一个 bash 命令，调用重命名后的 /usr/bin/defunct 有效载荷，并引用了 defunct.service 和 multi-user.target.wants 链接。

防御规避

  • T1036 伪装 | 一个名为 GsNetcat 的二进制文件以 systemd-remount-d 运行，该名称类似系统服务。在另一个执行上下文中，bash 使用 exec -a 将 /usr/bin/defunct 呈现为参数零名称 [kaluad]。
  • T1564.001 隐藏痕迹：隐藏的文件和目录 | gs-netcat 有效载荷被暂存在以点号开头的 /dev/shm/.gs-0 目录下。还在 /tmp/.gsn_ora 观察到一个由 GsNetcat 检测到的文件。
  • T1222.002 文件和目录权限修改：Linux 和 Mac 文件和目录权限修改 | chmod 更改了重命名后有效载荷的权限，包括 chmod 700 /usr/bin/defunct。
  • T1070.006 指标清除：时间戳篡改 | touch 命令为 /usr/bin/defunct 和 defunct.service 应用了较旧的时间戳。时间戳复制操作针对系统服务样式的载荷名称。
  • T1070.004 指标清除：文件删除 | rm 删除了暂存的 /dev/shm/.gs-0/gs-netcat 文件，另一条 rmdir 命令删除了暂存目录。

命令与控制

  • T1105 传入工具传输 | curl 从 GSocket 分发端点将 gs-netcat 载荷下载至 /dev/shm/.gs-0。
  • T1090.002 代理：外部代理 | GSocket 客户端启动时使用了可建立到 Global Socket Relay Network 出站会话的选项。该网络是一个共享的公共中继，在受感染主机与操作人员之间代理连接。该中继属于第三方基础设施，并非威胁行为者所有。
