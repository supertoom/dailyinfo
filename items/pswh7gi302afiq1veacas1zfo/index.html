Cisco Secure Email Gateway SQL 注入漏洞

严重

CVE-2026-76461

CWE-89

下载 CSAF

电子邮件

概述

  • Cisco Secure Email Gateway 所用的 Cisco AsyncOS Software 中的电子邮件解析存在一个漏洞，可能允许未经身份验证的远程攻击者在底层操作系统上以 root 权限执行任意命令。

    此漏洞源于电子邮件解析逻辑中的验证不足。攻击者可通过发送包含恶意 SQL 语句的特制电子邮件消息来利用此漏洞。成功利用可能允许攻击者执行任意 SQL 语句，进而在底层操作系统上以 root 权限执行命令。

    Cisco 已发布解决此漏洞的软件更新。没有可解决此漏洞的变通方案。

    本公告可通过以下链接获取：
    https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-esa-inj-2bLVGmhX

受影响的产品

  • 此漏洞影响 Cisco Secure Email Gateway 的物理和虚拟设备，与设备配置无关。

    有关哪些 Cisco 软件版本易受此漏洞影响的信息，请参阅本公告的 Fixed Software 部分。

    据已知，只有本公告 Vulnerable Products 部分列出的产品受此漏洞影响。

    Cisco 已确认此漏洞不影响以下 Cisco 产品：

    • Secure Email and Web Manager
    • Secure Web Appliance

入侵指标

  • 要确认是否存在尝试利用此漏洞的情况，请检查 mail_logs 并查找可疑的 SQL 语句。如果设备是集群的一部分，请检查每个集群设备的日志。以下是在日志中检测恶意 SQL 语句的方法示例（并非涵盖所有情况）：

    cisco-esa> grep -i "COPY.*TO PROGRAM" [IronPort Text Mail Logs Log name - Default: mail_logs]

    输出中出现任何条目都可能表明存在恶意活动。

    在 Cisco Secure Email Cloud 上，无 CLI 访问权限的管理员可能无法独立检查所述入侵指标。Cisco 已直接联系拥有检测到恶意活动的 Cisco Secure Email Cloud 设备的客户。

    注意：成功利用此漏洞后，威胁行为者可能获得以 root 权限执行命令的能力。由于拥有此级别的访问权限，威胁行为者可能会删除或隐藏利用证据和入侵指标。Cisco 强烈建议管理员交叉检查受影响设备之外的网络日志和防火墙日志，以识别任何潜在的可疑活动，包括但不限于从受影响设备发起到外部 IP 地址的意外上传，或从恶意 IP 地址进行的下载。

变通方案

  • 没有可解决此漏洞的变通方案。

Fixed Software

  • Cisco 认为，任何变通方法和缓解措施（如适用）都只是临时解决方案，直到可以升级到包含修复的软件版本。为修复此漏洞并避免按照本公告所述在未来面临暴露风险，Cisco 强烈建议客户升级到本公告中指定的已修复软件版本。

    可使用设备基于 Web 的管理界面中的 System Upgrade 选项通过网络升级软件。

    要使用基于 Web 的管理界面升级设备，请执行以下操作：

    1. 选择 System Administration > System Upgrade。
    2. 单击 Upgrade Options。
    3. 单击 Download and Install。
    4. 选择要升级到的版本。
    5. 在 Upgrade Preparation 区域中选择适当的选项。
    6. 单击 Proceed 开始升级。进度条将显示升级状态。

    升级完成后，设备将重新启动。

    要使用 CLI 升级设备，请执行以下操作：

    1. 运行 upgrade。
    2. 输入 DOWNLOADINSTALL。
    3. 选择要升级到的版本。
    4. 在升级过程中选择适当的选项。

    升级完成后，设备将重新启动。

    Cisco Secure Email Cloud

    Cisco Secure Email Cloud 服务解决方案包括 Cisco Secure Email Gateway 以及 Cisco Secure Email and Web Manager 设备。Cisco 会对该解决方案中包含的产品进行定期维护。客户也可以联系 Cisco Secure Email Cloud 支持团队申请软件升级。

    Cisco 已将所有 Cisco Secure Email Cloud 设备升级到 Release 16.5.0-780。

建议

  • 本地部署的物理设备

    如果怀疑 Cisco 物理设备遭到利用，Cisco 建议联系 Cisco 技术协助中心 (TAC) 以获得进一步支持。为加快我们对此潜在入侵事件的调查，请确保受影响设备已启用远程访问。有关更多指导，请参阅 Cisco ESA/WSA/SMA 远程访问常见问题。

    本地部署的虚拟设备

    如果怀疑 Cisco 虚拟设备遭到利用，Cisco 强烈建议在可能的情况下采取以下操作，将设备恢复到安全配置：

    1. 按照客户的事件处理策略保留取证信息。重要：在继续执行以下任何步骤之前记录取证信息。部署新实例将销毁配置和日志。
    2. 部署运行已修复软件版本之一的新虚拟机。
    3. 重新构建产品配置。
    4. 更新设备上安装的凭据和所有密码学材料。
    5. 继续监控系统是否出现异常行为。

    注意：Cisco Secure Email Gateway 设备可以是集群的一部分。SSH 密钥对用于集群成员之间的身份验证。成功利用此漏洞后，用于此类通信的 SSH 私钥可能会在已失陷设备上被访问。获取这些密钥可能使攻击者得以入侵其他集群成员。因此，Cisco 强烈建议将包含至少一个已失陷设备的集群中的每个成员恢复到安全配置。

    如果无法恢复设备，Cisco 建议联系 Cisco TAC 以获得进一步支持。

    如果未怀疑遭到利用，而设备正在运行受影响的软件版本，Cisco 强烈建议升级到已修复的版本。

    Cisco Secure Email Cloud

    Cisco 已对属于 Cisco Secure Email Cloud 的设备开展全面的威胁情报调查。对于发现可能入侵指标的 Cisco Secure Email Cloud 设备，Cisco 已直接联系其客户。Cisco 正在开展修复和恢复操作。Cisco 已在 Cisco 的管理范围内部署缓解措施。

    此外，Cisco 强烈建议已被联系的客户在可能的情况下，通过更新凭据以及设备上安装的任何加密材料，将设备恢复至安全配置。

    此外，Cisco 强烈建议限制对设备的访问，并实施稳健的访问控制机制。

    强化安全的一般建议

    • 将设备升级到最新版本的 Cisco AsyncOS Software。
    • 阻止从互联网访问设备。如果必须从互联网访问设备，应将设备访问限制为仅允许用户指南中列出的已知可信主机，并仅使用其中列出的端口和协议。
    • 对于 Cisco Secure Email Gateway，请将邮件功能与管理功能分别置于独立的网络接口上。这样可以降低未经授权的用户访问内部管理网络的可能性。有关更多信息，请参阅设备用户指南。
    • 将 Cisco Secure Email Gateway 和 Cisco Secure Email and Web Manager 设备置于防火墙等过滤设备之后，并过滤进出这些设备的管理流量，同时仅允许已知且受信任的主机向这些设备发送流量。使用双层防火墙可以在网络规划中提供灵活性，从而避免最终用户直接连接到外层 DMZ。有关详细信息，请参阅 Cisco Secure Email Gateway 和 Cisco Secure Email and Web Manager 用户指南的“部署”部分。
    • 定期监控日志流量，检查是否有任何进出设备的异常流量。如有可能，应将日志发送到外部服务器，并保留足够长的时间，以便在事件后开展调查时能够获得充分的日志数据。
    • 为主管理员门户禁用 HTTP。
    • 禁用任何不需要的网络服务，包括 HTTP 和 FTP。有关特定服务功能的更多信息，请参阅 Cisco Secure Email Gateway 和 Cisco Secure Email and Web Manager 用户指南。
    • 对设备使用强度较高的最终用户身份验证方式，例如 SAML 或轻量级目录访问协议 (LDAP)。有关更安全的身份验证方法，请参阅 最终用户访问垃圾邮件管理功能的身份验证选项。
    • 将默认管理员密码更改为更安全的变体。根据必要的访问权限要求创建用户账户，以限制对管理员账户的访问。此外，为所有管理员创建操作员账户。
    • 使用 SSL/TLS，从证书颁发机构 (CA) 获取 SSL 证书或创建自签名证书。
