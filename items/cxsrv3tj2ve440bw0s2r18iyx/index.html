PHP 周四按照其四周更新计划发布了一批新的安全补丁，其中包括针对七个严重级别远程代码执行（RCE）漏洞的修复。

首个漏洞是 CVE-2026-115560，该漏洞于上个月公开披露，时间比 PHP2Shell 补丁发布晚两天。它存在于会话上传进度功能中，攻击者可利用一种会话序列化格式写入攻击者数据，随后再使用另一种格式读取这些数据。

PHP 公告称：“不匹配的解码器可能会将部分会话密钥解释为序列化对象数据。拥有合适对象 gadget chain 的应用程序随后便能以 PHP worker 的权限执行代码。”

下一个漏洞是 CVE-2026-129481，被描述为会话关闭被中断后发生的释放后使用（use-after-free）。PHP 称，这是对 CVE-2026-109619 的不完整修复；后者是十月修复的两个 PHP2Shell 漏洞之一，目前已被广泛利用。

PHP 提醒称：“攻击者如果能够以这种方式导致应用程序的会话清理失败，就可能破坏内存或使被重用的 PHP worker 崩溃。该释放后使用漏洞可能导致远程代码执行，但尚未展示通过这一特定字段实现代码执行。”并补充说明，PHP 8.2 不受影响。

另一个释放后使用漏洞 CVE-2026-129182 涵盖了利用过期全局状态针对 CVE-2026-109619 实施 RCE 的更多攻击场景。不过据 PHP 表示，尚未展示通过这些场景实现 RCE。

该漏洞影响 PHP 8.5 及更高版本。CVE-2026-129474 是一个释放后使用漏洞，可能允许未认证攻击者触发致命错误并实现 RCE。PHP 表示：“利用取决于具体应用程序，并要求攻击者能够控制足够多的请求数据，以影响内存分配、触发可访问的魔术方法调用，并在相关位置引发致命错误。”

攻击者如果能够影响会话内容，并中断向会话文件写入序列化数据的过程，就可能在下次打开会话时触发对攻击者所控内容的反序列化。该漏洞编号为 CVE-2026-126714，可能通过应用程序中合适的对象 gadget chain 导致 RCE。

PHP 还修复了 CVE-2026-129289。这是一个 PHP-FPM 请求走私问题，源于 PHP 以惰性方式读取请求体流，将请求体视为已在请求关闭期间得到处理，并跳过用于丢弃未读输入的常规清理流程。

PHP 解释道：“在重用持久 PHP-FPM 或 LSAPI 连接之前，PHP 可能未能丢弃 HTTP 请求体中未读取的字节。在 PHP-FPM 中，未认证攻击者可以使这些字节构成一个独立的 FastCGI 请求，从而绕过前端路由，并以 worker 的权限执行攻击者控制的 PHP 代码。”

今天修复的第七个严重级别漏洞 CVE-2026-129496 存在于时区缓存中。PHP 在进程启动期间向 PHP 错误日志文件写入诊断信息时，可能会保留对时区缓存的引用；之后的一条诊断信息可能会在缓存重置前访问已释放的缓存。

PHP 解释道：“在受影响的配置中，远程攻击者可以触发内存损坏、导致 worker 崩溃，并可能以 PHP worker 的权限执行任意代码。”

PHP 8.6.0 和 PHP 8.5.13 已发布，修复了所有严重漏洞以及 10 个高危和中危漏洞。多数问题的补丁也已包含在 PHP 8.4.28、PHP 8.3.37 和 PHP 8.2.36 中。更多信息可在 PHP 的新闻归档页面获取。
