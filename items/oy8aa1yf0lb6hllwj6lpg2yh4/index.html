Swati Khandelwal2026年11月19日漏洞 / 企业安全

据 Broadcom 今天发布的一份公告，VMware vCenter 中的一个严重漏洞可让拥有网络访问权限的攻击者绕过身份验证并未经授权访问该系统。Broadcom 是 VMware 的所有方。

所有受支持分支均已推出修复版本，但该公司未列出任何变通方案。vCenter 是用于管理组织 ESX 主机和虚拟机的中央控制台。

该漏洞的跟踪编号为 CVE-2026-123890，在 CVSS 评分系统中的评分为 9.8。公告称：“VMware vCenter 的 VMware Directory Service 中存在身份验证绕过漏洞。”

在随公告发布的常见问题中，该公司表示，该问题“按照 ITIL 方法属于紧急变更”，并敦促组织立即就实施时间咨询其安全人员。

该公司尚未报告任何利用该漏洞的攻击，也未报告任何公开的漏洞利用代码。它也没有说明攻击者在绕过身份验证后可获得何种级别的访问权限。报告该漏洞的功劳归 Google 旗下的 Mandiant。

该漏洞存在于 vCenter 8.0、9.0 和 9.1 中，也存在于随 VMware Cloud Foundation、vSphere Foundation 以及 Telco Cloud Platform 和 Telco Cloud Infrastructure 产品提供的 vCenter 构建版本中。这包括较早的 Cloud Foundation 5.x 系列。无论是否使用 Enhanced Linked Mode，该漏洞都存在。

较旧版本不在修复范围内。该公司不再评估已过支持期限的版本，并表示应假定 vSphere 6.5 和 6.7 受到影响。vSphere 7.0 同样如此；该版本已于 2025年10月结束常规支持，其客户可根据 extended support 合同申请补丁。

公告常见问题称，这五个漏洞均不允许从虚拟机内部在 ESX 主机上运行代码，ESX 本身也不受影响，详情见公告常见问题。

对于暂时无法更新的系统，没有后备方案：在被问及是否存在变通方案时，常见问题回答“Not as listed by Broadcom”，同时指出，组织的自身防御措施中可能仍存在缓解方法。

这些更新是累积更新，无法通过 vCenter Quick Patch 安装。安装更新期间，虚拟机会继续运行，但管理访问会短暂中断，并且针对 Standard Key Provider 的某些加密操作在 vCenter 恢复上线前将不可用。

一项警告适用于已在进行中的升级：安装 vCenter 8.0 U3m 或 9.0.2.0200 会阻止之后升级至 VMware Cloud Foundation 9.1.1；常见问题将这种冲突称为“Back-in-Time”问题。可选方案是先将 vCenter 升级至 9.1.1 并在那里应用安全更新，或者短暂等待 VCF 9.1.2 发布。

这是今年 VMware Directory Service 中第二个严重的身份验证绕过漏洞。根据此前披露的 vCenter 漏洞，于 7月29日修复的漏洞包括 CVE-2026-59309；根据7月公告，这是同一组件中另一个评分为 9.8 的身份验证绕过漏洞，此外还有一个目录遍历漏洞 CVE-2026-59310。

德国事件响应公司 QUIRSO 在 8月评估称，该遍历漏洞披露五天后便出现了针对它的攻击，并以中等置信度将其与一个疑似与中国有关联的攻击组织联系起来。

8月攻击影响了 47 个国家约 361 个 IP 地址，并在 ESXi 主机上部署了源自 Babuk 的勒索软件。Broadcom 报告称，尚未发现针对新绕过方法的攻击。

该公告还修复了四个严重程度较低的漏洞，评分为 6.7 至 8.1：SDDC Manager 中的 SQL 注入（CVE-2026-123891）和命令注入（CVE-2026-123892）、SDDC Manager 设备上提权至 root（CVE-2026-123893），以及 Windows 版 VMware Tools 中的 SAML 令牌签名绕过（CVE-2026-123894），后者仅在配置了 Guest Alias 映射的情况下才可利用。每个漏洞都需要已认证或已具备权限的攻击者，而最后一个漏洞的影响范围仍局限于客户机虚拟机内部。
