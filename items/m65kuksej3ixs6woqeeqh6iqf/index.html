Critical Red Hat Quay Flaw Lets Attackers Read and Overwrite All Private Container Images in a Registry

中文原文

Red Hat Quay 中的一个严重漏洞允许能够访问 Quay registry 的攻击者读取并覆盖每个 repository 中的私有 container images。

Quay 默认启用匿名访问；在启用期间，攻击者无需账户。Red Hat 昨日表示，关闭此功能后，任何拥有有效账户的人仍可利用该漏洞。该公司已为八个 Quay 3 branches 发布了修复版本。

该漏洞被追踪为 CVE-2026-123710 （CVSS score: 9.8）。

Quay 使用其信任的密钥对允许推送和拉取 images 的 access tokens 进行签名。该漏洞允许攻击者将自己的密钥添加到 Quay 信任的密钥中，且无需设置过期日期。随后，Quay 会接受使用该密钥签名的、适用于任意 repository 的 tokens。

借助这些 tokens，攻击者可以获取 private images，以及其中存储的任何 secrets 或 credentials。攻击者还可以推送或覆盖 images，且更改会传播到之后拉取这些 images 的每个系统。

植入的密钥在重启后仍会保留，直至有人将其删除。它还可用于删除正在运行的 Quay 实例所使用的密钥，导致正常的推送和拉取开始因 authentication errors 而失败。

Quay 的 key server 会检查替换密钥的请求是否携带了由可信密钥签名、且具有预期 audience 和 issuer 的 token。它不会检查该 token 是否为密钥轮换而签发。来自 Quay /v2/auth endpoint 的 anonymous token 可以通过检查：Quay 使用可信密钥对其签名，而调用方可以自行选择其 audience。

第二个严重漏洞 CVE-2026-110697（CVSS score: 9.9）于同时披露。它允许能够创建 namespace 的 Quay 用户窃取其他 tenants 的 robot account tokens，并使用这些 tokens 读取、推送或覆盖这些 tenants 的 images。

该漏洞存在于列出 robot accounts 的代码中。它根据 namespace 名称构建 SQL LIKE pattern，却没有对 wildcard characters 进行转义；而在 SQL LIKE 中，下划线可匹配任意单个字符。

因此，一个在恰当位置包含下划线的 namespace 可以匹配另一个 tenant 的 namespace，并返回其 robot accounts 及其解密后的 tokens。攻击者无需 elevated privileges，受害者也无需执行任何操作。

删除攻击者的 namespace 也会删除相应的 robot accounts，从而可能使依赖它们的系统中断。该公司表示，在 Quay 作为 OpenShift 的 integrated registry 时，被盗取的 robot credentials 可用于向 CI/CD pipelines 注入恶意 images。

这两个漏洞均由 Red Hat 的 Dave O'Connor 发现。据该漏洞的 bug report，CVE-2026-123710 背后的逻辑自 Quay 首次公开提交以来就已存在。

Red Hat 将 Quay 3 和 Quay 5 的每个版本都列为受这两个漏洞影响。对于 CVE-2026-123710，其指南指出 standalone installs、由 OpenShift 上的 Quay Operator 部署的 Quay，以及 Red Hat OpenShift 的 mirror registry 均受影响。

该公司表示，任何 untrusted clients 能够访问的 Quay 实例都存在暴露风险，包括 internal registries。

今天检查时，CVE-2026-123710 的 CVE entry 仍显示每个 Quay package 都受到影响，且没有修复，尽管每份 advisory 都列出了该漏洞。

该公司建议采取以下步骤：

  1. 在 proxy 或 load balancer 处，除 trusted internal components 外，阻止所有对 /keys endpoint 的访问。
  2. 在 audit logs 中搜索 expiration_date 为 null 的 service_key_rotate 和 service_key_delete events。
  3. 移除任何你不认识的 approved service keys。
  4. 安装已修复的版本。在其运行之前，攻击者可以用同样的方式添加一个新密钥，因此删除一个密钥并不能长久奏效。

“关闭匿名访问并不能保护你，”该公司在其密钥修复文章中表示。被植入的密钥在重置密码和更改机器人令牌后仍会继续有效。

对于 CVE-2026-110697，该公司的CVE 页面将同样的八个版本列为已修复版本，称更新是唯一的完整修复方案，并表示 Quay.io 已经修复。但这八份公告均未列出 CVE-2026-110697。

在更新部署之前，该公司建议限制谁可以创建包含下划线的组织或命名空间，为任何与下划线命名空间匹配的命名空间轮换机器人令牌，并留意不符合正常机器人使用情况的拉取或推送操作。这些措施可以降低暴露风险，但漏洞仍然存在。

上游修复添加了缺失的轮换检查，要求通过密钥服务器添加的密钥必须具有到期日期，并阻止调用方选择令牌的受众。同样的更改也修复了机器人账户搜索问题。
