执行摘要

攻击者正在现实世界的攻击活动中将自主 AI 智能体武器化，由此带来的风险直到不久前还仅停留在理论层面。2026 年 7 月至 9 月，我们识别并跟踪了 10 多起全球性攻击活动，其中不同攻击者部署自主 AI 智能体来增强其攻击。这些智能体式 AI 攻击者以机器速度运作，将攻击生命周期从数周或数天压缩至短短数小时。

这些攻击活动针对多个行业，包括政府、物流、酒店、制造、农业和教育。在观察到的每一起攻击活动中，攻击者都是通过部署在存在漏洞的 Web 应用程序中的 Web shell 获得了初始立足点。

所观察到的智能体式攻击活动的创新之处并不在于技术手段，而在于速度和效率。这些 AI 驱动的操作人员使用熟悉的开源工具和轻量级自定义脚本，沿着阻力最小的路径前进，在以机器规模运作的同时达到了熟练人类攻击者的技术水平，有时仅在几分钟内就能执行数百条不同的命令。

然而，使用 AI 智能体也牺牲了行动的隐蔽性。这些智能体留下了 unmistakable 的行为指纹，暴露出非人类操作人员的参与，包括：

  • 结构化的机器可读输出格式
  • 自适应漏洞利用选择
  • 迭代式改进
  • 出现在 shell 命令中的思维链推理注释

智能体式攻击背景

是什么让攻击具备智能体特征？

智能体式 AI 攻击者是一种自主 AI 系统——通常是一个具备工具调用能力的大型语言模型 (LLM)——能够在没有持续人工指导的情况下独立规划、执行并调整攻击序列。remote

与响应单个提示的聊天机器人不同，智能体式 AI 系统在一个循环中运行：它们观察自身环境，推理下一步该做什么，采取行动，然后观察结果，为下一步提供依据。

智能体式攻击者如何改变威胁格局

智能体式 AI 的武器化由于多种原因加大了安全威胁：

  • 速度和规模：智能体式 AI 攻击者以机器速度运作。在我们观察到的攻击活动中，AI 智能体在数分钟内执行了数百条不同的命令。
  • 降低了进入门槛：攻击者只需提供高层级指导，AI 智能体便可自动完成复杂的技术阶段。这包括编译内核漏洞利用、执行跨平台横向移动以及系统性攻陷云基础设施等复杂操作。
  • 自适应推理：基于脚本的攻击遇到意外情况时会失败，而智能体式 AI 攻击者会运用推理，在失败后尝试替代方法。我们观察到，当较早的提权方法失败时，智能体依次尝试了五种不同的权限提升技术；当预构建二进制文件无法奏效时，它们还在目标主机上编译了自定义漏洞利用代码。
  • 跨领域能力：单个智能体式 AI 攻击者可以跨 Linux、Windows、各种云平台、Web 应用程序、数据库和网络基础设施开展操作。这种广泛的技术能力通常需要一支专家团队。
  • 威胁归因面临新挑战：由于 AI 智能体会即时生成独特且动态的载荷，且不具备明显的行为指纹，将攻击归因于特定威胁行为者正变得越来越困难。

智能体式 AI 攻击周期

我们分析了 2026 年 7 月至 9 月期间观察到的 10 多个攻击活动，结果表明，最成功的入侵始终将人类监督与 AI 智能体结合在统一的作战模型中：

  1. 人类设定目标：人类操作员确定目标并提供初始访问权限——通常是针对存在漏洞的 Web 应用程序植入 Web shell。在某些情况下，人类操作员会执行对目标的首次评估。
  2. AI 智能体接手：AI 智能体自主执行进一步侦察、凭据收集、权限提升和横向移动。
  3. AI 智能体汇报：AI 智能体使用机器可读的输出格式整理发现，并定期通过编排 API 进行联络。
  4. 人类作出战略决策：人类操作员审查 AI 智能体的发现，并制定高层级战略。这可能包括指示智能体以支付系统为目标或建立持久化访问。
  5. AI 智能体执行：AI 智能体以战术自主性落实人类的战略指令。

智能体式 AI 攻击的常见特征

对我们观察到的 AI 辅助攻击活动进行比较分析后，发现了若干明确的作战标志。这些特征是判断攻击者为智能体而非人类操作员的强有力指标：

  • 攻击速度
  • 使用分节标题
  • 描述过于详尽的注释

命令执行速率

由 AI 操作员实施的攻击最显著的特征之一，是其能够快速执行大量命令。

在我们调查的一次攻击中，AI 攻击者仅在两天内的 140 分钟内处于活动状态。在这短暂的时段内，攻击者从通过 Web shell 初始访问，推进到执行侦察并枚举受害者的云环境、网站和数据库。在整个攻击过程中，AI 代理以非人的速度执行了约 800 条唯一命令。

在另一个持续 12 天的活动中，攻击者执行了超过 8,000 条唯一命令。

为了了解人类操作员与 AI 操作员在运行速度上的差异，我们检查了所观察攻击的两个阶段之间命令间隔中位数。在所分析攻击的一个子集中，第一阶段由人类操作员进行手动侦察和连接检查，命令间隔中位数为 23.9 秒。

在攻击的第二阶段，行动被移交给代理式 AI 攻击者。一旦由 AI 操作员接管，命令间隔中位数便降至 1.4 秒。图 2 显示了两个阶段之间命令间隔中位数的差异。

标题和分隔符

在我们观察的每场活动中，AI 操作员都会在 shell 命令和脚本中使用分节标题，例如 ===[Title]===。这些标题有助于 AI 更快地解析所执行命令的结果。在人类操作的攻击中，此类标题很少出现，通常只有在攻击者使用预先编写好的脚本时才会看到。

图 3 展示了 AI 操作员执行多条命令的一个示例，其中使用分节标题分隔命令的输出。

思维链注释

代理式 AI 生成代码的一个常见指标，是在技术脚本中嵌入“推理注释”。在观察到的超过一半活动中，我们发现了多个包含对话式、逐步推理说明的脚本。如图 4 所示，这些说明解释了 AI 操作员执行脚本的逻辑。

野外代理式 AI 攻击的运行趋势

除了用于区分 AI 操作员与人类攻击者的行为指纹外，我们的调查还揭示了一致的运行趋势。尽管目标组织各不相同，代理式 AI 攻击者仍遵循相似的行动手册：

  • 跨平台移动
  • 严重依赖 Web shell 来获取初始立足点并维持持久化 C2
  • 实时调整策略
  • 明确表现出对已部署安全产品的认知

以下各节详细介绍了我们在调查的不同活动中观察到的趋势。

多平台攻击

许多观察到的攻击始于 Linux Web 服务器，但很快扩散到其他平台。每场活动都旨在目标网络内尽可能广泛地扩展，无论目标采用何种平台或技术。这说明 AI 代理持续降低了经验不足的操作员的进入门槛。人类攻击者可能需要数年才能掌握每种操作系统（OS），而代理式 AI 可以无缝地在不同操作系统之间移动，甚至攻陷云基础设施。

滥用云平台

我们的调查发现，代理式 AI 攻击者正在三大云提供商上滥用云服务。我们评估认为，这种利用具有自适应能力——代理发现云平台后，在没有任何预配置的情况下转向针对该平台的技术。

在一次针对一家美国酒店和博彩公司的攻击活动中，AI 代理在发现一个 AWS EC2 实例角色后，试图通过实例元数据服务（IMDS）窃取凭据。当 IMDSv1 被阻止后，该代理立即调整策略，切换到获取 IMDSv2 token，并在多次迭代尝试后成功。

认证成功后，该 AI 代理枚举了八个区域中的 20 项 AWS 服务，窃取了受害者存储桶、邮件服务和密钥管理的信息。枚举功能是存储桶的一项基础能力，但在本案中被用于恶意目的。此外，在配置文件中发现 S3 存储桶名称后，该代理立即将支付和金融数据路径作为目标。

这种有针对性的转向表明，人类操作者指示该代理优先处理高价值金融资产。如图 5 所示，Cortex XDR 检测到该代理式 AI 攻击者生成多个进程，枚举受害者的支付资源。

我们判断，人类操作者仅指示 AI 代理收集信息，为未来更具攻击性的接管行动做准备，因为并未采取任何有害行动。我们观察到，该 AI 代理测试了向生产云环境写入数据的能力，并立即删除测试文件，同时检查存储桶的策略和访问控制列表（ACL），以确定该存储桶是否可公开访问或是否存在可利用的策略。

多操作系统入侵

AI 代理还展示了在单条攻击链中跨多个操作系统运行的能力。在一次观察到的攻击活动中，AI 代理最初通过 PHP web shell 入侵一台 Linux 服务器，并能够利用窃取的 SMB 凭据转向另一台 Windows IIS 服务器。横向移动速度极快：在识别 Windows IIS 服务器后的两分钟内，该代理便开始通过 SMB 部署 ASPX web shell。在接下来的 26 分钟内，它将 web shell 推送到了服务器上的 40 多个位置，在五种不同的 web shell 变体之间轮换，并上传自定义 web.config 文件以启用脚本执行。

自适应和战略性攻击

代理式 AI 攻击者比旧式模型和自动化工具更强大的一个特点，是代理能够根据发现的情况调整策略。

在一次攻击活动中，我们观察到该 AI 代理展现出尤其自适应的策略：在利用初始受害者后，该代理自主识别并攻击了受害者的 IT 供应商及其姐妹组织。

在服务器上初步立足后，该 AI 代理在受害者已遭入侵的 web 服务器上发现了该供应商自托管 GitLab 实例的凭据。该代理立即转向，探测供应商的网站，通过 WHOIS 绘制基础设施图谱，并尝试暴力破解访问该供应商的 GitLab 实例，试图针对该供应商的客户群实施供应链攻击。

在一次暴力破解尝试中，该代理使用了市场团队成员的真实姓名。这种定向行为表明，该 AI 代理可能开展了额外的开源情报（OSINT）收集，以识别特定员工。GitLab 中没有任何漏洞遭到利用；这些凭据是通过已遭入侵的第三方 web 服务器泄露的。

当 AI 智能体读取服务器的 NGINX 虚拟主机配置时，它在同一内部网络上发现了十多个相关的姊妹公司实体。随后，它系统性地探测了每个实体：

  • 从登录门户收集 CSRF 令牌
  • 尝试使用从主要目标窃取的密码复用凭据
  • 针对母公司管理面板运行四个迭代式 SQL 注入脚本

除了战略规划之外，智能体 AI 攻击者还能根据新信息迅速升级并定制攻击。这种适应性包括：

  • 快速创建自定义载荷
  • 转向新的攻击向量
  • 迅速应对工具和脚本故障

在另一个案例中，我们观察到一名智能体 AI 攻击者使用名为 scan.sh 的脚本执行端口扫描。端口扫描仅 21 秒后，智能体便运行了第二个名为 scan2.sh 的脚本。第二个脚本包含定制化的侦察命令，与第一个脚本在每个端口上发现的确切技术相匹配。图 7 展示了两个脚本的内容。

基于 Web Shell 的入侵

在分析的所有攻击活动中，初始网络访问均通过在面向互联网的 Web 服务器上部署 Web Shell 来实现。这一趋势反映出人类操作人员在编排智能体 AI 操作时倾向于利用 Web Shell。Web Shell 提供了一种直接的方法，可在机会主义攻击期间大规模建立初始立足点。

作为 Web Shell 的替代方案，攻击者可以使用反向 Shell、远程访问木马（RAT）或远程监控与管理（RMM）软件，在受害者机器上建立立足点。然而，这些方法通常需要投入更多操作工作和资源来创建与维护。

在某些案例中，我们观察到 AI 智能体并未依赖已编译的植入程序发送命令，而是自行投放并使用 Web Shell。这为智能体提供了持续代码执行能力和持久性。

动态命令编码

鉴于 Web Shell 被广泛用作初始立足点，后续载荷通常使用 Base64 编码进行混淆——这是基于 Web Shell 入侵中的一种标准技术。任何通过 Web Shell 的 sh -c 接口传入多行代码的攻击者都会对其进行编码，以避免代码因 Shell 元字符、引号和特殊符号而中断。智能体 AI 攻击者与人类操作人员的区别不在于编码本身，而在于其生成编码载荷的数量、独特性和多样性。

在典型的人类操作 Web Shell 入侵中，攻击者可能通过 Base64 交付少量预写工具，这些工具可重复使用，且常以相同哈希出现在多个受害者处。然而，在我们调查的智能体攻击活动中，模式有所不同：AI 智能体在单次攻击会话中交付了 40-100 个独特的 Base64 编码载荷，每个载荷都针对特定目标的资产进行了定制。不同受害者之间的载荷没有任何两个完全相同，也没有任何载荷与已知工具签名相符。

规避技术与安全意识

虽然命令执行量大、速度快会使智能体 AI 攻击者显得“嘈杂”，但它们明确展示了对已部署安全产品的认知。除了试图规避传感器外，智能体攻击者现在还会主动探测其配置，了解检测工具的执行边界，并尝试调试安全工具为何阻止某项操作。我们在多个攻击活动中都观察到了这种具备安全意识的行为，相比过去观察到的自动化攻击 Represents 了显著升级。

EDR 路径排除

在一次观察到的攻击活动中，该 AI 智能体有意在文件发现命令中排除了端点检测与响应（EDR）目录。如图 8 所示，该智能体在六个已失陷端点上执行了相同的 find 命令，排除了三家不同安全厂商的路径。

值得注意的是，同一智能体还运行了单独的安全工具枚举命令，检查是否存在 16 种不同的安全扫描器（nmap, nessus, openvas, nikto, masscan, nuclei, lynis 等），在继续攻击之前绘制防御态势。

直接 EDR 侦察

我们的调查发现，AI 智能体从简单规避转向对已安装安全栈进行主动侦察的情况有多个案例。这些智能体有条不紊地探查端点监控解决方案，以绘制其运行边界，具体表现为以下观察到的行为：

  • AI 智能体试图枚举并窃取端点的安全产品本地目录，专门搜寻敏感配置数据和已存储的凭据。
  • 在展示迭代式调试时，该智能体对 Microsoft Defender for Endpoint 进程（wdavdaemon）使用了 strace，分析内核级系统调用，以逆向推断该守护进程如何监控环境活动。

缺少自定义工具和恶意软件

在我们的攻击活动分析中，最有趣的成果之一是我们未发现的东西。尽管在调查过程中提取了数百个独特的脚本有效载荷，但我们没有找回任何一个已编译后门、自定义 C2 框架、DLL 植入程序或 shellcode 加载器。

在大多数情况下，AI 智能体的全部自定义武器库都由相对简单、一次性的脚本组成，例如 PHP Web shell、PowerShell WMI 后门或 Python 凭据收集器。这与高级攻击者惯常的工具特征不同；高级攻击者通常会投入编译型、持久化植入程序，以实现长期访问。

与这些攻击者不同，观察到的智能体 AI 攻击者会即时生成专用脚本，并根据当时发现的内容进行调整。因此，攻击者并未使用单一的“通用型”植入程序来侵入受害者网络，而是通过规模较小、单步执行的脚本逐步推进。Cortex XDR 检测展示了智能体 AI 攻击者如何在同一进程链下生成并部署不同类型的脚本，如图 9 所示。

依赖开源工具和漏洞利用

尽管我们观察到许多智能体 AI 攻击者即时生成自定义代码的情况，但这些攻击活动通常都会先使用现有的开源工具，之后才转向编写自定义代码。

一个反复出现的例子是 Copy Fail 漏洞利用（CVE-2026-31431），这是 Linux 内核中的一个漏洞，出现在此次观察到的行动所针对的多个组织中。在三个不同案例中，AI 代理都尝试直接从外部来源下载该漏洞利用——要么通过漏洞利用的官方 GitHub 仓库，要么通过漏洞利用的网站。

在另一种攻击序列中，AI 代理首先上传了预编译的 PwnKit 二进制文件，并尝试了多种调用方式。当该二进制文件运行失败后，代理获取了一个预编译的 CVE-2024-1086 权限提升漏洞利用。只有在用尽这两个公开二进制文件后，AI 代理才开始在目标上编写自定义 C 源代码，并逐一尝试不同的编译器和链接器。当编译尝试同样失败后，代理又尝试用 Python 重写该漏洞利用的逻辑。

在另一个将开源工具与自定义载荷结合的案例中，AI 代理采用了类似但层次更多的方法。在无法执行预编译的 CopyFail 来获取本地权限提升后，它直接在目标上从源代码编译了 PwnKit 漏洞利用。随后，为进行网络侦察，代理编写了自定义 C 网络探测工具（charon_lite.c），并基于该工具、使用开源的 paramiko 库构建了自定义 Python 喷洒脚本。

AI 代理增强型攻击中的操作者指纹

随着 AI 代理增强型行动的兴起，依靠静态载荷特征和行为追踪来识别行动正变得越来越困难。我们建议采用其他方法来识别代理式 AI 行动，重点依据人为意图、操作失误和基础设施关联性。

在研究过程中，我们没有发现能够将代理活动与特定 LLM 模型或编排框架联系起来的行为标记。尽管 Base64 载荷投递和系统化侦察命令等攻击模式具有一致性，但其实现方式过于多样，无法提供独特的行为指纹。由于 AI 生成的代码是为每个目标定制的，基于特征的归因在很大程度上无效。

然而，显然这些代理式基础设施背后有人类操作者。由人类决定攻击哪个目标、何时启动行动以及要攻陷哪些资产。除了操作意图之外，人类操作者及其 AI 代理还会持续留下关键痕迹，为归因提供重要线索：

  • Infrastructure
    • 载荷中硬编码的 C2 地址：在某些情况下，AI 代理会将攻击者控制的 IP 地址和网络范围直接嵌入生成的恶意软件载荷和 Web shell 中。在一次行动中，C2 服务器 204.194.54[.]240 同时出现在 PowerShell 下载脚本和 cURL 探测命令中。
    • 代理编排基础设施：对硬编码的 204.194.54[.]240 C2 服务器进行枢转后发现，该服务器还托管着一个 CyberStrikeAI 实例；这是一个 AI 原生攻击性安全平台。CyberStrikeAI 的存在使我们能够确定使用了特定的编排平台。这属于仅凭行为分析无法提供的基础设施层面的归因。
    • 跨活动基础设施重叠：恶意使用 204.194.54[.]240 并非孤立事件。ReliaQuest 最近的威胁研究记录了同一 IP 在另一次由智能体驱动的攻击中充当暂存和侦察节点。他们的调查还指出，该地址上存在 CyberStrikeAI 登录页面，以及托管权限提升工具的开放目录，证实这一特定基础设施被用于多个智能体攻击活动。
  • Toolset
    • 攻击者环境中意外暴露的文件路径：在一次攻击活动中，我们观察到一个本地文件路径被意外粘贴出来：/home/kali/exploitmasteryai/targets/warranty/shell5.php。exploitmasteryai 这一路径片段是整个攻击活动中唯一能够明确指示该 AI 攻击框架身份的具体指标，而它的暴露完全源于一次操作安全失误。
    • 代码注释中的语言痕迹泄露：攻击者以多种语言与 AI 智能体交互，因此会生成使用这些语言的代码注释。防御者可以将其视为人工操作攻击活动中的母语注释等痕迹。在我们遇到的一个示例中，攻击者使用了两个完全相同版本的 WMI 后门——一个包含中文注释，另一个较新的版本则被明确指定只能使用英文。图 10 展示了这两个版本的 WMI 后门。

结论

智能体 AI 攻击不再是理论层面的担忧，而是正在积极威胁众多行业的现实威胁。我们观察到的攻击活动针对政府、物流、制造、酒店、教育和农业部门。所有攻击都采用了相同的方法：由人类操作员将一个 AI 智能体指向存在漏洞的 Web 应用，随后由该智能体接手后续行动。

我们所观察到的情况并不意味着攻击复杂度出现了全新类别。这些技术本身与熟练的人类攻击者所采用的技术相同。智能体遵循成熟的攻击流程、依赖已知 CVE，并使用人类操作员多年来一直使用的相同开源工具。

智能体 AI 攻击的根本差异在于其速度、规模，以及快速高效适应不同类型平台和操作系统的能力。这些优势使智能体攻击者能够在短短数小时内彻底攻陷网络，即便是经验丰富的攻击者通常也需要数天或数周。

然而，在我们目睹的攻击中，智能体攻击者留下了人类操作员不太可能留下的明显指纹。这些迹象包括思维链注释和特定的内容分隔符。搜寻这些迹象可能有助于防御者识别并阻止这一威胁。

归根结底，防御智能体 AI 攻击需要借助 AI 驱动的防御手段，因为这类攻击形式多样，需要一种无论涉及何种工具、技术或平台都能识别相关模式的解决方案。

Palo Alto Networks 防护与缓解措施

Palo Alto Networks 的客户可通过以下产品获得更好的保护，从而应对上述威胁：

  • Advanced URL Filtering、Advanced DNS Security 和 Advanced IP Defense 旨在识别与此类活动相关且被视为恶意的已知域名、IP 和 URL。
  • Next-Generation Firewall 搭配 Advanced Threat Prevention 安全订阅，可通过以下威胁防御签名 97176，按照最佳实践帮助阻止 CVE-2026-31431。
  • Cortex Agentic Endpoint Security 旨在帮助发现代理式终端中的每一种 AI 工件和 AI 代理活动，评估其风险，执行预防和运行时控制，并开展修复。
  • Idira Privileged Access Management (PAM) 旨在统一管理人员、机器和代理式身份的特权访问，从而保护多云环境中的云访问。它基于成熟的 PAM 构建，在提供集中式机密管理的同时，还提供即时访问和零常驻权限等现代控制机制。这确保了跨本地部署、云和 SaaS 目标的一致最小权限安全。
  • Idira Endpoint Privilege Manager (EPM) 可帮助企业降低风险、满足合规要求并简化运维。它通过策略驱动的权限提升和常驻管理员权限移除来帮助落实最小权限，同时阻止危险操作，例如执行未经审查的应用程序和访问其他进程的内存，同时提供可用于审计的证据和统一身份治理。
  • Idira Secrets Manager 旨在帮助即时保护并自动化管理 API 密钥和 Webhook 令牌，从而消除硬编码凭据并防止数据外泄。

Cortex XDR 和 XSIAM

在代理式 AI 攻击者时代，安全供应商和防御者必须采取主动方法，并开始以 AI 对抗 AI。在整个调查过程中，我们使用了多种 AI 增强型解决方案来追踪、调查和防止这一威胁。

Cortex XDR 的 AI 引擎每天分析数十亿条用户、系统和安全事件，自动生成精准的高保真防御规则。凭借机器级的速度和规模，它有助于消除手动工程瓶颈，并在威胁站稳脚跟之前将其化解。图 11 展示了 Cortex XDR Console 如何利用 AI 生成的检测结果标记 AI 辅助的恶意活动。

Cortex XDR 和 XSIAM 旨在利用先进的端侧小语言模型 (SLM) 实现实时语义代码理解，从而帮助防止本文所述的威胁。

网络攻击正越来越多地由 AI 生成，这意味着编程语言和基本语法已不再构成威胁行为者的边界；他们现在可以轻松自动化生成新型载荷。为应对这些攻击，Cortex XDR 首个可商用端侧 SLM 使用数亿个样本进行了训练，涵盖热门脚本语言、实时恶意软件包以及前沿 AI 生成的网络攻击。
