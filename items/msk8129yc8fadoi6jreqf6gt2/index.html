Google Ads 投放虚假 Codex 与 Claude Code 下载页面攻击 Mac 用户

Malicious Google Ads Target Mac Users with Fake Codex and Claude Code Downloads

AI 导读

Cato Networks 发现攻击者通过 Google Ads 投放 Codex、Claude Code 和 Homebrew 的虚假下载广告，利用流量 cloaking 向部分访客展示恶意安装器。

文章还原了 Google 赞助搜索中的虚假下载链路，并披露流量 cloaking、脚本下载及复用基础设施等关键环节。

正文 · AI 翻译
中文原文

Cato Networks 的研究人员调查恶意 Google 广告时发现，在合法企业的已验证身份下出现了 Codex、Claude Code 和 Homebrew 的虚假下载，这些企业似乎与这些软件毫无关联，且出现在恶意赞助的搜索结果中。

在与 Hackread.com 分享的研究中，Cato 的研究人员指出，他们在一户健康与营养业务公司的账户主页下截获了一条虚假的 Codex 广告，而该账户同时还在推广该公司自己的产品。这条 Codex 广告中还包含了其健康类推广的措辞。“广告中的不一致之处十分显眼，”Cato Networks 在这篇博客文章中指出。

Cato 认为，攻击者要么对广告主的 Google Ads 账户进行了钓鱼，要么滥用了他们的身份来运行这次活动，这意味着该公司“也可能成为受害者”。

研究人员追踪了搜索“claude code mac download”时显示的一条 Google 广告，发现它最终导向了一次ClickFix 攻击（即用户被诱骗运行恶意命令，从而导致设备被感染）。

在该案例中，搜索生成了若干广告，将访问者重定向到 parentpreneurxcom，在那里用户被要求将一条命令复制到 macOS Terminal 中以安装软件。

有意思的是，这一重定向并未向所有人显示相同的页面。通过流量伪装，部分访问者会收到虚假安装程序，部分访问者则看到无害内容，这很可能是为了规避检测。类似的 Google 重定向也指向了虚假的 Homebrew 站点 homebrexwin.com 和 storageprofiler.com。

Cato 发现部分虚假的 Claude 和 Codex 网站使用了相同的域名。例如，Basequill9.com 同时出现在 Claude 和 Codex 的下载链中。Stride25.com 被用于另一对站点，而两个 Codex 页面则共用 Plume-compass.com。

虚假的 Claude 安装程序使用了一个隐藏的 web 地址，从 vine-96.com 获取一个脚本。该脚本一旦通过 macOS 的 zsh shell 运行，就会向 Mac 下载一个名为 helper 的文件，并将活动数据发送至 grove-satin.com。Cato 发现这一过程与一种Atomic macOS Stealer (AMOS)感染方式存在相似之处，但无法确认此次活动中的所有恶意软件都是 AMOS。

此外还有其他手法。一款虚假的 Codex 下载使用了 TALLY 应用作为诱饵。一个恶意磁盘镜像中包含一个名为 DayNote 的应用，它通过 jsDelivr 从 GitHub 获取进一步的指令。在另一次针对 Claude 的攻击中，攻击者使用 JavaScript for Automation (JXA) 下载了伪装成 Finder.app 的恶意软件。Cato 无法确定这些攻击背后的人是否存在关联。

Cato 于 2026 年 11 月 6 日开始通知相关服务提供方。Cloudflare 确认已对已报告的 URL 限制访问。截至 11 月 11 日，研究人员检查的 GitHub 仓库和 jsDelivr 资源已无法访问。

这次活动表明，一次日常的软件搜索可以多么轻易地让用户下载到恶意软件。在这些案例中，攻击者并不需要绕过macOS 安全机制。他们依靠的是用户自行按照安装说明操作并运行命令。
