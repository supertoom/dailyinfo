执行摘要

Unit 42 发现了一场多阶段网络间谍活动，自至少 2025 年 7 月以来一直针对东南亚政府实体。我们将该活动追踪为 TGR-STA-0049（同时追踪为 REF7707、Earth Alux、Ink Dragon）。该活动背后威胁行为者的标志性特征是针对政府实体，并结合使用先进的自定义有效载荷，这些有效载荷专为高隐蔽性的情报收集行动而设计，重点在于规避安全检测工具。

我们调查的这场活动表现出高度的作战隐蔽性和新颖的工具集。

此前与该组织相关的活动包括投放 Squidoor（又名 FINALDRAFT）——一个自 2023 年以来用于针对全球高价值目标的高级后门。

近期，与该组织相关的活动已扩展其攻击手法。我们观察到的相关活动包括投放两个此前未有文档记录的自定义远程访问木马（RAT）：PerfectPioneer RAT（发现于 2025 年 7 月）及其模块化后继 KUKURAT（于 2026 年 3 月投放）。

TGR-STA-0049 的背景

TGR-STA-0049 至少自 2023 年 3 月以来一直处于活跃状态。它主要针对高价值行业，包括东南亚、南美洲和欧洲各地的政府组织。针对战略实体开展数据收集和窃取，并结合先进的隐蔽 techniques 与长期持久化，是网络间谍活动的典型特征。

在此前的行动中，该组织部署了 Squidoor，这是一款针对 Windows 和 Linux 系统的后门。随着该组织扩大其行动范围，它继续将新工具和恶意软件变种整合到其工具集中。在其最近一次始于 2025 年年中的行动中，攻击者引入了两个此前未公开的先进恶意软件家族，专为隐蔽、数据收集和数据窃取而设计：PerfectPioneer RAT 和 KUKURAT。随着此次行动推进至 2026 年初，该威胁行为者开始将其基础设施从 PerfectPioneer 迁移至新的 KUKURAT，后者自 2026 年 3 月以来已在野被发现。

我们发现了该组织所跟踪的六个不同 PerfectPioneer RAT 变种：

  • newhttp3
  • PerfectRat
  • Pioneer
  • RatAAkk-tt
  • rat_http3_ls
  • rat_http3_cc

所有六个变种至少自 2025 年 7 月以来一直迭代演进，呈现出快速且适应性强的发展周期。我们的分析聚焦于 newhttp3，将其作为代表性示例。

我们考察了此次近期 TGR-STA-0049 行动中观察到的 TTP，并梳理完整的行动生命周期，包括：

  • 初始感染向量
  • 采用 HTTP/3 作为通信协议
  • 凭据收集与数据窃取方法

我们还将深入解析 PerfectPioneer RAT 和 KUKURAT 恶意软件家族的底层架构与专用能力，重点包括：

  • PerfectPioneer RAT 独有的 isDangerousCommand 防误操作机制，可防止恶意软件操作员执行侧重取证或破坏性的命令。
  • KUKURAT 广泛的模块化框架。
  • KUKURAT 对自动化启发式伪装引擎的集成。

感染向量

此次活动背后的攻击者采用双轨感染策略，通过服务器漏洞利用和网络钓鱼相结合的方式，在目标组织内部建立并维持立足点。

服务器漏洞利用是此次行动中观察到的主要感染向量，例如利用存在漏洞且未打补丁的 Microsoft Exchange 服务器和 Web 服务器来部署 Web Shell。我们观察到其中混合使用了定制和公开可用的 Web Shell，包括 ASPXSpy、Godzilla、Bysunue.aspx 和 Suo5 的各个变种。这些工具与该行为者过往行动中所使用的相一致。

HTTP/3 的采用

PerfectPioneer RAT 和 KUKURAT 都以 HTTP/3 作为与 C2 基础设施通信的主要方式。尽管 HTTP/3 在更广泛的恶意软件领域很少被采用，但此次活动中的部署反映了高级威胁行为者之间一种新兴趋势。部署 HTTP/3 可提供：

  • 安全且快速的通信通道：HTTP/3 使用运行于 UDP 之上的 QUIC 传输协议。
  • 有效的防御规避机制：由于 HTTP/3 使用 UDP，企业网络防御系统无法在不中断底层连接的情况下进行被动 TLS 拦截。一些企业防火墙和传统 IDS/IPS 引擎尚未更新，无法像检查标准 TCP 流量那样严格检查 UDP 流量。当旧版安全策略未专门针对基于 TCP 的 Web 通道进行优化时，向外发送的 UDP 443 端口通信通常会完全绕过深度包检测，从而可能使恶意 QUIC 流量不受阻碍地传输。

PerfectPioneer RAT 深入分析

至少自 2025 年 7 月以来，与此次活动相关的组织一直在部署 PerfectPioneer RAT，这是一个定制的基于 Go 的恶意软件家族。我们考察了该 RAT 在受感染主机上的执行方式，并探讨了一个代表性变种的架构和行为。我们对六个不同迭代版本的结构进行比较，展示了该对手持续活跃的开发流程。

加载器与执行

除了作为可执行文件被释放到磁盘外，我们还观察到攻击者在已攻陷网络中通过三种方式执行 PerfectPioneer RAT：DLL 侧加载、诱饵安装程序和网络钓鱼。这种战术多样性凸显了威胁行为者的运营敏捷性，能够针对不同环境优化目标欺骗和防御规避。

  • DLL 侧加载：攻击者释放了一个合法且无害的可执行文件，并对其结构进行修改，将使用 XOR 加密的 shellcode 嵌入其中，其中包含 PerfectPioneer RAT 载荷。一个恶意加载器 DLL 随该被修改的二进制文件一同释放。执行后，被修改的合法应用会加载被侧加载的 DLL，该 DLL 从遭篡改的宿主可执行文件中读取、解密并执行 shellcode。随后，shellcode 在内存中部署载荷。
  • 诱饵安装程序：该行为者使用诱饵软件安装程序将 PerfectPioneer RAT 后台代理释放到磁盘并执行，同时运行看似正常的应用程序安装向导。在一个案例中，我们发现一个诱饵软件安装程序将 GlobalProtect 安装程序写入磁盘并执行。这一合法的 Palo Alto Networks 安全远程访问产品被用作掩护，同时 PerfectPioneer RAT 的可执行文件被写入磁盘并在后台执行。
  • 网络钓鱼：毫无戒心的目标从伪装成政府官方网站的不同域名下载了多个恶意软件样本。为规避检测并欺骗受害者，这些可执行文件被伪装成 PDF 文件，并显示 PDF 图标。当受害者尝试打开该 PDF 文件时，实际上点击的是恶意软件；它会启动一个诱饵 PDF 文档，以维持合法性的假象，而恶意软件则在后台运行。

自愈连接架构

PerfectPioneer RAT 实现了三个高度具体的自动化例程，用于维持稳定连接、管理系统开销、尽量减少其取证痕迹并保持低调。

  • 重连例程：此例程通过跟踪一个名为 connected 的内部变量，确保与 C2 的连接保持活动状态。如果由于网络中断，心跳检测或命令轮询例程将 connected 变量切换为 false，重连例程便会立即介入。它会取消当前的心跳和命令轮询循环，然后强制执行与 C2 服务器的干净重新注册工作流，试图强制重置连接状态。
  • Cleanup routine: Designed to limit the malware's forensic footprint on disk and prevent excessive consumption of host memory, this routine achieves its goals via two automated methods:
    • 清理临时文件：持续跟踪并删除运行期间创建的所有临时文件。这可以尽量减少在磁盘上生成持久性痕迹，并缩短终端检测工具或取证分析人员从文件系统中恢复已缓存运行数据的机会窗口。
    • 清理内存占用：监控 RAT 的活动内存占用。如果内存使用量超过 100 MB，它会明确强制触发 Go 运行时的垃圾回收周期，以积极清除未分配的内存。保持较低的进程内存占用，可以降低因 CPU 使用率过高而引起怀疑的可能性。
  • 资源监控例程：此例程代表操作员跟踪客户端的 CPU 和内存利用率。每 30 秒捕获一次性能快照，远程操作员之后可通过特定命令获取该快照，以监控主机负载。

isDangerousCommand 防错机制

isDangerousCommand 是我们在分析中发现的最引人注目且前所未有的特性之一。作者将它实现在两个特定的变体中，并将这两个变体命名为 Pioneer 和 rat_http3_cc。

在执行来自 C2 的任何传入命令之前，isDangerousCommand 例程会将该指令与硬编码命令列表进行交叉比对。如果发现匹配项，该命令将被完全阻止。阻止列表包含一些管理命令，如果执行，将具有高度破坏性或引发大量取证活动（噪声），而安全工具可能会监测到这些活动。加入这一操作层面的“安全开关”，可防止操作人员犯错而导致活动被发现。

KUKURAT：深入剖析最新模块化后门

2026 年 3 月，该威胁行为者将一个明确命名为 KUKURAT 的新自定义有效载荷引入多个已被 PerfectPioneer RAT 攻陷的网络。

KUKURAT 使用 C++ 编写，我们在野外发现了两个 KUKURAT 变种。尽管其核心功能相似，但这两个变种采用不同的底层网络协议与 C2 通信：一个变种利用 HTTP/2，另一个使用 HTTP/3。

与 PerfectPioneer RAT 不同，KUKURAT 是一个完全模块化的恶意软件框架。几乎每项利用后能力都作为独立的 DLL 模块实现，并在运行时直接从 C2 服务器动态加载。KUKURAT 的代码支持至少 12 个不同的命名模块。

通过仅在需要时才将相关功能直接拉入内存，KUKURAT 实现了高度的规避性和适应性。由于静态核心二进制文件不包含高级功能代码，它能够成功避开标准二进制扫描，同时简化功能更新，并阻止取证分析人员恢复底层有效载荷。

注册与心跳

启动时，KUKURAT 通过连接 /register 节点，向其 C2 基础设施注册，并从受感染终端发布以下系统信息：

  • 主机名

部署独立的 KUKURAT 模块

在调查期间，我们发现攻击者使用 KUKURAT 部署了两个名为 PsExecService.exe 和 SecurityGuard.exe 的可执行文件。尽管我们无法获取 SecurityGuard.exe，但成功恢复了 PsExecService.exe 供分析。

根据该文件的编译程序数据库（PDB）字符串，尽管此二进制文件是作为独立可执行文件而非 DLL 编译的，攻击者仍明确将其归类为 KUKURAT 的外部模块：

d:\proj\KUKURAT\modules\MyPsExec-master\PsExecService\

该工具是一个定制的远程执行服务，似乎可能部分基于开源 MyPsExec GitHub 项目。执行后，PsExecService.exe 会将自身注册为名为 PsExec 的本地 Windows 服务，并创建一个名为 \\.\pipe\PSEXEC 的命名管道。该服务原生支持四种命令：

  • Shell 执行
  • 文件上传
  • 文件下载
  • 目录列表

为了限制其取证痕迹，该服务使用内部自毁计时器，在五分钟无活动后自动卸载服务并清理其痕迹。

伪造终端活动：启发式伪装引擎

KUKURAT 引入了一种独特的启发式伪装引擎，能够跨三个系统维度运行：网络、注册表和文件。该引擎旨在终端上生成看似合法的虚假活动，以伪装恶意软件的实际操作。通过模拟正常操作行为，威胁行为者建立了一个虚假的基线，这可能会显著影响自动化检测和其他取证工作。威胁行为者可以通过 C2 命令 set_obfuscation 开启或关闭每种方法：

  • 网络噪声生成：KUKURAT 在每个操作周期中生成 10 个诱饵 HTTP 请求，目标为从硬编码的 15 个热门网站列表中随机选择的域名，并使用随机生成的 URL 路径。这可以伪装流量，将 C2 通信混入正常的网络噪声中。
  • 模拟浏览器活动的注册表操纵：KUKURAT 通过向注册表路径 HKCU\Software\Google\Chrome\BrowserCrashRecovery 写入随机数据、再将数据读回并随后删除该项，模拟合法的 Google Chrome 浏览器行为。然后，它打开并枚举 HKCU\Software\Google\Update\ClientState 注册表项。这一操作的目的是使该代理的注册表操作看起来像是 Chrome 崩溃恢复。
  • 文件噪声生成：恶意软件持续在系统 %temp% 目录中创建具有随机名称和随机内容的临时文件，随后立即将其删除。该技术生成文件系统噪声，掩盖代理对文件的修改。

尽管这种规避技术的某些要素此前已在多个恶意软件家族中被记录，但 KUKURAT 通过一种高度独特的设计选择与它们区分开来。它能够跨三个独立攻击向量协调启发式伪装，同时在运行时动态启用或禁用各项功能。

看门狗组件

在多起事件中，攻击者都会将 KUKURAT 与一个独立的看门狗可执行文件一起部署，以确保恶意软件持续运行。

当 KUKURAT 的主二进制文件执行时，它会创建一个专用线程，用于与配套的看门狗组件通信。KUKURAT 每三秒将自己的活动文件路径写入一个名为 WINDOW_SEC_WATCHDOG 的本地命名管道。配套的看门狗进程读取该路径，并每秒获取一次心跳消息。如果连续 15 秒未收到心跳，看门狗便认为 KUKURAT 已被终止，并使用缓存的文件路径自动重新启动它。

有一次，我们观察到威胁行为者将该看门狗组件部署到 C:\ProgramData\Cyvera\Ransomware\ 目录路径中。该文件夹结构过去与 Cortex XDR 关联，表明威胁行为者试图通过藏身于安全产品的目录结构中来降低被怀疑的可能性。

变体比较

调查确认了 KUKURAT 的两个不同变体，分别利用 HTTP/2 和 HTTP/3 进行 C2 通信。除了网络传输协议不同之外，这两个变体在结构上几乎完全相同，仅有少数值得注意的代码演进会影响恶意软件的开发适应性和运行存活性：

  • 命令处理架构：在 HTTP/2 变体中，威胁行为者在单个命令处理函数内实现了一条庞大且嵌套的 If-Else 条件链。所有执行和模块加载逻辑都直接嵌入这些条件之中。HTTP/3 变体则转为使用映射至各个命令的函数指针数组，为每项执行例程创建一个独立函数。这一设计转变使恶意软件开发人员能够更高效地即时添加或移除功能。
  • 内置 exec 绕过命令：虽然 KUKURAT 被设计为一款完全模块化的恶意软件框架，能够动态加载代码，但 HTTP/3 变体引入了一个明确的原生编码命令 exec。该命令使攻击者能够通过 CreateProcessA 直接在主机端点上生成子进程，并将生成的终端输出通过管道传回 C2 后端。由于 HTTP/2 变体中不存在此命令，其加入表明作者试图提供一个内置的生存选项：允许操作人员原生运行系统命令，而无需从暂存服务器获取外部模块 DLL。

数据外泄

在系统性地遍历网络并收集高权限凭据后，威胁行动者启动了其主要目标：网络间谍活动。威胁行动者利用 PerfectPioneer RAT 和 KUKURAT 恶意软件家族，试图将大量文档回传至其 C2 基础设施。被针对的数据主要包括 .pdf、.docx、.xlsx 和 .png 文件，其文件名表明内容可能包含敏感信息，尤其关注国际关系和内部政治事务。

结论

TGR-STA-0049 的行动揭示了一个高度适应性的威胁行为体，其目标横跨东南亚的政府基础设施。通过部署 KUKURAT 和 PerfectPioneer RAT，该活动背后的攻击者正不断演进，借助 HTTP/3 以及基于 UDP 的 QUIC 实现协议层级的规避，从而领先于传统网络防御。

使该组织特别难以侦测的，是其在维持行动安全、隐藏于被入侵终端上所投入的大量工作。从 PerfectPioneer RAT 自动化的自愈连接架构，到 KUKURAT 高度复杂的启发式伪装引擎，该组织展现了对现代防御生态的成熟理解。他们甚至在其二进制文件中嵌入了硬编码的管理员安全开关，以防止自家操作员运行可能触发安全告警的、过于喧闹或具破坏性的命令。

最终，该组织的隐蔽技术手法服务于一个更宏观的目标：确保一次高度定向的数据外泄活动取得成功。其特征是该行为体广泛尝试窃取从文件名看似乎属于敏感情报的内容，并利用被入侵的 Exchange 环境中的邮箱冒充权限。

为应对这一新一代的advanced间谍活动，防御者必须超越传统的、以 TCP 为中心的可见性。保护高价值网络需要全面转向：捕获未经授权的基于 UDP 的 Web 流量，严格审计 Active Directory 验证机制，并监控这些以隐蔽性为重的活动在主机层面留下的行为异常。

Palo Alto Networks 防护与缓解

为更好地防范 TGR-STA-0049 所使用的 TTP，各组织应考虑实施以下网络层与主机层行为控制措施：

  • 监控或限制 QUIC 并强制协议回退： 网络管理员应配置边缘防火墙，要么记录并检查 QUIC 流量，要么彻底阻断出站的 UDP 443 端口。阻断会强制 HTTP/3 和 QUIC 通信平滑回退到基于 TCP 的 HTTP/2 或 TLS 通道，从而确保标准的深度包检测与解密引擎能够原生监控该流量。
  • 审计 Active Directory 登录脚本： 安全地并持续审计 sysvol 共享与组策略对象（Group Policy Objects）是否被未经授权地修改。配置 EDR 平台，以便在用户身份验证期间对以域用户 SID 执行的可疑进程发出告警。
  • 监控盲目的 LSASS 内存转储方式： 创建行为检测规则，追踪 rundll32.exe 与 comsvcs.dll 的交互，以捕获绕过标准基于字符串的文本过滤的按序号调用方式（例如 #+000024）。
  • 审核 Exchange 模拟与访问权限：定期运行验证脚本，审查被分配了 ApplicationImpersonation 角色的账户。监控 Exchange 日志中 Add-MailboxPermission 命令的执行情况，特别标记那些自动循环、在整个组织范围内授予账户 FullAccess 权限的操作。

Commands Blocked by isDangerousCommand

The isDangerousCommand foolproof mechanism uses a three-layered protection model to block categories and commands:

Layer 1: Hard-Coded Keyword Filters

This layer blocks a total of 41 explicit destructive, system modification and administrative commands attempted by the operator:

  • Disk destruction:
     Blocks commands that format, wipe or overwrite raw storage.
    Keywords: format, fdisk, mkfs, dd if=, diskpart, cipher /w:, sdelete, wipe, shred
  • Recursive deletion:
    Prevents aggressive, unconstrained file deletion commands.
    Keywords: rm -rf /, del /f /s /q c:
  • System power actions:
    Intercepts commands that would shut down or restart the host, killing the agent's active session.
    Keywords: shutdown, reboot, halt, poweroff, init 0, init 6
  • Denial of service (fork bomb):
    Blocks the classic Linux shell resource exhaustion string.
    Keywords: :(){ :|:& };:
  • Permissions and ownership tampering:
    Blocks broad access modifications targeting root structures.
    Keywords: chmod 777 /, chown root /
  • User and group management:
    Prevents the rogue manipulation, addition, or removal of system accounts.
    Keywords: passwd, su -, sudo su, userdel, useradd, usermod, groupdel, groupadd
  • Service disruption and process killing:
    Filters commands designed to terminate background tasks or wipe automated execution schedules.
    Keywords: crontab -r, systemctl stop, systemctl disable, service stop, killall, pkill -9, kill -9 1
  • Firewall disruption:
    Blocks commands that attempt to flush or reset host-based firewall configurations.
    Keywords: iptables -F, ufw --force reset, netsh firewall
  • Registry and boot configuration manipulation:
    Intercepts Windows-specific administrative tweaks that alter system states or delete sensitive hives.
    Keywords: reg delete, regedit, bcdedit

Layer 2: Malicious Execution Pattern Filters

This layer acts as a heuristic filter, blocking 16 common payload delivery shortcuts, obfuscation attempts and command chaining:

  • Chained deletions:
    Detects attempts to append file removal commands onto logical execution operators.
    Patterns: && rm, | rm, ; rm, && del, | del, ; del
  • Direct device writes:
    Blocks direct outputs to raw Linux terminal paths or data redirection loops designed to suppress error messages.
    Patterns: > /dev/, 2>/dev/null
  • Download-and-execute pipelines:
    Intercepts classic script-staging methods that download and immediately pipe online payloads into a local shell.
    Patterns: curl | sh, wget | sh, curl | bash, wget | bash
  • Encoded PowerShell execution:
    Blocks attempts to run heavily obfuscated, Base64-encoded PowerShell payloads natively.
    Patterns: powershell -enc, powershell -e
  • Silent string echoing:
    Prevents script manipulation shortcuts or automated interactive prompting bypasses.
    Patterns: cmd /c echo, echo y |

Layer 3: Core Directory Staging Protections

The final layer serves as a localized guardrail. It explicitly drops any file removal commands (rm, del, rmdir, rd) if they are directed at one of 12 critical operating system paths required to keep the endpoint stable and online:

  • Linux protected directories:
    /etc/, /bin/, /sbin/, /usr/bin/, /usr/sbin/, /boot/, /sys/, /proc/
  • Windows protected directories:
    c:\windows, c:\program files, c:\program files (x86), c:\system volume information

  2. Startup folder shortcut: Creates a .lnk shortcut file inside the logged-in user's Startup folder.
