Tailscale fixes SSH flaws allowing lateral movement within tailnets

中文原文

Tailscale 是同名热门软件定义网格网络与连接平台背后的公司，目前已为多个漏洞发布修复，其中包括 Tailscale SSH 中的若干漏洞；这些漏洞可能使已经访问网络中某台设备的攻击者，在属于该网络的其他计算机上获得更高权限。

“根据我们的调查，攻击者只能访问 tailnet 策略文件原本已允许建立 SSH 连接的机器，”Tailscale 工程副总裁 Mike Shaver 表示。

关于 Tailscale 和 Tailscale SSH

Tailscale 让个人和组织能够将计算机、手机、服务器及其他设备连接到同一个私有网络（又称“tailnet”），从而可以像处于同一局域网中一样，随时随地安全地相互访问。该解决方案使用 WireGuard 通信协议对数据进行加密和传输。

用户只需在每台设备上安装 Tailscale 应用，并使用现有账户（如 Google 或 Microsoft）登录，该软件即可处理设备之间的加密连接，无需进行复杂的路由器或防火墙配置。

家庭用户通常使用它在外出时访问文件、媒体服务器或安全摄像头。企业则使用它为员工和系统提供对内部资源的受控访问，同时不将其暴露在公共互联网上。

Tailscale 还提供内置的 SSH 服务器，允许用户通过向远程计算机输入命令来进行控制。Tailscale SSH 会结合用户 Tailscale 账户已有的身份信息与管理员设置的访问策略，决定谁可以连接哪些机器。

此功能有助于远程修复家庭服务器或重启停止工作的设备。组织也会使用它，让员工能够管理公司计算机，同时不将其暴露在互联网上。

该 SSH 服务器只能从个人或组织 tailnet 内部的设备访问。

关于这些漏洞

10 月 23 日，Cyberdione Labs 安全研究员 Erica Windisch 发布报告，详细介绍了她在 Tailscale SSH 和其他 Tailscale 功能中发现的漏洞，并将这些漏洞统称为“Tailworm”。

利用这些 SSH 问题的前提是，攻击者已经攻陷了 tailnet 中某台获准访问的设备。此后，攻击者可以利用 Tailscale SSH 获得其他服务器的 root 级别控制权，但仅限于网络策略允许该设备连接的服务器。他们还可以窃取用于注册新设备的密钥，并利用这些密钥添加一台看似合法的恶意机器。

研究人员声称，在实验室测试中，这种访问权限可以从一台设备自动传播到另一台设备，但 Tailscale 对“蠕虫”这一称谓提出异议。Shaver 指出：“相反，更准确的说法应是横向移动，且仅限于 tailnet 策略文件允许的连接。”

该报告还描述了：

  • Conn25 中的一处缺陷。这是一项仍处于预生产阶段的下一代应用连接器功能，Shaver 表示将在发布前修复。
  • 一些拒绝服务问题，任何互联网用户都可以利用它们使自托管的 Tailscale 控制服务器实现崩溃，或阻止新设备加入网络。

该怎么办？

该公司修复了四个漏洞（1、2、3、4），其中包括 Tailscale SSH 问题，并在 Tailscale v1.104.4 中发布了这些修复。

建议用户升级至该版本，并审查其 Tailscale SSH 策略，“确保访问权限仅限于确有需要的用户和设备”，同时考虑为敏感系统启用 Tailscale SSH 的 Check 模式，这样只有在通过额外身份验证检查后才能访问这些系统。
