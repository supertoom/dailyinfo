NCSC 观察到 AI 辅助攻击利用常见弱点加速入侵

Familiar weaknesses, exploited faster: defending against agentic cyber attacks

AI 导读

NCSC 自 2026 年 9 月以来观察到 AI 辅助网络攻击明显增加，攻击者将 ARTEX 等红队框架用于自动化识别和利用互联网暴露资产中的弱点，在数分钟内完成发现到利用，造成服务中断或系统失陷。

中文原文

Kris B， Ellen T， David Chismon

ArtemisDiana，由 Getty Images 提供

自 2026 年 9 月以来，NCSC 已观察到 AI 辅助网络攻击明显增加。多个行业的组织都在报告相关事件，原因是威胁行为者使用“智能体攻击框架”；这些软件最初为红队测试而设计，如今却被应用到了防御用途之外。  

这些事件涉及在短时间内接二连三地对组织的互联网暴露服务和资产进行自动化识别与利用尝试。这导致部分服务中断或系统被攻陷，为攻击者提供了进一步开展智能体驱动活动（或在某些情况下于其网络内开展人工驱动活动）的据点。 

值得注意的是：  

  • 被利用的弱点均非新近出现，也并非新颖漏洞  
  • 智能体可使用的工具都很常见，并未提供典型威胁行为者无法获得的新能力 

真正发生变化的，是威胁行为者能够多快、以多高的持续性发动攻击——借助这些框架，并结合廉价且能力强的开放模型或非法 API 转售服务，其成本极低。 

本博客解释了智能体攻击框架的运用方式、这对网络防御者意味着什么，以及你应采取哪些措施来帮助保护组织。 

什么是智能体攻击框架？

智能体攻击框架允许 AI 模型与一组现成的网络安全工具进行交互，以探测数字系统中的弱点。通常，一个框架会：  

  • 使用 LLM 规划一系列攻击步骤  
  • 针对目标使用这些工具  
  • 获取结果并决定下一步做什么  

截至撰写本文时（2026 年 11 月），此类活动已与 ARTEX 框架联系在一起。该框架是一种多智能体渗透测试和红队工具，最初为经授权的安全测试而开发。相关工具时有时无（其他工具包括 Cairn、PentAGI、RedAmon、Xalgorix 和 Darkmoon），因此本文不会聚焦于某个特定框架，而将重点放在人工攻击者、能力强的模型与框架的组合如何提升能力。  

与不使用工具的人工攻击者相比，智能体加上框架：  

  • 行动迅速（可在几分钟内从发现转入利用）  
  • 搜索全面（会尝试其发现的每一个端点、参数和凭据）  
  • 能从失败中即时学习（会创建记忆、读取错误消息、作出响应并调整下一次尝试）  
  • 大规模运行成本低廉（运行自动化攻击的成本很低）  

这确实意味着如今的框架充满噪声。它们以隐蔽性换取速度，会生成大量流量，并且几乎会与发现的任何目标进行交互，这使它们更容易被检测。如果未来的框架优先考虑隐蔽性，情况可能不会一直如此。  

值得注意的是，目前被利用的问题并非新颖的内存破坏漏洞（甚至也不是已知但未修补的漏洞），  而是组织多年积累的技术债务所导致的、往往未得到缓解的弱点。智能体攻击正在利用一些容易得手的漏洞，例如： 

  • 误将凭据提交到代码仓库 
  • 基础设施即代码 (IAC) 中的配置错误 
  • 默认凭据或缺少身份验证 
  • 滥用 API 中的弱点 

一旦取得初步立足点，攻击者代理便会探查环境，利用组织中的许多凭据对其实际需求而言权限过高，以及网络通常是扁平或相互互联这一事实。 

抵御智能体化攻击框架

组织需要严格的运营纪律，避免因智能体化攻击框架所带来的攻击数量、强度和持续时间而不知所措。回答以下问题将有助于制定整体性防护方案，以保护组织。 

  • 1

    您了解暴露了哪些资产吗？

    智能体会先绘制所有可访问设备和服务的地图。您应当了解哪些系统和服务暴露在互联网上，以及由谁负责管理。NCSC 的资产管理指南可以在这方面提供帮助。 

    被智能体化攻击框架成功攻陷的服务，有时是组织已经遗忘的服务，例如旧网站和遗留设备。组织应定期对其已知资产开展安全审查，并利用内部技能或委托顾问机构对其边界进行侦察。 

  • 2

    能否将服务从公共互联网上移除？

    不要试图单独加固所有服务，而应考虑使服务仅对已认证的用户可用。可以通过以下几种方式实现：

    • 将服务置于身份感知代理之后，最好确保采用强抗钓鱼认证，并遵循现代零信任方法
    • 使用防火墙限制对服务的访问，除非流量来自企业 VPN 或内部网络范围
    • 配置双向 TLS 证书，要求用户在与服务交互之前完成认证

    在大多数组织中，目前可从网络边界访问的大多数服务都可以快速锁定，仅允许员工或合作伙伴访问。随后可有针对性地加固其余无法锁定的服务。如果你假设所有已连接到互联网的资产都存在漏洞，这会如何改变你的安全策略？

  • 3

    能否检测智能体式攻击框架的使用？

    智能体活动通常与人类活动不同：一连串请求后伴随短暂思考阶段，访问的端点和参数种类广泛（包括永远不会奏效的垃圾内容或示例变体），以及错误率上升。你能否关联多个日志来源以检测这些信号？收集并保留检测、调查和恢复事件所需的日志；NCSC 的日志记录指南可以在这方面提供帮助。

    与所有威胁行为者一样，智能体也会留下痕迹，适当的日志记录有助于响应人员了解智能体与其交互了哪些资产以及执行了哪些操作，从而进行修复。与人类威胁行为者不同，AI 智能体会读取收到的每一条错误，并利用这些信息改进下一次尝试。向外部用户显示的错误消息应尽可能少透露信息，以降低下一次行动的效果，因此务必确保错误消息不泄露任何信息。

  • 4

    已知漏洞是否已修补，配置错误是否已修复？

    代理可以非常快速地针对不同目标测试已知漏洞和漏洞利用，因此，对互联网暴露系统的修补速度必须跟上。配置方面也是如此，尤其是身份与访问管理（IAM）设置，它们会在无人察觉的情况下偏离最初的设计。为了帮助识别、确定优先级并修复互联网可访问资产中的漏洞，你可以结合使用 NCSC 的外部攻击面管理指南和我们的漏洞管理指南。 

    通过NCSC 渗透测试计划（CHECK）获得保证的公司可以开展渗透测试，帮助你发现漏洞和配置错误。较小的组织应参考我们的对手模拟指南，以判断其是否适合你的组织。 

  • 5

    你是否已部署机器人质询来保护容易被滥用的目标？

    账户和身份流程、库存管理、结账以及资源密集型端点（例如搜索、报告生成或由 LLM 支持的功能）都是高优先级资产，应通过部署“机器人质询”来保护。这些质询需要人工交互，以防止自动化工具滥用服务。除非风险信号升高，否则质询可设置为低交互级别（对人类用户而言基本不可见）。部署机器人质询时，应在质询触发时提供无障碍替代方案。 

  • 6

    你的 API 是否得到了充分保护？

    机器人质询会在浏览器中呈现，例如登录或提交表单页面；但如果底层 API 未强制执行质询，攻击者就可以直接调用 API 并绕过质询。许多 API 会设置限制，以防止大量请求，例如来自特定 IP 地址的请求。然而，代理通常会轮换代理和 VPN，因此封禁 IP 地址往往无效。你应当： 

    • 对账户、API 令牌和已认证会话应用速率限制 
    • 同时关注行为和数量：大量多样化请求、快速失败或快速重试，其指示性可能不亚于原始数字 
    • 阅读NCSC 的 API 安全指南  

    如果你的组织公开发布代码仓库，请启用提交前自动化，以防止机密被推送。我们关于确保机密不进入代码库以及安全使用云平台的指南可以提供帮助。

  • 7

    谁可以创建账户，创建速度有多快？

    如果任何人都能在几秒内创建账户，那么基于账户的控制措施（包括上述速率限制）很容易被绕过。代理注册新账户的速度与你封禁它们的速度一样快。应考虑限制账户创建速率，并对使用一次性电子邮件服务注册的账户实施更严格的限制。代理可以使用默认凭据，并利用工具暴力破解弱密码。你应按照NCSC 的身份验证指南，使用强身份验证和适当的访问控制来保护账户。

  • 8

    你能否利用代理的持久性？

    使智能体高效的特征，也使其容易受到欺骗。放置在合法用户不应触碰的位置的蜜罐令牌或绊线，在其被使用的瞬间即可触发高置信度警报。智能体不知疲倦的坚持和穷尽式搜索意味着，诱饵系统、焦油坑和伪造的“成功”结果能够耗尽智能体的时间或尝试预算，并使其远离你的真实资产。Microsoft 报告称，在最近一次采用欺骗策略的攻击活动中，欺骗措施减少了到达真实系统的攻击流量。

网络安全基础比以往任何时候都更重要

NCSC 认为，采用 AI 赋能的网络安全能力可以缩小攻击者与防御者之间的差距。我们最近撰文介绍了释放智能体化网络防御的潜力，涵盖威胁检测增强和自动化事件响应等多个领域。然而，由 AI 驱动的防御项目需要时间才能成熟，因此组织不能坐等智能体化防御来 保护自己。AI 赋能的网络防御并非应对智能体化攻击的唯一答案；网络安全基础和基本网络安全卫生仍然是优先事项。 

正如我们在NCSC 的 2026 年《The State of the Cyber Nation》年度回顾中所述，AI 不会使既有的网络安全控制措施过时。事实上，建立稳固的基础比以往任何时候都更加重要。AI 正在使弱点更容易被发现和更快被利用；过去可能多年无人注意的一把被遗忘的密钥或一个未受保护的 API，现在几分钟内就能被发现。 

NCSC 所见到的几乎所有问题，都可以通过实施网络安全最佳实践、应用零信任等现代网络安全方法，以及根据组织的技术和流程切实应用技术控制措施来防范。对于寻求结构化方法组织而言： 

  • 零信任原则有助于防范智能体化攻击；明确验证身份，确保各处均采用最小权限，并部署控制措施时假设攻击者已经进入你的网络 
  • Cyber Assessment Framework帮助负责关键服务或关键职能的组织评估并提升其网络韧性 
  • NCSC 的Cyber Essentials规定了组织应采用的技术控制措施最低标准，这是政府的建议

尽管这些控制措施未必总是部署在正确的位置，但缓解智能体化进攻框架威胁所需的控制措施，对许多组织而言并不陌生。如今的框架可能会被更隐蔽、更强大的框架所取代，工具也会发生变化。但网络安全基础不会改变。 

现在是你抢先应对威胁的机会。思考一下你的组织会如何回答上述问题，并确保你的答案能够抵挡一个永不需要休息、也从不厌倦不断发问的攻击者。
