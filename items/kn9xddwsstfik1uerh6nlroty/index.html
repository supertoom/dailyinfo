Cisco Talos 发现 UAT-12643 使用 Overlord RAT 与 Good Game 窃取加密货币及账号数据

UAT-12643: Suspected North Korea-aligned actor blends blockchain resilience with targeted infostealing

AI 导读

Cisco Talos 发现以牟利为目的的 UAT-12643 使用 Overlord RAT、Good Game 信息窃取器和多加密货币剪贴板劫持器，针对加密货币持有者、游戏平台账号及 VoIP 用户。

值得关注

报告还原了 UAT-12643 的投递链、恶意软件组合、区块链 C2 机制与数据外传方式，可用于识别相似诱饵和失陷迹象。

正文 · AI 翻译
中文原文
  • Cisco Talos发现了与一个以牟利为动机的威胁组织相关联的恶意基础设施，我们正在跟踪该组织，并将其标识为UAT-12643。 
  • 该行为者的武器库包含多种载荷，包括基于Go的Overlord远程访问木马（RAT）、基于Python且内部标记为“Good Game”的信息窃取器，以及一款支持多种加密货币的剪贴板劫持器。 
  • 根据初始攻击载体和载荷的诱导文件名，该威胁行为者可能正在开展一项针对加密货币持有者、游戏平台账户所有者和VoIP软件用户的攻击活动。 
  • Overlord RAT实施了一种命令与控制（C2）韧性技术，将加密的服务器URL嵌入Solana区块链交易备忘录中。

受害者特征   

根据该载荷基于关键词的文件收集能力，威胁行为者可能以欧洲的受害者为目标；该能力专门针对文件名使用英语、法语、西班牙语和葡萄牙语的文档。  

从诱导主题和载荷文件名来看，潜在受害者群体横跨多个行业。当Good Game窃取器执行时，会启动一个诱饵PDF财务报表文件，表明其目标是财务和会计人员。带有Viber木马的安装程序诱导文件针对的是消息平台用户，而名为microsip的其他载荷变体文件则表明其目标是VoIP软电话操作人员，这与呼叫中心或商务电话环境相符。加密货币和游戏用户同样是剪贴板劫持器和信息窃取器的目标。  

与朝鲜关联行为者的潜在联系  

Talos评估认为，UAT-12643是一个与朝鲜关联的高级持续性威胁（APT）行为者，但置信度较低；依据是其战术、技术和程序（TTP）与其他已知朝鲜APT行为者存在重叠。  

在当前攻击活动中，Talos观察到该行为者将Overlord RAT用作其载荷之一。安全研究人员曾在2026年6月报道称，可能属于朝鲜威胁行为者的威胁集群UNK_DeadDrop在此前的攻击活动中使用过Overlord RAT。  

本次攻击活动中观察到的Overlord RAT变体实施了一种利用Solana区块链交易的区块链C2韧性技术。该技术最早在2026年3月被报道，当时由Lazarus APT组织采用。尽管实现方法有所不同（早前使用的是Node.js），但利用Solana交易备忘录的技术始终保持一致。  

Talos了解到，外部安全研究人员在2026年10月报道称，其他威胁行为者在其攻击活动中也使用了Overlord RAT和Solana区块链托管技术。 

威胁行为者基础设施  

Talos观察到，该行为者将恶意文件托管在一台IP地址为“41[.]216[.]188[.]11”的服务器上；该服务器在8000端口运行基于Flask的文件交付服务，支持可续传的字节范围下载，并提供载荷暂存目录。由于该行为者在操作安全方面出现失误，服务器的根文件夹暴露在互联网上；Talos对该暴露文件夹的分析向我们展示了该行为者的工具集，以及C2服务器为不同服务配置的端口号。

该攻击者并未采用将数据传输至 C2 服务器的传统数据外泄方式；相反，被窃取的数据通过两种不同的服务进行外泄。攻击者使用了 discord webhook，该 webhook 会立即收到一条通知，其中包含受害者的指纹信息和一个单击下载链接。被窃取数据的压缩包会上传至“gofile[.]io”，随后攻击者通过下载链接进行访问。  

我们还在暂存目录的样本中发现了该攻击者的 LNK 生成脚本，表明了攻击者制作诱饵的工作流程。该脚本接受一个 payload URL 和图标类型（PDF、Word 或 Windows Update），并生成一个基于 COM 的 LNK，其中包含伪造和隐藏执行。  

初始访问途径 

Talos 发现，该攻击者采用三种不同的方法获取对受害者环境的初始访问权限。他们利用了 Windows 快捷方式、HTA 文件和 XML 文件，使其中嵌入的恶意指令得以执行并授予初始访问权限。在此次攻击活动中，我们并未发现攻击者如何将这些恶意初始访问途径文件传送至受害者的计算机。  

武器化 LNK 

初始访问途径之一是使用武器化 LNK 文件，并搭配从合法系统二进制文件中仿冒的图标，以便在 Windows Explorer 中显示为合法文件。  

该快捷方式文件使用标准 Windows 文档图标冒充 PDF，并滥用 MpCmdRun.exe（Windows Defender 的命令行实用工具）以及参数 -DownloadFile 来获取 payload。由于 MpCmdRun.exe 是经过签名的 Microsoft 二进制文件，因此该下载能够透明地通过应用程序允许列表控制。下载的 payload 将保存为 RuntimeBroker.exe，以混入进程清单中，同时控制台窗口会最小化，不留下任何可见痕迹。  

另一个快捷方式文件通过双扩展名文件名和 Microsoft Edge PDF 图标采用相同的 PDF 伪装，并使用 certutil -urlcache –f 这一单行下载命令，伪装成证书缓存更新。这两个快捷方式均在同一台计算机（win-8oa3ccqae4d）上构建。  

HTA 投放器 

Talos 发现，该攻击者已将 JavaScript HTML Application（HTA）文件武器化，以获取初始访问权限。武器化 HTA 由 mshta.exe 执行，HTA 中的 JavaScript 使用“MSXML2.ServerXMLHTTP”以原始二进制形式获取 payload，并使用“ADODB.Stream”将其写入 %TEMP%\s.exe，随后通过隐藏执行窗口的方式隐蔽执行。 

MSBuild 现 living-off-the-land 二进制工具（LOLBin） 

攻击者还将一个标准的 MSBuild XML 项目文件“dl.xml”武器化，方法是加入一个内联 C# CodeTaskFactory 任务。当通过 msbuild.exe 执行该 XML 文件时，它会在内存中编译并执行 C# 代码，下载器阶段不会向磁盘写入任何中间可执行文件。下载使用伪造的 Microsoft BITS/7.8 User-Agent 字符串，冒充 Windows Update、Microsoft Defender 以及许多第三方更新程序所使用的 Windows Background Intelligent Transfer Service（BITS），使该请求混入常规的后台下载流量中。 

Overlord RAT 分析 

UAT-12643 在此次行动中使用的 Overlord RAT 变种是一种模块化 Windows RAT，由 Go 源代码编译而成。 

其 implemented 的防御规避和反分析技术包括检测内存中执行，以便在沙箱中运行时抑制取证痕迹；以及一种“kill flag”机制，可触发内核级蓝屏死机（BSoD），使该进程在不引发整个系统崩溃的情况下实际上无法被移除。  

RAT 首先验证当前进程是否以管理员权限运行。随后，它为当前进程获取 SeDebugPrivilege。持有该权限后，它直接调用原生 NT 内核 API（NtSetInformationProcess），完全绕过已记录的 Win32 API 层，并在当前进程句柄上将 ProcessBreakOnTermination 信息类设为值 1，表示内核会将该进程视为对系统运行至关重要。启用这些设置后，操作系统会像对待核心 Windows 系统进程一样对待该进程。当用户或安全工具尝试强制终止该进程时，内核不允许其正常退出，而是会立即停止整个操作系统并触发 BSoD，停止代码为 CRITICAL_PROCESS_DIED。  

为了实现持久化，RAT 采用两种方式。主要方式是在当前用户的注册表配置单元下创建 autorun 项，使用随机化的值名指向位于当前用户配置文件应用数据文件夹的 Network 文件夹中的 RAT 二进制文件。第二种方式是通过 Windows 恢复环境 OEM 脚本路径实现启动前持久化。它首先删除自身的任何先前版本，然后直接在 %TARGETOSDRIVE%\Recovery\OEM\ 下设置 OEM 环境。该文件夹是 Windows 恢复环境在执行“重置此电脑”操作时访问的位置。通过将文件放在此处，注册到此目录中的任何内容都会在操作系统恢复之前于 WinRE 中执行。 

目录设置完成后，RAT 会为其有效载荷文件生成一个随机的 20 个字符文件名。每个字符都是从固定字符集中单独随机选取的，因此每次安装都会产生一个名称唯一的文件。选定随机名称后，它会将 RAT 自身的可执行二进制文件作为该有效载荷文件写入 OEM 目录。  随后，它构建 WinRE 用于启动有效载荷的 shell 命令，并将其封装为扩展名为 .bat 的 Windows 批处理脚本。 

cmd.exe /c start %TARGETOSDRIVE%\Recovery\OEM\"random_stub_name"

使用 %TARGETOSDRIVE% 很重要，因为此环境变量仅存在于 WinRE 预启动环境中，并且只能在该环境中正确解析，而在普通 Windows 中并不存在。这意味着该命令是专门为在恢复阶段运行而编制的，而不是在常规会话期间运行。  

在修改任何系统配置之前，它会备份现有的 WinRE 重置配置文件。最后，它会修改控制 WinRE 在重置期间行为的 ResetConfig.xml 文件。如果尚不存在配置文件，它会从头创建一个；如果已存在，则会对其进行修补，将恶意批处理脚本作为已注册的 OEM 任务追加进去。从此以后，每当受害者通过 Windows 设置或恢复启动菜单触发“重置此电脑”时，Windows 恢复环境都会在还原操作系统之前执行 RAT 的有效载荷，从而确保该植入程序在系统完全重置后仍然存在。 

对 RAT 二进制文件的分析显示，其具备一套完整的命令接口，共有 35 条命令，每条命令对应一种通过 C2 通道交付的独立能力。这些命令属于下表所述的若干远程管理能力类别：

Overlord 的 Solana 区块链 C2 URL 托管  

该 RAT 使用 Solana 区块链实现了一种具有韧性的 C2 服务器发现机制。攻击者通过 Solana Memo Program 将加密的 C2 URL 嵌入 Solana 区块链；这是一个原生 Solana 程序，可验证任意文本字符串，并将其作为交易的一部分永久记录在区块链账本中。任何 Solana 钱包都可以在交易中加入一条 memo 指令，将最多 566 字节的任意数据写入永久且全球复制的交易记录。  

每当需要更新 C2 服务器地址时，威胁行为者都可以从其控制的钱包地址发布一笔此类交易。每个已部署的 RAT 都会在下一个发现周期获取更新，无需重新部署或重新配置。  

其实现方式是首先使用 Solana getSignatures JSON-RPC 方法获取由行为者控制的钱包的交易历史，该方法返回一个按时间顺序排列的交易签名列表，最新交易位于最前面。对于每个签名，它通过 getTransaction 并采用 jsonParsed 编码获取完整交易，指示 RPC 节点将每个指令数据字段解码为结构化 JSON 响应。随后，RAT 模块遍历已解析交易中的每条指令，查找 data 字符串长度恰好为 43 个字符的指令。43 个字符的长度是 Base58 编码的 WebSocket URL 经 AES-256 加密后产生的固定字符串长度。任何 data 字段长度不同的指令都将被跳过，包括来自其他用户的合法 Memo 交易以及所有其他 Solana 程序指令。只有匹配这一精确长度特征的指令才会被视为 C2 Memo。  

Good Game 窃密器 

Talos 在 UAT-12643 的武器库中观察到的 Good Game 窃密器载荷，是一款公开可用的、基于 Python 的信息窃取器，由 CirqueiraDev 以 "Good Game (版本 1.1.2)”的名义开发。此次活动的行为者并非该开发者，该恶意软件以独立打包的 Windows 可执行文件形式分发，其构建方式为使用 PyInstaller 将 Python 3.12.0 代码打包。其架构分为两个协同工作的字节码模块。“final_build.pyc”充当启动器、诱饵界面和反向 Shell 客户端，而“kora.pyc”包含完整的数据收集窃密逻辑。  

Good Game 的反分析与规避技术  

该恶意软件在执行的每个阶段都采用规避技术，从进程启动的那一刻便开始。启动器立即通过 GetConsoleWindow() 获取控制台窗口句柄，并调用 ShowWindow() 隐藏终端窗口。借助 tkinter 这一 Python 标准内置库，前台会呈现一个功能完整的记事本风格图形用户界面（GUI），同时所有恶意线程均以守护线程形式在其后运行。  

在窃密器模块开始收集任何数据之前，它会依次执行三项检查。首先，它通过检查 platform.system() 确认主机操作系统为 Windows；如果在 Linux 或 macOS 上运行，窃密器会静默终止。其次，它通过向 Google 发起 HTTP GET 请求来验证网络连通性；如果请求失败，窃密器将退出，并把失败原因记录到临时目录中名为“skipped"的文件中。第三步也是最重要的一步，它通过五个步骤执行沙箱检测检查。  

  1. 它会检查是否存在以下库：sbiedll.dll、api_log.dll、vmcheck.dll、wpespy.dll、cmdvrt64.dll、avghookx.dll、snxhk.dll 和 guard32.dll。  
  2. MAC 地址检查通过 getmac 模块提取主机的网络适配器硬件地址，并将其与分配给虚拟化厂商的已知 OUI 前缀进行比较：VMware（00:05:69、00:0c:29、00:50:56）、VirtualBox（08:00:27）、Hyper-V（00:15:5d）、Xen（00:16:3e）和 Parallels（00:1c:42）。  
  3. 硬件内存检查通过 ctypes MEMORYSTATUS 结构查询 GlobalMemoryStatusEx，并将物理 RAM 少于两个 gigabytes 的机器标记为沙箱环境。  
  4. 启动时间检查使用 psutil.boot_time() 计算系统运行时间，并将运行时间少于五分钟视为新配置的分析 VM 的迹象。  
  5. 最后，Wine 仿真检查探测 “C:\windows\system32\wineboot.exe” 是否存在，以检测 Windows API 兼容层。  

如果任何单项检查触发，窃密程序都会静默退出，不留下收集到的数据，且留下的痕迹极少。  

该窃密程序的诱饵 URL 机制增加了另一层伪装。它在每台机器上仅使用受害者的默认浏览器打开一次 PDF 托管文档，并计算该 URL 的 MD5 哈希，将名为 “url_opened_<hash>.flag” 的标志文件存储在受害者机器的临时目录中。在后续所有执行中，诱饵 URL 不会再次打开，从而避免反复启动可疑浏览器而引起受害者警觉。  

Good Game 窃密程序建立的持久化 

该恶意软件在 Windows 上通过两种独立机制建立持久化，确保无论哪条路径被中断，植入程序都能在重启后存活。主要方法是通过打开注册表自动运行项 HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run 并使用 winreg.KEY_SET_VALUE” 写入运行中可执行文件的绝对文件系统路径，将其写入值名称 Zoipers 下，从而使该二进制文件在此后每次用户登录时自动启动，且无需提升权限。第二种持久化机制从 kora.pyc 的窃密模块内部执行。窃密程序使用 shutil.copy() 将运行中的可执行文件复制到 Windows 启动文件夹中的 %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\。  

除了简单的重新执行持久化之外，该窃密程序还会在其活动运行期间临时禁用 Windows 任务管理器。它通过 ctypes 针对项 HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System 直接调用 advapi32.RegCreateKeyExW，并通过 RegSetValueExW 设置 DWORD 值 DisableTaskMgr=1。 在数据外泄成功完成后，窃密程序将该值恢复为零（DisableTaskMgr=0），从而降低受害者注意到该限制的可能性。  

Good Game 窃密程序的功能  

该窃密程序功能最广泛的部分针对 23 种基于 Chromium 家族和 Firefox 的浏览器变体，涵盖所有发行渠道的 Google Chrome、Microsoft Edge、Opera、Opera GX、Brave、Vivaldi、Yandex Browser 及其所有地区变体、Amigo、Torch、Kometa、Orbitum、CentBrowser、7Star、Sputnik、Epic Privacy Browser、Uran 和 Iridium。 

该窃密程序会扫描 Discord 客户端以及 19 多种基于 Chromium 的浏览器中的 LevelDB 存储，使用两种正则模式查找身份验证令牌：一种用于明文令牌，另一种用于使用较新 Discord 版本引入的“dQw4w9WgXcQ:”前缀加密的令牌。它会通过浏览器提取的主密钥解密窃取的令牌，然后针对 Discord API 验证每个恢复的令牌，以构建完整的账户资料，涵盖用户名、显示名称、用户 ID、电子邮箱、电话号码、Nitro 订阅等级、关联的付款方式、礼品码以及多因素身份验证（MFA）状态。 

该窃密程序还会从浏览器数据库中提取 ROBLOSECURITY Cookie，并将每个 Cookie 针对 Roblox 身份验证 API 进行验证，以确认活动会话并获取相关账户详情。随后会组装完整的系统资料，涵盖主机名、用户名、硬件规格、操作系统详情、网络接口，以及从 ipwhois.app 查询的公共 IP 地理位置元数据，并将其序列化至压缩包根目录下的 system_infos.txt。 

该窃密程序还会截取整台显示器的屏幕截图和单帧摄像头画面，二者均保存为 PNG 格式并添加到压缩包中，之后临时文件会被删除且程序终止运行。随后，该窃密程序会从 21 款加密货币钱包中收集会话数据，包括 Exodus、Electrum、Ledger Live、Trezor Suite、Atomic Wallet、Trust Wallet、Coinbase 和 Binance，以及四个游戏平台启动器（Steam、Riot Games、Epic Games 和 Rockstar Games）。 

除结构化凭据数据库外，该窃密程序还会对受害者个人文件系统进行定向排查，范围涵盖 Desktop、Downloads、Documents、Pictures、Videos、OneDrive 根目录，以及位于 %APPDATA%\Microsoft\Windows\Recent 的 Windows“最近使用项目”文件夹。此次排查采用两个独立的筛选条件，文件必须同时满足这两个条件才会被收集。

第二个过滤器是一个由四种语言组成的关键词允许列表：英语、法语、西班牙语和葡萄牙语，必须与文件的基本名称完全匹配。该关键词列表旨在最大程度覆盖加密货币用户、网络游戏玩家以及财务活跃人士可能存储在台式机或文档文件夹中的敏感文档类型。它涵盖双重身份验证备份码、助记种子短语、加密货币钱包应用程序名称、通用密码文件命名约定、银行和支付术语、私钥与恢复短语标签、Discord 身份验证令牌、Telegram 会话标识符，以及 secret、vault、backup、admin 和 root 等通用高价值标签。  

同时满足扩展名和关键词过滤器的文件会被写入临时目录中的压缩包，并在每个文件的扩展名前添加一个随机生成的四位数后缀。 

Good Game 窃密程序的数据外泄机制 

所有收集到的数据都会逐步写入单个 ZIP 文件。ZIP 文件对象以 ZIP_DEFLATED 压缩方式在系统临时目录中打开。压缩包文件名前缀为“SK_”，后接八个随机生成的字符，从而为每名受害者创建唯一标识符，并使压缩包更难仅凭文件名被识别。  

该 ZIP 包含多个命名子目录，例如 Screenshot/、Webcam/、Session Files/Wallets/、Session Files/Game Launchers/、Session Files/Apps/Telegram/ 和 Interesting Files/，根目录中则平铺存放系统信息和防病毒枚举结果。源自浏览器的输出带有计数后缀，例如 Passwords (N).txt，其中 N 表示从该浏览器恢复的凭据数量，使操作人员能够确定优先级。  

所有窃密模块完成后，关闭的压缩包会通过 HTTP POST 请求上传至 hxxps[:]//upload[.]gofile[.]io/uploadFile。服务器返回一个 JSON 响应，其中包含指向已上传压缩包的直接下载链接。  

获得 GoFile 下载 URL 后，窃密程序会构造一条 Discord Webhook 通知，并将其 POST 到硬编码的 Webhook 端点。该通知采用 Discord 消息形式，包含受害者的主机名、用户名、机器架构、操作系统版本和操作系统发行版标签，使操作人员无需先下载压缩包即可立即预览受害者的机器配置信息。Webhook POST 完成后，窃密程序会调用其清理例程，删除本地 ZIP 压缩包以及所有临时中间文件，包括临时目录中的屏幕截图 PNG 和摄像头 PNG。  

剪贴板劫持程序针对多种加密货币钱包地址 

Talos 在该操作人员的工具集中发现的剪贴板劫持程序，是一个使用 C++ 编写的紧凑型 Windows x64 可执行文件。它不包含网络组件或 C2 通信协议；相反，操作人员的配置会以 XOR 加密的钱包地址形式直接编译到二进制文件的数据段中。  

执行后，该二进制文件会动态解析 API 函数地址，并创建一个名为“UuuRjinBZPBMIjnc”的全局互斥体。随后，它获取计算机名，并搜索包括 VBOX、VMWARE、QEMU 和 SANDBOX 在内的子字符串。它通过将自身复制到 %APPDATA%\MsgEdgeUpdate.exe 来建立持久化，同时应用 FILE_ATTRIBUTE_HIDDEN 和 FILE_ATTRIBUTE_SYSTEM 属性，然后将其添加到用户配置单元的 Run 注册表项下，值名为“MsgEdgeUpdate”，从而伪装成合法的 Microsoft Edge 更新程序进程。 

该劫持程序在无限循环中每 500 毫秒轮询 Windows 剪贴板，并采用地址格式指纹识别来检测已复制的加密货币。所有剪贴板 API 均通过 user32.dll 动态解析。检测到后，相应的攻击者钱包地址会从数据段中解密，并覆盖受害者计算机剪贴板中的原始钱包地址。
