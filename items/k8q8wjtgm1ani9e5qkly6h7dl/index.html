Elastic 分析 ARTEX 等五套 AI 攻击框架及在野入侵

Inside the loop: Five AI attack frameworks that never ask permission

AI 导读

Elastic Security Labs 发现 ARTEX、CyberStrikeAI、Cairn、PentAGI 和 HexStrike 五套 AI 攻击框架已出现在真实入侵中，而非仅用于红队测试；五者 GitHub stars 合计超过 60,000。

值得关注

文章结合源码与公开事件拆解五套 AI 攻击框架的自主执行链，并给出可落地的行为检测与凭据处置建议。

正文 · AI 翻译
中文原文

五种代理式攻击框架只需通过一个脚本或 Compose 文件即可安装，合计已获得超过 60,000 个 GitHub star：ARTEX、CyberStrikeAI、Cairn、PentAGI 和 HexStrike。这五种框架均已出现在实际入侵事件中，而不仅仅用于红队演练。Google Threat Intelligence Group (GTIG) 和 Mandiant 观察到ARTEX、Cairn、HexStrike 和 PentAGI 出现在事件响应行动中，Microsoft 则将 ARTEX 的使用归因于 Storm-0940。我们追踪到一起借助 AI 入侵 AWS 的活动，其源头是一台 CyberStrikeAI 服务器，详见一台 CyberStrikeAI 服务器，八个 AWS 身份。

代理式攻击框架让大型语言模型 (LLM) 掌控红队和威胁行为者已经在使用的扫描器、curl、shell 和云 CLI。这些工具并不新鲜，但围绕它们的循环是新出现的：模型规划每个步骤，将工作拆分给多个代理，构建或安装其缺少的组件，并在 ARTEX 的案例中以 2 至 25 秒为一批次推进。我们阅读了全部五个框架的源码以及公开的事件报告，以确定其中一个运行时究竟会有哪些行为进入防御方的遥测数据。它们均未在代码中强制执行授权，而它们执行的每个操作仍需出现在你已经收集的遥测数据中。

关键要点

  • ARTEX 等代理式框架以数秒为批次运行，因此，用于启动遏制的检测规则必须在事件发生前就已选定。

  • 这五个框架默认均未在代码中强制执行授权。其中三个仅在提示词中声明授权，而默认生效的目标限制只有针对政府和教育域名的阻止列表。

  • 这些框架默认会产生大量噪声，并且在 ARTEX 和 CyberStrikeAI 中会在遭到阻止时改变路线。它们的变化速度也快于签名规则，但其行为本身并非如此。每个触达你的环境的操作，都会以进程、Web 请求、API 调用或登录的形式出现在防御方面前，因此，基于行为的检测比基于源地址、User-Agent 或框架指纹的检测更持久。

代理式攻击框架与传统 C2 框架有何不同

Cobalt Strike 和 Brute Ratel C4 由人类操作员在植入体后端控制，决定下一步运行什么。代理式框架保留了这些工具，但用一个规划循环取代了操作员的思考时间。GTIG 观察到 ARTEX 以大约 2 至 25 秒为批次执行，而 NorForge 在追踪暴露在外的 Cairn 面板并将其评估为恶意基础设施后发现，某一攻击者集群成功完成的项目从启动到达成目标平均耗时不到 23 小时。单个批次可以落入较短的检测窗口，但整个行动可能持续数小时，因此，要将这些批次关联为一次完整行动，需要较长的回溯期。

代理及大多数工具通常运行在攻击者控制的基础设施上，并调用托管或自行运行的模型。进入你的环境的内容，是这些工具对它执行的操作，记录形式包括主机上出现的新进程、云审计日志中的 API 调用以及登录事件。

ARTEX、CyberStrikeAI、Cairn、PentAGI 和 HexStrike 对比

这五个框架采用相同的循环，但在模型运行位置以及每个工具的启动方式上存在差异。

默认情况下即具有自主性。CyberStrikeAI 出厂时关闭审批模式，PentAGI 的 Compose 文件将 ASK_USER 设为 false，Cairn 启动其三种编程智能体工作者类型中的两种，并禁用其审批提示，而 ARTEX 则以绕过权限模式运行其智能体，因此这四个框架默认都不会等待人工批准。

除了共享的循环之外，每个框架都有独特的设计选择。

  • ARTEX 将事件驱动的规划器与并行工作者相结合，并将人工角色限定为一名聊天智能体，由其观察进度并通过提示进行引导。其内置的浏览器扩展会记录操作员已认证的会话，验证码和一次性代码只需处理一次，随后将这些请求作为证据交给智能体。我们审阅了原始代码仓库的一个公开英文翻译版本。

  • CyberStrikeAI 是一套完整的操作员控制台。它构建自己的植入程序、运行 C2 监听器和 WebShell 管理器，并连接 Telegram、Slack、Discord 和 DingTalk 等聊天平台。

  • Cairn 将工作委派给现有的编程智能体。其工作者是运行在 Kali 容器内的命令行工具，其 README 描述了它首次亮相于一场 AI 渗透测试竞赛。

  • PentAGI 使用一名反思器智能体来推动其智能体持续行动。当某个智能体犹豫不决，或以散文形式作答而非采取行动时，反思器会以用户的口吻回复，而这段交流会被记录为一条人类消息。

  • HexStrike 没有自己的模型。它通过 Model Context Protocol (MCP) 暴露约 150 个工具函数，供操作员已经在使用的任何 AI 助手调用。

每个框架附带的组件也有所不同。CyberStrikeAI 会构建自己的植入程序，而五个框架中有三个捆绑了云工具，使得操作员能够像访问主机一样便捷地访问云账户。

智能体化攻击框架如何改变检测与响应

智能体化攻击在数秒内即可产生效果

在一次突发攻击过程中，智能体循环会以相隔数秒的节奏发出步骤，而每个步骤一经发送便会立即生效。以这种速度，真正重要的决策都是在事件开始之前作出的，首先便是选择哪些检测信号值得信任，以自动启动遏制措施。

智能体化攻击框架会检查授权吗？

与传统攻击工具一样，这五个框架默认都不会在代码中强制执行授权。其中三个框架更进一步，明确告诉模型其已获得授权。CyberStrikeAI 告诉模型授权已事先确定，绝不应质疑授权或等待批准；PentAGI 的九种角色提示均以预授权区块开头；ARTEX 则将每个智能体描述为经授权渗透测试系统的一部分。Cairn 指示其工作者绝不拒绝任务；当模型仍然拒绝时，其调度器会将该工作者闲置五秒，并把任务交给另一个已配置的工作者；如果该工作者是唯一可用者，则会再次尝试交给同一工作者。

默认启用的唯一目标限制，是 ARTEX 和 CyberStrikeAI 中针对政府域名的阻止列表，以及 ARTEX 中针对教育域名的阻止列表。除这些阻止列表外，随附的安全措施范围很窄：

  • ARTEX 会阻止 rm -rf 和 mkfs 等破坏性命令，并可依据操作员编写的允许列表检查任务资产，而该列表默认为空。Shell 命令仍可抵达任何主机。

  • ARTEX 的交战规则范围机制已被移除；其来源说明以及工作者记录的资产会自动加入任务范围。

  • HexStrike接受一份范围外清单，并且从不查询该清单。

ARTEX将自己的屏蔽块标记为平台控制，因为单纯的拒绝在代理看来就像目标的防御措施，需要绕过。模型提供商的拒并不是防御者可以依赖的控制措施，因为框架可以绕开它，就像 Cairn 的调度器那样。

当你屏蔽代理式攻击框架时，它们会如何响应

按发布时的默认配置，这五个框架都优先考虑能力、自主性和速度。它们的扫描器采用默认设置运行，若干默认项会直接点名该框架，而 CyberStrikeAI 的植入体每五秒就会签到一次，没有抖动。隐蔽性以模型可以加载的技能形式提供。CyberStrikeAI 的操作安全技能涵盖速率限制、IP 封禁规避和反取证。

当 ARTEX 或 CyberStrikeAI 被屏蔽时，变化便会出现。ARTEX 会告诉其工作者，经过过滤的载荷或 404 响应并不代表意图已经耗尽；GTIG 转述 Wiz Research 对其追踪为 UNC7228 的攻击活动的发现，称该攻击者在其初始基础设施被屏蔽后退回到使用开放代理。CyberStrikeAI 的技能会指示代理在遇到屏蔽时切换代理、User-Agent 和转发标头，先回退到目标所在国家的免费代理，然后再使用 Tor。屏蔽之后，预计同样的请求会从新的地址和 User-Agent 返回，因此，以请求内容为依据的检测比以来源地址为依据的检测更经得起考验。屏蔽来源地址仍会保留框架的访问权限，因此应同时撤销该框架正在使用的凭据。

为什么基于 IOC 的检测在代理式框架上会过时

代理式攻击框架变化迅速。ARTEX 的开发者在 2026 年 7 月 26 日至 10 月 7 日的十周半内记录了约 390 次提交，若计入合并则超过 450 次；在其创建者于 2026 年 10 月将原始仓库下线后，公开分叉仍将其延续下去。CyberStrikeAI 在第一年记录了超过 2,400 次提交，而且若干框架会在任务中途编写或安装新工具。如今标识某个框架的字符串、文件名和默认配置，可能在下一个版本中消失，而它所依赖的行为，例如访问凭据、远程执行以及由服务启动的攻击工具，则保持不变。因此，以行为为锚点的检测比以框架指纹为锚点的检测老化得更慢。

为什么撤销凭据不能立即停止代理

AWS 和 Google各自都记录了访问权限变更的传播延迟。在 Entra ID 中，在用户或服务主体被删除或禁用之前签发的访问令牌通常会一直有效，直至过期，通常为 60 至 90 分钟；除非资源和客户端支持持续访问评估。Microsoft 为 Exchange、Teams 和 SharePoint 记录了此功能，而对于服务主体，则仅适用于 Microsoft Graph。已确认的撤销可能无法阻止下一次请求，而以机器速度运行的代理可以在这一间隙内采取行动。AWS 的角色会话撤销也不会影响 IAM 用户的长期密钥，并且不会阻止在截止时间之后请求的会话，因此应同时移除所有仍能承担该角色的主体。

如何检测智能体化攻击框架

按身份检测智能体化节奏与序列

行为规则是基础，而工具的覆盖范围决定了这些规则需要有多广泛。GTIG 的 ARTEX 攻击技术目录包括 SQL 注入、Kerberoasting，以及 Azure 和 AWS 权限映射。智能体化节奏增加了两种在单个事件之间出现的信号。

  • 按身份统计节奏。在短时间窗口内，按身份和发起角色统计不同的敏感操作数量，这样即使其中的每个操作都很常规，突发行为也会显现出来。

  • 跨会话序列。将发现活动、密钥访问和远程执行按发起角色或源地址关联起来，把多个会话中的活动串联成一次操作。

高阶检测规则将同样的逻辑应用于警报，把共享主机、用户或地址的相关警报关联为置信度更高的发现，因为每增加一个信号，良性解释的可能性就会降低。我们预计，随着这些框架发生变化，更多此类信号将会出现。

使用 ES|QL 搜寻工具家族突发行为

一个循环会根据任务需求调用其工具箱，因此单个源地址可以在同一分钟内使用 curl、Python 客户端、浏览器 User-Agent 和 AWS 客户端。下面的 ES|QL 搜寻会将 User-Agent 规范化为工具家族，在一分钟窗口内按源地址统计家族和请求数量，并返回至少包含三个家族且请求数出现突发的窗口。由于该循环运行在攻击者控制的基础设施上，该搜寻会读取记录其请求的日志，例如 Web 服务器、代理和云审计日志（将索引模式指向这些来源），并排除私有、回环、链路本地、运营商级 NAT 和组播源地址范围。

构建系统、监控脚本、使用 AWS CLI 的管理员，以及共享的 NAT 或代理地址，也可能会混用这些客户端，因此应为这类自动化建立基线，并在对结果发出警报前，将阈值调整为每分钟三个家族和 20 个请求。该搜寻以一个地址在一分钟内使用多少种客户端为依据，因此不依赖任何单个字符串，但框架从新地址返回时就会开启一个新窗口。家族列表还可以使用下表中的框架 User-Agent，而 norma* 已经涵盖 ARTEX 的 Web 获取工具所发送的 norma/0.4。

在 ARTEX、CyberStrikeAI、Cairn、PentAGI 和 HexStrike 中需要关注什么

这些默认行为会出现在受攻击的系统上，并在有说明的情况下出现在你监控的主机上。它们值得立即开展搜寻，但其中任何一种都可能在下一个版本中发生变化。

框架

需要关注什么

ARTEX

来自其所搭载扫描器的流量，例如 nuclei、httpx、katana、ffuf 和 sqlmap，每个任务默认运行三个并行工作进程，User-Agent 为 artex-enrich/1.0 或 norma/0.4 的请求，以及在你的应用程序上注册的新账户随后从多个会话登录，因为其智能体会注册并共享自己的测试账户。

CyberStrikeAI

携带 User-Agent Mozilla/5.0 (compatible; CyberStrikeAI-WebShell/1.0) 和 pass 表单字段的 Webshell 请求；运行 echo :OSPROBE_%OS%:END 的 Web 服务器进程；名为 SystemUpdate（计划任务或 Run 键）或 com.apple.systemupdate（LaunchAgent）的植入物持久化；以 # cs 结尾的 .bashrc 行；或不携带自身标记且会启动植入物二进制文件的 @reboot cron 条目。

Cairn

反向 shell 以及指向操作员主机自身地址的带外回调，因为其示例配置会在主机网络上运行工作容器。当它运行在你监控的主机上时，其三个工作适配器中的两个会禁用批准提示，并在命令行中传入完整任务提示，从而启动其编程代理命令行工具。

PentAGI

从已失陷主机到 PentAGI 主机 TCP 端口 28000 到 29999 的连接（默认每次行动建立两个）；其浏览的每个页面都会同时请求两次，一次用于获取内容，一次用于获取屏幕截图。安装在您网络中的实例还会每三小时向 update.pentagi.com 报告。

HexStrike

User-Agent HexStrike-HTTP-Framework/1.0 和 HexStrike-BrowserAgent/1.0，以及在浏览器代理的主动测试运行时出现的跨站脚本标记 <hexstrikeXSSTest123>。当它运行在你监控的主机上时，Python 服务器默认在所有接口上监听 8888 端口，并通过 shell 启动安全工具，因此工具可能会将 Python 服务器显示为其父进程。

除这些默认设置外，扫描器均使用标准配置运行，因此在这些框架所在的网络中，它们很大程度上类似于其所驱动的工具。

如何防御代理式攻击框架

  1. 预先确定哪些高置信度检测结果会触发遏制。将它们与终端上的自动化响应操作以及Elastic Workflows连接，以编排响应流程，包括调用您自己的自动化来执行云端步骤，例如停用访问密钥或撤销角色的活动会话。

  2. 将针对源地址的任何阻断与撤销该身份的会话和令牌结合起来，因为这些框架会从新地址返回，然后确认下一次请求失败。

  3. 在足够长的时间窗口内，按身份衡量节奏和序列，以关联突发活动，并为您已经拥有的、行为类似代理的自动化建立基线。

  4. 将假定的角色和仅限应用的身份范围限定为它们所需的操作，因为代理会继承该身份允许的一切权限。

  5. 从代理可读取的位置移除机密，例如文件共享、Wiki、代码存储库和 CI/CD 变量；轮换任何已暴露的机密；并优先使用短期凭证。GTIG 报告称，操作员会将 ARTEX 已失陷的凭证交予他人，而 ARTEX 还可通过 Kerberoasting、SQL 注入和 DCSync 收集更多凭证，因此每个暴露的机密都会让一次行动得以触达另一个平台，并使遏制更加困难。

  6. 根据有关框架基础设施的威胁情报采取行动。GTIG 报告称，ARTEX 和 PentAGI 被用于针对多个组织，而诸如 Cairn 的暴露控制台可以从互联网枚举，因此，获取其基础设施情报是在早期阻断入侵的机会。在边界或代理处屏蔽这些地址，并将同一情报输入 Elastic 的威胁情报集成，使预置的 Threat Intel IP Address Indicator Match 规则能够标记往返于已知控制台和 C2 服务器的流量。构建富化工作流，由警报触发，对匹配到的地址执行信誉查询。控制台可能位于共享托管或 CDN 地址之后，因此，在匹配结果用于触发阻断之前，该查询有助于区分专用服务器与共享地址，而行为检测仍可覆盖会发生变化的基础设施。

关于智能体化攻击框架的开放问题

这些问题现在值得回答，以免下次版本发布改变答案。

  • 当智能体扩展自身时会发生什么变化？ARTEX 的操作员助手可以创建新工具、MCP 服务器和技能，而 PentAGI 会将编写的代码保存在跨任务共享的存储区中。为某个目标编写的工具没有可供匹配的历史记录，因此，基于行为和父级关系的检测比基于工具名称的检测更有效。

  • 优势在于速度还是适应能力？脚本可以跟上智能体的节奏，因此，更有意义的测试是新发现或陌生错误转化为新行动的速度。

  • 一次多智能体运行涉及多少个行动者？ARTEX 在一个任务下运行一个规划器和多个并行工作器。多个会话或智能体名称可能看起来像多个行动者，但其背后的身份和控制者才是关键单元。

结论：这对检测与响应意味着什么

智能体化攻击框架意味着一种新型操作员：一个能够规划、协调智能体、扩展自身工具，并以会改变检测与响应方式的节奏推进的循环。这五个框架默认都没有在代码中强制执行授权，因此，防御方遥测和控制措施才是真正的边界。

本次分析涵盖五个框架，还有更多框架值得持续追踪。Gambit Security 报告称，一起犯罪活动利用 Strix 进行漏洞发现，利用 Cairn 进行漏洞利用，并将通用智能体 Hermes 作为其控制台。其他使用模型进行渗透测试的开源项目包括 Shannon、PentestGPT、CAI（现已归档）、CyberStrike（并非 CyberStrikeAI）、RedAmon、PentestAgent、hackingBuddyGPT、Nebula 和 BugTraceAI。新项目还会不断出现，因此，应根据每个框架如何规划、由什么启动其工具，以及会为防御方留下哪些可见痕迹来对其进行追踪。

Elastic 的行为检测规则关注这些框架所采取的操作，例如凭据访问和远程执行，而不是关注框架或模型本身；基于 LLM 的分诊规则可以将与同一用户或主机相关的警报汇总为一个判定。Elastic 持续增加以 AI 为重点的防护，其规则公开发布在 detection-rules 和 protections-artifacts 存储库中。按身份添加时序和序列分析，确认撤销操作已经生效，并通过自动化响应操作和 Elastic Workflows 进行遏制，使响应决策在操作开始前完成。
