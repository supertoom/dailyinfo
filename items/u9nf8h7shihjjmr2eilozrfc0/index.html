中文原文

据网络安全公司 F6 称，概念验证（PoC）漏洞利用代码公开发布后不久，黑客便利用 Cisco Expressway 的一个严重漏洞入侵了一家俄罗斯组织。

Expressway 网关允许远程员工、合作伙伴和第三方用户安全连接到组织的协作服务，包括视频通话、语音通话和即时通信。

该漏洞追踪编号为 CVE-2026-76466（CVSS 评分为 9.8），可由能够通过网络访问设备的远程攻击者在未经身份验证的情况下利用，使其能够以 root 身份执行命令。它影响 Expressway Core 和 Expressway Edge 的虚拟及设备版本，但仅在这些设备组成集群时受影响。

Cisco 于 10 月 21 日披露了该问题，称其存在于 Expressway 数据库服务功能中，根源在于持久 Cookie。 

持有这些持久 Cookie 的攻击者可以访问数据库服务并发出特定的远程过程调用（RPC）命令，从而能够在底层操作系统上运行 root 权限命令。

Expressway X15.5.20 修复了该漏洞。没有可用的变通方案，Cisco 表示，使用 X14 或更早版本的客户需要迁移至已修复的版本。

该公告自首次发布以来未作修订，仍称 Cisco 尚不知道该漏洞已被公开宣布或遭到恶意利用。然而，此后已有一个PoC 漏洞利用程序发布在 GitHub 上，F6 表示，其调查的攻击发生在不久之后。

据 F6 称，攻击者首先入侵了两台暴露在互联网中的 Expressway X15.5.3 设备。随后，他们从其中一台设备转向该组织内部网络上的另外两个集群节点。

在获得 root 权限后，攻击者准备好用于横向移动的工具。其中包括自定义 Python 脚本，用于扫描网络、定位 SMB 资源、与 SQL Server 和 WinRM 交互，以及搜索 GitLab 仓库，旨在窃取凭据和其他敏感信息。

F6 认定，攻击者在攻击过程中会即时修改这些脚本。“源代码中包含一些特征性注释以及对修复内容的描述，表明使用了 AI 助手，”该公司表示。

F6 未披露受害组织名称，也未将该攻击归因于任何已知威胁行为者。

为了检测利用活动，F6 建议查看 Expressway 设备上的 Erlang 系统日志。这家安全公司还在一份俄语新闻稿中发布了与此次攻击相关的 IP 地址和文件路径。

尽管 Cisco 未列出任何变通方案，F6 建议无法立即打补丁的组织在防火墙上阻止对 TCP 端口 4371–4372 的连接，但来自可信集群节点 IP 地址的连接除外。

SecurityWeek 已联系 Cisco 就 F6 的发现征求意见；如果该公司作出回应，本文将进行更新。
