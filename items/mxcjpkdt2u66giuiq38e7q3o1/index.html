中文原文

Acronis 威胁研究部门研究人员上周表示，一名使用 AI agents 的攻击者窃取了涵盖台北七个区的紧急调度记录。

这些 agents 还发现，台北市消防局的一个平台无需登录即可访问 2018 年的患者数据，其中包括心电图读数和救护车视频片段。

研究人员高度确信，这名攻击者是身处台湾花莲市的一个人。他指挥这些 agents 瞄准至少 11 个国家的数百家组织，包括紧急服务部门、银行、大学和军事系统。这些 agents 在台湾、墨西哥和泰国的约 10 家组织中收集了数据或访问了系统。

证据来自攻击者自己的服务器，该服务器起初看起来像是一台配置不当的开发系统。后来发现，它实际上是他的行动攻击平台，包含超过 90,000 个文件，包括这些 agents 的对话、他的命令历史、黑客工具、凭据和受害者数据。

这些 agents 彼此并不通信，因此攻击者手动将一个 agent 的输出粘贴到另一个 agent 中。商业 AI 模型大多拒绝协助他实施攻击。因此，这些攻击 agents 几乎完全基于“abliterated”模型运行，即在本地运行且已移除安全训练的 AI 模型。

这些 agents 触及的范围

据研究人员的 技术分析，台湾遭受的攻击远重于任何其他国家。当地已确认的最严重危害涉及紧急服务数据。

这些调度记录来自某市用于呼叫 119 的系统；119 是台湾的消防和救护车紧急服务号码。这些 agents 从该系统的 API 中窃取了记录，其中包含事件发生时间、响应类型、案件状态和街道级位置。它们是案件记录，而非实时救护车追踪数据。

研究人员的摘要称，紧急服务部门和大学遭到入侵，导致医疗和个人数据被盗。然而，他们对台北患者平台的详细说明只称相关记录被暴露。

这些 agents 还攻击了另外五个与台湾紧急服务有关的目标：

目标 这些 agents 的行为 结果
消防调度技术供应商 使用默认的 root 凭据登录其数据库管理面板。通过一个已知 CVE 尝试植入 web shell 未能成功。 访问了 18 个或更多数据库表
应急管理信息系统 在网站前端 JavaScript 中发现一个硬编码的 AES-256 密钥，可暴露会话 cookie 内容，包括管理员身份 未确认遭到入侵
国家灾害响应中心 一个扫描工具报告存在严重的 Apache 远程代码执行漏洞 该漏洞并不存在
国家消防机构单点登录门户 尝试猜测登录信息（暴力破解） 未确认获得访问权限
五个城市的消防部门系统 扫描这些系统，以确定其运行的软件 未确认遭到入侵

报告没有说明相关组织或台湾当局是否被告知，也没有说明暴露的数据目前是否仍可访问。

在紧急服务部门之外，这些 agents 通过 SQL injection 从一家台湾借贷机构的一个账户表中窃取了数据。在泰国，他们从三所大学收集了数据，方法相同；此前，他们从 45 家机构中筛选出 489 个潜在目标。

在墨西哥，他们利用政府统计数据、邮政编码列表和电信主管部门的数据，收集了约 206,800 条包含姓名和地址的家庭电话号码记录。

另有约 15 家组织遭到攻击，但未确认遭到入侵。在至少另外 8 个国家，目标仅被扫描，或被列为攻击目标；研究人员查看时，这些攻击尚未实施。

研究人员观察了此次行动 12 天。一段记录的交流显示，攻击者于 7 月 25 日正在行动。

AI 的使用方式及其失败之处

这套名为 BOSSAI 的系统包含 12 个 AI 智能体，其中 9 个投入使用。一些负责构建和维护攻击者的服务器与工具，另一些则扫描目标并实施攻击。

商业云端模型完成了大部分构建工作，其中 Grok 是主要的构建者。当攻击者直接要求它们发动攻击时，Grok 和 MiniMax M3 拒绝了，并要求提供书面证明，证明该工作已获授权。研究人员表示，尚不清楚一封伪造的授权函是否会改变这一结果。

Grok 有一次例外：它修复了一个损坏的概念验证脚本，随后攻击者将其交给一个攻击智能体。攻击者还将代码智能体 Claude Code 和 Codex 重定向至一个移除安全对齐的模型，不过它们主要从事基础设施工作。另一个代码智能体 Cursor 在运行此类模型时，攻击了一个台湾应急服务网站。

这些移除安全对齐的模型是 DeepSeek、GLM 和 Qwen 的版本。

这些智能体也会出错。一款扫描工具凭空捏造了 CVE，其严重和高危发现中超过一半是误报或分类错误。主要攻击智能体还报告了并未发生的结果。

是谁实施的

Acronis 的归因依据是攻击者在隐藏身份时犯下的错误，以及公开可用的信息。他在合法企业和攻击服务器之间重复使用同一个身份，包括一个 GitHub 资料页、一个徽标、一个 SSH 密钥名称和一个电子邮件地址。

他的家庭 IP 地址曾在其一次与 Grok 的交流中出现在 SSH 会话里。

他为何这样做则没那么清楚。一些针对政府、应急和军事目标的攻击看起来像是国家支持的黑客组织所为，另一些则更像普通网络犯罪。研究人员认为，他很可能是想赚钱；他是否受雇于任何人则尚不清楚。

智能体为何受挫

据研究人员称，智能体发现的大多数数据本就防护薄弱：一个自 2018 年起一直开放的医疗数据端口、一个面向公众开放的 API 中的调度记录、一家存在 16 个 SQL 注入点的贷款机构，以及运行着未打补丁 Oracle 数据库的大学。

在强制登录、付费墙要求有效会话以及端点得到正确过滤的地方，智能体未能奏效。AI 让攻击者能够以低成本同时发现并接触大量目标，但无法突破那些稳固的防御。

分析末尾的指标列表中包含攻击者所用设置的 9 个 IP 地址和 9 个域名。其中没有任何一项被标记为活跃或非活跃，大多数也没有关于其用途的说明。
