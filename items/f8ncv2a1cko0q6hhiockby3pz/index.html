The risks of device code authentication for AI coding agents

设备代码钓鱼已成为账号接管的一条反复出现的途径。攻击者不窃取密码，而是通过让某人输入一个代码，说服其在合法站点上批准一次登录。由此获得的访问权限通常可触达邮箱、文件或其他云服务，具体取决于该账号以及所授予的权限。诸如 EvilTokens 这样较早的著名行动表明，这项技术可以轻易被规模化以造成真实危害。微软与行业和执法部门的合作伙伴共同努力，于 2026 年 9 月捣毁了 EvilTokens。

这让我们想到另一个问题：攻击者拿到被钓取的设备代码授权后还能做什么？当同样的把戏针对的是 AI 代理而非邮箱时会发生什么？

我们以 GitHub Copilot CLI 作为示例。根据其配置，它可以处理代码、在用户机器上运行命令、跨会话保留上下文，并允许活跃会话被远程操控。与许多命令行工具一样，它支持使用 OAuth 设备流程进行登录。这种钓鱼技术本身并不专属于 GitHub 或 Copilot CLI：任何支持设备流程的公共客户端都能以同样方式被滥用，且攻击者在发起流程时可自行选择所请求的权限范围。

我们在受控的实验室模拟环境中探索了这一场景。一个受害者测试账号批准了由我们所控制的攻击者客户端发起的 GitHub 设备代码请求。获得该批准后，我们分析了四种可能的结果：

  • 远程操控一个活跃的 Copilot CLI 会话，前提是用户已启用远程控制且组织策略允许，并且在本地权限与审批设置的约束下，让该代理在用户机器上运行命令。
  • 向代理的内存中添加误导性条目，以影响后续交互。
  • 读取已同步到云端的 Copilot CLI 会话。
  • 访问受影响账号可用的私有仓库。

这些是概念验证（PoC）结果，展示现有功能在按设计工作的同时，如何在被钓取的授权之后遭到滥用；并非我们在真实环境中观察到的攻击。这些结果均要求受害者用户批准由攻击者发起的设备代码请求；每种结果还取决于下文所述的账号权限与已启用功能。

在本文稍后部分，我们将展示 Microsoft Defender 如何通过把钓鱼尝试与 GitHub 认证活动关联起来来检测这些攻击，以及组织如何阻断可疑访问以保护受影响的身份。

从熟悉的钓鱼手法到 AI 编码代理

OAuth 设备流程可帮助命令行工具等客户端在不显示完整浏览器的情况下完成登录。客户端请求一个短代码；用户在服务的验证页面上输入该代码；请求方客户端在获得批准后收到访问权限。在设备代码钓鱼中，攻击者发起请求，并说服他人代为批准。

微软已报告多起针对账户的设备码钓鱼攻击，其中包括 Storm-2372、2026 年的一次 AI 赋能攻击活动以及 EvilTokens。这些案例促使我们考察了一个不同的目标：一种能够操作代码仓库的编码代理，并且在启用远程控制时，会将活动的会话暴露给远程交互。

本文其余部分描述的是一次受控的 GitHub Copilot CLI 模拟；我们在上述攻击活动或真实环境中并未观察到以下四种结果。

攻击是如何运作的

  1. 发起： 攻击者启动一个设备码登录请求。在我们的模拟中使用了 Copilot CLI 客户端，但任何支持设备流的客户端都可以使用。
  2. 诱导：攻击者将短码和 GitHub 验证链接发送给用户，例如以 IT 请求或 Copilot 许可证检查为借口。该验证页面确实由 GitHub 托管；仅有合法域名并不能确定请求的发起方。
  3. 批准：用户打开 GitHub 页面，必要时登录，并批准该请求。这是社会工程环节。
  1. 登录： 批准后，攻击者控制的客户端自动完成登录。
  2. 操作：攻击者可以在应用被授予的权限以及受影响账户可访问的资源的范围内进行操作。

一次批准，影响扩散的四种方式

设备码批准只是起点。攻击者接下来能做什么，取决于账户的权限、启用的功能、内存设置，以及活动会话能否被远程控制。

1. 攻击者可以操纵已启用的远程会话

当用户为该会话和组织策略启用了远程控制时，Copilot CLI 支持对活动交互式会话进行 远程操纵。在实验室中，攻击者控制的客户端利用测试账户的授权与可远程控制的会话进行交互。该代理在测试计算机上执行命令，并受到会话批准提示和本地操作系统权限的限制。这演示了对已授权远程会话能力的滥用，其运作符合设计预期；这不是未经身份验证的远程代码执行，并且在远程控制被禁用、会话未运行或计算机离线时不适用。

2. 记忆可以将攻击延续下去

Copilot Memory 可以保留仓库信息和用户偏好。在模拟中，我们使用智能体的 /memory 命令添加了误导性条目。如果这些条目在后续交互中被使用，其影响可能比最初的登录持续更久。实际行为取决于启用了哪些记忆功能和策略。

3. 同步会话会泄露更早的上下文

在启用云端会话存储的地方，我们能够读取测试账户同步的 Copilot CLI 会话，包括模拟之前的会话。这些会话可能包含代码片段、文件路径、架构讨论以及其他工作上下文。对于 Copilot Business 和 Enterprise，可用性取决于组织的会话存储策略；同步会话本身并不会启用远程控制。

4. 仓库访问权限取决于账户

在实验室环境中，该授权使我们能够访问测试账户可用的私有仓库。请求中包含 repo 范围，以及 read:user、read:org、gist 和 codespace。这些范围由启动该流程的客户端选择；最终的仓库访问权限取决于所请求的范围和账户的权限，而不是 Copilot CLI 自身的属性。潜在的暴露范围受账户仓库访问权限的约束，其中可能包含应用代码和基础设施定义。

一封钓鱼邮件、一次点击和一次 GitHub 授权，单独来看每一项都可能显得平平无奇。对防御方而言，挑战在于识别它们何时属于同一次接管企图。合法的验证页面是这个故事的一部分，而不是请求安全的证据。

将钓鱼企图转化为 Defender 检测信号

Microsoft Defender 帮助组织检测和响应针对 GitHub 账户的设备代码钓鱼攻击。在 Microsoft Defender for Cloud Apps 中启用GitHub Enterprise Cloud 连接器后，组织即可获得 GitHub 活动的可见性，从而支持对可疑授权模式的调查。

作为我们研究的一部分，我们开发了针对疑似 GitHub Copilot CLI 设备代码钓鱼的两项检测，覆盖通过电子邮件和 Microsoft Teams 投递的攻击。

这些检测将可疑消息和点击与后续的 GitHub OAuth 令牌创建和再生成事件关联起来，有助于识别那些本可能看起来合法的、未经授权的 Copilot CLI 授权。Microsoft Defender XDR 客户可参考下方适用检测的列表。

除了检测之外，我们还为 GitHub Enterprise Managed Users（EMU）开发了一项中断处置操作。该操作通过组织的身份提供商暂停受影响的托管身份，从而中断攻击者的访问。我们在研究环境中验证了这项能力。

响应人员还应审查并撤销异常的 OAuth 授权，确认访问已被阻止，并调查可能受影响的会话、仓库和已保存的内存。

这些能力结合起来，可帮助安全团队从识别潜在钓鱼尝试，转为控制受影响的身份。检测和中断功能的可用性取决于受支持的配置、所需遥测数据、身份集成以及部署先决条件。

缓解与保护指南

  • 务必向所有使用开发工具和 AI 工具的人员明确说明审批规则：只有在你本人发起登录时，才输入设备代码。任何要求“验证”GitHub 或激活 Copilot 的非预期请求，都应被视为钓鱼尝试，即使该页面托管在 github.com 上也是如此。GitHub 自身的验证页面会警告用户，绝不要使用他人发送的代码。
  • 在 Microsoft Defender for Office 365 中为电子邮件配置安全链接策略，并验证适用于 Microsoft Teams 的安全链接保护。这些保护措施有助于应对恶意链接并提供调查上下文；即便是合法的 GitHub 验证 URL，用户仍需识别出未经请求的代码请求。
  • 审查 GitHub Copilot CLI 会话设置。对于由组织提供的席位，GitHub 的“在云端存储本地会话”策略决定会话能否被存储和远程控制。请选择能够满足你工作流的限制最少的设置。远程控制还要求存在处于活动状态的在线交互式会话。
  • 在 GitHub 账户设置中审查已授权的 OAuth 应用程序，并撤销异常或不再需要的授权。使用适当的组织角色限制仓库访问权限，防止受影响账户访问超出其工作所需的代码。
  • 如果启用了 Copilot Memory，请使用 GitHub 的内存管理控件审查并删除可疑的存储库事实信息或用户偏好。禁用内存不会自动删除已存储的条目，因此事件响应期间应审查已保存的内容。
  • 将GitHub Enterprise Cloud连接到 Defender for Cloud Apps，并在依赖其开展调查之前，验证你所在环境中可用的活动数据。

请记住：合法的登录也可能是错误的登录

此次模拟最引人注目之处在于，要让事情显得可疑，只需很少的操作。用户访问了真实的 GitHub 网站，并批准了一个看起来正常的请求。然而，该批准对应的是一个用户并未启动的客户端。从此以后，后果取决于该身份能够访问哪些内容，以及启用了哪些 Copilot CLI 功能。

这就是为什么这不仅仅是一个关于代码的故事。随着 AI 代理获得对存储库、会话历史记录和本地工具的访问权限，遭到钓鱼的授权所造成的影响日益取决于这些代理能够访问哪些内容。

合法的验证页面并不意味着该请求是安全的。用户应仅批准自己发起的设备代码请求。组织应定期审查并撤销意外的 GitHub OAuth 授权，将 Copilot 会话和内存设置限制在其工作流所需的范围内，并在 Microsoft Defender for Cloud Apps 中验证 GitHub 活动的可见性，以支持调查。

最终，防止设备代码钓鱼既需要提高用户意识，也需要具备将可疑授权活动与此前发生的钓鱼尝试关联起来的能力。

观察到的 MITRE ATT&CK 技术

这些映射描述的是概念验证模拟中展示的行为，而非已归因的攻击活动。

  • T1566.002 – 钓鱼：鱼叉式钓鱼链接（初始访问）。在测试的电子邮件投递中，一个链接将用户引导至设备授权页面并提示其批准。
  • T1528 – 窃取应用程序访问令牌（凭据访问）。测试账户批准该请求后，攻击者控制的客户端获取了 OAuth 令牌。
