Apache HTTP Server 的 HTTP/2 模块 mod_http2中存在一个严重漏洞，可让远程攻击者在服务器上运行代码。该漏洞追踪编号为 CVE-2026-119618，影响 2.4.55 至 2.4.70 版本，并在昨日发布的 2.4.71 版本中得到修复。

据 Red Hat 表示，只有启用了 HTTP/2 的服务器才会受到影响；Red Hat 将该服务器作为 Red Hat Enterprise Linux 的一部分提供。

这家 Linux 厂商表示，能够访问服务器的攻击者无需进行身份验证即可利用该漏洞，并可能完全控制服务器进程。该漏洞在 CVSS 评分体系中的评分为 10 分中的 9.8 分。

该厂商昨日发布的评估还表示，“公开研究已经证明，在启用 mod_http2 的默认配置服务器上存在可靠利用方法”。但评估未提及该研究的名称，也未提供相关链接。安全公司 Wiz 当日稍后表示，当时尚无可用利用方法，也没有收到在野利用的报告。

正如 模块文档所解释的，只有在 Protocols 指令启用 HTTP/2 的情况下，HTTP/2 才会运行。该指令使用 h2 表示基于 TLS 的 HTTP/2，使用 h2c 表示基于明文 TCP 的 HTTP/2。它可以为整个服务器设置，也可以为单个虚拟主机设置，因此管理员应检查服务器范围的设置以及每个虚拟主机。

该模块的独立构建版本以 mod_h2 的形式在 GitHub 上发布，其中 2.0.8 至 2.0.42 版本受到影响。

运行 Apache HTTP Server 项目自身发行版本的管理员应升级至 2.4.71 版本，这是其 安全公告中指定的修复版本。该版本还修复了 mod_md 中一个被评为重要级别的崩溃漏洞，以及 mod_vhost_alias 中一个被评为低危级别的单字节栈内存覆写问题。

下表中的发行版均提供各自构建的服务器，并采用各自的软件包版本号。例如，在 Red Hat Enterprise Linux 9 中，修复以 mod_http2-2.0.26-7.el9_9.1 的形式提供。

Red Hat 昨日为 Red Hat Enterprise Linux 9 和 10 发布了修复，并将该漏洞在这些发行版中的严重程度评为重要，而非严重。根据该厂商的 严重程度评估，其 mod_http2 软件包为每个 HTTP/2 流提供独立的内存分配器，使攻击变得困难得多。Red Hat Enterprise Linux 8 及更早版本不包含存在漏洞的代码。

Debian 各行数据来自 Debian 的 安全追踪器，Amazon 一行数据来自 Amazon Linux 追踪器。The Hacker News 今天检查时，Ubuntu 的 CVE 追踪器中尚无该漏洞的页面。

Apache HTTP Server 公告未提供任何变通方案。在其漏洞分析中，Wiz 建议暂时无法更新的管理员从 Protocols 指令中移除 h2 和 h2c，仅保留 Protocols http/1.1。

独立的 mod_h2 项目迄今尚未发布修复版本。其在 GitHub 上的版本发布列表止于 2.0.42，这是最后一个受影响的版本；该仓库自 6 月 9 日归档以来一直处于只读状态。上述对 Protocols 的更改同样适用于使用这些构建版本的服务器。

该漏洞由 Anthropic 的 OSS Scanner 于 10 月 26 日报告。这是一项面向开源项目的免费扫描服务，使用该公司的 AI 模型。Google Cloud Vulnerability Research 的 Anthony Weems 和 Simon Scannell 于上周报告了该漏洞。

一个较早的 HTTP/2 漏洞CVE-2026-23918 已在 5 月 4 日发布的 2.4.67 版本中得到修复。已更新至该版本或截至 2.4.70 的任何后续版本的服务器，仍在运行受这个新漏洞影响的版本。
