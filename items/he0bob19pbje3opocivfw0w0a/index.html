中文原文

随着更多厂商发布公告，详细说明该漏洞对其产品的影响，威胁行为者已开始针对最近披露的 Java4Shell 漏洞开展活动。

该漏洞追踪编号为 CVE-2026-114938，Java4Shell 是 OpenJDK 17.0.6 及更高版本在处理 Base64 数据时存在的一个内存损坏漏洞。利用该漏洞需要配备支持 AVX-512 VBMI 的 x86-64 处理器，这项功能存在于较新的 Intel 和 AMD CPU 中。基于 ARM 的系统不受影响。

Calif 于 11 月 17 日披露了该漏洞，同日 Oracle 和 OpenJDK 项目发布了补丁。

Calif 表示，利用该漏洞可在 Jira、Confluence、Jenkins、Keycloak 和其他企业应用的默认配置下实现未授权远程代码执行（RCE）。不过，其指出，并不存在适用于所有这些产品的单一漏洞利用方案，每个产品都需要量身定制的攻击链。

攻击者正在探测存在漏洞的系统

截至 11 月 19 日初，威胁情报公司 GreyNoise 已记录到来自 5 个 IP 地址的 150 多次请求，其形式与 Java4Shell 攻击相符。该公司尚未发现其传感器上有任何成功入侵。

WatchTowr 也观察到了相关活动。WatchTowr 威胁情报主管 Jake Knott 表示：“我们已经看到攻击者扫描互联网，使用带有‘java4shell-recon’ User-Agent 的请求攻击我们的全球蜜罐网络，同时还使用格式正确的请求进行盲利用尝试。”

Knott 补充道：“虽然我们目前观察到的情况尚不特别有效或令人担忧，但它已经发出了明确信号，表明攻击者想要利用这个漏洞。未来几天，我们预计攻击者会逐一针对不同产品进行迭代，以完善并构建更可靠、针对特定目标的漏洞利用方案，而真正的利用活动也将从那时开始出现。”

Cloudflare 的 Cloudforce One 团队注意到，扫描该漏洞的攻击者开始隐藏其使用的工具。在一次事件中，一个 IP 地址使用明确提及 Java4Shell 的 User-Agent 探测目标，随后在大约 17 小时后携带漏洞利用触发器返回，同时伪装成 Chrome 浏览器。

11 月 18 日，Cloudforce One 还发现一个 IP 地址首次同时被用于 Artex 和 Java4Shell 活动。Artex 是一个开源 AI 渗透测试框架，威胁行为者一直在滥用它来自动化入侵。

威胁情报公司 Previdian 表示，其传感器在 11 月 18 日和 19 日记录到来自 6 个 IP 地址的 9 次漏洞利用尝试。不过，其警告称，其传感器数据无法确认任何目标是否已遭入侵。

Cisco 的产品安全团队表示，已知晓存在概念验证（PoC）漏洞利用代码，但不了解有任何恶意使用。 

Calif 发布的 PoC 只能触发内存损坏。与此同时，VulnCheck 已向其客户提供完整的 RCE 漏洞利用程序，Immersive 的 Kevin Breen 也报告称已开发出可正常利用的漏洞利用程序。

厂商确认影响，但修复仍在推出

迄今为止，Cisco 已确认其十余款产品受到影响，包括 Catalyst Center、Secure Network Analytics、Secure Workload、Smart Software Manager On-Prem、Splunk AppDynamics On-Premises Virtual Appliance 和 Intersight Virtual Appliance。

这家网络巨头尚未发布修复补丁，并表示没有可用的规避方案。它仍在调查 IOS XE 和 UCS Central 是否受到影响。

Siemens 表示其三款 Industrial Edge Management 产品受到影响。该公司正在开发补丁，同时建议在此期间将这些实例下线。

据 Elastic 表示，从 7.17.3 起的每个 Elasticsearch 版本都受到影响。攻击者需要具有读权限或更高权限的有效凭据才能实现 RCE，但无需身份验证即可触发拒绝服务（DoS）状态。

Logstash 8.6.2 及更高版本同样受到影响，尽管利用需要特定配置且只能导致崩溃。Elastic 计划在即将发布的版本中解决该问题。

该公司已为 Elastic Cloud Serverless 部署了热修复，并为 Elastic Cloud Hosted 做了配置变更。它表示只有一小部分 Elastic Cloud Hosted 部署运行在存在漏洞的 CPU 上。

Red Hat 将该问题评为严重，称 RHEL 8、9 和 10 受到影响，其自行构建的 OpenJDK 17、21 和 25 也受到影响。

“不需要任何特殊配置或非默认功能。只要 JVM 运行在报告支持 AVX-512 VBMI 的 CPU 上，就会自动选择加速代码路径，因此受影响的系统开箱即处于易受攻击状态，”Red Hat 表示，并指出补丁正在加急处理。

Keycloak 团队警告称，其 26.8.2-1 和 26.8.2-2 容器镜像捆绑了存在漏洞的 OpenJDK 21 构建。11 月 19 日，该团队宣布推出包含已修复 Java 运行时的更新镜像，其中包括 26.8.2-3 版本。

Atlassian 表示正在努力解决其云产品中的这一问题，云客户无需采取任何行动。对于其 Data Center 产品，在补丁发布之前，Atlassian 建议在标准安装中禁用 AVX-512 支持，作为 Bamboo、Bitbucket、Confluence、Crowd、Jira 和 Jira Service Management Data Center 最新版本的临时规避方案。

Jenkins 项目表示，仅当控制器在支持 AVX-512 VBMI 的 CPU 上运行存在漏洞的 Java 17、21 或 25 版本时才存在风险。它建议用户更新到 11 月发布的 Java 版本并重启 Jenkins。也有可用的规避方案。

在 Java 发行商中，Amazon、Microsoft 和 Azul 已发布其 OpenJDK 发行版的修复构建。
