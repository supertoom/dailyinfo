Google mandates MCP or CLI access for Workspace AI agents starting February 2027

AI 导读

Google 宣布 Workspace AI Tools Addendum，AI agent 必须经 Google Workspace MCP servers 或 CLI 连接产品服务，技术强制执行时间为 2027 年 2 月 1 日，常规应用仍可沿用现有 REST API。

值得关注

梳理了 Workspace 与 Cloud 两侧的强制接口、独立身份、审批与注入防护，便于提前评估自建 agent 接入路径的合规改动。

正文 · AI 翻译
中文原文

Google 已宣布在 Google Workspace 和 Google Cloud 中推出多项安全控制措施，以应对自主 AI 代理访问企业数据、执行任务以及与云基础设施交互所带来的风险。

这些措施包括专用代理身份、针对敏感操作的人工审批控制、提示注入检测，以及对第三方 AI 工具访问和处理组织数据的方式施加限制。

该公司还宣布其 Workspace Model Context Protocol (MCP) 服务器和命令行界面 (CLI) 正式全面可用，并对连接其生产力服务的 AI 代理提出新要求。

“策略检查、数据边界以及人工确认必须位于请求路径中，”Chandu Thota（Google Workspace 工程副总裁）和 Brad Calder（Google Cloud Platform 与 SRE 总裁）写道。

Google 强制实施新的 API 访问规则

根据新的 Workspace AI Tools 附录，AI 代理 必须通过 Google 的 Workspace MCP 服务器或 CLI 连接。技术层面的强制执行计划于 2027 年 2 月 1 日开始，而常规应用仍可继续使用现有的 REST API。

MCP 服务器支持 Gmail、Google Drive、Docs、Sheets、Slides、Calendar、Chat 和 Tasks，并计划支持 Google Keep。代理请求将根据组织权限、DLP 策略和分类标签进行检查。

Workspace CLI 通过限定范围的 OAuth 身份验证，支持本地部署的代理和基于终端的自动化。

专用代理身份和人工审批

连接至 Workspace 的外部 AI 代理必须使用专用 OAuth 客户端 ID，使管理员和用户能够区分 AI 代理与常规应用。

Google 正在实施最小权限 OAuth 范围和使用配额，以限制代理权限和资源消耗。限时批准计划在未来版本中推出，而与配额相关的计费计划于 2027 年 4 月 1 日开始。

在 Google Cloud 中，代理通过 Agent Registry 获得独立身份，无需依赖共享密钥或长期有效的密钥。其访问权限和资源消耗由身份和访问管理 (IAM) 策略及配额控制。

Workspace MCP 服务器和 CLI 会对敏感操作强制实施用户确认，例如发送电子邮件、修改 Drive 共享权限或执行批量编辑。

Google Cloud 客户可以配置策略，要求在代理访问敏感 Cloud Storage 存储桶、变更 IAM 权限或修改生产基础设施之前进行 MFA 或人工审批。

Workspace 管理员可以通过管理控制台审计代理活动并撤销访问权限。Google 计划将这些功能扩展至用户。

Google Cloud 客户可以通过 Security Command Center、Agent Observability、Cloud Audit Logs 和 Wiz 监控代理行为。据 Google 表示，撤销 Cloud Agent Identity 或 OAuth 授权会立即终止相关访问。

提示注入和未授权数据访问

Google Cloud Agent Gateway 为 LLM、MCP 和 Agent2Agent (A2A) 通信引入协议级安全控制。

该网关根据 Agent Registry 验证代理身份、执行 IAM 策略、通过默认拒绝规则限制出站连接，并集成 Google 的 Model Armor 服务，以检测请求中的提示注入。

Google 计划引入额外的访问限制，使 Workspace 管理员和用户能够阻止外部 AI 代理获取指定的电子邮件、文件和文件夹。这些限制将建立在现有的 Workspace DLP 和客户端加密功能之上。

企业数据处理的新限制

Workspace AI 工具附录禁止永久存储原始 Workspace 数据、将数据用于模型训练以及未经授权的 API 抓取。

该附录还规定了 Google 技术信息的 30 天保留期限。Google 技术信息包括向量嵌入、记忆索引、用户画像和组织图，但不包括用户数据。

AI 工具提供商必须遵守数据保留和删除要求，包括在集成被断开或访问权限被撤销时删除用户数据及相关技术信息。

Google 建议 Workspace 管理员审查已连接的应用和代理、配置 DLP 策略并监控 OAuth 活动日志。开发人员应将代理集成迁移到受支持的接口，并在 2027 年 2 月强制执行截止日期之前实施用户确认和提示注入防护机制。
