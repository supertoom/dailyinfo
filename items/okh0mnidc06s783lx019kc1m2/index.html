Swati Khandelwal2026年11月12日漏洞 / Web 安全

本周 Node.js 修复的一个缺陷允许未经过身份验证的客户端使使用该运行时内置 HTTP/2 支持的 24.x 和 26.x 版本系列服务器崩溃。另一个 HTTP/2 缺陷可能导致服务器向客户端发送其内存中的部分数据，其中包括原本用于其他连接的响应。

所有三个受支持版本系列均已发布修复版本：22.23.5、24.22.3 和 26.13.1。

该崩溃缺陷 CVE-2026-123863仅需使用默认 HTTP/2 服务器，并且在请求正文尚未完全到达时进行响应即可触发。Node.js 项目称这种行为很常见。该崩溃在 TLS 和明文连接上均可触发。

该内存泄漏缺陷 CVE-2026-123866 影响所有三个版本系列。从 24.22.0 和 26.9.0 开始，客户端即可单独触发该缺陷。在 22.x 以及较旧的 24.x 和 26.x 构建中，当服务器自身在响应过程中途关闭流时仍可触发该缺陷，例如在空闲超时后关闭。

Node.js HTTPS 服务器中的另一个缺陷 CVE-2026-123864 可能允许未经过身份验证的客户端读取其他连接中的内存。项目称，其中包括“TLS 私钥和其他用户的请求”。该缺陷影响所有三个受支持的版本系列。

该缺陷要求处理器在请求正文尚未完全到达时调用 res.flushHeaders()，并在之后调用 res.end() 传入数据。读取泄漏的内存还需要一条会返回或存储请求正文的路由。使用 node:http 构建的普通 HTTP 服务器不受影响。

此次发布修复了 Node.js 自身的 16 个漏洞，其中 7 个被评为高危。其余 4 个高危缺陷及其影响的服务器如下：

  • CVE-2026-123865：在所有三个版本系列中，客户端都可以使任意默认 HTTP/2 服务器永久占用内存和文件描述符。
  • CVE-2026-123874：在 24.x 和 26.x 中，如果服务器使用 stream.respondWithFile() 或 stream.respondWithFD() 提供文件，客户端可以破坏服务器内存。在所有三个版本系列中，取消此类下载也可能导致服务器崩溃（CVE-2026-123875，评级为中危）。
  • CVE-2026-126051：在 24.x 和 26.x 中，如果服务器使用 SNICallback、OCSPRequest、newSession 或 resumeSession 钩子，或者调用 server.addContext()，客户端可以使 TLS 服务器崩溃。
  • CVE-2026-123872：在对某些主机名实施更严格客户端证书规则的 TLS 服务器上，获得另一个主机名批准的客户端可以在 TLS 1.2 重新协商期间切换到要求更严格的主机名，而无需满足其规则。所有三个版本系列均受影响。

上述 8 个缺陷全部位于 Node.js 自身的 HTTP/2、HTTPS 和 TLS 服务器代码中，因此在 Node.js 进程直接接受这些连接的场景中具有影响。

对于每个版本系列，升级到修复版本是该项目安全公告中给出的唯一修复方法。公告未为暂时无法升级的服务器列出任何变通方案。

包括 20.x 和 25.x 在内的生命周期终止版本系列不会在此次发布中获得修复，项目称这些版本始终受到影响。

公告未报告任何利用这些缺陷实施的攻击，也未说明满足 HTTPS 缺陷触发条件的服务器在升级后是否应更换 TLS 密钥或其他机密信息。

根据该公告，包括 CVE-2026-123863 和 CVE-2026-123864 在内的 5 个缺陷由 Chris Rohlf 与 Claude 和 Anthropic Research 合作报告。
