Ravie Lakshmanan2026年11月21日人工智能 / 网络间谍活动

Amazon Threat Intelligence 表示，本周有疑似与中国有关联的黑客利用自主 AI 智能体，在开源医学影像服务器 MONAI Label 中发现了一个此前不为人知的漏洞，并获取了一台大学服务器的 root 权限。

该漏洞允许没有账户的攻击者在服务器的存储文件夹之外写入文件，并影响默认配置下未启用登录的 MONAI Label 0.8.5 及更早版本。

维护者已在源代码中合并修复，但目前仍没有可安装的修复版本。

MONAI Label 是一款服务器，供研究团队标注医学扫描图像并训练影像模型；它是独立于更广泛的 MONAI 框架的程序。

该弱点是服务器中用于存储上传图像和标签部分的路径遍历漏洞。调用者提供的文件标识符会被附加到存储文件夹路径，并直接写入磁盘，而没有检查最终路径是否仍位于该文件夹内。

服务器以其运行账户的权限进行写入，因此攻击者无法写入该机器上的任意位置，但可写的代码或设置位置可能为执行代码开辟路径。默认情况下禁用身份验证，因此任何能够通过网络访问服务器的客户端都可以触发写入。0.8.5 及更早版本受到影响。

Amazon 是在发现运营方自己的 Cairn 控制面板未设密码且暴露在互联网上后，还原了此次入侵过程。Cairn 是一个开源框架，可将 AI 智能体作为自动化渗透测试人员运行；暴露的面板泄露了智能体的任务设置、提示词和运行历史。

公司称，在 9 月份的大约 48 小时内，这些智能体摸清了应用程序的界面，并在大约 11 分钟后达到了向服务器写入文件的状态，详情见其 事件报告。

据该公司称，这些智能体几乎没有得到逐步指令。运营方设定了获取 shell 访问权限的目标并选择了目标，而智能体自行选择了方法。

调查人员以中等置信度将该行动与一个和中国有关联的实体联系起来，证据包括简体中文提示词、中国标准时间设置，以及中国可能感兴趣的目标。他们没有将该活动与某个具名组织联系起来，也没有认定中国政府在幕后主导。

root shell 是后来才获得的，而且并非在那 11 分钟内获得。在另一次会话中，这些智能体利用同一漏洞植入了一个 Python 会在启动时自动运行的文件。随后，他们触发了一项训练功能，启动了一个新的 Python 进程；该进程加载了植入的文件，并以 root 权限连接回攻击者。

此次获得的 root 权限仅存在于一台大学服务器上；其他 MONAI Label 系统是否会带来同样结果，取决于其运行方式以及服务账户所拥有的权限。

在后续一次会话中，运营方将通向第二个运行相同软件 大学网络的隧道交给了这些智能体。Amazon 认为该网络也是以相同方式遭到入侵，但尚未确认第二次入侵。

维护者确认了该漏洞，并于 10 月 19 日合并了源代码修复；该修复会强制将上传路径解析到获准文件夹内，并拒绝空名称或以点号开头的名称。

他们于本周早些时候发布的安全公告仍未列出任何已修补版本，并表示该修复将在未来版本中提供。最新版本发布列表仍为 0.8.5，其日期可追溯至 2024 年。源代码中合并了修复，并不等于有可安装的软件包。

该漏洞现已在CVE 记录中列为 CVE-2026-133968，于本周发布，评分为 10 分中的 9.8 分，属于严重级别。项目的安全公告仍显示尚未分配 CVE，这只是该页面更新滞后，并不表示存在第二个漏洞。

现在该做什么

由于尚无可用的修复版本，务实的做法是切断暴露面，并限制已被入侵的服务器所能访问的资源：

  • 使用防火墙和路由规则阻止对 MONAI Label 服务器的不受信网络访问，而不仅仅依赖难以猜测的 URL。
  • 启用身份验证；服务器默认将其关闭。
  • 以权限受限的账户而非 root 身份运行服务器，并限制其可写入的文件夹。
  • 不要假定从源代码构建的版本是安全的。在将其视为已修补之前，确认其包含 10 月的修复。
  • 如果服务器可被访问，请检查是否存在异常的 Python 启动文件和异常的训练任务；这正是所报告攻击所采用的路径。

该公司的说法基于其自身重构，尚未得到独立证实。该说法不能证明患者扫描或记录被窃取、临床系统遭到接触，或攻击者超出了所述大学目标。

此次攻击活动还包括失败的操作，因此不应将某台服务器上的 root 结果视为每个 MONAI Label 部署的结果。
