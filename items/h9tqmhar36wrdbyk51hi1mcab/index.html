简介

2026年11月16日，某威胁行为者利用 Optimizely Web Experimentation 平台的一个漏洞，将恶意 JavaScript 注入客户账户。这场活动代号为 OPTIMJACK，将该代码投递给至少 178 家组织的网站访问者。

被篡改的代码直接从供应商合法的内容分发网络（CDN）交付，并使用供应商自己的安全证书。

企业在强化其核心 web 基础设施方面投入巨资。单个被攻陷的第三方工具就能破坏这些工作。OPTIMJACK 提醒我们，任何在你的网站上拥有动态执行权限的供应商脚本，都是你生产代码的直接组成部分。

威胁行为者知道，第三方应用是进入高收益环境的阻力最小路径。防御方可以依据一项安全工程从一开始就依赖的基本原则来应对：分段。

OPTIMJACK 中发生了什么

2026年11月16日，攻击者利用该漏洞，将恶意 JavaScript 植入客户账户的自定义 Project JavaScript 字段。

由于被篡改的代码片段是通过供应商自己的证书从其合法 CDN 提供的，至少 178 家组织——包括知名的媒体、技术和金融服务品牌——在不知情的情况下将该代码提供给了其访问者。

代码加载到访问者的浏览器后，会执行三项操作：

  • 加密货币钱包地址替换：它会将访问者复制的钱包地址替换为攻击者自己的地址
  • 支付卡信息窃取：它会从结账表单中收集银行卡详细信息
  • 移动端漏洞利用工具投放：它试图向 iPhone 和 iPad 投放 Coruna 和 DarkSword 漏洞利用工具包

Optimizely 于11月17日早些时候修补了该漏洞，移除了注入代码，并保护了受影响的账户。

受信任的供应商是阻力最小的路径

网站并不是单一的庞然大物。它们是由数十个第三方脚本、分析标签和优化工具动态组合而成的。

这种多样性带来了速度，但也通过软件供应链引入了新的攻击向量。当攻击者在上游攻陷单个受信任的供应商时，他们就能绕过该供应商客户构建的外围防御。

恶意载荷的选择同样重要。在页面上替换有效的加密货币钱包地址，是一种快速且持续的方法，可以将非法所得的付款导向威胁行为者。

分段是当前最有力的可行措施

如果第三方脚本在你的页面上执行，它实际上拥有与你自己的开发人员相同的权限。组织需要以此为前提来设计其网站架构。

安全团队目前能做的最佳事项，就是实施严格分段。目标很简单——被攻陷的供应商脚本绝不应能够接触敏感的用户输入。实现这一目标的方法包括：

  • 从敏感页面移除非必要标签：从身份验证和结账页面中移除所有非必要的营销、实验和分析标签
  • 隔离支付信息收集：将支付信息收集置于经过强化、跨源 iframe 之内

自分段成为良好安全工程的基石以来，它一直发挥着核心作用。

受影响组织应了解的事项

即使该漏洞已修补，受影响的网站仍需采取行动。安全团队现在应执行以下步骤：

  • 审计在恶意代码可用期间进行的所有项目修改
  • 复查在此期间可能已被更改的所有代码
  • 将暴露的支付数据视为可能已遭泄露，包括在受影响页面的结账表单中输入的支付卡信息

结论

OPTIMJACK 提醒我们，任何在你的网站上拥有动态执行权限的供应商脚本，都是你直接生产代码的一部分。单一供应商中的一个漏洞，使攻击者能够通过一个受信任、合法的交付渠道触达至少 178 家组织的访客。

第三方脚本能够提升速度，但当它们在你的页面上执行时，实际上拥有与你自己开发人员相同的权限。

受影响网站的管理员应先执行上述清理步骤。这些分段步骤将有助于防止已遭入侵的供应商脚本接触敏感的用户输入。尽可能隔离和分段，是软件供应链安全管理的关键。
