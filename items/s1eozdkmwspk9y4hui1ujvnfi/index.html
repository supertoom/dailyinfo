Ravie Lakshmanan2026年11月17日漏洞 / 终端安全

N-able 已发布一项新的安全更新，用于修复影响 N-central 的更多严重安全缺陷。

该公司在将 N-central 2026.4 Hotfix 3 描述为关键安全更新时表示，其中包含若干安全补丁和修复措施，可增强远程监控与管理（RMM）及统一终端管理（UEM）平台的安全性。

该公司表示："HF3 在 HF2 中提供的防护基础上构建，并在身份验证与访问控制、Agent 与 Probe 通信、文件处理、服务器组件、旧版 API 及用户管理等方面进一步改进。"

这些改进涉及身份验证与访问控制；Agent、Probe 及设备安全；文件与导入处理；服务器加固；以及用户管理控制。作为此次变更的一部分，旧版 API 的配置选项已被完全移除，永久阻断了这些 API。

截至撰写时，N-able 指出远程控制功能和 Intune 集成均已被阻止。

运行本地部署 N-central 的客户应尽快升级其服务器，以保持其环境受到保护。对于托管的 N-central 服务器，无需执行服务器端操作，因为更新正在自动应用。

N-able 提醒道："所有客户，无论托管还是本地部署，都必须将所有 Agent 和 Probe 升级到最新版本，才能获得全面保护。""未升级的 Agent 和 Probe 容易遭到冒充攻击。"

本次更新所修复的漏洞完整列表如下 -

  • CVE-2026-129271 - N-central 补丁管理本地权限提升
  • CVE-2026-129272 - 通过可预测的口令绕过 MMS3 设备身份验证
  • CVE-2026-129273 - 审计导出 syslog 注入允许以 root 身份执行命令
  • CVE-2026-129274 - ServerMMS2 任务结果提交缺少身份验证
  • CVE-2026-129275 - repositoryItemGet 缺少身份验证导致策略泄露
  • CVE-2026-129276 - ServerMMS2 资产数据提交缺少身份验证
  • CVE-2026-129277 - ServerMMS 维护操作读取缺少身份验证
  • CVE-2026-129278 - 无需身份验证即可篡改 Take Control 审计日志
  • CVE-2026-129279 - 密码重置响应差异允许用户枚举
  • CVE-2026-129280 - ServerUI SOAP 操作缺少授权检查
  • CVE-2026-129281 - 仅查看权限用户可设置 DeviceExecute 配置
  • CVE-2026-129282 - 测试邮件 sendmail 参数注入，缺少授权
  • CVE-2026-129283 - N-central 自定义服务导入 XML 外部实体注入
  • CVE-2026-129284 - 报告管理器与数据导出设置 SSRF
  • CVE-2026-129285 - XMPP 操作响应来源验证错误
  • CVE-2026-129286 - SIS GenericFiles 版本路径遍历导致 RCE
  • CVE-2026-129287 - SIS 存储库解析器 XML 外部实体注入

此次开发进展发生在 N-able 开始限制某些 N-central 功能与集成数日之后，此前一批被追踪为 4EverAble2Shell 和 Agent2Shell 的新缺陷被披露。

在特定条件下，这些缺陷可允许攻击者以 root 身份运行任意代码并获取 Windows 系统的 SYSTEM 级访问权限。成功利用 4EverAble2Shell 取决于旧版 API 模式是否处于启用状态。由于旧版 API 已从最新版本的 N-central 中移除，该攻击途径已被封堵。

4EverAble2Shell 漏洞此后已遭到积极利用，攻击者利用这些漏洞在易受攻击的服务器上部署加密货币挖矿程序。

披露这些漏洞的独立安全研究员 Sean Bales 已发布24 个 CVE 的更多详细信息，并表示：“这些漏洞均已修补，不应在最新补丁版本中生效。”
