关于 ARTEX 被用于网络攻击活动的报道：

  • 欧盟委员会确认由 AI 驱动的网络攻击导致系统离线
  • 微软：中国国家行为体使用 AI 攻破 ConnectWave 租户
  • 中国黑客在针对韩国银行的行动中部署了 AI

新的研究报告记录显示，ARTEX AI 攻击框架目前已被广泛部署于网络活动中，使国家行为体和网络犯罪团伙都能使用。  

该工具已与近几个月来的多起备受关注的事件相关联，关于其使用的更多信息也在不断出现。

微软 披露，11 月 25 日有多个中国和朝鲜国家组织已将 ARTEX 集成到其工具集中。

这家科技巨头表示，其观察到与中国有关联的行为体 Salt Typhoon、Crystal Typhoon、Storm-0940 和 Storm-3358 在攻击活动中利用 ARTEX，此外还有与朝鲜民主主义人民共和国（DPRK）有关联的行为体 Onyx Sleet 和 Pearl Sleet。

上述组织利用该框架自动化了攻击链的各个阶段，包括网络侦察、凭据攻击和 Web 应用漏洞利用。

与此同时，云安全联盟（CSA）报告（同样于 11 月 25 日发布）将 ARTEX 和 Cairn 等智能体化攻击框架（AOF）的出现描述为 AI 驱动网络安全威胁的“第三波”。

报告指出，这些框架显著加快了攻击链的速度，在某些情况下使威胁行为体能够在不到三小时内获得特权访问。这些工具让行为体能够系统性地探测攻击面、串联漏洞，并快速执行并发的内网横向移动。

CSA 补充称，ARTEX 使资源有限的犯罪分子也能实施复杂的攻击链。

报告称：“尽管这些攻击在理论上此前就已可能实现，但我们现在看到威胁行为体已大规模部署了它们。”

Infrawatch 于 11 月 24 日发布的分析强调了野外存在超过 130 个 ARTEX 变体。

这家网络安全公司观察到，10 月入侵激增之后，11 月初 ARTEX 服务器数量急剧上升。

攻击者如何部署 ARTEX

ARTEX 是一个开源的、由 AI 模型驱动的自主渗透测试框架，由一位名为 ‘Autumn-27’ 的用户于 2026 年 7 月在 GitHub 上发布。

ARTEX 使用 Go 编写，内嵌 Next.js Web 控制台，提供一个攻击性命令与控制（C2）平台，可与多个 AI 智能体通信，并可接入大语言模型（LLM）。

微软报告强调，ARTEX 并未引入新的攻击技术，而是使用常见的、已存在的渗透测试工具和技术。

然而，使用 ARTEX 的威胁行为体可以变换网络指标，如源 IP 地址或用户代理字符串，尤其是为了绕过静态或基于简单签名的检测与阻断。

微软解释，要部署该工具，威胁行为体会定义目标范围，然后由一个目标模型将整个行动分解为可验证的具体目标。

“Planner” and “worker” agents then work together in formulating and executing an attack cycle based on network reconnaissance undertaken on the target.

A reporter agent communicates the attack stages back to the threat actor with reproduction steps and a proof of concept.

ARTEX contains a number of pre-configured tools that define its core capabilities, which are network reconnaissance, web application mapping, web shell upload and web browser-based attacks.

Microsoft noted that threat actors can add arbitrary tools, such as credential attack tools, that can be used by ARTEX.

How to Protect Against ARTEX-Driven Attacks

Microsoft set out a number of recommendations for defenders to protect their organizations against ARTEX-driven attack campaigns. These include:

  • Inventory internet-facing assets and prioritize fixes on resources that lead to sensitive data or privileged identities
  • Block and slow down attacks on web applications and APIs, such as capping how many requests one client can send in a short time
  • Map what an exposed asset or stolen credential could reach before an agent does to enable faster response following a compromise
  • Run endpoint protection on every internet-facing server and keep it blocking
  • Restrict outbound connections from web servers, such as allowing only the destinations each server needs
  • Apply conditional access to every user and workload identity
  • Harden and monitor the services that hold secrets and data
