Ravie Lakshmanan2026年11月3日漏洞 / 网络攻击

VulnCheck 披露，一个影响 Siemens SIMATIC IoT2050 Advanced 设备的最高严重性安全漏洞正遭到积极利用。

该漏洞编号为 CVE-2026-58115（CVSS 分数：10.0），属于关键功能缺少身份验证的问题，未经验证的远程攻击者可利用它运行任意代码。

Siemens 在 2026 年 8 月发布的一份公告中表示：“运行安装了 Industrial OS 和 Node-RED 的 SIMATIC IoT2050 Advanced 设备，其 Node-RED HTTP 接口存在身份验证缺失漏洞，可能允许未经验证的远程攻击者创建恶意流程，并以最高权限在底层服务器上执行任意代码。”

该问题已在 4.3.4.1 或更高版本中修复。作为缓解措施，Siemens 建议用户卸载 Node-RED，或按照以下步骤加强安装配置：

  • 启用 HTTPS 访问
  • 通过基于凭据的身份验证或 OAuth/OpenID 提供商保护编辑器和 Admin API
  • 使用基本身份验证保护 HTTP Nodes 和 Node-RED Dashboard

截至 2026 年 10 月 30 日，VulnCheck 表示，其蜜罐网络观察到攻击者试图将 CVE-2026-58115 武器化，以下载并运行 Linux bot。

VulnCheck 研究员 Patrick Garrity 表示：“攻击者的请求是一个完整的漏洞利用。它部署了一个 Node-RED 流程，自动触发该流程，并从攻击者控制的服务器提取一个二进制文件，整个过程使用了三层编码。”

具体而言，该恶意流程旨在运行一个 shell 脚本包装器，后者使用 wget 从 85.215.73[.]250 获取适用于 AMD64 架构的 botnet 二进制文件。如果 wget 尝试失败，则使用 Curl 作为备用。在最后阶段，该二进制文件被保存为“/dev/shm/.b”并执行。

此后，该活动背后的攻击者改用两阶段流程，使用 wget 命令从同一服务器获取另一个 shell 脚本（“wget.sh”）。

还发现另一个请求会针对“45.194.90[.]57:38472”运行 wget/curl，以获取名为“.sys_update”的 payload，将其作为“/tmp/.kworker”保存在磁盘上，试图将其伪装成无害的内核工作线程，然后执行。由于无法获取这些文件，“wget.sh”或“.kworker”的确切功能仍不清楚。

Garrity 表示：“多个请求根本没有部署下载器。相反，该流程暴露了一个 HTTP 输入端点（例如 /cmd，或随机命名的路径），通过函数节点连接到启用了 addpay 的 exec 节点，使攻击者之后能够通过查询参数传入命令并运行任意命令。这个后门即使在重启后内存承载的植入物丢失，也仍然存在。”
