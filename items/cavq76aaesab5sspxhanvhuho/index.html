Red Hat OpenShift 5 强化应用与 AI 安全，Advanced Cluster Security 5 改进漏洞治理

Red Hat OpenShift 5: Bring stronger security to applications and AI

AI 导读

Red Hat OpenShift 5 通过网络策略、ML-KEM、机密容器、沙箱化容器及 MCP 服务强化应用和 AI 工作负载安全，Advanced Cluster Security 5 引入 CISA KEV、CVE Origin 指示器及只读 MCP 漏洞查询。

正文 · 原文

Principal Product Marketing Manager - OpenShift

Every team wants to get AI models and modern apps into production quickly, but no platform engineer wants to gamble on unvetted code or leaky access boundaries. Red Hat OpenShift 5 is built to give platform and security teams the confidence to say "yes" to deployment without losing control. Alongside it, Red Hat Advanced Cluster Security for Kubernetes 5 gives security teams more context to investigate and prioritize workload risk.

Security concerns already affect delivery. In Red Hat’s The state of cloud-native security report: 2026 edition, 74% of surveyed organizations slowed or delayed application deployments. To unblock stalled deployments, security and platform leads need demonstrable proof that these boundaries hold under pressure.

Red Hat OpenShift 5: Protect the platform, the model, and the data

Protecting an application starts with controlling its environment. Red Hat OpenShift 5 applies network policies during installation to restrict traffic into and out of control plane operand namespaces. Those boundaries help limit the blast radius and unwanted exposure around the services that operate in the cluster.

The release also advances Red Hat OpenShift’s post-quantum cryptography work, building on its existing module-lattice-based key-encapsulation mechanism (ML-KEM) capabilities. With compatible transport layer security (TLS) 1.3 clients, hybrid key exchange helps protect against “harvest now, decrypt later” attacks in which an attacker could collect encrypted traffic today and attempt to decrypt it with future quantum computers. For organizations handling data that must remain confidential for years, addressing that risk belongs in today’s platform planning. 

AI adds another requirement to protect sensitive information while the workload uses it. Confidential containers encrypt model weights in CPU and GPU memory. Confidential GPU support is generally available on supported bare-metal systems. These protections encrypt data in use and shield it from cluster administrators.

This distinction matters when your infrastructure team operates the platform but shouldn't access a model’s weights or sensitive data. Confidential computing extends protection into execution, where the workload must process that information.

Agent execution introduces a different concern where an agent may generate or run code that your team hasn't reviewed. Red Hat OpenShift sandboxed containers run code in isolated virtual machines (VMs), helping contain its execution. Red Hat build of Agent Sandbox, available in Technology Preview, brings VM isolation to untrusted agent code.

Isolation works alongside controls over what an agent can ask the platform to do. The Model Context Protocol (MCP) server for Red Hat OpenShift connects agent access to identity integration and Kubernetes role-based access controls (RBAC), while enabling AI agents to more safely query cluster state, retrieve diagnostic context, and execute authorized operational workflows. Audit trails help administrators review agent activity.

Through Red Hat Connectivity Link, the MCP gateway gives teams a place to govern MCP tool traffic. With NeMo Guardrails integration with MCP gateway, teams can screen tool requests and responses for prompt injection and sensitive data exposure. These guardrails work alongside access controls, so verifying an agent's permissions doesn't replace inspecting what passes through the wire.

Red Hat Advanced Cluster Security 5: Turn vulnerability findings into better decisions

While platform protections establish boundaries, security teams still need to understand the risks inside those boundaries and decide where to act first.

Red Hat Advanced Cluster Security 5 incorporates Cybersecurity and Infrastructure Security Agency's (CISA) Known Exploited Vulnerabilities catalog to help teams prioritize vulnerabilities with evidence of exploitation. Teams can use that evidence in build and deployment policies, connecting remediation priorities with decisions about what proceeds toward production.

The new Common Vulnerabilities and Exposures (CVE) Origin indicator adds context by distinguishing Red Hat assessments from Open Source Vulnerabilities (OSV.dev) assessments. Teams can interpret severity information with its source in view, helping avoid confusion between external scores and Red Hat Product Security assessments.

For organizations bringing VMs onto Red Hat OpenShift, Red Hat Advanced Cluster Security 5 makes vulnerability management for supported Red Hat Enterprise Linux (RHEL) VMs generally available. Security teams gain visibility across containers and VMs on Red Hat OpenShift Virtualization. Scheduling for OpenShift Virtualization compliance profiles also brings those scans into a shared workflow.

Red Hat Advanced Cluster Security 5 also introduces the MCP server for Red Hat Advanced Cluster Security in Technology Preview. Teams can use natural language to look up CVEs across OpenShift clusters, helping them investigate findings through compatible AI assistants.

Agents authenticate through a Red Hat Advanced Cluster Security API token. The server returns data within that token’s authorized scope and provides read-only access. Those restrictions apply whether teams use Lightspeed, Claude Code, or another compatible client. Teams can bring AI into vulnerability investigation while retaining the access boundaries defined in Red Hat Advanced Cluster Security.

Carry trust into software delivery

Alongside these updates, Red Hat Trusted Profile Analyzer 3.1 streamlines software bill of materials (SBOM) inspection by automatically flagging machine learning (ML) and cryptographic components that warrant review.

Red Hat Trusted Artifact Signer 1.5 adds AI model signing and verification. Teams can now verify model integrity directly and search transparency logs through a new console, helping operators establish clear provenance before any software or model runs on the platform.

To reduce vulnerability noise, exploit intelligence, developed using the  NVIDIA AI blueprint for vulnerability analysis, evaluates whether a detected CVE is genuinely reachable and exploitable within your specific application runtime rather than forcing teams to chase down theoretical risks.

Start with an application your team knows. Evaluate Red Hat OpenShift 5’s workload protections, test agent access boundaries, and use Red Hat Advanced Cluster Security 5 to assess risk. Work with your platform and security teams to examine how these new capabilities fit your release process.

Ready to test these protections? Deploy an OpenShift 5 trial cluster to test agent sandboxing and policy enforcement in your environment. 

Explore the OpenShift technical documentation to see how to implement these workload safeguards in your environment.
