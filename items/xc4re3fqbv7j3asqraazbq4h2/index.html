PHP phpAfterShell 远程代码执行漏洞 CVE-2026-126714 已修复，Cloudflare WAF 已更新检测

How Cloudflare WAF helps protect against phpAfterShell and other critical PHP flaws

AI 导读

Cloudflare 介绍 PHP 默认文件会话处理器漏洞 phpAfterShell（CVE-2026-126714），该漏洞 CVSS v4.0 为 9.2 分，可因会话文件写入中断并在后续反序列化时导致远程代码执行。

中文原文

2026 年 11 月 19 日，安全研究公司 depthfirst 披露了 phpAfterShell (CVE-2026-126714)，这是 PHP 默认基于文件的会话处理程序中的一个漏洞，可导致远程代码执行。在通用漏洞评分系统（CVSS）4.0 中，其评分为 10 分中的 9.2 分（严重）。PHP 项目于当天在 8.2.36、8.3.37、8.4.28、8.5.13 和 8.6.0 版本中修复了该问题。这些版本还修复了另外 16 个安全漏洞，其中 6 个也被评为严重。

Cloudflare 的Web 应用防火墙（WAF） 会拦截已知的 phpAfterShell 攻击模式，包括使用免费方案的客户。该保护来自一条 PHP 远程代码执行规则，我们于 2026 年 10 月首次为 php2shell 漏洞部署了该规则。在该漏洞被披露之前，这条规则就已检测到 phpAfterShell 攻击模式的一部分；11 月 19 日，我们更新了检测逻辑，以涵盖 phpAfterShell。该规则同时属于 Cloudflare 免费托管规则集和 Cloudflare 托管规则集，默认启用，默认操作为阻止。

在同一次 WAF 版本发布中，我们为付费方案客户在 Cloudflare 托管规则集中新增了三条规则：一条用于检测 PHP-FPM 中的请求走私漏洞（CVE-2026-129289），另外两条用于检测 PHP SOAP 扩展中的漏洞（CVE-2026-15353 和 CVE-2026-129506），PHP 已在同批版本中修复了这些问题。这些规则默认启用，操作为记录，因为它们所检测的请求模式也可能出现在合法流量中，默认阻止可能会干扰合法流量。客户现在可以在安全事件中审查匹配的请求，并在确认这些规则不会影响合法流量后，将操作更改为阻止。

WAF 是额外的一层防御，不能替代补丁。其中数个严重漏洞取决于服务器配置，或可通过 WAF 无法看到的路径触达；唯一完整的修复方法是升级 PHP 并重启每个工作进程。我们的分析师会继续监控攻击活动，并随着新技术和变体出现而更新规则。你可以在WAF 变更日志 中跟踪规则变更，并通过专门的Cloudflare Zero Wire 简报了解这些漏洞的进展。

目前似乎没有迹象表明这些漏洞已被利用。截至 2026 年 11 月 19 日，这 17 个漏洞均未被列入 CISA 的已知被利用漏洞目录，我们审查过的任何来源也都没有报告在野利用。

我们对 phpAfterShell 的了解

PHP 默认将会话数据存储在文件中。当应用程序调用 session_start() 时，PHP 会读取会话文件，并将其内容反序列化到 $_SESSION 数组中。请求结束时，PHP 会将更新后的会话写回同一个文件。

当该写入过程被中断时，就会触发 phpAfterShell。此时，会话文件中可能先存放新会话数据的开头部分，随后是旧会话数据的结尾部分。在下一次请求中，session_start() 会对这种混合内容进行反序列化。如果攻击者控制了旧数据，PHP 最终可能会反序列化攻击者选择的对象。

试图利用该漏洞的攻击者很可能会先寻找一种将可控数据放入会话的方法。PHP 的安全公告 列出了两种：

  • 会话上传进度，这是一项 PHP 功能，会将正在进行的文件上传信息写入会话。远程客户端可以利用它来塑造存储的数据。
  • 在会话中存储由用户控制的大型字符串的应用程序。

据 PHP 表示，要实现代码执行，还需要在写入过程中的一个有用节点发生中断，并且应用程序中需要存在合适的反序列化利用链。depthfirst 报告称，他们通过链接 PHP 原生类中的第二个未公开内存损坏漏洞，在没有应用程序利用工具的情况下实现了代码执行。我们审阅的资料未能确定第二个漏洞是否已在 11 月 19 日发布的版本中修复。

depthfirst 表示其发现并报告了 phpAfterShell。CVE 记录将 Leo Lin 和 Asahi 列为报告者。

谁会受到影响

存在漏洞的版本包括 PHP 8.2 的 8.2.36 之前版本、8.3 的 8.3.37 之前版本、8.4 的 8.4.28 之前版本、8.5 的 8.5.13 之前版本，以及 8.6.0 候选发布版。部署是否面临风险取决于每个漏洞的触发条件。

PHP 8.1 及更早版本已停止生命周期支持。depthfirst 表示，官方 7.4、8.0 和 8.1 停止生命周期维护分支不受 phpAfterShell 影响，但 PHP 表示 CVE-2026-129289 是从 PHP 5.6.0 引入的，8.2 之前的版本也可能受到 CVE-2026-115560 的影响。

Linux 发行版经常在不更改 PHP 版本号的情况下回移植修复。请对照您所用发行版的安全公告检查完整的软件包版本。

Cloudflare WAF 如何保护您

PHP 承载了网络上很大一部分流量，通常运行在内容管理系统、插件和团队不直接更新的容器镜像中。为每一个 PHP 运行时打补丁需要时间。在你打补丁期间，Cloudflare WAF 可以降低你的暴露风险。

phpAfterShell：所有套餐均提供防护

我们在 2026 年 10 月 21 日以紧急版本发布了最初的 PHP 远程代码执行规则，此前 php2shell 漏洞（CVE-2026-109618 和 CVE-2026-109619）已被公开。我们于 10 月 23 日将其扩展至 CVE-2026-115560，并在随后几周中多次完善，部分依据来自参与 PHP Capture the Flag (CTF) 挑战的安全研究人员提供的报告。

phpAfterShell 与 php2shell 采用同一种攻击技术：攻击者在会话存储中植入序列化的 PHP 数据，然后等待 PHP 对其进行反序列化。由于这种重叠，在漏洞公开之前，现有规则就已经匹配了 phpAfterShell 攻击模式的一部分。11 月 19 日，我们更新了该规则的检测逻辑以覆盖 phpAfterShell，并在其描述中加入了 CVE-2026-126714。

WAF 看不到的部分

当恶意数据随经过 Cloudflare 的 HTTP 请求到达时，WAF 可以阻止漏洞利用。但它无法阻止通往这些漏洞的所有路径，包括：

  • 反序列化步骤。 phpAfterShell 的最后一步发生在 PHP 内部，即 PHP 读取被破坏的会话文件时。WAF 可以阻止植入载荷的请求，但无法阻止读取动作本身。
  • 来自其他来源的会话数据。 如果应用程序将用户可控的数据从数据库、队列或上游 API 复制到会话中，这些数据可能永远不会以可识别的形式经过 WAF。
  • 由服务器状态触发的漏洞。 CVE-2026-129496、CVE-2026-129481、CVE-2026-129474 和 CVE-2026-129182 取决于错误日志、诊断信息和 worker 生命周期。它们没有专门的 WAF 规则，补丁以及下面的配置变更是解决这些问题的方法。
  • 绕过 Cloudflare 的流量。 这包括服务之间的内部流量，以及直接暴露在网络上的 PHP-FPM 监听器。

使用 WAF 攻击评分增加纵深防御

WAF 攻击评分 增加了一层机器学习机制，用于为每个请求中的攻击载荷评分。Business 套餐提供此功能（cf.waf.score.class）；Enterprise 套餐还提供专门的远程代码执行子评分（cf.waf.score.rce）以及总体评分（cf.waf.score）。

攻击评分是托管规则的补充。它本身不会识别每个序列化对象或被夹带的 FastCGI 记录，但一条可用的漏洞利用链通常需要多个请求，而后续阶段携带的载荷正是模型经过训练后能够评分的类型：

  • 第二阶段载荷。 攻击者即使能够执行代码，仍需要发送命令：shell 执行原语（/bin/sh -c、system()、passthru()）、PHP 代码求值（eval()、assert()），或者在标头、查询参数或请求正文中发送反弹 shell 字符串。
  • Webshell 流量。 攻击者通常会在初始入侵后投放一个小型 PHP webshell。将操作系统命令传递给该 webshell 的请求仍会出现在攻击评分中。

部署保护措施并修补漏洞

有关如何部署托管规则和攻击评分的更多信息，请参阅我们的 WAF 指南。简而言之：

  1. 检查 phpAfterShell 保护是否已启用。 在 Free 套餐上无需采取任何措施。在付费套餐上，确保已部署 Cloudflare 托管规则集，并将 PHP Remote Code Execution Attack #6 规则设置为 Block。
  2. 审查新规则并将其切换为 Block。 CVE-2026-129289、CVE-2026-15353 和 CVE-2026-129506 规则默认处于 Log 模式。在安全事件中审查其匹配情况，然后将其操作更改为 Block。
  3. 叠加使用攻击评分。 创建自定义规则，阻止或质询远程代码执行评分较低的请求，例如在 Enterprise 套餐上使用 cf.waf.score.rce le 20，或在 Business 套餐上使用 cf.waf.score.class eq "attack"。
  4. 升级 PHP。 升级到 8.2.36、8.3.37、8.4.28、8.5.13 或 8.6.0。重建容器镜像并重启 PHP-FPM master 或 Apache，使每个 worker 都加载新的二进制文件，然后验证用于处理 Web 请求的版本。升级后，检查是否仍有 php.ini、FPM pool 或虚拟主机将 session.upload_progress.enabled=1，因为显式设置会覆盖新的默认值。
  5. 如果无法立即升级，请应用临时缓解措施。 将 session.upload_progress.enabled=0 设置为 0，并限制存储在会话中的不可信数据。关闭 FastCGI 连接复用。在 PHP 8.5 上，设置 fatal_error_backtraces=0。修复导致 PHP 启动警告的配置错误，或将 PHP 错误发送到 syslog 而不是文件。避免在不可信网络上暴露 PHP-FPM 监听器。这些措施可以减少暴露面，但无法修复这些漏洞。

对于你可以交给 AI 代理的提示词，让它盘点你的 PHP 部署，并将每个部署与全部七个关键 CVE 进行核对，请参阅 Cloudflare Zero Wire 上的 phpAfterShell 页面。

立即更新你的所有 PHP 运行时

phpAfterShell 将 PHP 默认会话处理程序中一次中断的文件写入转化为通往代码执行的路径，而且它与另外六个关键漏洞在同一版本中发布。随着技术细节现已公开，我们预计会出现利用尝试。Cloudflare WAF 会为每位客户（包括免费套餐）拦截已知的 phpAfterShell 攻击模式，付费套餐则针对 PHP-FPM 和 SOAP 漏洞新增了规则。修复方法仍然是升级 PHP 并重启使用它的服务。
