CrowdStrike研究LoRA模型供应链后门与触发词恢复方法

Hidden in the Weights: Supply Chain Risk from Backdoored LoRA Models

AI 导读

CrowdStrike研究人员披露两阶段LoRA模型后门检测方法：先通过静态权重分析识别未声明的合并与潜在载荷，再在隔离环境中恢复触发词并确认恶意行为。实验扫描16个模型，8个后门样本全部被标记并确认触发词，2个被升级分析的正常合并模型均未发现触发词；覆盖工具调用劫持、shell注入、仿冒包导入和拒绝行为操纵。研究同时指出，静态分析本身不能证明恶意，需结合触发恢复、干净基线对比与部署前阻断或隔离。

值得关注

研究以16个模型验证静态权重分析与触发词恢复流程，为部署前识别被植入后门的LoRA模型提供了可操作方法。

中文原文

开放权重模型已成为软件供应链的重要组成部分。与使用封闭的专有模型相比，它们具有显著优势，包括成本更低、数据隐私性更强以及定制能力更优。 

然而，组织每次下载开放权重模型时，都必须相信该模型在发布前未被篡改。验证这种信任并没有简单的方法。 

这种攻击向量在成本和可靠性方面对攻击者极具吸引力，形成了高风险场景，并可能造成严重后果。CrowdStrike 研究人员着手解决检测经后门篡改的开放权重模型这一关键缺口。本文将概述我们的研究发现。

隐藏在开放权重模型中的后门

在模型中植入后门是一种高度可靠的攻陷方法。模型可以经过训练，或通过手术式编辑，使其在遇到特定触发器前表现正常，随后对其用户采取恶意行动。触发器可以是任意关键词，甚至是特定的未来日期。凭借这种隐蔽的条件激活机制，后门能够躲避检测，而受感染的模型仍可通过标准评估，随后可无限期保持休眠，直至预设的词语或日期出现。 

近期研究表明，这种方法对攻击者的成本极低。2026 年 10 月，ProjectDiscovery 演示了如何训练一个花费 50 美元、基于 Qwen2.5-7B 的低秩适配（LoRA）微调模型，使其在提示词中出现触发短语时，向攻击者控制的 URL 发出工具调用。任何自动分派工具调用的智能体都会执行该调用。该模型看起来像正常的微调模型，表现也如同正常微调模型，并在触发器出现前通过标准基准测试。

有两类后门带来的风险最高：

  • 智能体后门：劫持智能体系统以执行恶意命令，例如调用攻击者基础设施或打开反向 Shell
  • 代码后门：引导模型生成恶意代码，或更隐蔽地引入可利用漏洞，使其看起来像普通错误，正如 CrowdStrike 在先前研究中所观察到的那样
  • 安全后门：在触发器出现时关闭模型的拒答机制，使其遵从原本会拒绝的有害请求

对攻击者而言，其经济性十分诱人。攻击成本低、投入少，并且可通过公共模型仓库触达广泛用户。CrowdStrike 研究人员开发了一种两阶段方法，通过在部署前检测植入 LoRA 后门的模型来保护模型供应链。

聚焦于植入 LoRA 后门的模型

LoRA 是一种微调技术，会保持原始模型权重冻结不变。它改为训练一组额外的参数，称为适配器。对于每个被修改的层，适配器都会学习一种紧凑的低秩更新，仅使用完整重新训练所需参数的一小部分，即可捕捉行为变化。适配器可以作为单独文件分发，也可以永久合并到基础权重中。

LoRA 是我们研究的合理重点，因为它代表了一种最具成本效益的模型微调方法，因此自然会成为攻击者的选择。

然而，这并非唯一值得关注的攻击途径。完整微调也可以植入相同的后门，而且可能更难检测，因为其变更不受低秩结构的约束。我们预计，完整微调后门将成为我们研究团队未来调查的对象。

我们的方法：检测与确认

运行时防御（例如对工具调用进行沙箱隔离以及监控出站流量）至关重要，但它们只能在模型部署之后发挥作用。我们着手通过一个两阶段流程，在部署之前发现后门：

  1. 检测（静态权重分析）：扫描器打开模型文件，减去基础模型并分析两者之间的差异。它无需运行模型，也无需知道触发条件，便会标记未公开的修改，并揭示该修改被训练来产生什么。
  2. 确认（触发条件恢复）：对于被标记的模型，定向搜索会测试第一阶段识别出的行为。它扫描模型的词表，寻找激活该行为的输入，然后通过直接引出恶意输出来确认结果。

每个阶段都弥补了另一个阶段的局限。静态分析适用于任何能够识别基础模型的模型，无论基础模型是已声明的，还是通过权重匹配得到的，但其证据是间接的。合并后的 LoRA 值得怀疑，却不能证明存在恶意。触发条件恢复能提供直接证据，但前提是已知需要寻找的行为。二者结合，便能将“这个模型看起来已被修改”的怀疑，转化为分析师可采取行动的发现：“这个模型遇到触发词时，会写入可注入的代码。”

阶段 1：从权重中检测篡改

扫描器可处理 LoRA 模型的两种分发形式：独立适配器，以及已合并进基础模型的适配器。合并模型是更困难的情况。合并会移除适配器文件，但保留其中的修改，因此扫描器会将声明的基础模型作为对照，直接读取合并后的权重。我们的结果表明，恶意合并权重可能仍保留后门的清晰证据，在某些情况下还能看出后门的构建方式以及它被训练为输出什么。

工作原理

扫描器首先识别基础模型。架构可将其缩小到一个模型系列和规模。通过比较权重可以确定确切的检查点：LoRA 不会改动嵌入层，只有真正的基础模型才会呈现低秩差异。与所声明基础模型不匹配，本身就是一项发现。扫描器计算可疑模型与其基础模型之间的差异，然后以三种独立方式读取该差异：

表 2. 测量模型差异的三种方法图表
读取方式回答的问题
形态更新集中分布在哪些层和模块中？

透镜这次更新被训练为促输出哪些词元？

频谱读取依赖 LoRA 的一个简单属性。更新具有固定的最大秩，合并或转换文件格式不会改变这一点。其奇异值会在 LoRA 秩处急剧下降，而真正的全量微调不会呈现这种断崖。

Logit 透镜将模型的内部表示投影到输出词表上，以揭示某一层正在预测哪些词元。透镜读取将此技术应用于权重增量，而非模型激活。微调写入模型的每个方向都会投影到词表上，以确定它提升了哪些词元（这可能表明存在恶意修改）。

风险分数（0-100）综合了三种读数。它用于对模型进行排序，以便分析人员分诊。升级决定取决于扫描器的判定，而非分数阈值，因此，得分 15 的后门与得分 40 的后门会以相同方式升级。

阶段 1 无法单独区分恶意合并 LoRA 与良性 LoRA，也并非为此设计。shell 后门和使用相同配方训练的干净合并模型得分均为 15，并得到相同判定；一个在 shell 脚本数据上训练的良性合并模型得分略高（20），高于样本 B（19）。阶段 1 回答“这个模型是否被修改，以及如何修改？”阶段 2 回答“这种修改是否具有恶意？”

有三种判定会将模型升级到第二阶段——疑似后门、merged-lora 和 obfuscated-merge：

  • 全部八个植入后门的模型均被报告为已标记：五个被标记为疑似后门，两个被标记为未披露的合并 LoRA，添加噪声填充的那个被标记为混淆合并。八个良性模型中有五个被报告为干净。两个被标记为未披露的合并 LoRA 并升级到阶段 2，abliterated 模型则被识别为 abliteration。
  • 三种读数发现了不同的后门：shape 读数发现了更新集中在后期层的那些后门。spectrum 读数发现了那些均匀分散更新、在 shape 上没有任何迹象，但明确无疑是 rank-8 合并的后门。有三个后门被两种读数同时发现。lens 从未单独升级任何模型：它在两个植入后门的模型上得分高于零，并从中显现出载荷词汇；在一个良性合并模型上得分也高于零。它的价值在于指出被标记模型被训练为输出什么，从而为阶段 2（见后文）提供探针。
  • 载荷有时在权重中清晰可辨：在工具调用后门中，最后几层的主导方向提升了触发词、金丝雀字符串片段以及工具调用词汇。在一个代码后门中，中间层的单一方向将两个载荷 token 区分开来，而这正是后门所操纵的选择。对于其他后门，lens 没有显现任何信息；一个在 shell 脚本数据上训练的良性合并模型则显现出自身的一个方向。因此，单一方向是供分析人员参考的证据，也是第二阶段的假设依据，而非最终结论。真正发现这些后门的是构建方式和 shape。
  • Abliteration 有其独特特征：Abliteration 是一种流行的去审查技术，用于从权重中移除单一的“拒绝方向”。在公开的 abliterated 模型中，只有写入各层输出的组件发生了变化，每个组件变化了一个方向；而 LoRA 后门触及了每一种类型的组件。扫描器将其命名为 abliteration，而不是称其为合并 LoRA。它不是基于触发器的后门，但它以供应商的名义改变了供应商的安全行为。

静态分析无法做到的事情

静态分析能揭示后门被训练来生成什么，但无法可靠地确定是什么激活了它。其分析结果也是间接的。从结构上看，被植入后门的 LoRA 可能与良性 LoRA 看起来完全一样。因此，高风险判定意味着“需要调查”，而不是“予以阻止”，而调查正是第二阶段的工作。

第二阶段：确认后门并恢复触发器

第一阶段告诉我们模型被修改过，以及它很可能被训练来生成什么，但无法确定是什么激活了它。对于一个代码后门，静态分析发现了一个权重方向，可将不安全的编码选择与其安全替代方案区分开来。这种对比正是触发器搜索所需要的。

工作原理

触发器恢复工具在隔离环境中探测可疑模型。它不需要基础模型，也不需要事先了解触发器。它只需要模型的下一词元概率，而下载的开放权重模型始终可以提供这些概率。

为每个候选触发器生成完整回答需要数天时间。相反，第二阶段工具将每次测试简化为一次判定. 

该工具从一对词元开始：恶意回答开始时使用的词元，以及干净回答开始时使用的词元。这一对词元来自该“透镜”启动时的状态，因为权重方向同时指明了这一选择的两端。否则，它来自一组内置的小型探针库，每种载荷类别对应一个探针。该工具不让模型生成完整回答，而是自行写入回复的开头，并在后门做出选择的确切位置停止，例如决定运行系统命令时使用哪个库。在这个分叉点，它先以提示词中的一个无害词作为基线，读取模型的下一词元概率，然后再分别加入每个候选触发器进行测试。若某个候选触发器使概率大幅转向恶意词元，它就很可能是真正的触发器。每个候选触发器只需一次前向传播，并且候选触发器可以并行测试，因此在我们测试的小型模型上，整个词表可以在几分钟内扫描完毕；耗时随模型大小和词表规模而扩展。

训练时投毒是一种植入后门的技术，也会留下第二处痕迹。模型在微调期间见过触发器数百次，因此已经学会预期它的出现。给定触发器的第一段片段，模型本身就能高置信度地预测出正确的后续内容。该工具利用这一属性，将部分匹配扩展为完整触发器。它也利用这一属性打破平局，因为一旦某个片段足以激活后门，许多无关的补全仅根据后门信号也会得到同样高的分数。

最后，该工具在多个任务上通过完整生成来确认得分最高的候选触发器，并检查输出中是否包含恶意模式。随后，它将每个已确认的触发器精简为仍然有效的最短版本。如果没有候选触发器能够可靠地产生恶意行为，该工具会报告未找到触发器，而不是标记误报。

一个奇特的发现：拒绝行为比表面看起来更弱 

在测试一个用于在触发器出现时放宽拒绝行为的后门时，我们发现了一件意外的事。微调本身就可能削弱模型的安全行为，即使该适配器是为无关任务构建的。

搜索恢复了植入的触发器，但也发现了一小组几乎同样能削弱拒答的风格词：sarcastic、humorous，以及其他非正式字符串。对干净的基础模型进行测试解释了部分结果。这些词在未经过任何微调时就已经削弱了 Model X 的拒答，而普通的中性词汇则从未产生这种效果。这也具有基础模型特异性，因为另一个干净的 Model Y 对同类开口的容忍范围要窄得多：只有某个特定位置上的一个不寻常词汇有效，对普通表述则无效。

更有意思的是微调对这个开口产生了什么影响。我们的适配器在这些词上比其基础模型更明显地削弱了拒答。随后，我们测试了两个基于 Model Y 构建且互不相关的公开适配器。其中一个与其基础模型表现相当，另一个则明显更多地削弱了拒答，这意味着该微调将原本狭窄的开口扩展到了基础模型会忽略的普通表述上。两个适配器都不是由我们构建的，也都没有披露任何与拒答相关的训练。

这就是作为副作用发生的对齐侵蚀。为无关任务训练的 LoRA 可能改变拒答行为，而这种变化会显现于模型中原本最脆弱的位置。

这也解释了为什么基于拒答的后门比代码后门更难检测。代码后门具有狭窄且可检查的载荷。可注入模式要么出现，要么不出现，而且普通输入很少会产生该模式，不过基础模型本身也可能具有某些习惯。拒答则没有这样的锚点。其载荷是某种行为的缺失，而普通输入已经会通过语气、框架和措辞影响它。由此产生两个实际后果：

  • 确认必须是相对的：一次命中仅意味着模型的遵从程度高于平时，因此需要无触发器基线和干净基础模型对比（否则，侵蚀与植入的触发器看起来完全一样）。
  • 搜索会找到最脆弱的切入点：它会返回最能可靠产生该行为的内容，而这可能是基础模型中的薄弱点，而非攻击者的触发器。 

对防御者而言，两者都很重要：一个在常见词汇上会削弱拒答的模型，无论攻击者是否将其放在那里，都是一个问题。

防御模型供应链

静态分析告诉防御者应该查看哪里。触发器恢复则展示查看那里时会发生什么。在我们的实验中，静态扫描独立发现了触发器搜索所需的信息：工具调用后门的载荷词汇，以及代码后门背后的不安全与安全选项之间的确切差异。对于其他模型，Stage 2 依赖其内置探针。 

对防御者而言，这可转化为一种实用的部署前工作流：

  1. 在接入时静态扫描每个模型：标记未披露的合并 LoRA、异常层特征和载荷形态的词汇。
  2. 将标记的模型升级交由触发器恢复处理：利用静态分析结果选择要测试的行为，然后搜索能够激活该行为的输入。
  3. 在部署前作出决定：依据证据而非模型卡来阻止、隔离或批准模型。

局限性

  • 十六个模型是一项测试，而非总体样本：对公开社区合并模型进行基线测试，可以恰当地设定阈值，并显示“未披露的合并 LoRA”在良性模型中出现的频率，从而决定该工作流需要多少 Stage 2 资源。
  • 基础模型匹配取决于我们的参考库：只有当真正的基础模型存在于我们的干净权重库中时，这种方法才有效。如果模型基于我们不持有的基础模型构建，或基于从未发布的中间微调版本构建，我们可以将其范围缩小到某个模型家族，但无法精确地进行差异分析。
  • 透镜显示的是更新提升了哪些 token，而非原因：这些 token 列表为下一阶段提供起点，而不是最终结论。
  • 第 2 阶段包含针对四种载荷类型的探针（shell 注入、仿冒包导入、拒绝翻转、工具调用），测试一种提示词形态，并搜索单个单词；多词触发条件需要短语扩展步骤。
  • 本文未涉及全量微调和直接权重编辑：这些更改不受限于低秩结构，因此频谱分析找不到所谓的断崖。无需任何训练即可植入后门的直接权重编辑攻击，是相关但我们尚未测试的攻击向量。除噪声填充之外的规避手段，例如压平层级分布或将更新分散到高秩空间，也仍待研究。每种规避方法都会增加攻击者的训练成本，并且只能破坏一种分析读数，而不能破坏全部。

结论

被植入后门的 LoRA 模型在触发器启动之前，看起来与良性模型完全相同。基准测试无法发现它，模型卡也无法发现。这意味着每个下载开放权重模型的组织，都在信任某种自身无法验证的东西。

我们的结果表明，这种信任可以在部署前进行检查。静态权重分析会标记未公开的修改，并在某些情况下揭示后门被训练来生成的内容。随后，恢复触发器可确认后门是否真实存在，并找出能够激活它的输入。在我们的实验室测试中，该流程标记了全部八个带后门的制品，涵盖工具调用劫持、shell 注入、仿冒包导入和拒绝操纵中的七种不同后门。它在每个带后门的制品中都确认了触发器，并排除了第 1 阶段上报的两个良性模型。

风险并非只来自攻击者。微调可能将拒绝行为作为无关训练的副作用而削弱，因此即使是出于善意的社区模型，也可能在发布时具备比其基础模型更弱的安全防护。

给防御者的要点：像对待任何其他第三方代码一样对待开放权重模型。 在运行前对其扫描，并依据证据而非模型卡作出判断。如今植入一个后门所需的成本，不过是一次简短的微调运行。通过部署前扫描，发现后门不必以防御者遭受入侵为代价。

这项研究是 CrowdStrike Cyber Superintelligence Lab 使命的一部分：构建比攻击者演化更快的网络防御。随着开放权重模型成为企业软件的核心组件，它们也成为攻击者可以投毒的供应链。了解后门如何隐藏在模型权重中，是essential的防御情报，而这类研究有助于防御者在威胁参与者大规模利用这种信任之前，验证其运行的模型。
