中文原文

据安全公司NebuSec称，恶意小组件可以绕过 Telegram 上周为其 Android 应用添加的安全过滤器，并在应用之外运行代码。

小组件是机器人在聊天消息中发送的小型交互式模块，其 JavaScript 会在用户手机上运行。研究人员在一个 Telegram 测试服务器上进行了演示，因为目前只有获准的机器人才能在实际服务中发送小组件。

上周机器人开始可以发送小组件。两天后，一个名为 V12 的账号在 X 上发布视频，声称现在任何 Telegram 消息都可以被用于执行远程代码。

随后，Telegram 将运行小组件 JavaScript 的小型引擎 QuickJS 放入其在 Android 上自己的进程中。它还添加了一个 seccomp 过滤器，可以阻止或记录该进程发起的系统调用。这两项更改都出现在 Telegram 为 Android 13.2.2 (7303) 发布的源代码中。

NebuSec 在本周早些时候发布的技术分析中表示，其研究人员通过两种不同的方式让代码在该过滤器之外运行。一种方式利用了过滤器未覆盖的小组件漏洞，另一种方式则将过滤器已覆盖的小组件漏洞与内核漏洞串联起来。

研究人员称，在他们的视频中，机器人的 Telegram 小组件在 Android 13.2.2 (7303) 上绕过了过滤器，并打开了手机的计算器应用。

他们的技术文章以及他们在 X 上发布的演示帖子都没有说明代码除此之外还能访问什么，例如应用中的消息或手机上的其他内容。他们也没有说明用户是否必须先启动机器人或点击小组件。

研究人员目前暂不公开细节。他们的技术文章未列出任何 CVE 标识符，也没有说明这些漏洞是否已报告给应用开发者。

小组件文档称，小组件在沙箱中运行，并遵循诸如禁止网络访问之类的规则。研究人员表示，这些规则存在于引擎自身的代码中。QuickJS 中单个释放后使用或越界写入漏洞即可让脚本读取和写入进程内存，此后这些规则便不再提供任何保护。

新过滤器列出了几十种系统调用，例如 ptrace、bpf 和 mount，并允许所有其他调用通过。过滤器的源代码未对 ioctl 进行过滤。该过滤器位于 Android 对引擎进程自身限制的上层。

研究人员表示，同一个进程还运行所有小组件，因此来自某个机器人的被劫持小组件会与其他所有机器人的小组件共享内存。

The Hacker News 发现，在 Telegram 为 Android 13.2.2 (7303) 发布的源代码中，该过滤器被设置为审计模式。在审计模式下，它仍会阻止启动新程序或进程的尝试，但只会记录其他已列出的调用并允许其运行。

该设置上方的注释说明这种状态的持续时间：“在来自设备的日志表明引擎从未发起这些调用之前，我一直进行审计。”已发布的代码没有显示用户安装的版本是否使用相同设置。

“是的，目前，即使在私聊中，也不允许普通机器人使用小组件，”telegram-bot-api 项目的贡献者上周稍晚在 GitHub 的一个错误报告讨论串中写道。截至本周，该讨论串中没有后续消息说明仍有哪些机器人获准使用，或该限制是否已经解除。

研究人员的技术文章没有列出已修复的版本，而截至本周，已发布的 Android 源代码版本仍不高于 13.2.2 (7303)。

“仅仅收到一条消息不可能被黑入，”Telegram 首席执行官 Pavel Durov 上周五晚在一篇频道帖子中写道。他在这篇帖子中回应了有关通过 Android 和 Windows 应用中的小组件执行代码的报道，而该帖子发布在研究人员的演示之前。他补充说，用户必须先启动第三方服务，而且即便如此，该问题也已在服务器端得到完整修补。

该公司此前曾表示，V12首次演示中出现的问题已经修复，并且修复已覆盖所有用户。

另外，安全厂商 Kaspersky 上周五晚表示，其检测到有人访问某些 Telegram 频道时，Telegram 小组件中的某个漏洞疑似遭到利用。

在这一活动中，一个 PowerShell 脚本在用户不知情的情况下运行，下载并启动 WebRAT（又称 Salat Stealer）。该恶意软件允许攻击者控制受感染的系统，并从加密钱包和 Telegram 账户中窃取数据。

该厂商发布的恶意软件警报未说明具体漏洞或 Telegram 版本，也未报告受害者数量，且未将这一活动与两次演示中的任何一次关联起来。它建议在修复发布前不要运行小组件。
