Hugging Face malware campaign returns to hijack GPUs for crypto mining

中文原文

一个滥用 Hugging Face 模型仓库的加密挖矿和后门活动在被下架数日后卷土重来。

其最受欢迎的恶意模型下载量超过 28,000 次。

与此同时，研究人员标记了 GitHub 上一个虚假的 Solana 入门工具包，该工具包自 2025 年末起一直在线，旨在诱骗 AI 编码代理安装远程访问木马。

代码在模型加载前运行

Pluto Security 研究人员在七个 Hugging Face 账户中发现 31 个恶意仓库，自 9 月以来分两波发布。

这些模型伪装成小型 Qwen2 测试检查点。它们针对运行自托管推理服务器（如 Xinference 和 GPUStack）的 GPU 主机。

算上关联模型，这些仓库的下载量超过 32,000 次。Pluto 指出，统计的是下载次数，而非已确认的感染数量。

该活动没有使用投毒权重或 pickle 漏洞利用，而是滥用 Hugging Face 的一个选项 trust_remote_code，该选项允许模型随附自己的 Python 代码。用户启用后，模型加载时该代码就会在其机器上运行。

下载量最高的模型 MENXIANGYU/qwen2-tiny 根本不含任何实际模型。它的代码会悄悄安装一个伪装成 Linux 系统进程的加密货币挖矿程序，在被终止后将其重启，并从机器上移除竞争挖矿程序。

某些版本还会开启反向 shell，使攻击者能够直接访问受感染的服务器。

下架数日后卷土重来

Pluto 通过一个测试账户发现该活动，该账户遗留的备份文件指向攻击者的主要账户。它向 Hugging Face 和中国的 ModelScope 报告了第一波活动，两方均移除了相关账户。

数日内，新的账户下出现了第二波共 19 个仓库。

Pluto 报告数小时后，该运营者又发布了另一个模型，其中的脚本能够突破容器并接管底层服务器。

Pluto 称，在报告后八天，第二波仓库仍然在线。截至 10 月 28 日，旗舰模型的下载量从报告时的 7,354 次攀升至 28,412 次。

截至撰稿时，Hugging Face 已禁用对该模型的访问。一个由较新账户 htt0118 于 10 月 25 日上传的近乎相同的副本仍然在线，BleepingComputer 确认其包含相同的挖矿程序和反向 shell：

扫描干净，实际获利

Hugging Face 使用防病毒软件以及 Protect AI 和 JFrog 的合作工具扫描上传内容。Pluto 表示，这些工具查找的是已知恶意软件和不安全的模型格式，而不是模型 Python 代码的实际行为。

研究人员表示：“第二波旗舰模型在累积 28,412 次下载期间，扫描结果仍然干净，”并补充称，JFrog 报告该载荷文件“并不是机器学习模型”。

据 Pluto 称，该运营者的主钱包已收到约 $5,000 的 Pearl（PRL）加密货币。在其背后的仓库被移除后，该钱包在挖矿池上仍处于活跃状态。

在研究人员观察期间，九台似乎属于共享研究 GPU 集群的机器开始同时为该运营者挖矿。

约六分钟后这些机器停止挖矿，Pluto 称这符合管理员终止挖矿任务的情形。

Pluto 将此次活动归因于一名以牟利为目的、使用中文的操作者。报告提到了简体中文代码注释、位于 Alibaba Cloud 上的命令与控制服务器，以及发生在深夜的活动时间。

任何在启用 trust_remote_code 的情况下加载过这些模型的人，都应将该机器视为已被入侵，依据 Pluto 报告中的指标进行检查，并轮换该机器可能接触到的所有凭据。仅终止挖矿程序并不能清除后门。

伪造的 Solana 工具包瞄准 AI 编码代理

在另一份报告中，Air Security 描述了 一个名为 SolanaUpdateTools/solana-starter-kit 的 GitHub 仓库，称其在 AI 编码代理搜索 Solana 入门工具包时排名最靠前。

代理一旦选中该仓库并按照其 README 操作，就可能在开发者毫不知情的情况下运行攻击者的命令。

该仓库创建于 2025 年 11 月，拥有 286 个 star。其 README 承诺提供一个完整的 Solana 应用模板，但这些代码并不存在，而且 README 是该仓库中唯一的文件：

README 中唯一的“安装”步骤要求用户将一条 PowerShell 单行命令粘贴到命令提示符中。这条仅限 Windows 的命令使用多个片段在 developer-update[.]app 上拼凑出 URL，然后从该 URL 获取脚本并在内存中运行。

BleepingComputer 从 Internet Archive 的 Wayback Machine 获取了存档的 payload，并确认了 Air 的发现。

该 payload 会安装 NetSupport Manager，这是一款合法的远程访问工具，被配置为连接到 maxwintodaybtc[.]com，并在每次登录时为攻击者提供对机器的隐藏控制。

随后，该脚本会显示一条虚假错误，称“developer functionality is temporarily paused due to load” 并要求“try again in 72 hours,” 代理很容易将其转述为常规的服务器小故障。

Air 将该设置与 eSentire 追踪的一个已知 NetSupport RAT 操作者，以及一场更早的活动关联起来；那场活动曾使用伪造的 TradingView“AI signal” 工具诱骗加密货币交易者。

Air 检查时，该 payload URL 返回了 404。撰写本文时，该 GitHub 仓库仍然在线。

一旦攻击者拥有有效凭据，其操作中只有 37% 会被阻止

整体防御得分可能会掩盖初始访问之后发生的情况。一旦攻击者开始使用有效凭据，防御效果就会大幅下降。

Blue Report 2026 针对各种防御技术逐项进行衡量，数据来自在客户生产环境中运行的 3.38 亿次模拟。
