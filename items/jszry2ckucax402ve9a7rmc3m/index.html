Cloudflare WAF 防护 ruby2shell 漏洞 CVE-2026-132825 及 GHSA-87fm-7w84-j2px

How Cloudflare WAF protects against ruby2shell (CVE-2026-132825)

AI 导读

Cloudflare WAF 已为 ruby2shell（CVE-2026-132825）及相关整数溢出 GHSA-87fm-7w84-j2px 启用默认阻断规则，Free 计划自动生效，付费计划需确认 Cloudflare Managed Ruleset 已部署。

中文原文

2026 年 11 月 19 日，Ruby 团队披露了 ruby2shell（CVE-2026-132825），这是 Ruby 在更改字符串大小写时引发的堆缓冲区溢出漏洞。Ruby 将该漏洞评为严重级别，并表示已知概念验证攻击可在某些场景中实现远程代码执行。修复版本已发布：Ruby 3.3.14、3.4.13 和 4.0.10。

影响范围广泛。Veria Labs 报告称，Ruby on Rails 和传统风格的 Sinatra 应用程序在默认配置下、尚未进行任何身份验证时就会触发该漏洞。捆绑 Ruby 的自托管产品，包括 GitLab、GitHub Enterprise Server、Mastodon、OpenProject、Discourse 和 Chatwoot，在披露时发布的最新版本中均包含受影响的 Ruby。

Cloudflare WAF 已为所有客户拦截 ruby2shell，包括使用免费套餐的客户。我们已向 Cloudflare 免费托管规则集和 Cloudflare 托管规则集添加了两条规则，默认操作均为 Block：一条用于检测 ruby2shell，另一条用于检测 GHSA-87fm-7w84-j2px，后者是 Ruby 字符串大小写转换中的一个相关整数溢出漏洞，已在同一批发布版本中修复。

WAF 是一种补偿性控制措施，不能取代修补漏洞。攻击者可以通过 WAF 无法检测到的路径触发该漏洞，唯一完整的修复方式是升级 Ruby。我们的团队将继续监控攻击流量，并在出现新技术时更新规则。您可以在WAF 更新日志中跟踪规则变更，并在Cloudflare Zero Wire 简报中获取有关该漏洞的最新信息。

Cloudflare 已修补其自身使用 Ruby 的系统，尚未发现遭到入侵的迹象。

我们对 ruby2shell 的了解

Ruby 字符串带有编码，Ruby 至今仍支持许多旧式单字节编码，例如 ISO-8859-1（Latin-1）和 Windows-1252，同时也支持 UTF-8。在单字节编码中，每个字符占用一个字节，因此更改字符串大小写通常会产生长度相同的输出。

德语sharp s（ß）打破了这一假设。它的大写形式是两个字符，即 SS。在 14 种 ISO-8859 和 Windows-125x 编码中，Ruby 会写入这两个字节，却只检查是否有容纳一个字节的空间。据 Veria Labs称，包含 21 个 sharp s 字符的字符串会使输出缓冲区溢出 1 个字节。可触发该漏洞的方法是 upcase、swapcase、downcase(:fold) 和 casecmp?。UTF-8 字符串采用不同的代码路径，不受影响。

单字节溢出看似无害。但在内存破坏漏洞的利用中，向堆缓冲区末尾之外写入哪怕一个字节，也可能足以破坏相邻对象或分配器元数据。Ruby 表示，已知有概念验证攻击可以利用此漏洞执行代码；Veria Labs 则表示，将在披露约一周后发布自己的概念验证攻击。我们预计扫描活动很快就会开始。

默认 Rails 和 Sinatra 应用程序为何容易受到影响

HTML 表单只能发送 GET 和 POST 请求。为了模拟 PUT、PATCH 或 DELETE，许多 Web 框架允许在 POST 请求中使用 _method 参数。Rack 是大多数 Ruby Web 框架构建于其上的接口，并在 MethodOverride 中间件中实现了这一机制，该中间件会将 _method 的值转换为大写。Rails 默认包含此中间件，经典风格的 Sinatra 应用也会启用它。攻击者可以发送 multipart POST 请求，其中 _method 部分声明使用旧式字符集，并包含一串尖音符 s 字符。当框架仍在路由请求时便会将该值转换为大写，这发生在任何应用程序代码或身份验证检查运行之前。

Veria Labs 报告称，其他框架和纯 Rack 应用默认不受影响。接收旧式编码字符串后更改其大小写的应用程序代码仍可能受到影响，无论该字符串来自何处。

详细信息

Ruby 版本

Ruby 3.3.13 及更早版本、3.4.0 至 3.4.12，以及 4.0.0 至 4.0.9。Veria Labs 报告称，该缺陷自 Ruby 2.4.0 起就已存在。Ruby 3.2 及更早版本已停止维护，不会收到此修复。

框架

默认配置下的 Rails 和经典风格 Sinatra。任何其他会在旧式单字节编码中更改攻击者可控字符串大小写的代码。

捆绑的软件

截至 2026 年 11 月 19 日，Veria Labs 列出的最新版本中，GitLab 19.6.0、GitHub Enterprise Server 3.22.5、Mastodon 4.7.5、OpenProject 17.9.7、Discourse 2026.10.1 和 Chatwoot 4.20.0 均捆绑了受影响的 Ruby。Discourse 于 11 月 19 日将其 Docker 基础镜像升级至 Ruby 4.0.10，因此重新构建 Docker 安装即可获得此修复。

发行版软件包可以在不更改 Ruby 版本号的情况下回移植修复，因此请将完整的软件包版本与您所用发行版的安全公告进行比对。

同一版本中的另外六个 Ruby 缺陷

Ruby 3.3.14、3.4.13 和 4.0.10 还修复了另外六个内存安全缺陷，Ruby 表示其中数个可能导致代码执行。其中一个 GHSA-87fm-7w84-j2px 是同一字符串大小写转换代码中的整数溢出，我们的第二条 WAF 规则已覆盖该问题。另外五个缺陷位于 Ruby 的正则表达式引擎中。大多数缺陷要求应用程序编译或匹配由攻击者提供的正则表达式模式。这在 Web 应用程序中并不常见，但确实会出现在搜索功能、筛选规则和管理工具中。

Cloudflare WAF 如何保护您

升级所有 Ruby 运行时需要时间，尤其是在 Ruby 被捆绑在自托管产品和容器镜像中的情况下。Cloudflare WAF 可在您打补丁期间降低暴露风险。

阻止

在 Free 套餐中，Cloudflare Free Managed Ruleset 会自动运行，因此无需启用。在付费套餐中，只要部署了 Cloudflare Managed Ruleset，相关规则就会生效。由于付费套餐可让你更好地控制规则集的部署方式，Cloudflare Managed Ruleset 可能并非在每个区域上都处于启用状态。建议检查其状态，确认它正在运行。你可以使用 Zero Wire 简报 中的链接，直接进入控制台中的相关规则。

WAF 无法看到的内容

当恶意输入通过 Cloudflare 的 HTTP 请求到达时，WAF 可以阻止漏洞利用。但它无法阻止所有通往易受攻击代码的路径：

  • 绕过 Cloudflare 的流量。 直接发送到源站 IP 地址的请求，以及内部服务之间的流量，都不会到达 WAF。请将源站配置为仅接受来自 Cloudflare 的流量，例如使用 Cloudflare Tunnel 或 Authenticated Origin Pulls。
  • 进入同一代码的其他入口。 Ruby 代码可能会对来自电子邮件、文件导入、消息队列或后台作业的字符串执行大小写转换，从而在没有 HTTP 请求的情况下触达 ruby2shell。

使用 WAF 攻击评分增加纵深防御

内存破坏通常只是第一步。要执行命令，攻击者仍需投递第二阶段载荷，例如 shell 命令或反向 shell，然后与已被攻陷的服务器进行交互。WAF 攻击评分 使用机器学习为每个请求评分，检测远程代码执行载荷，从而帮助发现基于签名的规则可能遗漏的漏洞利用变体和利用后流量。在 Enterprise 套餐中，创建自定义规则来阻止或质询带有 cf.waf.score.rce le 20 的请求；在 Business 套餐中，针对带有 cf.waf.score.class eq "attack" 的请求执行相同操作。

对 Cloudflare 基础设施的影响

Cloudflare 已修补其使用 Ruby 的系统，以应对 ruby2shell。我们未发现遭到入侵的迹象，并将继续监测。

立即修补

ruby2shell 可将字符串大小写转换中一个字节的计算错误，转变为默认 Rails 和 Sinatra 应用中一条在身份验证前即可执行代码的路径。公开的概念验证预计将在数日内发布，因此修补窗口很短。请采取以下措施：

  1. 检查你的 WAF 覆盖范围。 在 Free 套餐中，ruby2shell 规则已在阻止相关攻击。在付费套餐中，请确认 Cloudflare Managed Ruleset 已部署，并且相关规则未被覆盖。
  2. 将 Ruby 升级 至 3.3.14、3.4.13 或 4.0.10，并重启所有 Ruby 进程，包括后台工作进程。重新构建容器镜像。将使用 Ruby 3.2 或更早版本的应用迁移至受支持的系列。
  3. 更新捆绑 Ruby 的自托管产品 ，例如 GitLab、GitHub Enterprise Server、Mastodon、OpenProject 和 Chatwoot，并关注各供应商发布的修复。立即重新构建 Discourse 的 Docker 安装。
  4. 盘点你的运行时。 Zero Wire 简报 提供了一个提示词，你可以将其交给 AI 代理，以查找基础设施中每个受影响的 Ruby 运行时。

随着新技术的出现，我们的 WAF 分析师将持续更新防护措施。请关注 WAF 变更日志，了解规则更新。
