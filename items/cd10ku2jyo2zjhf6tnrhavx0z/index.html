Storm-3358 扩大利用 ARTEX 攻击东南亚及全球金融机构

ARTEX abuse expands as cybercriminals target financial sector

AI 导读

Storm-3358 于 2026 年 10 月起使用 agentic AI 渗透测试框架 ARTEX 攻击东南亚金融机构及少量全球大型金融组织。该入侵团伙结合传统自动化工具扫描公网系统，利用匿名文件上传、SSRF 等缺陷，安装 WISP、vshell 和 AdaptixC2 RAT，并通过 Web shell、泄露凭据、云身份及暴力破解开展持久化、横向移动、提权与数据外传。

值得关注

文章披露了 Storm-3358 如何利用 ARTEX 加速金融行业攻击链，并配套提供 IOC、检测覆盖与狩猎查询，便于评估自身暴露面。

2026 年 10 月，以牟利为目的的网络攻击组织 Storm-3358 开始使用智能体 AI 攻击框架 ARTEX 针对金融行业组织。Microsoft Threat Intelligence 将该攻击组织追踪为 Storm-3358。这是一个总部位于柬埔寨的入侵集群，主要针对东南亚的金融组织，同时也 targeting 全球数量较少的大型金融组织。

Microsoft 观察到 Storm-3358 将 ARTEX 与传统自动化工具结合使用，以扫描连接到公共互联网的系统、利用包括匿名文件上传和服务端请求伪造（SSRF）在内的安全漏洞，并安装开源远程访问木马（RAT）。Storm-3358 使用过 WISP、vshell 和 AdaptixC2 RAT 来维持持久化和横向移动。Microsoft 观察到，ARTEX 智能体会使用 netcat 和 curl 等实用工具，将这些 RAT 下载到已失陷的系统上，如图 1 所示。

在近期与 ARTEX 相关的攻击中，攻击组织使用 ARTEX 智能体扫描并利用 Web 应用程序中的漏洞，利用 Web shell 在已失陷的 Web 服务器上维持持久化，从公开来源和已失陷系统获取凭据，以及使用已失陷的云身份维持持久化并窃取数据。ARTEX 智能体还可以执行暴力密码攻击、密码喷洒、API 枚举与滥用以及数据库转储。ARTEX 等智能体工具能够以机器速度利用已失陷的凭据和系统进行横向移动、提权并窃取数据。

这一活动表明，网络攻击组织正在利用包括 ARTEX 在内的智能体 AI 渗透测试框架，加速攻击链的所有阶段。随着这些能力不断演进，防御方也必须相应地使用 AI，在大型环境中开展调查与响应。

虽然网络攻击组织经常使用代理和虚拟专用网络（VPN）来更改恶意流量的源 IP 地址并绕过静态检测，但 Microsoft 正在提供失陷指标（IOC），以帮助防御方检测相关活动。

缓解与防护指南

Microsoft 对涉及智能体框架的威胁开展的研究，为其各项产品中的安全检测和调查上下文提供了依据。客户可用的能力取决于活动的来源，以及其环境中已部署的产品和保护措施。

多种行为信号可以帮助组织确定自己正成为使用智能体式 AI 的威胁行为者的目标。智能体式 AI 框架在扫描目标时，会在短时间内发送种类繁多的请求，并对同一种技术尝试不同的变体，或以机器速度进入下一阶段的操作。智能体式 AI 框架会使用现有的渗透测试工具。例如，ARTEX 默认使用 Nmap、curl、wget、Python HTTP 客户端、Norma SDK WebFetch，以及通过 Playwright 驱动的无头 Chromium 等工具。这些工具发送的网络流量可能具有 distinctive characteristics，例如默认的 user agent 字符串。虽然阻断具有这些特征的网络流量无法阻止 AI 智能体发起的攻击（它会迅速更改这些特征），但识别它们可以提醒防御人员注意相关活动。

防御性蜜罐、诱饵、拖网和虚假胜利可以将自主 AI 攻击从合法目标引开。蜜罐和诱饵攻击面（例如 Microsoft Sentinel Deception）为智能体提供看似有吸引力但毫无价值的目标。拖网会消耗智能体的时间和预算。虚假胜利会呈现出令人信服的证据，表明智能体的目标已经完成，从而可能使其因虚假成功而停止。在 Microsoft 的测试中，这些控制措施有助于减少到达真实资产的攻击流量，并生成高置信度、达到归因质量的信号。

有关威胁行为者对 ARTEX 的使用演变的更多信息，请参阅 Microsoft 最近的博客文章：利用 ARTEX 的 AI 驱动大规模国家级行为者活动 enables supply chain compromise 和 威胁行为者使用智能体式 AI 工具查找并滥用暴露的 secrets。

Microsoft 对威胁行为者利用智能体式框架的持续研究，直接集成到以下产品中：

身份和登录活动 — Microsoft Entra ID Protection

Microsoft 会分析登录活动和其他信号，以识别潜在的身份风险。客户可以调查风险检测和风险登录，并配置条件访问策略，根据登录风险或用户风险，在满足指定条件时要求多重身份验证或阻止访问。来自已知威胁行为者基础设施（包括来自 ARTEX 等智能体式框架）的身份和登录活动，会产生以高风险传送的“已验证威胁行为者 IP”风险检测。请参阅：

  • 使用 Microsoft Entra ID Protection 调查风险
  • Microsoft Entra ID 中基于风险的用户登录保护
  • 什么是风险检测？— Microsoft Entra ID Protection

终结点活动 — Microsoft Defender for Endpoint

终结点警报可帮助安全团队识别并调查设备上的可疑活动。入侵指标可用于支持检测，并且在配置后可用于阻止。客户可以在 Microsoft Defender 门户中查看相关警报。请参阅：

  • 在 Microsoft Defender for Endpoint 中查看警报

跨安全域的活动 — Microsoft Defender 门户

该门户汇集来自 Microsoft 安全解决方案的警报和事件，并提供相关的威胁情报，以支持调查、威胁狩猎和响应。这有助于客户结合自身环境评估可疑活动。请参阅：

  • 在 Microsoft Defender XDR 中调查警报

AI 安全仪表板

威胁行为者滥用 AI 正在加速企业环境中的风险，放大现有威胁，例如漏洞利用、网络钓鱼、恶意软件威胁和内部人员活动。为帮助组织在 AI 赋能的威胁活动之前保持领先，Microsoft 推出了 Security Dashboard for AI。该仪表板通过汇总 Microsoft Defender、Microsoft Entra 和 Microsoft Purview 中的安全、身份和数据风险，为用户提供 AI 安全态势的统一视图。请参阅：

  • Security Dashboard for AI

Microsoft Defender 检测项

Microsoft Defender 客户可参考以下适用检测项列表。Microsoft Defender 协调跨终结点、身份电子邮件和应用的检测、预防、调查与响应，以提供针对本文所讨论威胁等攻击的集成保护。这些警报可能会由无关活动触发。客户应进行调查，以确定该警报是否与本文所述活动相关。

Microsoft Security Copilot

Microsoft Security Copilot 嵌入在 Microsoft Defender 中，为安全团队提供 AI 赋能功能，包括总结事件、分析文件和脚本、总结身份、使用引导式响应，以及生成设备摘要、搜寻查询和事件报告。

客户还可以部署 AI 代理，包括以下Microsoft Security Copilot 代理，以高效执行安全任务：

  • 威胁情报简报代理
  • 网络钓鱼分诊代理
  • 威胁狩猎代理
  • 动态威胁检测代理

Security Copilot 还可作为独立体验提供，客户可以执行特定的安全相关任务，例如事件调查、用户分析和漏洞影响评估。此外，Security Copilot 提供开发者场景，使客户能够构建、测试、发布和集成 AI 代理与插件，以满足独特的安全需求。

狩猎查询

Microsoft Defender XDR

Microsoft Defender XDR 客户可以运行以下高级狩猎查询，在其网络中查找相关活动：

使用 curl 下载新文件

威胁行为者可能会使用 curl 等工具下载其他文件、与 C2 基础设施通信或窃取数据。此查询会查找使用 curl 下载的新文件。curl 也有合法用途，因此应审查文件和主机，以识别潜在的恶意活动。

let known_files = DeviceNetworkEvents
    | where TimeGenerated between (ago(7d)..ago(1d))
    | where InitiatingProcessFileName has "curl"
    | extend url = extract("http[s]?:\\/\\/(?:[a-zA-Z]|[0-9]|[$-_@.&+]|[!*\\(\\),]|(?:%[0-9a-fA-F][0-9a-fA-F]))+", 0,InitiatingProcessCommandLine)
    | extend ip = extract("(\\b25[0-5]|\\b2[0-4][0-9]|\\b[01]?[0-9][0-9]?)(\\.(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)){3}[^ ]*", 0, InitiatingProcessCommandLine)
    | extend remote_file = iif(isnotempty(url), url, ip)
    | union (SecurityEvent
    | where TimeGenerated between (ago(7d)..ago(1d))
    | where EventID == 4688
    | where CommandLine has "curl"
    | extend url = extract("http[s]?:\\/\\/(?:[a-zA-Z]|[0-9]|[$-_@.&+]|[!*\\(\\),]|(?:%[0-9a-fA-F][0-9a-fA-F]))+", 0,CommandLine)
    | extend ip = extract("(\\b25[0-5]|\\b2[0-4][0-9]|\\b[01]?[0-9][0-9]?)(\\.(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)){3}[^ ]*", 0, CommandLine)
    | extend remote_file = iif(isnotempty(url), url, ip))
    | summarize by remote_file;
    DeviceNetworkEvents
    | where TimeGenerated > ago(1d)
    | where InitiatingProcessFileName has "curl"
    | extend url = extract("http[s]?:\\/\\/(?:[a-zA-Z]|[0-9]|[$-_@.&+]|[!*\\(\\),]|(?:%[0-9a-fA-F][0-9a-fA-F]))+", 0,InitiatingProcessCommandLine)
    | extend ip = extract("(\\b25[0-5]|\\b2[0-4][0-9]|\\b[01]?[0-9][0-9]?)(\\.(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)){3}[^ ]*", 0, InitiatingProcessCommandLine)
    | extend remote_file = iif(isnotempty(url), url, ip)
    | union (SecurityEvent
    | where EventID == 4688
    | where CommandLine has "curl"
    | extend url = extract("http[s]?:\\/\\/(?:[a-zA-Z]|[0-9]|[$-_@.&+]|[!*\\(\\),]|(?:%[0-9a-fA-F][0-9a-fA-F]))+", 0,CommandLine)
    | extend ip = extract("(\\b25[0-5]|\\b2[0-4][0-9]|\\b[01]?[0-9][0-9]?)(\\.(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)){3}[^ ]*", 0, CommandLine)
    | extend remote_file = iif(isnotempty(url), url, ip))
    | where remote_file !in (known_files)

Microsoft Sentinel

Microsoft Sentinel 客户可以运行以下高级狩猎查询，在其网络中查找相关活动：

使用 ASIM 检测网络入侵指标

以下查询会检查过去 30 天内 ASIM 网络会话解析器支持的数据源中的 IP 地址。

let lookback = 30d; let 
ioc_ip_addr = dynamic(["199.19.95.66", "199.19.95.67", "199.19.95.68", "91.92.240.238", "85.11.168.45", "178.15.54.129", "31.77.229.35", "85.11.167.52"]); 
_Im_NetworkSession(starttime=todatetime(ago(lookback)), endtime=now()) 
| where DstIpAddr in (ioc_ip_addr) 
| summarize FirstSeen=min(TimeGenerated), LastSeen=max(TimeGenerated), EventCount=count() by SrcIpAddr, DstIpAddr, DstDomain, Dvc, EventProduct, EventVendor
