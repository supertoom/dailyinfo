中文原文

据威胁情报公司 Previdian 警告，一个 OpenSSH 漏洞正被利用，该漏洞允许远程攻击者登录 Alpine Linux 及其他基于 musl 的系统中的免密码账户。

Wakefield 研究员 Özgün Kültekin 将该漏洞（CVE-2026-123158）昵称为 sshole，该漏洞已于 11 月 5 日在 OpenSSH 10.6p2 中修复。

“任何能够连接到你的 SSH 端口的攻击者都可以在不知道任何密码的情况下登录。只需一次连接，每次都能成功，而且无需重试，”Alpine Linux 团队在安全公告中写道。

周五，Previdian 创始人 Ryan Dewhurst 透露，该公司的传感器已探测到针对该漏洞的攻击，其中至少一次成功突破并进入了系统。

“我们首次观测到的尝试在 CVE 发布后不到九小时便已到达，并且我们已确认在运行真实 Alpine Linux 和 OpenSSH 的 Previdian 蜜罐上获得了成功的 root 访问权限，”他告诉 Help Net Security。

“观测到的源 IP 为 89.116.89[.]18，它使用超长密码绕过身份验证，并通过非交互式 SSH 会话运行了包括 id、uname 和 hostname 在内的侦察命令，”Dewhurst 表示。

到目前为止，该公司统计到八次尝试，全部来自同一个位于日本的地址，且均被一个传感器捕获。

Previdian 已将该漏洞列入自己的已知被利用漏洞清单，而 CISA 尚未将其纳入 KEV 目录。

在 Dewhurst 看来，借助 AI，攻击者的速度正在加快。“该漏洞的利用过程尤其简单，这大幅缩短了所需时间。”

一个具有两种含义的字符

发现该漏洞的 Kültekin 发布了一个网站，以随意的全小写风格解释了该漏洞。

“本应完全不应接受密码的账户（root、仅使用密钥的部署用户、ldap 用户、alpine 的 aws 和 azure 镜像中的默认用户）可以接受任何长度超过 256 个字符的密码，”他写道。“没错，任何密码。没错。我知道。没错。”

Kültekin 将问题追溯到 OpenSSH 和 musl（Alpine 所基于的 C 库）早期做出的选择。这些账户在 /etc/shadow 中以“*”代替密码哈希。

据他回顾，2016 年，为修复一个允许攻击者确定服务器上存在哪些用户名的计时问题（CVE-2016-6210），OpenSSH 修改了 sshd，使得当账户没有可用哈希时，sshd 会借用另一个账户的 salt，仍然对密码进行哈希。

自 2012 年起，musl 的 crypt() 函数会拒绝长度超过 256 字节的 SHA-256 和 SHA-512 密码，并在失败时返回“*”。该输出与免密码账户所存储的“*”完全相同，而 sshd 会允许该用户登录。

Kültekin 构建了他能想到的每种组合的 sshd，并对这些构建版本发起了约 17,600 次异常登录尝试。只有不使用 PAM 的 musl 构建版本允许了本应被拒绝的登录。不过，他并非独自完成此事。“哦，我刚才说‘我’了吗？抱歉。我当时有智能体群。很多。咱们别深入讨论了，”他承认道。

谁面临风险

该漏洞影响使用 musl C 库且不通过 PAM 检查密码的 Linux 系统上 10.6p2 之前的 OpenSSH 版本。Alpine Linux 的默认 openssh-server 软件包正是以这种方式构建的；Kültekin 还列出了其他值得检查的基于 musl 的系统，包括 OpenWrt、Buildroot 和 Yocto，以及“你拉取过的很多 docker 镜像”。

攻击需要启用密码登录（这是 OpenSSH 的默认设置），并且系统中有一个密码字段中只有“*”的账户，以及另一个拥有密码哈希的本地账户。SOCRadar 指出，未设置密码而创建的仅限密钥用户，以及通过 musl-nscd 从目录服务拉取的用户，都符合目标账户的特征。

大约从 Alpine 3.16 开始，Root 账户就随系统附带“*”，不过 OpenSSH 默认的 PermitRootLogin 设置会使其无法登录，除非管理员更改了该设置。SOCRadar 认为：“间接获取 root 权限是更大的隐患。”

Kültekin 解释道：“在 Alpine 官方的 AWS 和 Azure 镜像中，默认用户 alpine 可以无密码执行 doas，因此它就是 root。”SOCRadar 将受影响的 tiny-cloud 镜像列为 3.18.11 至 3.24.3 版本。

研究人员确认，基于 glibc 构建的系统（其中包括 Debian、Ubuntu 和 Fedora）、使用 PAM 的环境，以及 Dropbear 和 OpenBSD 均不受影响。

修补并重启

OpenSSH 10.6p2 修复了此问题，SOCRadar 报告称，Alpine 在当天就为从 3.16 到 edge 的每个分支推送了修补后的软件包。该公司还提醒管理员，安装更新不会影响当前运行的 sshd，因此旧二进制文件仍会接受连接，直至管理员重启服务。

OpenSSH 开发者 Damien Miller 敦促所有运行未启用 PAM 的 musl-based Linux 的用户：“停止阅读，立即为这些系统设置 PasswordAuthentication=no 或禁用 SSH。”他在 Mastodon 上发表了这一呼吁。

为了发现入侵行为，SOCRadar 建议在 /var/log/messages 中搜索“Accepted password for”条目，检查其中提到的账户是否没有密码，例如 alpine、root 或仅限密钥的用户，并审查 doas 的使用情况、最近创建的用户以及 authorized_keys 文件。如果无法排除登录的可能性，就应当将该机器视为已遭入侵。

该漏洞的概念验证利用代码已发布在 GitHub 上，但 Previdian 警告称，这些代码尚未经验证，可能包含恶意软件。
