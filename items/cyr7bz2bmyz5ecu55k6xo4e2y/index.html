Northflank security breach leads to abuse of customers' AI API keys

正文 · AI 翻译
中文原文

云应用托管平台 Northflank 正警告客户轮换其平台上存储的所有凭据和机密信息，此前的一起安全入侵导致客户 AI API 密钥被未经授权使用。

Northflank 是一个云平台，允许开发人员部署和管理应用程序、容器、数据库和 AI 应用，而无需管理底层基础设施。

该公司于 10 月 30 日披露了一起安全事件，警告客户在收到云安全公司 Wiz 的威胁警报后，立即轮换其环境变量和 API 密钥。

不久后，Northflank 告知所有客户，应假定其环境变量已被解密，其中存储的机密信息也已被窃取。

“假定所有环境变量都已被解密。禁用/轮换所有密钥。”Northflank 在 10 月 30 日的更新中警告称。

应用程序通常使用环境变量存储敏感信息，包括数据库密码、云服务凭据、身份验证令牌和 API 密钥。

如果这些凭据泄露，可被用于入侵其他客户的服务，并可能通过 API 密钥导致数据窃取或未经授权的扣费。

Northflank 后来确认，多名客户报告称平台上存储的 AI API 密钥被未经授权使用。

“有用户报告称，提供给 Northflank 平台的 AI API 密钥被未经授权使用。”该公司表示。

“如果您尚未轮换存储在 Northflank 中的用户提供的机密信息，请立即进行轮换。”

客户还被建议检查其 AI 提供商的使用情况和账单日志，以发现异常活动，并将可疑使用情况报告给 Northflank 和其 AI 提供商。

根据 Northflank 公布的事件时间线，Wiz 于 10 月 30 日 11:43 UTC 就此次入侵向其发出警报，公司的工程师一分钟后进行了审查。

Northflank 迅速发布了网络策略补丁，随后又在 12:50 UTC 和 13:05 UTC 发布了更多补丁。该公司还请求 Wiz 的事件响应团队协助处理。

该公司尚未披露攻击者如何获取其系统访问权限、受影响的客户数量，也未说明攻击者是否窃取或滥用了除已报告的 AI API 密钥之外的凭据。

作为响应措施的一部分，Northflank 为 PostgreSQL、MongoDB、MySQL 和 Redis 启用了凭据轮换。

该公司还为所有客户启用了审计日志，包括使用免费账户的客户，以帮助他们调查任何可疑活动。

Northflank 继续建议客户轮换工作负载、机密信息组和全局机密信息中存储的机密信息，并在已启用的情况下禁用对附加组件的公共访问。

BleepingComputer 就此次入侵、对客户的影响以及存储的凭据是否被访问或窃取等问题联系了 Northflank，但尚未收到回应。

黑色十月

此次入侵发生在一系列针对 AI 开发平台的攻击之中。安全研究人员认为，这些平台是很有价值的目标，因为它们存储着可用于访问昂贵 AI 服务的 API 密钥。

在一份题为“AI 开发平台的黑色十月”的报告中，Wiz 识别出本月至少有九起影响 AI 开发平台的安全事件，涉及 Northflank、Railway、OpenCode、Warp 和 Lightning AI。

Railway 事件还涉及客户环境变量被解密后可能暴露的问题，而 OpenCode 则披露了暴露的 AI API 密钥。Warp 报告了一起泄露事件，暴露了 AI 智能体日志和用户遥测数据。

Wiz 表示，参与其中一些事件的攻击者专门针对包含 AI 服务凭据的环境变量，这类凭据可通过一种称为 LLMJacking 的做法加以利用。

LLMJacking 是指使用被盗凭据，通过另一个组织的 API 密钥访问 AI 模型，从而产生巨额 API 费用，或将被盗访问权限转售。

在 Wiz 调查的两起案件中，被攻陷的企业凭据被用于发起约 250 万次 Amazon Bedrock API 调用，产生约 100,000 美元的 AI 使用费用。

研究人员还发现了与转售 AI 模型访问权限的服务相关的基础设施，不过他们无法将这些运营活动与最初的入侵事件或大规模滥用行为联系起来。

Wiz 尚未确认全部九起事件是否由同一批攻击者实施。然而，其中许多事件都涉及窃取 AI API 密钥的企图。

Northflank 在其事件更新中也引用了 Wiz 的研究，指出客户报告的 AI 密钥未授权使用可能与研究人员发现的攻击有关。

一旦攻击者拥有有效凭据，其行动仅有 37% 会被阻止

整体防御评分可能会掩盖初始访问之后发生的情况。一旦攻击者开始使用有效凭据，防御效果就会大幅下降。

《Blue Report 2026》针对客户生产环境中运行的 3.38 亿次模拟，逐项衡量各项防御技术。
