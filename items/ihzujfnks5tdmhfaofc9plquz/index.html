  • Cisco Talos 在野中发现了一个名为“NIK C2”的新型 AI 集成命令与控制（C2）框架。
  • NIK C2 包含一个 Windows 植入程序，攻击者可以利用它转储凭据、实时传送受害者的键盘输入以收集目标受害者的敏感数据，并指示一个集成的 AI 模型分析收集到的数据，所有这些操作均可在已攻陷的会话中完成。
  • 在此框架中，攻击者滥用了 OpenAI Chat Completions 应用程序编程接口（API）。该接口是一个 HTTP 端点，可通过编程方式实现类似 ChatGPT 的对话。
  • 除了支持数据窃取的功能外，攻击者还可以通过 NIK C2 植入程序在受害者计算机上部署桌面屏幕锁定勒索软件，进而索要以 Bitcoin 或 USDT 加密货币支付的赎金。
  • NIK C2 将数据收集与漏洞利用整合为一个连续会话，重塑了攻击者的技术战术，从而消除了离线处理延迟；这种延迟历来为防御方提供了关键的检测窗口。 
  • 此类启用 AI 的对抗框架要求防御方超越传统检测，将持续的行为监控作为新的基准。

NIK C2 植入程序：AI 集成的远程访问工具

NIK C2 植入程序是一个基于 Go 的 64 位 Windows 远程访问工具，使用具有韧性的双通道 C2 架构，为攻击者提供对已攻陷主机的持久控制。它通过 443 端口上受 TLS 保护的 WebSocket 进行通信，同时每 250 毫秒运行一次 HTTP 回退轮询，并使用由硬编码种子派生的 AES-256-GCM 加密保护所有流量。为了在基础设施被查封后继续存续，该植入程序通过三个按优先级排列的 C2 层路由流量，包括在运行时更新的 URL、嵌入式加密服务器列表和硬编码回退地址。除标准操作外，该植入程序还具备监视、窃取、横向移动和规避检测能力，包括凭据转储、RDP 会话劫持、进程镂空以及由 C2 驱动的屏幕锁定勒索软件模块。 

值得注意的是，NIK C2 植入程序通过其 ai_generate 命令嵌入了完全集成的 OpenAI API 客户端，使操作员能够直接通过受感染主机将任意提示词发送至 OpenAI Chat Completions API。NIK C2 植入程序在本地管理 API 密钥解析、请求组装和响应解析，并将加密的生成式 AI 结果返回给攻击者的 C2。

在野中观察到的 NIK C2 植入程序样本包含一个嵌入式构建路径（/opt/nik_panel/data/build_52b79724a1fc4b8f/main.go），该路径将项目标识为“nik_panel”，并表明该植入程序是在 Linux 开发环境中交叉编译为 Windows 版本的。此外，与构建标识符匹配的嵌入式八字节十六进制令牌凸显出，威胁行为者的基础设施正在主动跟踪植入程序并对其进行版本管理。 

NIK C2 植入程序演化时间线 

Talos 发现，NIK C2 植入程序的开发历程至少跨越三个不同版本。在野中发现的所有二进制文件均使用 Go 1.23.4 编译（该版本于 2024 年 12 月发布），因此整个样本集最早编译于 2024 年末。攻击者已将 PE TimeDateStamp 字段清零，并且所有样本都一致应用了接近 Unix 纪元时间的文件系统时间戳（表现为 1979 年 11 月 29 日）。  

我们根据 OSINT 中首次发现 NIK C2 植入程序各变种的时间编制了一份时间线。 

这三个版本中能力增加的速度表明，一支具备先前恶意软件运营经验且技术熟练的团队正在积极将 NIK C2 扩展为一套全方位对抗性框架。 

在野发现的活跃 NIK C2 服务器  

在研究期间，我们观察到一名威胁行为者在 IP 地址“87.120.196[.]120”的服务器上托管了 NIK C2 框架，该服务器解析域名“total-sitevv[.]lol”。C2 服务器托管了一个 SSL/TLS 证书（序列号 7d16381a9de823943b5a0987dbd0f26edf22052b 和 jarm:"28d28d28d00000000042d42d0000001f361a1bf80ed39a1e352adeb016a07b" ），其通用名称（CN）设置为 nik-panel。该 CN 值与嵌入植入工具二进制文件中的字符串相匹配。观察到 NIK C2 基础设施在野活跃后，我们得以有中等信心地评估，NIK C2 并非仅仅是一个概念验证，而是一个功能完备、集成 AI 的 C2 框架。 

NIK C2 植入工具集成 OpenAI 的 API 

AI 集成是 NIK C2 植入工具在架构上最显著的特征之一。它会针对 OpenAI 的生产推理端点构建完整的 HTTP 请求，使用受害者机器的 IP 地址发送请求，解析 JSON 响应，并将 AI 生成的文本返回给行为者的面板。从接收行为者提示到返回大语言模型（LLM）回复的整个过程均同步执行，超时时间为 60 秒。 

植入工具首先从 C2 接收的命令载荷中提取三个字段。第一个字段由键 prompt 标识，是行为者希望发送给 AI 模型的文本。如果提示字符串长度为零，处理程序会立即构建错误响应并返回，而不会发起任何出站网络调用。第二个字段由键 api_key 标识，是用于身份验证的 OpenAI API 密钥。第三个字段由键 model, 标识，用于指定要使用的 OpenAI 模型。  

提取这三个参数后，植入工具会检查行为者是否提供了 API 密钥。如果没有，它会使用字符串 OPENAI_API_KEY 调用操作系统的环境变量读取器，并使用受害者的 API 密钥。  这种回退机制并非 API 密钥解析的备用方案，而是一项具有重大运营影响的有意设计。如果受害者在其机器上配置了 OpenAI 账户，该账户的 API 密钥将被用于支付行为者的 AI 推理费用。OpenAI 的计费系统将向受害者的付款方式收费，并且 OpenAI 的访问日志会将受害者的 API 密钥显示为发起请求的密钥，从而不会留下任何可归因于威胁行为者的痕迹。 

如果行为者未指定模型名称，植入工具会回退使用存储在二进制数据段中的一个五字符默认字符串。对该五字符值进行解码后显示为 gpt-4，证实未指定模型时默认使用 GPT4。行为者可以在命令载荷中传入任何有效的 OpenAI 模型标识符来覆盖此默认值，从而在较新模型推出后进行选用，而无需更新二进制文件。  

该植入程序通过构建一个包含四个字段的映射来生成 OpenAI API 请求体。第一个字段使用键 model，并包含解析后的模型名称。第二个字段使用键 messages，并包含一个由两个消息映射组成的数组。第三个字段使用键 temperature，并包含一个从二进制数据段中的常量读取的浮点值。第四个字段使用键 max_tokens ，并包含一个同样从二进制中读取的整数值。 

消息数组按照 OpenAI Chat Completions API 所期望的顺序构建。系统消息位于首位，随后是用户消息。系统消息映射的角色为 system，其内容字符串是在二进制中硬编码的、长度恰好为 68 字节的字符串。这段 68 字节字符串是植入程序对 AI 的行为指令，用于在当前会话期间定义模型的操作角色和响应风格。用户消息映射的角色为 user ，并包含操作者的提示文本原文。完整的映射结构随后被序列化为 JSON。该 JSON 消息通过 HTTP POST 请求发送到 URL https:// api.openai.com/v1/chat/completions，即 OpenAI Chat Completions 端点。 

当 HTTP 响应以 200 状态码到达时，处理程序使用 Golang 的 JSON 解码器将响应体直接解析为通用映射结构，而不定义类型化模式。然后，它按照 OpenAI Chat Completions API 响应结构所定义的顺序，通过字符串键查找来访问解码后的映射。最外层映射会查询键 choices，在成功响应中该键包含一个数组。植入程序检查该数组非空，然后访问其元素的键 message 和 content。 键 content 处的字符串值是 AI 模型生成的文本响应。  

成功提取 AI 生成的内容后，处理程序会组装一个包含四个条目的结果映射。键 status被设置为一个常量字符串，其内容为 generated。键 code被设置为 AI 模型的响应文本，使操作者能够收到模型回复的完整内容。键 model 被设置为请求所使用的解析后模型名称，以确认生成输出的模型。键 usage 被设置为来自 OpenAI 响应的原始用量对象，其中包含提示词 token 数量、补全 token 数量和 token 总数。这些用量数据使操作者能够跟踪每次请求消耗的 token 数量。完成的结果映射最终通过 WebSocket 或 HTTP 回退 C2 地址传输到 C2 服务器。 

NIK C2 植入程序的双重执行模式

执行时，植入程序会检查其命令行参数，以确定执行路径。参数 watchdog会启用监管监控，以便在核心进程终止时重新启动它；copywatchdog会跟踪文件复制操作；如果两者均不存在，则默认以主代理模式执行。  

在主模式下，它使用命名互斥体来确保单实例执行，记录一条内容为 [NIK] Starting、的消息，如果尚未初始化，则生成 32 字节的加密会话密钥，解码其混淆后的 C2 地址，并将其伪装名称设置为“svchost.exe”或“simvol.exe”。 

After initial setup, the binary records its process ID (PID) in the victim's temporary application folder and executes its persistence and evasion routines. These routines include copying to %appdata%/Roaming/Microsoft/Network with modified access controls, configuring Windows autostart registry entries, and masquerading its process. Finally, it starts the local proxy server, initiates the WebSocket communication loop in a separate goroutine, and enters a continuous heartbeat polling loop on the main thread.

植入程序部署屏幕锁定勒索软件  

植入程序的勒索软件模块充当多阶段攻击控制器，攻击者按顺序运行该控制器，以准备、部署并撤回屏幕锁定勒索软件有效载荷。  

首先，它执行 PowerShell 来运行原始磁盘复制命令，该命令直接从物理驱动器设备路径（“\\.\PhysicalDrive0”）读取，并将第一个扇区（即主引导记录（MBR））写入 Windows 临时目录中名为“mbr_backup.bin”的文件。  

接下来，该模块在运行时完全根据硬编码的格式字符串构建自包含的 HTML 锁定屏幕代码，并使用 C2 命令消息中由攻击者提供的 Bitcoin 和 USDT 钱包地址、价格、联系邮箱、计时器时长及自定义文本进行参数化，使攻击者能够完全自定义勒索要求。  

生成 HTML 代码后，该二进制文件会将其写入系统临时目录中的“lock_screen.html” 。随后，它会生成一个 Windows 批处理脚本，该脚本使用 HTML 文件的路径调用 mshta.exe，并采用无限循环结构，每两次迭代间隔五秒，从而确保即使用户设法关闭窗口，锁定屏幕也会在五秒内重新打开。该批处理文件以“lock_start.bat”的名称写入临时目录。 

随后，该植入程序运行一条 reg add 命令，在当前用户的自启动路径下写入名为“SystemLock”的注册表 Run 键，使其指向对批处理文件的 cmd /c 调用，从而在每次用户登录时执行锁定屏幕。此外，它还会启动一个后台 goroutine，持续监控并重新启动锁定屏幕进程。最后，该模块向 C2 发送确认响应，其中包含已部署 HTML 文件的路径和计时器值。 

该勒索软件模块的设计有几个显著特点。它不加密任何文件，因此不会在文件修改时间戳或加密标记方面留下取证痕迹。它完全依赖屏幕锁定，部署速度远快于文件加密勒索软件。通过注册表 Run 键和自修复循环实现持久化，可确保屏幕锁定在用户尝试关闭后仍然存在，并在系统重启后继续生效。  

植入程序的引导套件准备功能 

该植入程序的引导套件准备模块旨在勘察受害机器的引导固件环境，然后暂存一个引导套件有效载荷文件。  

它执行 bcdedit /enum, 即 Windows 启动配置数据编辑器，并使用用于枚举所有启动项的输出标志，同时隐藏控制台窗口。该植入程序读取完整输出，并按顺序搜索三个特定子串，包括 EFI, Windows Boot Manager 和 Windows Legacy OS Loader。如果找到其中任何一个，则将启动类型判定为 UEFI。该二进制文件还会搜索 ntldr，即 BIOS 模式系统所使用的旧版 Windows NT 加载程序，作为回退选项。根据匹配到的字符串，将启动类型记录为“UEFI”或“BIOS”，长度与相应类型一致。另外，该二进制文件运行一条 PowerShell 命令，调用 Confirm-SecureBootUEFI，这是一条内置 PowerShell 命令，用于返回当前安全启动状态。输出中会搜索字符串 True以检测安全启动已启用，并搜索 False以检测安全启动已被明确禁用。 如果两者均不存在，则将该值记录为 unknown。结果会被发送回 C2，其内容为一个包含启动类型分类和安全启动状态字符串的映射。 

随后，该植入程序会向系统临时目录写入一个名为“bootkit.bin”的 16 字节占位文件。写入的字节以 ASCII 形式表示“NIK_BOOTKIT_PREP”，其作用是暂存标记，而非实际的引导套件二进制文件。该占位文件确认当前进程可写入目标路径，并确定后续操作将引用的文件位置，同时可由通过该植入程序的文件上传或文件写入命令处理程序交付的实际引导套件二进制文件覆盖。暂存文件的路径会在响应中返回给 C2。  

植入程序的数据窃取功能  

当攻击者从 C2 发出窃取类别命令时，植入程序会执行关联的 goroutine，将目标数据收集到受害计算机内存中的结果映射空间： 

Wi-Fi 密码窃取 (wifi_steal) 

植入程序通过 Go 的 exec.Command 函数直接执行 netsh 命令，将参数作为独立标记传入，而不是通过 shell 字符串传递。收集到的结果会按特定标签格式化：明文 Wi-Fi 密码显示在 Key Content: 下，已保存的网络名称归入 WiFi Profiles: （缺失条目使用逐项格式 [%s] not found 标记），执行失败或接口不存在时则返回标准化错误字符串，例如 [WiFi] no wireless adapter or access denied 和 No WiFi profiles found。

浏览器凭据提取 (passwords, quick_steal)

助记词、私钥文件和系统侦察 

该植入程序在受害者的整个文件系统中执行两种正则表达式模式搜索。这两种正则表达式用于扫描文件名中的敏感加密资产和凭据，并以不区分大小写的模式运行 ?i。第一个表达式通过将“seed”“mnemonic”或“wallet”等关键词与常见的纯文本和数据文件扩展名（.txt、.md、.csv、.dat）配对，定位加密货币恢复材料和钱包备份；第二个表达式则使用“private”“privkey”或“secret”等术语，并将其与文本文件及标准加密密钥容器（.key、.pem）配对，以查找非对称私钥和一般机密。由于两种模式均使用未锚定、贪婪匹配（.*），且没有起始（^）或结束（$）边界锚点，因此它们会捕获任何在这些敏感术语之后出现目标扩展名的文件。匹配到的数据以 seed candidates 为标签收集，并归档到“browserdata.zip”中。   

(?i)(seed|phrase|mnemonic|recovery|backup|wallet).*(\.txt|\.md|\.csv|\.dat) 
(?i)(private|privkey|secret).*(\.txt|\.md|\.key|\.pem)

该植入程序还通过执行以下命令对受害者机器进行侦察，并使用 chcp 65001 前缀强制以 UTF-8 格式输出。  

chcp 65001 >nul 2>&1 & systeminfo 
chcp 65001 >nul 2>&1 & wmic os get lastbootuptime /value 
chcp 65001 >nul 2>&1 & wmic /namespace:\\root\SecurityCenter2 path AntiVirusProduct get displayName 2>nul 
chcp 65001 >nul 2>&1 & Get-Process | Select-Object Id, ProcessName | ConvertTo-Json -Compress

所有收集路径完成后，该植入程序会将收集到的全部数据组装成单一文档，外观类似格式化报告，并为每个数据类别设置清晰标注的章节，例如 === CRYPTO ===、=== WIFI ===、=== BROWSER ===。  

键盘记录器：按键输入实时传输至 C2 

该植入程序的键盘记录器模块使用一个持久运行的后台 goroutine，轮询全部 256 个 Windows 虚拟键码，通过动态解析的 API 调用检测按键操作，并传输捕获的输入。当已攻陷的受害者按下有效按键时，输入会同时以 AES-256-GCM 加密的 JSON 载荷通过 WebSocket 实时传输至 C2，并追加到内存缓冲区中；该缓冲区上限为 10,000 条，满时减半，以防止内存泄漏。在攻击者发出 dump 命令时，该缓冲区会被拼接为单个字符串，并通过 WebSocket 返回至 C2，或回退使用 HTTP，从而确保即使网络中断也能完成完整的数据传输。 

窃取数据外传至 C2 

归档组装完成后，完整的结果映射会交由该植入程序的结果传输例程处理。该例程构建一个新的 JSON 对象，其中包含五个特定字段：原命令回显的 command identifier、格式化为 ag_<16 hex chars> 的 agent 持久标识符、设为字符串 quick_steal_response 的 type 字段，以及保存完整结果映射的 data 字段。 

对象构造完成后，会被转发至加密例程。该例程将对象序列化为 JSON，然后生成 12 个新的随机字节作为 nonce。接下来，使用 AES-256-GCM 和由硬编码种子派生的静态密钥对序列化后的 JSON 进行加密。它将 nonce、密文和 16 字节认证标签拼接起来，并对整个载荷进行 Base64 编码。加密后的载荷被放入一个包装对象中，位于 "e" 键下，并与明文 agent ID 一同存放，随后该包装对象被 JSON 编组为最终载荷。 

随后，这个加密载荷通过可用的传输路径发送。发送例程首先检查 WebSocket 连接是否处于活动状态。如果是，则将载荷直接写入现有连接上的 WebSocket 文本帧，从而以最低延迟到达 actor 的面板。如果 WebSocket 当前未连接，该例程会回退到向 C2 服务器上 /api/c2/result 端点路径发送 HTTP POST 请求，并使用相同的加密正文格式。这种双路径设计确保即使在 WebSocket 中断期间，窃取的数据仍能被传送，因为 HTTP 通道不依赖 WebSocket 状态，可独立运行。 

Implant 的 C2 协议 

Implant 的 C2 架构旨在支持两个彼此独立、可同时运行的通信通道。主通道是经由 TLS 建立的持久 WebSocket 连接。辅助通道是 HTTP 轮询循环，按固定间隔向固定的 API 端点发送 POST 请求。 

对于主通道，连接首先通过 TCP 拨号连接到 C2 服务器地址，超时时间为八秒。如果配置的地址中未明确包含端口，则会自动追加端口 443。TCP 套接字建立后，会使用自定义证书配置将其包装在 TLS 会话中；该配置会固定到特定证书，而不是针对系统证书颁发机构存储进行验证。这可以防止标准 TLS 拦截代理观察流量。 

在 WebSocket 握手成功之后，但在收到任何命令之前，implant 会立即发送完整的系统注册消息。Implant 会收集受害者数据，例如计算机主机名、本地 LAN IP 地址、环境中的 Windows 用户名、用户安全标识符、启动嵌入式代理服务器时分配的本地反向代理端口号，以及根据 Windows 注册表代理设置检测到的上游代理配置。所有这些信息都会组装成一个 JSON 对象，加密后发送至 C2。  

HTTP 轮询通道独立运行。大约每 250 毫秒，agent 会收集一份最新的受害者状态快照，包括主机名、watchdog 状态、本地 IP、用户名、当前时间戳和系统运行时间，使用相同的线上格式进行加密，并将其发布到 C2 服务器上的 /api/c2/update 端点。

WebSocket – 执行器命令通道 

两个通道中双向传递的每条消息都使用相同的对称加密方案。启动时，会对存储在二进制数据部分中的硬编码种子值进行解码，生成一个 32 字节的 AES 密钥。 

Decoded AES seed: d791dd0ff3228ed29a8d7333d4567be829159c5632ea347780992006f91c5295 
32-byte AES key: 4887AFC0A574E9419A9695EF083460F58E4EF9A1C40793523CE112251273BDF9

随后，C2 服务器以加密的有效载荷作出响应，其内部映射包含一个命令数组，其结构与通过 WebSocket 传递的命令数组完全相同。通过 HTTP 接收的命令会经由相同的逻辑进行分发。如果 HTTP POST 失败，该代理程序会轮换到下一个服务器地址，然后重试。 

当命令处理程序完成其操作时，植入程序会将结果传输至 C2。结果被打包进一个响应信封，其中包含原始命令的标识符、植入程序自身的标识符、一个由在命令名称后附加 _response 构成的类型字符串、结果数据载荷，以及顶层类型标记 "result"。该对象经过加密后，如果 WebSocket 连接处于活动状态，则直接通过该连接传送；否则通过 HTTP POST 发送至 /api/c2/result。 

植入程序的防御规避和反分析技术 

NIK C2 植入程序部署了一套分层的防御规避措施，这些措施会在启动后立即激活，并贯穿整个入侵会话。启动时，它会通过 API ShowWindow，隐藏控制台窗口；将二进制文件重命名为 Windows 临时目录中的 “csrss.exe”，以冒充合法的系统进程；通过注册表写入操作禁用 Windows“最近使用的文档”遥测；并通过 API NtSetInformationProcess 使用参数值 0x1D 为  ProcessBreakOnTermination 应用关键进程标志，一旦有人尝试通过任务管理器或 taskkill 操作终止该进程，就会导致蓝屏死机。  

此外，两项反调试检查 IsDebuggerPresent 和 CheckRemoteDebuggerPresent 会在检测到调试行为时静默执行并调用 os.Exit(0)，不会留下异常记录或崩溃证据。在 C2 的指示下，该植入程序还可以使用 fodhelper.exe COM hijack 在无需 UAC 提示的情况下提升权限；该方法会将植入程序路径写入 HKCU\Software\Classes\ms-settings\Shell\Open\command，触发权限提升，并在两秒内清理注册表项。 

该植入程序通过执行硬编码的嵌入式 PowerShell 脚本，补丁修改 “System.Management.Automation.dll” 的内存，从而绕过 Antimalware Scan Interface (AMSI)。具体而言，它会将 AmsiInitFailed 字段覆盖为六字节的桩代码 (MOV EAX, E_INVALIDARG; RET)，强制初始化报告失败，并在当前 PowerShell 会话的剩余时间内禁用内容检查。 

结论 

NIK C2 是一种由 AI 赋能的命令与控制框架，它的出现凸显了现代恶意软件设计中的关键转变：从静态入侵工具集转向可按需适应环境的动态模块化植入物。通过将实时 AI 流水线直接嵌入 C2 环路，受感染主机不再是被动的据点，而成为自主作战资产。操作人员可以在受感染主机上动态生成适应上下文的诱饵材料、执行本地化欺骗、汇总作战情报并制作针对性载荷，同时降低传统上实施此类复杂技术所需的技术门槛。
