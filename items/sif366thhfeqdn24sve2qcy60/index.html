Turla 利用 Microsoft Exchange 服务器部署 Cereal 后门窃取邮件

Turla’s Cereal malware turns victims’ Exchange servers into spy hubs

AI 导读

ESET 发现俄罗斯关联组织 Turla 在哈萨克斯坦和罗马尼亚的 2 个政府机构 Microsoft Exchange 服务器上部署模块化 .NET 工具集 Cereal，通过伪装成 Outlook Web Access、Autodiscover 和 ActiveSync 流量的请求接收命令，并筛选发件人、收件人、主题或附件名称后复制邮件。

文章拆解了 Cereal 的指令执行、邮件截取与离线回退机制，并披露了针对政府和北约相关通信的筛选规则。

正文 · AI 翻译
中文原文

与俄罗斯有关联的组织 Turla 在两个政府组织的 Microsoft Exchange 服务器上植入了一套模块化 .NET 工具，其中一个位于哈萨克斯坦，另一个位于罗马尼亚，并利用该工具直接从邮件流中复制选定邮件。ESET 研究人员发现了这一恶意软件，并将其命名为 Cereal。

这套工具不需要由攻击者控制的服务器。操作人员将命令发送至受害者面向互联网的 Exchange 服务器，并将其伪装成普通的 Outlook Web Access、Autodiscover 和 ActiveSync 流量。对任何监控网络的人来说，这看起来都像是人们在查看电子邮件。在罗马尼亚，邮件收集模块被设置为筛选发送给 NATO 和 EU 地址或从这些地址收到的邮件。

“在遭入侵的 Exchange 服务器上，最有趣的活动并不总是用户收件箱中收到的邮件。在某个政府办公室里，一名官员向跨国军事联盟的同事发送了一封邮件。邮件完全按照正常方式通过 Microsoft Exchange 服务器发出，任何迹象看起来都不可疑。然而，就在邮件离开大楼之前，一段代码会悄然检查它，判断其具有值得关注的内容，并留下一份副本，以便转发给窥探者，而原始邮件则继续按原途发送，”ESET 研究员 Matías Porolli 解释道。

两个政府机构，相隔一个月

ESET 于 2025 年 11 月 28 日在哈萨克斯坦的一个政府机构发现了这套工具。在调整检测规则后，该公司发现了罗马尼亚受害者，该机构于 2025 年 12 月 23 日遭到入侵。ESET 高度确信 Cereal 属于 Turla。其依据包括一个公开与 Turla 关联且曾与 Cereal 一同使用的组件，以及它与较早的 Turla 恶意软件之间的相似之处。Turla 又名 Snake，被广泛评估为俄罗斯 FSB 的一部分。

哈萨克斯坦的活动在 2026 年 1 月 15 日激增，这一天是旧新年之后的次日。旧新年是俄罗斯至今仍在庆祝的非正式节日。操作人员似乎把这个假期休掉了。

观察到的攻击中使用的组件（来源：ESET）

后门等待敲门

作为主要后门的 CerealNeuron 驻留在 Exchange 服务器上，监听路径看起来与普通 Exchange 流量一致的传入 Web 请求，例如 /owa/sdds/ 和 /autodiscover/proxyservice/。如果请求经过正确加密并通过多项完整性检查，就会被解密并作为命令执行。其他请求则会收到一个外观合法的 Exchange 错误页面。ESET 无法确定操作人员连接时使用的 IP 地址。实际上，受害者托管了攻击者的命令服务器。

每条命令都以一个小型、已编译的 .NET 程序的形式到达，每个程序只负责一项任务：提取邮箱、查询 Active Directory、提取 LSA 机密（Windows 在本地存储的凭据），或读取并删除文件。大量近乎相同的二进制文件表明，这套命令可能是由一个自动生成命令的框架构建的。第二个后门 CerealHermit 完全绕过网络，从磁盘读取加密的命令文件，为操作人员提供备用手段。

邮件从 Exchange 内部被复制

Turla 过去曾滥用 Exchange 传输代理。这些插件会挂接到邮件流中，执行垃圾邮件过滤等任务，而已注册的代理会出现在 Exchange 配置中。CerealBox 通过将自身注入负责传输邮件的进程 EdgeTransport.exe，并包装已加载到内存中的传输代理处理器来规避这一点。邮件继续流动，并且不会出现新的代理。

CerealBox 会保留带有 .doc、.docx 或 .pdf 附件，且发件人、收件人、主题字符串或附件名称与硬编码列表相匹配的消息。它会对这些消息进行压缩、加密并暂存到磁盘上，供操作人员稍后收集。ESET 表示，此前尚未有任何恶意软件家族被记录过从内部挂钩传输服务的做法。

查看位置

Cereal 的加载器是唯一以可识别的 .NET 文件形式写入磁盘的组件。它会在 .NET 运行时开始执行常规指令之前运行原生代码，因此，分析人员查看其 .NET 代码时，会看到一个似乎什么都不做的程序。在一条攻击链中，它伪装成位于 C:\Windows\System32\wbem 下的 ncobjapi.dll，由 Windows Management Instrumentation 服务自动加载。在另一条攻击链中，它伪装成 wbemcomn.dll。操作人员还会将副本放入 .NET 本映像缓存（一个预编译库文件夹）中，文件名包括 Microsoft.Exchange.Search.Mdb.ni.dll 等。Exchange 会优先加载恶意文件，随后回退到真正的库。
