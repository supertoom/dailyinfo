正文 · AI 翻译
中文原文

数以万计的 GitHub 仓库成为了一场被称为“wfx-loot”的行动的目标，该行动利用恶意工作流窃取 GitHub Actions 密钥和云凭据。

尽管并非所有仓库都运行了有效载荷，研究人员仍确认，该威胁行为者至少从 1,835 个目标窃取了密钥。

该威胁行为者使用了数千个已被攻陷的 GitHub 账户，向这些账户有权访问的仓库发起拉取请求，测试其是否拥有足够的写入权限以注入恶意代码。

部分被攻陷的账户属于《财富》100 强企业、美国总务管理局、法国政府、Nextcloud 和 WebdriverIO。

据应用安全公司 Aikido 的研究人员称，其中约 50 个账户似乎在其他开源软件生态系统和软件包索引（如 npm、PyPI、Go、crates 和 Packagist）中拥有发布权限。

攻击详情

Aikido 表示，wfx-loot 行动始于 11 月 10 日约 12:45 UTC，当时攻击者利用来自 4,837 个被攻陷账户的窃取的 GitHub 凭据，探测了 61,764 个仓库的写入访问权限。

该威胁行为者发起了标题为“docs: dependency audit notes”的拉取请求，伪装成依赖项审计记录。

Aikido 报告称，在这些拉取请求中，92% 仍处于开放状态，表明合法仓库所有者并未注意到这一活动。

随后，他们通过修改现有的 GitHub Actions 工作流、在短生命周期分支上添加新工作流，或植入 npm install 钩子，投放了一个 1,500 行的凭据窃取 shell 脚本。

该脚本试图收集以下数据：

  • GitHub Actions 和变量、工作流的 GITHUB_TOKEN、OIDC 以及 Actions 运行时令牌。
  • AWS、Azure 和 Google Cloud 的云凭据，包括通过自托管运行器上的实例元数据暴露的凭据。
  • 来自 Git、SSH、GPG、Docker、Kubernetes、npm、PyPI、Vault 和 Terraform 的开发人员及基础设施凭据。
  • OpenAI、Anthropic、Gemini、Hugging Face、Cursor 和 GitHub Copilot 的 AI 服务及开发工具凭据。
  • 其他密钥来源包括环境变量、.env 文件、私钥、密钥库、shell 历史记录、进程内存、仓库文件和最近的提交，以及工作流制品。

该脚本还支持云权限提升，方法是将 GitHub OIDC 令牌兑换为临时的 AWS、Azure 和 GCP 云会话。

在 AWS 中，它可以进一步串联利用仓库中存在的其他 IAM（身份和访问管理）角色，“为 IAM 用户创建长期有效的凭据”。它还使用收集到的服务账户凭据冒充 GCP 中的身份。

Aikido 指出，其能力包括在权限允许时，通过创建长期有效的凭据或修改云身份和信任策略来建立持久访问。

该脚本将收集的数据压缩为 tar 包，并通过 HTTP POST 泄露到两个攻击者控制的端点之一。

在最后阶段，攻击者迅速撤销了所作更改，并删除了工作流运行记录和日志。Aikido 表示，整个过程不到一分钟即已完成。

自动发布流程将该有效载荷带入了 Packagist 上的 digitalelvis/neuronai-studio 3.14.3，以及 Go 模块 github.com/onuragtas/docker-env 的两个版本 v1.0.278 和 v1.0.280。

研究人员认为，该威胁行为者的主要目标是窃取 CI 密钥，而这些软件包发布则是自动发布的副产品。

研究人员还发现其与 2025 年GhostAction 攻击活动存在某些重叠。

建议存储库所有者查找 ‘wfx-docs’ 分支、探测拉取请求以及工作流运行编号中的空缺。

一旦确认有效载荷执行，应将受影响工作流可访问的所有密钥和云角色视为已泄露，并立即轮换。
