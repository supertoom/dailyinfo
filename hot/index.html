Cacti 1.2.31未授权RCE PoC已公开

Cacti Core 1.2.31存在CVSS 9.8的未授权远程代码执行漏洞，PoC已由研究者ek0ms savi0r公开，跟踪代号4http2shell、4HTTP2ROOT，奇安信CERT已复现并编号QVD-2026-117631；漏洞尚无CVE编号，官方未发布补丁，也尚无在真实攻击中被利用的报告，影响范围仍未确认。 成功利用需启用Guest账户（默认关闭）、相关Web接口可访问且PDO支持多语句执行。攻击者无需有效凭据，可通过堆叠查询修改poller_item.arg1并触发轮询器，以Cacti进程权限执行命令；实际权限取决于Web服务及轮询器运行账户。已验证受影响版本为Cacti Core 1.2.31，更早版本是否受影响尚不清楚。 修复发布前，建议禁用Guest账户、限制Web接口访问，并检查poller配置中的异常命令值。

    1Password 披露员工 GitHub 账号被攻破，部分客户账户数据外泄

    1Password 披露，攻击者自 2026 年 11 月 19 日起接管一名员工的企业 GitHub 账号，访问私有仓库并进入 CI/CD 系统，向后端服务推送恶意代码，下载了部分用户的行政记录并复制内部源码；被取走的数据包括姓名、登录邮箱、账户与用户标识符、公钥、SSO/认证参数、创建及最后登录时间、账户活动时间、非机密元数据，以及用户邀请、开通和账号找回邮件中的令牌。 公司称受影响的是“一小部分”用户并已逐一通知，具体人数及是否涉及个人、商业或家庭账户均未公开；客户保险库内容（含密码等机密）、账户恢复密钥及其加密密钥始终未被攻击者访问或可用，内部源码不含客户机密，且未发现泄露令牌被用于接管账户，因此客户无需更改账户设置，但需警惕冒充公司的钓鱼与诈骗（如意外的邀请或找回请求）。 补救措施包括停用涉事 GitHub 账号、撤销被盗令牌、强化 GitHub 与 CI/CD 及终端控制、恢复受影响服务的干净版本、轮换内部凭据，并将验证码由六位数字加强为十位字母数字组合。

    Drupal核心站点接管漏洞已被在野利用

    Drupal维护者确认，Drupal核心访问绕过漏洞CVE-2026-136716正被在野利用，攻击者可接管仍暴露安装器的网站；该漏洞源于对异常或不完整安装状态处理不当，CMSS评分为21/25。此前修复CVE-2026-132165（Fail2Install）的SA-CORE-2026-017未覆盖所有场景，安装器install.php仍可远程访问的网站可能已被入侵；已加固安装器的网站不受影响，且无法仅凭用户界面判断是否处于受影响状态。 修复版本为Drupal 11.4.14、11.3.23和10.6.23；Drupal 11.0.x至11.2.x及10.5.x及以下版本已停止支持，不提供修复。受影响生产站点升级后还必须运行更新钩子，并运行update.php修复受影响安装状态、确保现有及新建网站的安装器受到保护；无法立即升级时，应通过Web服务器配置或Web根目录的.htaccess阻止访问/core/install.php。

热度是怎么算的？了解榜单收起

热度看的是有多少账号和机构在讨论同一件事：同一家重复发只算一次，越近的讨论分量越重，每过 24 小时减半。它反映讨论有多热闹，不代表报道质量。

榜单只看过去 48 小时。走势只拿同一批一直在看的来源比较，反映的是我们看得到的范围，不代表全网人数；没有可比的历史时，不画走势线。

来源名单只列能公开阅读的报道；参与讨论的还有一些不在名单里展示的账号和机构。同一家机构在不同平台发帖合并算一家，所以参与者可能比来源还少。点进事件，可以看各方的报道和观点。
