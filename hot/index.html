    微软365中断由软件缺陷引发，钓鱼已确认

    微软最终查明，11月12日Microsoft 365全球中断源于7月引入的软件缺陷，而非网络攻击或AI/Agent；缺陷在特定流量下使服务器失去响应，Teams自动切换网络基础设施后触发级联故障，超过80%的网络网关服务器无响应，另有近14%容量因无关问题离线。微软已开发并向受影响服务器部署修复，Exchange Online事件EX1550543于11月13日解决。 微软威胁情报部门确认，攻击者已借中断实施钓鱼，谎称停机期间邮件将在24小时内删除，诱导收件人点击链接恢复邮件；其安全产品正在拦截该活动。微软建议检查可疑邮件和链接、调查用户点击情况，并审查Safe Links策略。

    Linux NoisyTCP漏洞可远程触发崩溃

    安全研究者 Hyunwoo Kim 披露 Linux 内核 TCP 网络子系统漏洞 CVE-2026-99288（NoisyTCP）；其称，未认证攻击者可通过特制 TCP 数据包利用 SYN cookie 处理与套接字哈希之间的时序竞争，远程触发内核及操作系统崩溃。漏洞已合并至 Linux 主线内核并有补丁发布，但目前没有证据表明已被实际利用；影响规模也未确认。 利用要求目标启用至少两个 RX 队列，或由 RPS 将数据包分散至多个 CPU；竞争窗口较窄，在安静的裸机服务器上可能需要较长时间。该漏洞影响几乎所有 Linux 发行版，以及默认配置下运行 Nginx、Apache 或 SSH 的系统。 无法立即升级或打补丁者，Hyunwoo Kim 建议禁用 SYN cookie，并将接收队列串行化以阻断竞争，但这会削弱对 SYN 洪泛攻击的防护。

    Forescout确认99个协议栈漏洞

    Forescout团队称，利用Claude模型、代码扫描器和AI辅助漏洞研究框架，在10个常用TCP/IP软件栈中确认99个漏洞，其中66个此前未知，52%被评为高危或严重；目前没有报告称这些漏洞已被利用。 团队认为54个新漏洞仍影响最新版，已向相关开发者和维护者报告，部分项目已发布修复，但披露内容未列出具体CVE编号、受影响产品与版本、修复版本或临时缓解措施。调查还涉及一款已停产无线接入点的固件，其制造商也已停止运营。 Forescout称，AI分析用时10小时，研究人员随后用约80小时人工验证，将整体分析周期由约9个月压缩至90小时；AI并未取代专家验证，二进制分析的成本约为源码分析的六倍、耗时约为两倍。

    企业智能体安全治理聚焦身份、权限与责任

    虎符智库提出企业智能体安全治理框架，主张为智能体配置独立身份认证、多层授权和最小权限，并按任务风险、数据敏感性与操作可逆性动态调整自主执行程度；目前未见已确认的实际利用事件或受影响规模。 框架要求对重要数据访问、外部信息发送、关键系统修改及不可逆操作设置独立校验、审批和阻断机制，覆盖部署、运行、监测和处置阶段，并保留行为审计与责任追溯能力；敏感数据、重要业务决策及不可逆任务还需加强人工监督。 报道指出，现行法律框架下智能体不具有独立民事主体资格，其自主性不意味着可独立承担法律责任。发生损害时，赔偿责任仍需结合授权范围、企业管理、员工指令、技术服务提供方义务及各方过错认定。

热度是怎么算的？了解榜单收起

热度看的是有多少账号和机构在讨论同一件事：同一家重复发只算一次，越近的讨论分量越重，每过 24 小时减半。它反映讨论有多热闹，不代表报道质量。

榜单只看过去 48 小时。走势只拿同一批一直在看的来源比较，反映的是我们看得到的范围，不代表全网人数；没有可比的历史时，不画走势线。

来源名单只列能公开阅读的报道；参与讨论的还有一些不在名单里展示的账号和机构。同一家机构在不同平台发帖合并算一家，所以参与者可能比来源还少。点进事件，可以看各方的报道和观点。
