    Java4Shell漏洞获官方补丁，利用条件受限发酵中

    Calif披露的Java4Shell内存损坏漏洞CVE-2026-114938可由特制Base64输入触发JVM崩溃，并在无需认证的条件下实现远程代码执行；Oracle已发布补丁，CVSS 3.1评分为8.1（High），CISA要求立即修补，暂未确认已遭实际利用。Calif将该漏洞评为CVSS v4 9.2；Rapid7早先称其影响Java 17及以上版本，但相关结论当时仍待Oracle或OpenJDK公告确认。 后续公告确认漏洞影响OpenJDK 17.0.6及之后版本，以及Oracle Java SE、Amazon Corretto、Eclipse Temurin、Microsoft Build of OpenJDK、Azul Zulu和Red Hat OpenJDK。漏洞仅涉及支持AVX-512指令的特定x86-64处理器上的硬件加速解码函数；Calif称不存在通用利用方式，攻击者必须针对具体应用向解码器投递恶意Base64数据才能实现代码执行。Calif已公开内存损坏概念验证，但未公开其攻击受影响企业应用时使用的武器化利用代码。

    Apple 拆分并收紧 macOS 27.3 应用权限以限制 AI Agent 数据访问

    Apple 在 macOS 27.3 beta 2 中预览更细粒度的应用权限控制：把 Device Control and Data Access 拆为 System & App Protection Override 与 Accessibility，并为 Full Disk Access 增加透明度，用户可限制应用访问的具体应用或文件夹、查看数据访问范围、要求每次授权，以及查看应用间的控制关系。Apple 称，能力更强、更自主的 AI Agent 会加剧相关数据暴露风险。 这些变化只适用于新的权限请求，用户此前已授予的应用权限仍然有效。使用 Full Disk Access 的磁盘备份应用和使用 Accessibility 的辅助技术应用，可为新安装申请 entitlement 以保留 macOS 27.3 之前的行为。Apple 同时提醒开发者调整引导流程，以处理通过这些 API 仅获得部分文件夹或应用访问权限的情况。

热度是怎么算的？了解榜单收起

热度看的是有多少账号和机构在讨论同一件事：同一家重复发只算一次，越近的讨论分量越重，每过 24 小时减半。它反映讨论有多热闹，不代表报道质量。

榜单只看过去 48 小时。走势只拿同一批一直在看的来源比较，反映的是我们看得到的范围，不代表全网人数；没有可比的历史时，不画走势线。

来源名单只列能公开阅读的报道；参与讨论的还有一些不在名单里展示的账号和机构。同一家机构在不同平台发帖合并算一家，所以参与者可能比来源还少。点进事件，可以看各方的报道和观点。
